## 一、官方能力（★ 先看这三条，它们决定了方案）

| # | 事实 | 出处 | 可信度 |
|---|---|---|---|
| 1 | ★ **官方唯一的滚动容器是「网格视窗」**（`ClientUIGridScrollerControl`）—— **没有独立的滚动条控件** ✗ | `docs/api-cache/mhtakr07vej4.txt:1740-1816` | `[官方原文]` |

★ **`scrollRect` 这个名字官方文档里【不存在】** ✗（grep 0 命中）—— 那是 **Unity** 的概念 ✗ 别按它找 ✓

## 二、两条路

### 甲 · 官方滚动条（★ 更标准，但**要动编辑器**）

**为什么必须动编辑器**：`scrollDirection` **只读** ✗ ⇒ 脚本造不出"横向网格视窗" ✓

**编辑器里要做两样**（★ 我给出逐步清单 ✓）：

1. **做一个「选关按钮」的列表项模板**
   - 新建一个**客户端控件模板**（或复制现有的 `clue` 模板 ✓ 它是现成能用的样本 ✓）
   - 名字随意 ✓（例如 `tpl.level`）
   - 里面放：底图（`bg`）、关卡名（`label`）等你想要的样式 ✓
   - ⚠️ ★ 官方限制：「**仅配置在列表项来源中的模板可应用网格视窗的列表滚动效果**，
     **配置在网格视窗层级下的控件不会应用此效果**」✓ ⇒ 模板要**独立于**网格视窗 ✓

2. **做一个网格视窗，并配成横向**
   - 新建**网格视窗控件** ✓ 名字例如 `levels.grid` ✓
   - **滚动方向 ⇒ 选「横向」** ✓ ← ★ 关键，且**只能在这儿配** ✗
   - **显示滚动条 ⇒ 打开** ✓（`showScrollBar` ✓ 官方白送的滚动条 ✓）
   - **引用控件模板 ⇒ 指向第 1 步那个模板** ✓
   - 位置/尺寸按选关条的可见区域摆 ✓
   - ⚠️ 网格视窗**自己在 `clues.grid` 里**是个活样本 ✓ 可以照着抄配置 ✓

**做完之后我接手** ✓：
- `RefreshItems(n, cb)` 填关卡 ✓（`selbtn.*` 那套脚本创建可以退役 ✓）
- `ScrollToItemAt(index, align)` 做"进选关时回到上次那关" ✓
- `GetItemIndex(item)` 反查点了哪一关 ✓
- ★ 项目里这套**已经有跑通的代码**（线索卡 ✓）⇒ 照抄 ✓

### 乙 · 全脚本（★ 零存档依赖，我全包）

选关按钮**本来就是脚本建的** ✓（`selbtn.N` ✓ 父级 `selbar` ✓）
⇒ 只要在脚本里给它们**加一个滚动偏移** ✓ ＋ 自画一条滚动条 ✓

| 要做 | 说明 |
|---|---|
| **滚动状态** | 控制器上一个 `sel_scroll` ✓（当前偏移 ✓） |
| **施加偏移** | 每帧把 `selbtn.N` 的 x 按偏移摆 ✓（**覆盖规划里的静态位置** ✓）|
| **输入** | ① **左右箭头按钮** ✓（触屏和键鼠都能用 ✓）② 方向键 ✓（官方有 `KeyboardCraftspersonKey36~39` ✓ 但要按"奇匠按键"语义名，别假定玩家绑的就是 `←→` ✓）|
| **滚动条** | 自画：一条**轨道** ＋ 一个**滑块** ✓（滑块长度 = 可见/总数 ✓）|
| **溢出才显示** | 内容不溢出时**不画** ✓（现在 4 关就是这种情况 ✓）|

⚠️ ★ **拖动在离线测不了** —— 项目记录过「模拟器的 pointer **只有 down/up、没有 move**」✗
⇒ 拖动要靠**真机**验 ✓；离线回归只能覆盖**箭头/方向键/溢出判定** ✓
