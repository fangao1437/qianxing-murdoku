## 五 ★★ 踩过的坑（★ 新同学最该先看这一节）

1. ★★ **文字不在 `.gil` 里** ✗ —— ★ 想"往档里填文案"是**做不到的** ✓ 只能编辑器手填或脚本写 ✓
2. ★★ **`.gil` 的坐标是画布绝对坐标** ✓ vs 设计空间 1920×1080 差 5/6 ✓
   ★ **别把 CSS 像素抄进 Lua** ✗；★ 也别凭"看着像"改数值 ✓
3. ★★ **容器坐标放在原点** ✓ —— ★ 父级不在原点时，三方读法会打架 ✓（`win` 的教训 ✓）
4. ★★ **父指针有两处**（`#503` 子列表 ＋ 记录顶层 `#504` ✓）—— ★ 建控件时两处都要改 ✓
5. ★★ **状态块稀疏编码**：0 不写 ✓ ⇒ ★ 读工具必须"缺分量补 0" ✓
   ★（★ 本轮就因为读工具丢"0 分量记录"，**整片弹窗没被查到** ✓）
6. ★★ **模拟器 ≠ 真机** ✗：`hex.*` 点不动 ✓、列表项不实例化 ✓、运行时设的图看不到 ✓
   ⇒ ★ **这三类只能在真机上验收** ✓
7. ★★ **别用 PowerShell 的 `Set-Content`/`Get-Content` 处理中文文件** ✗（会乱码 ✓ 已踩两次 ✓）
   ⇒ ★ 用编辑工具或 .NET `UTF8Encoding($false)` ✓
8. ★★ **"文档里记着这里有个坑" ≠ "坑被填了"** ✓ —— ★ 本轮两次都是：老注释写得好好的，
   代码却是错的 ✓ ⇒ ★ 发现就在**公共库**里修 ✓
9. ★ **`find()` 未命中会永久缓存 `false`** ✓（适配器里的老坑 ✓）⇒ ★ 别用它判"控件是不是刚建好" ✓
10. ★ **一个控件只能有一处权威写** ✗ —— ★ 两处都在写同一个属性 ⇒ 互相抵消、白烧引擎写 ✓
11. ★★ **`root` 在 `.gil` 里原本"没有几何"** ✗（状态块 0 个 ✓）——
    ★ 运行时是**脚本**把它撑成整屏 ✓ ⇒ ★ 屏幕上是对的 ✓、★ **编辑器里它不在画布正中** ✗
    ⇒ ★★ 后果：★ 在编辑器里**新加到 `root` 下的控件**，坐标是相对"编辑器认为的那个位置"写的 ✗
      ⇒ ★ 运行时会整体偏移 ✓（★ 2026-10-16 用户点名修的正是这件事 ✓）
    ★ 修法 ✓：★ `tools/gil/ensure_geom.mjs` 给"状态块为空"的记录**补一块几何** ✓ ——
      ★ `root` = 位置 `(0,0)`（= 画布正中 ✓ `.gil` 的 `#504` 是**中心相对偏移** ✓）+ 尺寸 `1600×900` ✓
    ★ 判据 ✓：★ 补完之后**除 `root` 外一条几何都没变** ✓（模拟器逐条对照 ✓ 见回执 §〇·补7 ✓）
