## 二、742 v13 与 743 两次优化的深度复盘

### 2.1 742 v13 做了什么（`tools/build_742_v13.mjs`，commit `50bc994`）
1. **`apply_screen_hide` 静态查表化**：将页面显隐判断从每次渲染重建逻辑改为模块级 `hide_exact` / `hide_group` 表查表 + `id:match("^([^.]+)%.")`。
2. **`Controller:_render_impl` 节点级存在性复用**：引入局部闭包 `exists_now()`，在 `create_control` 之后，同一节点的多个属性写入与 `rect` 写入共享第一次成功的 `adapter:find(n.id)` 检查结果；写入失败时置 `found = false` 保留重试语义。

- **优点**：逻辑保守、风险极低，在 `tests/shop_cold_render.lua` 上把 `FINDS` 压低了 40% 以上。
- **局限**：
  - 在真实运行时，`adapter:find(n.id)` 命中 `self.controls[n.id]` 只是纯 Lua 哈希表查询（单次耗时纳秒级、不跨越 C# 引擎边界），因此对真实引擎 API 跨界调用数影响几乎为 0；
  - `exists_now()` 是 `for i = 1, #nodes` 循环内的局部闭包，每次渲染每节点仍额外分配 1 个闭包对象；
  - 未触及 `OnUpdate` / `Murdoku.on_update` / `sync_adapt715r` / `Adapter:_index_lookup` 等真正决定手机端发热与掉帧的稳态每帧路径。

### 2.2 743 做了什么（`tools/build_743.mjs`）
1. **压缩 `STATIC_PATH_655` 静态路径表**：将 2,130 条重复带长父前缀的路径按 59 个父目录分组存储，首次查询时再拼接并拆成段数组缓存，内嵌 Lua 从 `933,324 B` 缩小至 `781,574 B`（**-151,750 B / -16.26%**），`.gil` 体积缩小 151.8 KB。
2. **消除 `_render_impl` 部分微分配**：
   - 将 `exists_now()` 提成模块级 `render_exists743`，并把已创建的 `select_ctrl ~= nil` 直接传给 `found`；
   - `last.__rect` 改为原地复用 `rect_record743`（3 处）；
   - 将 `build_layout` 中的 `ICON_ASSETS` 等只读常量表提至模块级；
   - `begin_furn_batch` / `end_furn_batch` 的 `pcall` 去掉匿名闭包。

- **优点**：显著压缩了脚本与存档体积、进一步减少 `shop_cold_render` 查找次数（3,487 → 2,866，-17.8%）与 945 帧全流程 `findCalls`（277,939 → 247,785，-10.8%），且 0 控件记录改动、严格通过 `writeGil` 校验。
- **局限（基于 8,578 节点真实控件树 Profiling 实测暴露）**：
  - 在 `cold_boot`、`nav_flow` 和四个页面的 300 帧稳态基准测试中，**743 与 742 v12 / v13 的引擎跨界 API 调用数几乎完全持平（0.0% 改善）**，稳态 5 秒（300 帧）仍高达 **120,412 ～ 141,909 次引擎调用**、**12.0 ～ 14.7 MB Lua GC 分配**！

## 三、744 深度运行时优化实施方案（24 项精准补丁）

本次优化严格遵守《关键功能清单与性能优化禁区.md》的 **11 条禁区**：
- **不删减任何 `pcall` 保护**（禁区 2）；
- **不替换树遍历自愈机制、不跨帧无校验缓存句柄**（禁区 3）；
- **不触碰 `hex.back` 入口与确认条联动、不删关内 30 帧 `face` 点亮与 `x` 70% 缩放、不删 `art685.mark.overlay` 每帧 `SetAsLastSibling` 复位、不动网格单射与 `gray` 射线关闭**（禁区 1, 4, 5, 8 等）；
- **不改动任何 `.gil` 控件记录**（仅修改唯一内嵌脚本字段，差异精确为 1 处）。

### 3.1 六大优化模块明细

1. **全树索引与缺失查找稳态指数退避（根治 57% CPU 与 75% `GetChildren`）**
   - `Adapter:_build_name_index` / `_index_lookup`：同 `_lookup_gen` 下若连续两次全树扫描节点数相同且非空，索引复核周期按 **`1s → 2s → 4s → 8s → 16s`** 指数退避；一旦 `_lookup_gen` 变更（切屏/切关）或缓存句柄回读 `.name` 失败，立即归零恢复 1s 敏感度并全树重建。
   - `Adapter:find` 缺失项 `_misses`：引入 `_miss_streak`，前 2 次未命中保持 `1.0s`（保证冷启动/切页头 2 秒内迟到控件毫秒级/秒级自愈），第 3 次起按 **`1s → 1s → 2s → 4s → 8s → 16s`** 指数退避；`invalidate_lookups`、`drop_lookup` 或找到控件时立刻清零。
   - `Adapter:enable_cursor`：改为按“现存已找到容器全部 `showCursor == true` 且连续 6 趟 `found` 数量稳定”判定收敛（全找到仍为 3 趟），消除因历史废弃名导致的永久每 20 帧空转；换屏/换关由 `rearm_cursor` 照常重新武装。

2. **`sync_adapt715r` 591 撕边叶按代缓存 + 读回守卫 + 选关卡字号脏检查（根治 91% 稳态 `SetVisible`）**
   - `ADAPT715R_TEARS`（6 组共 591 叶）：完全参照 `adapt715r.background`（649 叶）的 `st.leaves` / `st.leafState` 成熟范式，按 `gen` 缓存 `st.tearKids` 与 `st.tearState`，仅当 `selecting` 变更或 `force` 时批量同步并置顶，全部写入确认后固化。
   - `set_visible(c, want)`：写前先读 `c.active` / `c.visible`，已匹配直接返回 `true`（0 次无效写）。
   - `transform(name, x, y, s)`：写前先读 `GetAnchoredPosition` / `GetLocalScale`，使用严格浮点容差 `tol = 1e-5`（避免 20:9 ↔ 16:9 之间 `0.00194` 级精细缩放被 `0.002` 容差误跳过！），仅当真实变化时才调用 setter 并沿用原 `eps = 0.002` 回读校验。
   - `select.card.1..4.(info|title|result)` 字号重算：仅在 `selecting or force` 时执行，并结合 `{text, cardScale, cur_fontSize}` 三重脏检查，避免切页/稳态重复正则扫描与写属性。
   - `sync_econ742`：缓存上次成功应用的 `{page, cw, ch, scale, active}` 签名与控件句柄，未变且非 `force` 时早退，跳过每 0.25s 的 4 次重复写入。

3. **热路径全量消除 `pcall(function() ... end)` 匿名闭包分配（GC 分配骤降 59% ～ 86%）**
   - 在 `Adapter`、入口脚本与 `Controller` 中定义静态零分配 `pcall` 助手（`p744_name`, `p744_kids`, `p744_child`, `p744_vis`, `p744_set_vis`, `p744_ray_get`, `p744_ray_set`, `p744_cur_set`, `p744_field`, `m744_vis_get`, `m744_vis_set`, `e744_*` 等）；
   - `Controller:_set_prop` 改为 `pcall(adapter.set_property, adapter, id, key, value, nkey)`；
   - `Controller:_render_impl` 的 `find`、`create_control`、`destroy_control`、`play_effect` 均直接传方法与参数；
   - `index_in`、`path_lookup_655`、`enable_raycast`、`enforce_hidden_subtrees`、`murdoku_set_vis`、`help_visible`、`tut_visible`、`write_art_color650` 全部零闭包化，且 **100% 保留全部 `pcall` 保护**。

4. **增量隐藏子树 `Adapter:enforce_hidden_subtrees`**
   - `visible = true` 不再触发全局隐藏子树重扫，且从待隐藏集合移除该 ID；
   - `visible = false` 与 `_note_lookup_hit` 命中已隐藏 ID 时，仅将该 ID 加入 `_subtree_dirty_ids` 增量队列；
   - `invalidate_lookups` 与 `_fire` 保留全量 `_subtree_dirty = true` 兜底；
   - 遍历子控件写 `SetVisible(false)` 前先读 `k.visible`，已为 `false` 不重复下发。

5. **非关内稳态免每秒无故全量 `Murdoku.render()`**
   - `Murdoku.on_update` 中 `sec ~= current.last_tick` 仅在关内（`screen == nil`，存在 `hud.timer`）或上一帧存在待重试迟到控件（`_pending_retry744 == true`）时触发整帧 `render()`；
   - 结算倒计时仍由 `Controller:tick` 独立设 `self.dirty = true` 精确驱动，零延迟。

6. **高频模式匹配去正则 / 首字节快筛**
   - `apply_screen_hide` 用 `id:find(".", 1, true)` + `id:sub` 替代 `id:match("^([^.]+)%.")`；
   - `Controller:_render_impl` 的 `is_select_content744(id)` 与 `path_lookup_655` 动态路由分支均按 `id:byte(1)` 首字节过滤，O(1) 跳过 90%+ 无关控件名的多重模式匹配。
