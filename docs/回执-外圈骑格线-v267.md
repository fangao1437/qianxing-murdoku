## 〇 一句话

内部边在 v265 就骑在格线上了，**唯独外框那一圈还"贴格子内侧"** ⇒ 条形的外沿压在格子边上，
而格子边离外框内沿还差 1–2px ⇒ 这 1–2px 露的是**格子自己的颜色**（截图 8× 放大是一条橙细线）；
四个角上横竖两段的端头也因此错开 4px。v267 把**外圈也改成骑格线**：整圈**向外移半个厚（5px）**。

## 二 改了什么（一行判据）

```
d = outer and (cw / 2) or (pitch / 2)
        ↑ v267：外圈从 (cw − 厚)/2 → cw/2（向外移 厚/2 = 5px）
```

- 外圈条形外沿：格子边 −5px ⇒ **盖住 1–2px 细缝并压到外框内沿约 3px** ✓
- 四个角：横竖两段各越过格线 5px、又各向外多出 4px（长 = cw+8）⇒ **互相搭接**，缺口消失 ✓
- 内部边（v265 的 `pitch/2`）**一个字没动** ✓；尺寸（v266 的四件套）**一个字没动** ✓

## 五 真机待验（导入 `455`，第 2 关 6×6）

1. **外圈**：黑框里侧那条橙细线是否消失；墙是否看起来"就是棋盘的边"；
2. **四角**：左上/右上/左下/右下是否有那个 4px 小台阶（应无）；
3. 顺带确认：内部墙/门位置与前两版一致（这次没动它们）。

若外圈还想再往外/往里：改 `outer` 这一分支的 `cw / 2` 为 `cw / 2 + n`（n 为正 = 更靠外）。
