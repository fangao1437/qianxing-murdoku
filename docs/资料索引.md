## 0. 三十秒版（先看这三句）

1. **客户端控件 / Lua 脚本** ⇒ **只有** `get_client_document`（`list_client_documents` 列目录）。用服务端工具查会 0 命中。

3. **"本项目当初为什么这么定"** ⇒ 先 `00-索引.md`，再 `docs/Lua坑位清单.md` / `docs/显隐所有权与排查纪律.md` / 对应专题 md。

## 3. 资料域②：官方服务端文档 / 节点

**规模（本地实测）**：`docs/community-cache/kb-index.tsv` = **308 行数据 / 269 个唯一标题**（有 39 个标题重名，靠 `path_id` 区分）。

### 3.1 ★★ 核心陷阱：`get_node_info` 索引不全

**实测复现**（2026-10-09 本次）：

```
get_node_info(["发送客户端脚本信号"])  → matches: []  "未找到匹配「发送客户端脚本信号」的节点"
get_node_info(["客户端脚本信号"])      → matches: []
get_node_info(["脚本信号"])            → matches: []
```

**但这个节点确实存在**，有三条独立证据：

| 证据 | 入口 | 可信度 |
|---|---|---|
| 官方正文写着它 | `docs/api-cache/mhbgxf0nynww.txt:174-178`（"通过服务器节点【发送客户端脚本信号】可以向客户端脚本发送信号…`script:RegisterServerSignalHandler`"） | `[官方原文]` |

| 该盲点的完整记录 | `docs/社区资料-交付包/图片核对/图注核对报告.md` §5（L292–300） | `[项目自述]` |

⇒ ★ **"索引查不到" ≠ "不存在"。绝不能用 `get_node_info` 的空结果去下"这个节点没有"的结论。**
⇒ 本项目已有别的文档引用它：`docs/7.1-脚本API速查.md:272,282`、`docs/节点图接线与素材清单.md`、`docs/编辑器搭建指南.md:502`、`docs/网格视窗与计时器-查证结论.md:50`。

### 3.2 查不到节点时的**四条退路**（按顺序试）

1. **换 `get_document`**：按节点所属大类取文档，回复里带 **`related_nodes`**（这是一套**并行节点索引**）。
   实测：`get_document(["组件"])` 除了列出 12 篇文档，还直接返回了 16 条节点片段，来源 `official/guide/mhw66orrrfkm_执行节点.md`、`official/guide/mh2crq9jzueq_查询节点.md` 等（**这两个是知识库侧路径，不在本机磁盘上**，见 §12）。
2. **本地 grep 官方正文缓存**：`docs/research-raw/kb-docs.json`（162.8 KB）、`docs/community-cache/kb-all.json`。
   ⚠️ 但见 3.3：**本地缓存不全**。
3. **grep 纯文本转储**（最快）：`docs/research-raw/_api.txt`（68.6 KB）、`_rag-flat.txt`（80.5 KB）。
4. **`rag_search`**（自然语言兜底），⚠️ 语料偏社区，见 3.4。

## 8. 查证纪律（这些坑都真实踩过，别再踩）

### 8-1 ★「查不到」≠「不存在」
本轮实测到**三处**同类假阴性，都是"索引/缓存不全"而不是"东西没有"：

| # | 现象 | 真相 | 出处 |
|---:|---|---|---|
| 1 | `get_node_info("发送客户端脚本信号")` → 0 命中 | 节点**存在** | `docs/api-cache/mhbgxf0nynww.txt:174-178` + `p33-01.png` |
| 2 | `list_documents("网格视窗")` → 0 命中 | 文档**存在**，在客户端索引里 | `list_client_documents` 返回 10 篇含《网格视窗控件》 |
| 3 | `kb-all.json` 里 grep 不到 | **24 个唯一标题没有缓存的正文** | §3.3 统计表 |

⇒ **规矩**：任何"没找到"的结论，必须写**"我查了哪几个入口"**；只要还有一个入口没试，就不能说"没有"。

### 8-2 ★「扫过文本了」≠「扫过内容了」
上一轮报告说"4 个文件 **0 隐私命中**"，但**它扫的是文本**，而隐私（玩家 UID / 本机路径 / QQ 群）
**是 base64 嵌在图片里的** ⇒ 文本扫描**永远看不到**。把图导出来一看，**立刻命中**。
⇒ 出处：`docs/社区资料-交付包/图片核对/图注核对报告.md` §4.1（L227–230）。
⇒ **规矩**：下"扫描通过"结论前，先问**"我的扫描器覆盖了哪些载体"**（文本？图片？二进制？元数据？）。
   覆盖面不足时，只能说"**在这类载体上未命中**"，不能说"没有"。

### 8-3 ★ 社区资料必须标可信度，不许当官方用
统一三档，回答里**必须**打标：

| 标签 | 什么时候用 |
|---|---|
| `[官方原文]` | 出自官方文档正文 / 官方节点说明 / 官方配图（能给出文件名或 id） |
| `[社区说法]` | 出自讲义、米游社问答楼、第三方站、`rag_search` 的 `bbs-faq*` 命中 |
| `[无法证实]` | 官方文档里**找不到对应条目**（注意：≠ 错，只是"我不替它背书"） |

⇒ 实测依据：讲义 23 条断言里 **6 条无法证实**（`验证报告.md:442,457-464`）。
⇒ `rag_search` 更是**六成命中来自社区问答**（§3.4）⇒ **看 `file_name` 再决定打什么标**。

### 8-4 ★ 抽样 ≠ 全量，说清抽了多少、怎么抽的
写"可达率 92.6%"时必须同时写"**抽样 68 条**"（`社区资料与模拟器-索引.md:119`）。
本项目还有一次**抽样作废**的记录（`验证报告.md` §2.5，L303）—— 抽样方法本身也要复核。
⇒ **规矩**：报数字必须带 `n=`，并说明抽样口径；**全量统计和抽样估计要分开写**（本索引 §3.3、§3.4 是全量统计，已标注）。

### 8-5 ★ 报告结论要给「命令 + 实测读数」，不要只给结论
反例：只写"编码没问题"。正例：
```
node tools/check_encoding.mjs
== 编码/BOM 哨兵 ==  检查 458 个文件
  ✓ 全过（.lua/.mjs/.md/.json 无 BOM ✓）
exit=0
```
⇒ **规矩**：每条结论后面跟一行"怎么得到的"。**没给读数的结论按未验证处理。**

### 8-6 ★ 不要相信文档标题/概述里的计数
实测三例：`验证报告.md` §4.1 标题写"对照表（16 条）"**实际排到 #23**；
`docs/总目录.md` 说基线是 `完整界面53-选关翻页.gil` 而**该文件不存在**；
控件数在**三份文档里是 371 / 150 / 123**。
⇒ **规矩**：引用计数/版本前，**打开文件数一遍**，或改用自动生成的文件。

### 8-7 ★ 不要用 HTTP 状态码判断页面是否存在
`act.mihoyo.com` **任意路径都回 200**（本次用伪造 id 复现）。

### 8-8 ★ 编码规则在本项目是**两个方向**的
