## 二、对齐口径

- 实机截图 1604×960，白色标题栏到 y≈58 ⇒ 游戏画布 **`crop(4,58,1600,900)`**。
- 原始设计图 1280×720 ×1.25 ⇒ 设计坐标 1600×900。
- **实机截图与 `police-v10.png` 离线导出逐像素一致**（背景采样差 0~1），因此可以完全离线迭代，不必反复真机导入。

### 本轮新踩的坑（可复用）

1. **旋转符号**：`rotation=+r` ⇒ 右端更高；`−r` ⇒ 右端更低。设计图拍立得顶边斜率 −0.113 ⇒ 应为 **正角度 +8**，不是负角度（用 `rottest-*.png` 四组基准实测确认）。
2. **半透明条带不能重叠**：把渐变拆成 18~60 条带 `opacity` 的半透明矩形，相邻条带重叠 2px 会产生规律竖条纹；拍立得硬边投影 `opacity=0.95` 也会透出底下的渐变条。改成**不透明实色条带直接算混合色**、投影 `opacity=1` 后条纹消失。
3. **多边形扫描填充的步长**：7px 步长会让近竖直斜边出现明显阶梯；不是刚体矩形的形状一律用 ≤3px 步长，或保留刚体旋转矩形（1 个图元、边缘平滑）。
4. **袋体不是透视四边形**：左/右边缘拟合斜率都是 0.270~0.272（θ≈15.2°），底部那片浅橙折角是独立三角形，不是袋体变形；因此沿用刚体旋转矩形最稳。

## 四、复现

1. 改 `scene-v11.json`（或 `build-v11.cjs` 顶部常量）；
2. `node build-v11.cjs` → 拼图站 `/api/export/{gia,png}`；
3. `node verify-v11.cjs` 查 root 层；`artkit.mjs check --kind=gia --file=<...>` 查容器；
4. `.gia` 放入 `BeyondLocal/Beyond_Local_Export`，游戏内「导入外部资产 → 转存所选资产」。

## 五、未验证 / 已知差异

- **未做 v11 真机导入验证**；链路与 v10 一致（v10 已成功导入），但需用户截图复核。
