# 左侧线索区 · 编辑器摆放清单（封包第 4 块剩余部分）

> 为什么这一步**必须你来摆**：文字控件的硬前提（下有证据）。
> 摆完之后**剩下的全部由脚本完成**（填文字、显隐、滚动、点选）。

---

## 〇、先说清楚那个硬前提（这决定了分工）

**文字存不进 `.gil`，只能脚本写；但脚本也建不出文字控件 —— 它只能建"模板里本来就有"的东西。**

- 脚本能用模板建出的三类控件，各自带什么子控件（真机日志 + `.gil` 记录双向核对）：

  | 模板 | 索引 | 建出来的东西 | 子控件里有没有文字 |
  |---|---|---|---|
  | 格子 | `1073741876` | 能点、能设图 | **没有**（日志：`没有配的：text obj`）|
  | 纯图片 | `1073742357` | 只能显示一张图 | **没有** |
  | 容器 | `1073742330` | 只能当容器 | **没有** |

- 而 `.gil` 里**所有**带 `label`（文字）的记录，都在**编辑器摆的按钮**下面：
  `home.select` / `home.continue` / `home.shop` / `home.bag` / `action.back` —— 每个 59×40 或 120×40。
  ⇒ 脚本能写它们的文字（日志：`home.select 想要 "选关" → 读回 选关`），但**前提是它们先在编辑器里存在**。

⇒ 结论：**线索卡要显示文字，就必须先在编辑器里摆出带 `label` 的控件。**

## 二、头像调色板：`assets` 容器（日志末尾那条报错就是缺它）

真机日志原话：

```
调色板里没有素材「portrait.A」。
   建法：在编辑器里放一个容器（默认名 `assets`），每个素材放一个**图片控件**，
   控件名就是引用键（例如 `room.kitchen`），图在编辑器里配好。
   当前调色板：（空 —— 找不到 `assets` 容器？）
```

| 控件名 | 父级 | 说明 |
|---|---|---|
| `assets` | root | 调色板容器（**可以放在画布外/收起，它不需要显示**）|
| `portrait.A` … `portrait.E` | assets | 每个嫌疑人一张头像（**图片控件**，名字就是引用键）|

> 没摆之前，脚本会把头像那格**留空**（不报错、不影响其它功能）。

## 三、摆好之后脚本负责什么（你摆完只要说一声）

| 脚本做的事 | 依赖 |
|---|---|
| 按关卡数据算出每张卡的「角色名 / 线索正文 / 字母」并写进 `.who` / `.what` / `.letter` | 上面那些**文字控件** |
| 按角色切 `face` 的图（`portrait.X`）| `assets` 调色板 |
| 超出一屏时用 ▲▼ 滚动（`clues.up/down`）| 那几个按钮 |
| 点卡片 = 选中该线索（高亮，图上第 2 张是选中态）| 卡片本身可点 |
| 首页/选关时整块藏起来 | 已有逻辑，`clues.` 前缀已在隐藏名单里 |

## 四、摆的时候三个要点（都是踩过的坑）

1. **文字控件的名字**要**正好**是上面那几个（`clue.1.who` 等）—— 脚本是**按名字找**的，差一个字符就找不到。
2. **卡片本身要是"能收光标事件"的控件**（和 `home.select` 一样的预设按钮）——
   纯图片控件建出来的那些真机验证过**不支持光标事件**（日志：`控件 hex.* 不支持光标事件`）。
3. **摆完请重新「存为模板」**（如果你想让某种卡能被脚本批量复制）——
   否则模板存的是**那一刻的快照**，之后加的子控件不会跟着进副本。
   ⚠️ 但**这一步不需要模板**：脚本直接用你摆的这 5 张卡循环复用。
