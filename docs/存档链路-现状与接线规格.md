# 存档链路 —— 现状、断点与接线规格

> 建档：2026-10-13　｜　构建标记 **v222 → v223**
> ★ 用户提问：「**查询存档相关链路，这条路还没通**」✓ 本文是查证结果 ✓
> ★ 结论先说：★★ **客户端这一侧【已经通了】✓；断点在【服务端节点图】那两条 —— 一条都没接 ✗**

---

## 一 ★★★ 一句话定位

```
【客户端】UI 存档键 → save_now() → adapter:save()
                                       ├─ 本地缓存（内存）      ✓ 已有
                                       └─ 发 murdoku/save 信号  ✓ 已有
                                                  ↓
【服务端】★★ 【监听信号 murdoku/save】→ 写自定义变量     ✗★ 未接
                                                  ↓
【服务端】★★ 【实体创建时】→ 读变量 → 【发送信号 murdoku/restore】  ✗★ 未接
                                                  ↓
【客户端】signal_on(RESTORE) → Murdoku.restore()          ✓ 已有（在等信号）
```

⇒ ★ **两头都建好了，中间那两根管子没接** ✓

## 二 现状：客户端这一侧（**逐行可核**）

### 2.2 读档（读）—— **有两条路**

| 路 | 触发 | 位置 | 说明 |
|---|---|---|---|
| **① 本地** | 进关时 `opts.restore_save` | `main.lua` **L488-498** | `adapter:load("murdoku/save/<关卡>")` ⇒ `core:decode_state` + `set_elapsed` |
| ★ **② 服务器** | 收到 `murdoku/restore` | `main.lua` **L479-481** → **L2345-2359** `Murdoku.restore` | `signal_on(RESTORE, …)` **已注册** ✓ 收到就 `decode_state` + `set_elapsed` + `render(true)` ✓ |

### 2.3 ★★ 两条路的分别（这就是"没通"的用户可感表现）

★ **路 ① 是内存缓存** ✗ —— `Adapter:load` 读的是 `self.state[key]`，那是个 **Lua 表** ✓
　 ⇒ **一旦退出关卡 / 重进游戏，这张表就没了** ✗ ⇒ **存档就丢了** ✓

★ **路 ② 才是真正的"跨会话存档"** ✓ —— 但它**在等一个永远不会来的信号** ✗
　 因为服务端那两条**一条都没接** ✓ ⇒ ★ **所以玩家看到的：存档像是存了，重进就没了** ✓

## 三 ★★★ 断点：服务端要接的两条（**这就是本次要做的**）

### 3.1 信号参数表（★ 两张表的**个数不一样**，最容易错）

| 信号 | 参数（**严格按序**）| 个数 |
|---|---|---|
| ★ `murdoku/save` | `level_id`**字符串** · `state_code`**字符串** · `moves`**整数** · `elapsed`**整数** · `solved`**布尔** | ★ **5 个** |
| ★ `murdoku/restore` | `state_code`**字符串** · `moves`**整数** · `elapsed`**整数** · `solved`**布尔** | ★ **4 个**（**没有** `level_id` ✗）|

★ 出处 ✓：`engine_adapter_qianxing.lua` **L73-74** 的 `M.SIGNAL_SCHEMA` ＋ **L5701-5710** 的 `_save_params` ✓
★★ **`save` 有 5 个、`restore` 只有 4 个** ✓ —— 这个不对称是本文档最值得盯的一处 ✗✓

### 3.2 第 1 条：【监听信号 `murdoku/save`】→ 写变量

```
【监听信号 · murdoku/save】▷
   ├─→【设置自定义变量】目标实体 = 关卡实体
   │        变量名 = murdoku_save_state    变量值 ← 参数 state_code（字符串）
   ├─→【设置自定义变量】… 变量名 = murdoku_save_moves   变量值 ← moves（整数）
   ├─→【设置自定义变量】… 变量名 = murdoku_save_elapsed 变量值 ← elapsed（整数）
   ├─→【设置自定义变量】… 变量名 = murdoku_save_solved  变量值 ← solved（布尔）
   └─→【设置自定义变量】… 变量名 = murdoku_save_exists  变量值 ← ★ **常量「是」**（不用接线）
```

★ **为什么拆成 5 个变量而不是存一个结构体** ✗ —— 官方明确：
　 **局内存档不支持结构体 / 字典，只能存基本类型** ✓
　 （这条本项目踩过：早期版本试图存整张表，写不进去 ✓ 见 `docs/节点图接线与素材清单.md` §2.2 ✓）

★ 前 4 个是**数据** ✓；第 5 个 `murdoku_save_exists` 是**开关** ✓（见 §3.3 ✓）

### 3.3 第 2 条：【实体创建时】→ 发回 `murdoku/restore`

★★★ **2026-10-13 订正：判断"有没有存档"改用一个【布尔变量】当开关** ✗✓
　 本文件**上一版**写的是「`state_code` 非空才发」✗ —— 那要一个**字符串比较节点** ✓
　 ★ 而**它的确切名字我没查到** ✗（知识库索引不全 ✓ 本项目已知"查不到 ≠ 不存在"✓）
　 ⇒ ★ 改用 **`murdoku_save_exists`（布尔）** ✓ ⇒ 判断就变成把**一个布尔值**喂给【双分支】✓
　 ⇒ ★ **全程只用已核实的节点** ✓ 不用猜名字 ✓

```
【实体创建时】（挂在【关卡实体】上）▷
   ⇒【双分支】条件 ← 【获取自定义变量 murdoku_save_exists】的「变量值」（布尔）
        ├ 【否】⇒ ★ 空着不接 ✓（没存档，不发 ✓）
        └ 【是】⇒【发送信号 · murdoku/restore】▷
                   参数1 = murdoku_save_state   的变量值（字符串）
                   参数2 = murdoku_save_moves   的变量值（整数）
                   参数3 = murdoku_save_elapsed 的变量值（整数）
                   参数4 = murdoku_save_solved  的变量值（布尔）
```

★ **5 个【获取自定义变量】都是查询节点 ⇒ 没有 ▷、不需要执行流** ✗
　 ⇒ ★ **整条链只有 3 条执行流**：`实体创建时 ▷ → 双分支 ▷ →（是）发送信号 ▷` ✓
　 （它们的「目标实体」都接 `实体创建时` 的 **`事件源实体`** ✓ 一条线扇出即可 ✓）

★ **为什么用【实体创建时】而不是「关卡开始时」** ✗ —— 官方 FAQ 原话 ✓：
　> 「我想在游戏开始/关卡创建时就触发事件执行逻辑，但是没有找到关卡开始时类似事件？
　> 　A：建议在**关卡实体（LevelEntity）上挂载节点图，用【实体创建时】事件**来实现此效果」

★ **为什么必须加这个门** ✗ —— 官方【获取自定义变量】：「如果变量**不存在**，
　 则返回类型的**默认值**」✓ ⇒ 没存档时读到的是**空字符串** ✓
　 而 Lua 里**空字符串是真值** ✗ ⇒ 客户端的 `restore()` 会**拿着空串去 `decode_state`**
　 ⇒ **读档失败**（会打一行 `[murdoku] 读档失败：…`）✗ ⇒ **所以必须挡掉** ✓

★ **【发送信号】的用法** ✓（官方《信号》§四）：
　「在节点图中放置了发送信号节点后，**需要先选择【信号名】**；
　 　选择【信号名】后，该节点的**入参会新增**这个信号名对应的信号的所有参数」✓
　 ⇒ ★ 所以参数**不用手填**，选完信号名后按序接上去就行 ✓

## 四 ★★ 变量要声明在哪个实体上

★ 和结算那次同一个结论 ✓：**声明在【关卡实体】上** ✓
　 ⇒ 因为节点图挂在关卡实体上 ✓、`目标实体` 接 `事件源实体` 就是它 ✓

★★ **五个变量**（都在关卡实体的「自定义变量组件」里声明 ✓）**—— 2026-10-13 由 4 个订正为 5 个** ✗✓：

| 变量名 | 类型 | 默认值 | 用途 |
|---|---|---|---|
| `murdoku_save_state` | **字符串** | 留空 | 局面压缩码 |
| `murdoku_save_moves` | **整数** | 0 | 步数 |
| `murdoku_save_elapsed` | **整数** | 0 | 用时 |
| `murdoku_save_solved` | **布尔** | 否 | 是否已破案 |
| ★ `murdoku_save_exists` | **布尔** | 否 | ★ **有没有存档（当开关用）** |

★★ **类型必须与信号参数类型【完全一致】** ✗ —— 官方 FAQ 反复强调：
　「保证从**发出、查询、监听**所有节点的数据类型都和目标自定义变量数据类型**相等**」
　否则 ⇒ **静默不生效** ✗（不报错、只是不写入 ✓ 本项目最常见的失效形状 ✓）

★ **声明之后别改名字或类型** ✗ —— 官方：「会导致节点图中相关节点**无法执行**」✓

★ 变量名**不要重名**：同一个实体上自定义变量不能重名 ✓

## 六 ★★ 已知坑（动手前知道）

| # | 坑 | 说明 |
|---|---|---|
| 1 | ★★ **`save` 5 参 / `restore` 4 参** | 最容易把 `level_id` 也接到 `restore` 上去 ✗ |
| 2 | ★ **变量类型不匹配** | 静默不生效，不报错 ✓ |
