## §1 架构：家具改"模板化"，和 cell 同一条实例化路径

```
格子 cell.r.c 的 content/furn  ← 脚本按"这一格是哪件家具"实例化对应模板
        └─ furni.cell.r.c（模板实例，1 条 = 1 层）
              └─ L01…L12（模板里该件的全部图层：imageId/颜色/尺寸/位置）
```

- **每件家具一个客户端控件模板**（7 个）：`furn.chair`(9 层) / `furn.plant`(10) / `furn.statue`(10) /
  `furn.table.1`(10) / `furn.table.h2`(10) / `furn.table.v2`(10) / `furn.shelf`(12)
- 模板画布：单格件 108×108，横长桌 216×108，竖长桌 108×216（按原作比例单独一套）
- 实例化 **完全照 cell 的路**：`game.InstantiateClientUIControl(模板源 GUID, 父容器)`；
  模板源 GUID：1073746900 / 6902 / 6904 / 6906 / 6908 / 6910 / 6912（integrator 扫档确认，与建议号段一致）
- 落位：实例挂**锚点格的 `content/furn`**，尺寸 = 跨格数 × 格子尺寸，位置 = 整件中心相对该格中心（`furn_offset`）
- 缩放：模板层按 108 基准写死 ⇒ 脚本实例化后按 `f = 格子宽/108` 缩放子层（5×5 为 1:1，6×6 为 ≈0.83）
- 地毯仍走 3 层手搭（逐格切矩形），**不进模板**（它是跨格连续图形）

## §3 用户是否需要手动引用？—— **生成阶段不需要**

integrator 已**纯写 .gil** 完成：7 对模板（源 + 母本，各带一棵 content 子树，共 142 层）+ 7 个 `tpl.furn.*` 引用控件
（父 `fart.tpl` 隐藏容器）。四闸、roundtrip 逐字节、真撞号 0、幂等同 SHA 全过。

**唯一风险**：纯写出来的模板**从未上过真机**，不能 100% 保证 `InstantiateClientUIControl` 认它。
若真机上家具**整批不出现**（日志会有 `家具模板实例化失败 … 返回 nil`），才需要你做 4 步最小手工回退：
1. 编辑器 → 界面控件组管理 → 界面控件组库 → **客户端控件模板** →【添加客户端控件】→ 类型选「容器节点」；
2. 名字精确填 `furn.chair / plant / statue / table.1 / table.h2 / table.v2 / shelf`（7 个，**不用摆任何子控件**）；
3. 每个点「**存为模板**」；
4. 把存档给我 → 我用工具按名字找到 7 对，**自动填 71 层（两份拷贝）+ 引用控件**，其余不动。
