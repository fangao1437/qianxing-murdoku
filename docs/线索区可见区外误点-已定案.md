| # | 试过的判据 | 真机结果 | 版本 |

| 4 | **按位置·分时机**（只在引擎重进时判 ✗） | ✗ ★ **布局【之后】七项仍是同一个值** | v106 |

### ★★ 第 4 条是决定性的（v106 真机日志原文 ✓）

⇒ ★★ **"可见窗口起点"拿不到 ⇒ 区外判定无从下手** ✗ —— **这是硬限制，不是没找对 API** ✓

## 二、★ 两条结构方案（都不依赖"读窗口"✓）

### 甲 · **让视窗容得下全部内容**（不滚动 ⇒ 没有"区外"✓）

★ **思路**：`clues.grid` 现在 **400×544** ✓，而 7 条线索要 **20+7×96+6×8+20 = 760** ✗
　 ⇒ 只要**视窗高 ≥ 内容总长** ✓ ⇒ **列表不滚** ✓ ⇒ **不存在"区外"** ✓ ⇒ **问题消失** ✓✓

- ★ **改存档即可** ✓（`clues.grid` 的几何 ＋ 必要时 `clues` 容器 ✓）—— **我能直接做** ✓
- ⚠️ **代价**：★ 视窗变高 ⇒ **可能要挤掉别的区域** ✗ —— 得看 900 高的画布放不放得下 ✓
  （线索卡 96 高 × 7 = 728 ＋ 边距 40 = **768** ✓ 而屏高 900 ✓ **理论上放得下** ✓ 但要和棋盘让位 ✗）
- ★ **适合**：线索条数**固定且不多** ✓

### 乙 · **由脚本接管滚动**（★ 推荐 ✓ 而且它**就是用户要的滚动条**✓）

★ **思路**：★ `scrollProgress` 是**读写** ✓（官方 ✓）⇒ **脚本自己设滚动位置** ✓
　 ⇒ ★ 那就**由脚本记住窗口起点** ✓ ⇒ **能算可见项** ✓ ⇒ **能关掉区外的射线** ✓✓

要做三件事：
1. ★ `interactable = false` ✓ —— **关掉引擎自己的滚动** ✗（官方"是否可交互" ✓）⇒ 滚动权收归脚本 ✓
2. ★ **脚本写 `scrollProgress`** ✓（按"当前第几页 ÷ 总页数" ✓）
3. ★ **画一条自己的滚动条** ✓（`clues` 下 **已经有** `clues.track` / `clues.knob` / `clues.up` / `clues.down`
　 　/ `clues.bar` / `clues.count` / `clues.more` 这些**名字的设计** ✗ —— 真机日志的"还没建"名单里有它们 ✓
　 　⇒ ★ 说明**老路径本来就设计了自绘滚动条** ✓ 现在网格路径把它丢了 ✗ ⇒ **捡回来即可** ✓）

- ★ **同时解决两件事** ✓：① 区外误点 ✗ ② **用户要的滚动条** ✓
- ⚠️ **风险**：★ `scrollProgress` **写**得进吗 ✗（读是 `nil` ✗）—— ★ **需要一次真机验证** ✓
- ★ **适合**：★ **这是用户"要滚动条"那条需求的正确底座** ✓
