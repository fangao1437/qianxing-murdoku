### ①a 倒计时跟随换位
`modal.settle.countdown` 504 y **−200 → −95**（4 个状态同改，x/w/h 不动）。
−95 = 682 相对布局（结算键 −40 下方 55）随 683 整体 −108 后的落点。真机已有 `cancel.settle_shift = 30` 让「取消」下移腾位（用户截图第三、四键间距 107 vs 80 可证），因此 −95±20 与让位后的取消胶囊顶 −120 留 5px、与结算键胶囊底 −70 留 5px，**不重叠**。
`result.settle.countdown`（−258，684 已随结算四键换位）、`settle.btn.countdown`（−339，对应结算按钮从未换位）**保持不动**。

### ①b 恢复未启用结算变灰
`enabled` 分支保留原 `bg` 逻辑，并沿 `art` 容器遍历 6 个图片子层：

| 状态 | 3 层描边 `art683.*.outline.*` | 3 层填充 `art682.*.capsule.*` |
|---|---|---|
| `value=true`（可结算） | `#FF6C402E` | `#FFFCECD4` |
| `value=false`（未启用） | `#FF686B70` | `#FF686B70`（沿用原 Lua 灰值） |

`SETTLE_ART_TINT`（右下角结算票券 20 层）由 `sync_art647()` 每帧处理，本来就生效，本轮**未动**。

### ② 首页网格纸回设计位（两处真正分开调整）
**48 个静态子层与父层逐字节不改**（game 屏位置保持 686 现状），只改 `sync_art641()`：

```lua
-- home / select（原 0, 0）
local dx, dy = 0, 40.5
-- game 分支逐字不动
if screen == "game" then dx, dy = 105, 46 end
```

存档 y 向上为正 ⇒ home 父容器抬 40.5，首页网格纸回到 656 设计位；game 仍 (105,46) ⇒ **零变化**。这正是 680 已证实的「真机 Lua 覆盖父坐标」机制，用它做分屏而非改共享子层。离线预览需模拟该覆盖才与真机一致（`渲染对照687.mjs` 已按此画）。

## 四、边界 / 真机待验

1. **本版未导入游戏**。需真机确认：① 倒计时 −95 在真实字体度量下是否仍与「取消」胶囊留足间隙（离线算 5px；若偏挤可把 `cancel.settle_shift` 从 30 调到 34~36，倒计时同步微调）；② `art:GetChildren()` 在真机返回的 6 个子控件确实带 `imageColor` 且 `k.name` 可取（取不到时只是不染色，不会报错，分支用 `pcall` 包裹）；③ `sync_art641()` 在首帧 / lookup_gen 变化时能否把 home 的 (0,40.5) 下发（该分支只在切屏时执行，686 的 685 教训已确认此机制可靠）。
2. **网格纸回位量 40.5** 按 656 设计位与用户两张图量测得出。若真机觉得首页网格纸偏高/偏低，只需改 `sync_art641()` 里 home 的 dy 一个数，静态层与 game 屏都不用动 —— 这正是「分开调整」的收益。图2 与图3 的其它差异（卡片位置、教程圆按钮、便签、回形针、咖啡杯、按钮文字等）**按用户要求一律未动**。
3. 小叉热区取整后的 float32 落盘值为 **46.102291107177734**（规格设计值 46.10229206085205），差异 1e-6 量级，无视觉影响。
4. `dist/client_script.lua` 未重打包；源码已同步，将来重新 bundle 需重跑本轮全部闸门。**本轮未提交/推送 Git**。
