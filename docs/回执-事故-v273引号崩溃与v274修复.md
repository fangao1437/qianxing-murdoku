# 回执 —— 事故与修复：v273 构建标记里的 ASCII 引号（→ v274 交付）

> 日期：2026-10-18 ｜ 事故版本 **v273**（`存档/461-去教程-v273.gil`，**已改名为"编译失败勿用"**）
> 修复版本 **v274** ｜ 交付 **`存档/462-修v273引号崩溃-v274.gil`**
> 用户反馈：导入 v273 后编辑器弹「校验失败 / 脚本编译报错：`client_script.lua:20735: '}' expected near '<\1232>'`」

---

## 一 根因（是我的操作失误，不是逻辑改动）

v273 的构建标记说明是我**用 PowerShell 手写**的，里面带了 **ASCII 双引号**：

```lua
print("[murdoku] ===== 构建标记 v273 / … / 优化组：老计划里"还没实现的"开始清 —— …")
                                               └── 这两个 ASCII 引号把字符串**提前截断**了
```

⇒ Lua 在 `……老计划里` 处就结束了字符串字面量，后面的 `还没实现的` 被当成代码 ⇒ **`'}' expected`**。

- 报错行 `20735` 正是构建标记那一行（我在本地复现过：`lua53check` 报同一行同一个错）。
- **不是** `ui_controller` 的逻辑改动问题：去掉引号后整包 5.3 编译通过，35 套回归全绿。

## 二 为什么没在上交付前发现（这一点更重要）

本项目**本来就有两道闸**能抓住它，是我这轮**都没跑**：

| 闸 | 是哪一步 | 它会怎么报 |
|---|---|---|
| `node tools/lua53check/check.cjs dist/client_script.lua --run` | `check_all` **5/13** | 直接报 `20735: ')' expected`（我本地复现就是这个） |
| `powershell -File tools\lua_quote_scan.ps1` | `check_all` **2g** | 专门抓"一行里 ASCII 双引号个数为奇数"——这个坑项目里**已经踩过 4 次** |
| `lua tests/*.lua`（我跑的 35 套） | 离线回归 | ✗ **抓不到**：`entry_smoke` 用 `pcall` 包着加载，语法错被吞成一条失败断言之外的静默 |

⇒ 责任在流程：**"35 套全绿"不等于"包能编译"**。这两道闸以后每批收尾必跑。

## 三 修复内容

1. `lua/entry_client_script.lua`：标记里的 ASCII `"` → 中文书名括号 `「」`（`老计划里「还没实现的」开始清`）；
2. 顺手把版本推到 **v274**，并在说明里写明"修 v273 的引号崩溃"（这样日志首行能一眼区分坏档与好档）；
3. 重新打包 → 重新 embed → 新交付档 `462`；
4. 坏档 `461-去教程-v273.gil` **改名为 `461-去教程-v273-编译失败勿用.gil`**（保留证据，别误导入）。

## 五 流程改进（本批起生效）

每批收尾**必须**跑这三条，缺一条都不算交付：

```powershell
node tools\lua53check\check.cjs dist\client_script.lua --run   # 5/13：真 Lua 5.3 编译 + 顶层执行
powershell -ExecutionPolicy Bypass -File tools\lua_quote_scan.ps1   # 2g：ASCII 引号隐患
lua tests\*.lua 逐套                                            # 离线回归（35 套）
```

外加一条**本批新增**的自检（比上面三条更贴近真机）：

```powershell
# 从交付 .gil 里抽出内嵌脚本，单独编译一次 —— 编辑器就是编译这一份
# 取法：在 find_script 报的偏移附近搜 ASCII "--[[----"，从那里切 dist 的字节数
```

**规矩**：构建标记那行**只许用「」或中文引号**，禁止 ASCII `"`；改完立刻跑 ①②。
