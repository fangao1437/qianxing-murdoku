# 调查：模板引用控件的"嵌套"与"运行时改引用"（2026-10-22，v311）

> 用户问题（原话）：
> 「我在 cell 模板里加了一个模板引用控件，现在需要测试两件事：
> **① 模板引用控件引用的模板里还有一个模板引用控件时，第二层是否还能正常实例化**（官方既然允许这么建应该就是可以，查资料加实验一起走）；
> **② 脚本能不能在运行中改引用的模板**」

---

## 一、查资料结论（官方文档，两条）

### 1. 模板引用控件（文档 `mhucb6reudwm`）
- 定义：**可以引用其他客户端控件模板**，并提供预览；运行时模板引用控件的功能与表现**与被引用模板一致**；
- 它是**客户端控件**，**可挂客户端脚本**，支持被客户端脚本调用；
- 查询接口：**`ReferenceControl`**（见 API 文档）；
- 配置项：①「引用控件模板」= 选一个已存为客户端模板的控件；②手柄导航。

### 2. 客户端控件 API（文档 `mhtakr07vej4`）
- `ClientUIReferenceControl`（模板引用控件）字段：
  | 字段 | 类型 | 访问 | 说明 |
  |---|---|---|---|
  | `referencedPrefabIndex` | integer | **只读** | 引用控件模板索引 |
- **没有**任何 setter/切换方法（该类的"方法"栏为空，只有继承自 `ClientUIBaseControl` 的通用方法）。
- 相关的实例化接口是全局的：
  `game.InstantiateClientUIControl(controlPrefabIndex: integer, parent: ClientUIBaseControl) → ClientUIBaseControl`
  和 `game.DestroyClientUIControl(control)`。

### ⇒ 资料层面的判断
| 问题 | 文档结论 | 置信度 |
|---|---|---|
| ① 模板里再放模板引用控件（嵌套），第二层能否展开 | **没有明文禁止**（模板内可放客户端控件，引用控件也是客户端控件），但**也没有明文保证** ⇒ 必须实测 | 中 |
| ② 脚本运行时改"引用控件引用的模板" | **接口层面不支持**：`referencedPrefabIndex` 是**只读**，且类没有切换方法 ⇒ 只能实测"直接赋值/隐藏方法"是否被引擎放行 | 高（只读）/ 需实测（是否有隐藏通道） |

## 二、实验设计（已做进脚本 v311 + 测试存档）

### 探针脚本 `lua/tpl_probe.lua`（跟随 v311 打进存档，前缀日志 `[tplprobe]`）
启动时（`OnInit` 里、适配器就绪后）依次做：

1. **摸引用控件**
   - 用 `game.GetClientUIRoots()` 递归找名为 `furn` 的控件（= 用户加在 `cell.1.1/content` 里的模板引用控件）；
   - 打印 `typeof`、`referencedPrefabIndex` 回读值；
2. **试写**（问题 ② 的核心实验）
   - `ref.referencedPrefabIndex = <furn.plant 母本 GUID>` —— 记录 `pcall` 是否报错、写后回读值是否变化；
   - 逐个探测候选隐藏方法是否存在：`SetReferencedPrefabIndex` / `SetPrefabIndex` / `SetTemplateIndex` / `SetTemplate` / `ChangeTemplate` / `SetReference`（打印 `typeof`，有就下一步实际调用）；
3. **嵌套实例化**（问题 ① 的核心实验）
   - 用 `game.InstantiateClientUIControl(<furn.nest 源 GUID>, board)` 造一个"套娃模板"实例：
     `furn.nest` 的模板内容里放着一个**模板引用控件 `inner`**，它引用 `furn.plant`；
   - 递归打印该实例的子树（名字 / `typeof` / `referencedPrefabIndex`，最深 4 层）：
     - **若 `inner` 被展开** ⇒ 子树里会出现 `furn.plant` 的层（`L01…L10` 或图片控件）⇒ **嵌套可用**；
     - **若只看到 `inner [ClientUIReferenceControl]` 且没有再下一层** ⇒ 嵌套**不展开**，需要换方案。
4. 另外：用户手动改的 cell 模板链路本身（cell → cell 模板 → `furn` 引用 → `furn.nest` → `inner` → `furn.plant`）
   在关卡里就能**直接看**：进关卡后该格应该出现一盆植物，出现 = 两层引用在"模板实例化"路径上成立。

### 测试存档
- `516-模板测试-v1.gil`（integrator 出，基于用户手改的 `515.gil`）：新增 `furn.nest` 模板（内含 `inner` 引用 `furn.plant`）+ 把 `cell.1.1/content/furn` 引用指向 `furn.nest`；
- `517-模板测试-v2.gil` = 516 + v311 脚本（`cfg.tpl_probe = true`，GUID 已填）。

## 三、如果结论是"不行"，各自的后备方案

| 结论 | 后备方案 |
|---|---|
| **② 不能运行时改引用**（很可能） | ① 每个"家具种类"在 cell 模板里放**一个固定引用控件**（7 个引用控件，各引一个模板），脚本只切**显隐**——引用控件也是客户端控件，`SetVisible`/`SetActive` 都能用；cell 里固定 7 条，层数可接受（7 条 < 现 25 条 content 总量还能剩）。<br>② 或退回 `InstantiateClientUIControl(模板, 父)` 的 v310 方案（已验证可行，只是不在 cell 模板里）。 |
| **① 嵌套不展开** | 模板不做套娃：一件家具一个平铺模板（v310 已是这个形态）；需要"组合件"时在脚本里实例化多个模板并摆位。 |

## 四、真机操作（给用户）
1. 导入 `517-模板测试-v2.gil`，进**第一关**；
2. 观察 `cell.1.1`（左上第一格）——**出现一盆植物** = 两层引用（cell→nest→plant）在模板实例化路径上成立；
3. 把日志里所有 `[tplprobe]` 开头的行发回来（约 30~60 行），重点三组：
   - `referencedPrefabIndex 回读 = …` / `直接赋值 … ok=…` / `赋值后回读 = …`；
   - `候选方法 Set… => function/nil`；
   - `实例化成功…` 之后的 `树 …` / `直接子控件数:` / `子[i] name=… type=… ref=…`。
4. 若进关卡时第一格**没有**植物，也请一并说明（那就是嵌套在"cell 模板 → 实例"路径上也不成立）。

### 探针会打印什么（真机日志，前缀 `[tplprobe]`）
```
[tplprobe] ===== 开始（build=v311）=====
[tplprobe] 客户端根数量: 1
[tplprobe] 找到模板引用控件: true
[tplprobe] typeof = ClientUIReferenceControl  name= furn
[tplprobe] referencedPrefabIndex 回读 = 1073747096
[tplprobe] 直接赋值 = 1073747081  ok=true/false  err=…
[tplprobe] 赋值后回读 = …  改变了吗: true/false        ← ★ 问题②的答案
[tplprobe] 候选方法 SetReferencedPrefabIndex => function/nil
…（SetPrefabIndex / SetTemplateIndex / SetTemplate / ChangeTemplate / SetReference / SetPrefab）
[tplprobe] 嵌套模板实例化：prefab=1073747096 parent=board
[tplprobe] 实例化成功，name= tplprobe.nest
[tplprobe] 树 …                                        ← ★ 问题①的答案：inner 下有没有 L01…L10
[tplprobe] 直接子控件数: N
[tplprobe] 子[i] name=… type=… ref=… children=…
[tplprobe] ===== 结束 =====
```
**判定**：
- 问题①：`inner` 子树里出现 `L01…L10` ⇒ **嵌套可用**；`inner` 子控件数 0 ⇒ **模板内引用控件不展开**；
- 问题②：`赋值后回读 == 1073747081` 且 `改变了吗: true` ⇒ **能运行时改**；`ok=false` 或回读没变 ⇒ **不能**（与 API 文档"只读"一致）。
