### 4.1 ★★★★★ 「归一化会写死子控件尺寸」——`note` 装不下 24 号字 ⇒ 一个字都不显示

**这是本项目花掉六轮才定位的机制，弹窗文字不显示很可能同源。**

- **位置**：`lua/engine_adapter_qianxing.lua:2144-2153`（`_cells_paint` 里给格子的 `face/note/x` 统一设尺寸的那一段）。
- **元凶**（代码注释原文，`:2145-2149`）：
  > 「★★★★★ 2026-10-07 **这里就是"谁把 note 改成 100×30"的元凶**」
  > 「★ 原式：`math.max(8, cell_size - 8)` × `math.max(8, math.floor(cell_size * 0.28))`」
  > 「⇒ ★ `cell_size = 108` ⇒ **100 × 30** ✓ —— 与真机探针读到的 `100.0x30.0` 一字不差」
  > 「★ 而 24 号字的**行高 ≈ 36** ⇒ ★ **30 高装不下一行 ⇒ 整行被裁 ⇒ 一个字都不画**」
- **原公式**（备份里还留着）：`_bak-lua-弹窗版/engine_adapter_qianxing.lua:2147`
  `note:SetSizeDelta(math.max(8, cell_size - 8), math.max(8, math.floor(cell_size * 0.28)))`
- **修法**（当前 HEAD 已修，`:2150-2152`）：
  > 「★ 现在：★ 高改成 `max(40, cell_size × 0.40)` ⇒ ★ `108` 时 = **43** ✓ 一行稳稳装下」
  `note:SetSizeDelta(math.max(8, cell_size - 8), math.max(40, math.floor(cell_size * 0.40)))`
  （另外强制 `SetAnchoredPosition(0, 0)` 拉回格子中心：存档里的位置**运行时不被沿用**）
- **可复用的三条推论**（都出自同一段注释与 `docs/`）：
  1. **"看不到字" ≠ "没写进去"**：文本、visible、颜色、fontSize 都可能读回全对，**只有框高被改小了**。
     （`:2146-2149`：字数只在脚本显式给高框时才出现。）
  2. **存档里的几何不一定是运行时的几何**：`_bak-lua-弹窗版/ui_controller.lua` 与
     `lua/engine_adapter_qianxing.lua:4552` 都记着「存档里 `note` 的框在运行时【位置上不被沿用】」。
  3. **24 号字 ≈ 36 行高**是这里的硬门槛 —— 任何"高 < 36"的文字控件都要当成**高危**。
- **对弹窗的直接含义**（【推测】，但门槛是硬的）：存档里四个键的 `label` 是
  **`559×20`（三个）与 `125×20`（cancel）**，**20 < 36**。`label` 是否也被某段归一化/引擎裁掉，
  见 §5 未解问题 2。相关提交链：`336`（`a7fdd60`，定位元凶）、`337`（`e50f438`，收口）。

### 4.7 ★★★★ `rect.y` 是"从父容器**顶边**往下的偏移"，**不是**左下角原点的 `cy`

**这条是这次整理新查出来的，弄反了四个键就是倒序的。**

- 本项目 `build_layout` 里 `push/btn` 的 `rect` 用的是**左上角原点**的相对坐标（`mx`/`my` 是面板的左/下参照，
  `y` 往**下**增），而 `docs/控件坐标表-1600x900.md` 与设计稿的 `cy` 是**左下角原点、往上为正**。
- **三处独立验证**（用 `nx = (641.5 − rect.y 偏移×(5/6) − h/2×(5/6))` 换算，面板顶边 = 450 + 383/2 = **641.5**）：
  | 控件 | 代码里的 rect 偏移 | 换算得 cy | 坐标表/实测 cy |
  |---|---|---|---|
  | `intro.title` | `y = my + 80` | 549.8 | **550**（`控件坐标表:250`） |
  | `intro.body` | `y = my + 160` | 433.2 | **433**（`:251`） |
  | `modal.level.case_001` | `y = my + 126` | 508.2 | **508**（`:267`） |
  ⇒ **两者相差的正是"上下翻转"**。
- **第三处独立验证**：`cancel` 的 rect 是 `y = my + mh - 88`（= 372）⇒ 换算 cy = `641.5 − 310 − 25 = 306.5`
  ≈ `控件坐标表:261/265` 的 **307**（`modal.cancel` / `modal.again`）✓
- **后果（精确说法：① 与 ③ 被写反了，不是整体翻转）**：
  - `262` 那一版（以及 `versions/133/134` 里的）rect 偏移是 `exit=170 / save=246 / settle=322 / cancel=372`，
    在左上角原点语义下**顺序是对的**（exit 最小 = 最上），换算 cy ≈ `473 / 410 / 347 / 307`。
  - `285`/`286` 改成 `exit=338 / save=242 / settle=146 / cancel=(mh−88)`，
    ⇒ 换算 cy = **`330 / 410 / 490 / 306.5`**，于是屏幕上「**退出至菜单**」跑到了「**存档并结算**」**下面**。
    这正是陈旧计划里 `modal.exit cy=330`、`modal.settle cy=490` 的来源（C9），
    与设计稿的 `570 / 490 / 410 / 330` **正好把 ① 和 ③ 对调**。
  - ⇒ **把设计稿的 `cy` 当成 `rect.y` 抄，① 和 ③ 就会互换**（用户当年就是为此强调
    「严格按照我的文本从上到下」，见 `tools/gil/gen_modal_keys.mjs:4,35`）。
- **好消息**：`287` 之后（含 `_bak-lua-弹窗版` = `294`）四键的 `pos_runtime` **缺省** ⇒
  **脚本不下发几何** ⇒ 存档那套正确的顺序（cy 500/430/360/290）说了算。
  ⇒ **不要为了"精确对齐设计稿"重新给四键打开脚本几何，否则会把 `285/286` 的错序一起搬回来。**
- **顺带一条同源证据**：陈旧计划里 `modal.cancel` 仍是 `cx=1017 cy=307 w=133 h=50`（旧的编辑器几何），
  而不是 `exit_menu` 分支给的 rect —— 因为**同一个控件被多个计划节点写、只认第一个认领者**
  （B2/`event_claim` 机制，`lua/engine_adapter_qianxing.lua:150-177`）。
  ⇒ `modal.cancel` 这类**共用控件**的几何，"你以为写下去了，其实被别的状态抢了"。
- **正确换算法**（画布单位）：`rect.y 偏移 = (641.5 − 目标 cy − h/2) × 1.2`，
  其中脚本空间 = 画布 × **1.2**（`286` 的 `374×72` 脚本 ↔ 设计稿 `312×60` 画布，比值 1.2，两处对得上）。

### 4.8 改 `.gil` 记录数组的纪律（血泪四轮）

`docs/gil增删记录-避开手工下标.md`（整篇，2026-10-07）：

1. **内存断言过 ≠ 落盘复读过**：第四轮 `--probe` 内存断言 4/4 全过，**写盘后 `readGil` 复读只有 3/4**
   （`modal.exit` 那条不过）。⇒ **写盘后必须重新解析再断言一次**，不过就 `exit != 0` 且**不许留在交付路径**。
2. **同一轮里混"删除 + 插入"是高风险**：`rec.index` 是**读入时**的下标，删/插都会让它后面的记录漂移
   ⇒ `splice` 会落进别的记录内部把记录劈开（`check_childlist_top` 立刻报 exit 1）。
   优先级：**只改值 ✅ > 只追加 ✅ > 一次性收集+降序应用 ⚠️ > 边遍历边增删 ❌**。
3. 附带坑：字段对象自己带 `.field`（数字）而记录对象带 `.field`（对象）⇒ 判类型要用 `typeof x.field === 'object'`；
   `byName` 按"记录自己的名字"索引，`home.select.bg` 这条记录的 `name` 其实是 **`bg`** ⇒ 要按 `父名/子名` 两级查；
   **引擎属性名 ↔ `.gil` 字段号全项目无记录** ⇒ 判不了的属性**整份克隆一个已知能用的同类控件**。
4. 未结项：214 那轮"内存 4/4、复读 3/4"，**具体哪条哪个字段变了至今没定位**（当时只打了计数没打差异字段）。
   路线已改走"脚本 + 官方素材"，**不再阻塞**，坏档隔离在 `作废/`（未删留痕）。
5. **交付纪律**：自检不过就不交付，产物改名带 `-坏-` 移入 `作废/`，**不删**。
   `213-弹窗四键.gil` 始终干净（`check_childlist_top` exit 0）。

   验法：真机点一次四键，看有没有响应；同时把 `main.lua:628` 那行临时取消注释做 A/B，对比点击是否恢复。
2. **`label` 的 `20` 高会不会像 `note` 一样把 24 号字裁掉？**（§4.1 同源）
   存档里 `label` 是 `559×20`（三个）与 `125×20`（cancel），行高门槛 ≈36。
   验法：真机看四键有没有文字；或在适配器里加一行只读诊断，打印运行时 `label` 的 `sizeDeltaX/Y` 与 `fontSize`。
3. **四个键的宽度最终取 `480`（存档现状）还是 `312`（设计稿）？** 需要用户拍板。
   若取 312：要么改存档几何（走 §4.8 纪律），要么恢复"脚本管几何"——而后者上次直接导致 R6（点穿到棋盘）。
4. **陈旧计划里 `modal.exit cy=330`（倒序）是"代码写反"还是"dump 工具反了"？**
   已确证：`285/286` 的 rect 偏移是 `338/242/146/50`（左上原点），换算 cy = `330/410/490`（倒序）；
   设计稿与存档都是"退出至菜单在最上"。**机制上我判定是 rect 偏移与左下角 cy 语义混用**（§4.7），
   但仍需一条独立验证：重新 `dump_layout` 后，把 `modal.exit` 的 cy 与真机截图/编辑器里的位置对齐看一次。
5. **`murdoku/settle` 服务端节点图接了吗？** 工程内无法验证（`docs/` 里只有 `solved`/`save`/`restore`）。
   验法：在编辑器节点图里搜信号名 `murdoku/settle`；没有就按 `docs/节点图接线与素材清单.md` 的 2.x 接一个"结算关卡"节点。
6. **`modal.cancel` 被 6 个弹窗状态共用，要不要给它单开一个 `modal.exit_cancel`？**
   动它会波及指认/结果/选关/玩法四个面板（§2.1 警告）。验法：改名/改几何后，逐个状态开一遍。
7. **`DECOR` 豁免该恢复还是改成白名单？** 现在不在代码里（C3），而 R3/R4 的机制还在。
   验法：真机看 `clues` 头像卡与按钮是否"有图有字"；或先恢复 `DECOR` 再对比一次。
8. **`skip_intro` 的默认值要不要重新改回 `(opts.skip_intro ~= false)`？**
   `295` 撤回了它（C3）。当前若 `intro.*` 仍缺，则开场页闸门恒真 ⇒ **所有弹窗出不来**（R1）。
   验法：确认入口 `entry_client_script.lua` 有没有显式传 `skip_intro`；没有就必须改默认值。
9. **恢复时 `main.lua` 抄哪一版？** `_bak-lua-弹窗版/main.lua` = 提交 `279`（不是 294，C4），
   它带着已被废弃的"脚本封容器"逻辑。验法：只挑 `on_save` / `on_settle` 两个回调手工补，别整份覆盖。
10. **模拟器能不能给出弹窗的有效验收？**
    已知 PNG 截图对弹窗无效（R7）。⇒ 未定的是：`tools/sim/play_test.mjs` / `audit_flow.mjs` 里
    有没有覆盖 `exit_menu` 的用例（陈旧计划里有该状态）。验法：grep 测试脚本里的 `exit_menu`；没有就补一条"数据层断言"用例。
11. **四键在 `480×56` 时，`bg` 与按钮同尺寸是否要留边？**
    存档里 `bg = 480×56` = 按钮尺寸（G3），而素材 `107179` 是 `760×152`（宽高比 5:1，按钮是 8.57:1）
    ⇒ 拉伸后两端圆角的视觉比例需要人眼确认。验法：真机截图看圆角是否被压扁（`imageType` 用 Basic 还是 Stretch 也要定）。
12. **`213.1.gil` 与 `214-笔记居中基准.gil` 是否同一份？**（字节数都是 `1079037`，未做哈希比对）
    验法：`Get-FileHash` 两两比一下，避免索引里出现"同名不同物"。

## 7. 重做弹窗的最小步骤建议

> 原则：**先验"能不能点、能不能显"，再谈"好不好看"**；每一步都要有"我亲眼看到的那一行"。
