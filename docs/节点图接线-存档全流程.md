## 二 ★★ 设计要点：为什么用一个**布尔开关**来判断"有没有存档"

★ 本来的想法是「`state_code` 非空才发 `restore`」✓ 但那要一个**字符串比较**节点 ✗
　 —— ★ **它的确切名字我没查到** ✗（知识库索引不全 ✓ 本项目已知「查不到 ≠ 不存在」✓）
　 ⇒ 为了不让你在库里瞎找，本文改用**一个布尔变量当开关** ✓：

★★ **`murdoku_save_exists`**（布尔）—— 存过档就置「是」✓
　 ⇒ 判断"有没有存档"就变成把**一个布尔变量**喂给【双分支】✓
　 ⇒ ★ **全程只用我已核实的节点** ✓ 不用猜名字 ✓

## 三 ★★★ 逐步骤操作

### 第 1 步　登记两个信号

★ 位置：**节点图编辑页面 → 右键 → 快捷菜单 →「信号管理」** ✓
　（或**顶部菜单栏【窗口】→ 服务器信号管理器** ✓）

**信号 A：`murdoku/save`** —— 添加参数 **×5**，**类型按顺序**：

| 顺序 | 参数名（建议）| **类型** |
|---|---|---|
| 1 | `level_id` | **字符串** |
| 2 | `state_code` | **字符串** |
| 3 | `moves` | **整数** |
| 4 | `elapsed` | **整数** |
| 5 | `solved` | **布尔** |

**信号 B：`murdoku/restore`** —— 添加参数 **×4**：

| 顺序 | 参数名（建议）| **类型** |
|---|---|---|
| 1 | `state_code` | **字符串** |
| 2 | `moves` | **整数** |
| 3 | `elapsed` | **整数** |
| 4 | `solved` | **布尔** |

★ 参数**名字**随你取 ✓ **类型与顺序必须对** ✗（顺序 = 客户端 `AddX` 的调用顺序 ✓）

### 第 2 步　在【关卡实体】上声明 5 个自定义变量

```
Esc 界面 → 关卡设置 → 基础 → 关卡实体【查看】      ← 定位那个蓝色立方体
  → 选中它 → 【组件】页签 → 【自定义变量组件】→【详细编辑】→【新增自定义变量】
```

| # | 变量名 | **类型** | 默认值 |
|---|---|---|---|
| 1 | `murdoku_save_state` | **字符串** | 留空 |
| 2 | `murdoku_save_moves` | **整数** | 0 |
| 3 | `murdoku_save_elapsed` | **整数** | 0 |
| 4 | `murdoku_save_solved` | **布尔** | 否 |
| 5 | ★ `murdoku_save_exists` | **布尔** | 否 |

★★ **类型必须与信号参数类型【完全一致】** ✗ —— 官方 FAQ 反复强调：
　「保证从**发出、查询、监听**所有节点的数据类型都和目标自定义变量数据类型**相等**」
　⇒ 否则 **静默不生效**（不报错、只是不写入 ✓ 本项目最常见的失效形状 ✓）

★ **声明之后别再改名或改类型** ✗ —— 官方：「会导致节点图中相关节点**无法执行**」✓
★ 同一个实体上自定义变量**不能重名** ✓

### 第 3 步　接第 1 条：收到 `save` ⇒ 写变量

放 **1 个【监听信号】** + **5 个【设置自定义变量】**（执行节点 → 自定义变量 ✓）：

```
【监听信号 · murdoku/save】的 ▷（执行流）
   ├─→【设置自定义变量】变量名 = murdoku_save_state    变量值 ← 出参 state_code
   ├─→【设置自定义变量】变量名 = murdoku_save_moves    变量值 ← 出参 moves
   ├─→【设置自定义变量】变量名 = murdoku_save_elapsed  变量值 ← 出参 elapsed
   ├─→【设置自定义变量】变量名 = murdoku_save_solved   变量值 ← 出参 solved
   └─→【设置自定义变量】变量名 = murdoku_save_exists   变量值 ← 常量「是」★
```

★ 五条的 **目标实体** 都接同一个：**`监听信号` 的 `事件源实体`** ✓
　（图挂在关卡实体上 ⇒ 事件源实体 = 关卡实体 ✓ 和变量声明的地方是同一个 ✓ 和结算那次同一招 ✓）

★ **是否触发事件** 五条都设 **「否」** ✓（我们不需要"变量变化时"事件 ✓）

★ `murdoku_save_exists` 的**变量值**是**常量** ✓ —— 直接填「是」，不用接线 ✓

### 第 4 步　接第 2 条：进关时 ⇒ 读变量 ⇒ 发 `restore`

放 **1 个【实体创建时】** + **1 个【获取自定义变量】** + **1 个【双分支】** + **3 个【获取自定义变量】** + **1 个【发送信号】**：

```
【实体创建时】（事件节点 → 三、实体相关 → 1）▷
   →【获取自定义变量】(查询节点) 目标实体 =【获取自身实体】 变量名 = murdoku_save_exists
      → 出参「变量值」(布尔)
   →【双分支】(流程控制节点 → 一、通用) 条件 ← 上面那个布尔
        ├─【否】⇒ ★ 什么都不接 ✓（没存档，不发 ✓）
        └─【是】▷
             →【获取自定义变量】变量名 = murdoku_save_state    → 变量值
             →【获取自定义变量】变量名 = murdoku_save_moves    → 变量值
             →【获取自定义变量】变量名 = murdoku_save_elapsed  → 变量值
             →【发送信号】(执行节点 → 信号) 信号名 = murdoku/restore
                   参数1 state_code ← murdoku_save_state 的变量值
                   参数2 moves      ← murdoku_save_moves 的变量值
                   参数3 elapsed    ← murdoku_save_elapsed 的变量值
                   参数4 solved     ← murdoku_save_solved 的变量值（★ 见下）
```

★ **为什么用【实体创建时】而不是"关卡开始时"** ✗ —— 官方 FAQ 原话 ✓：
　> 「我想在游戏开始/关卡创建时就触发事件执行逻辑，但是没有找到关卡开始时类似事件？
　> 　A：建议在**关卡实体（LevelEntity）上挂载节点图，用【实体创建时】事件**来实现此效果」

★ **【发送信号】的用法** ✓（官方《信号》§四）：
　「在节点图中放置了发送信号节点后，**需要先选择【信号名】**；选择后该节点的**入参会新增**
　 　这个信号名对应的信号的所有参数」✓
　⇒ ★ 所以参数**不用手填**，选完 `murdoku/restore` 后**按序**把四条线接上就行 ✓

⚠️ **`solved` 那个参数**：第 4 条要的是**布尔** ✓，所以第 3 个【获取自定义变量】要读的是
　 **`murdoku_save_solved`**（★ 上图画的是 `_elapsed` ✓ 别接错 —— 一共要读 **4 个**变量 ✓）

### 第 5 步　保存

1. ★ **先退出试玩** ✗ —— 官方纪律：「**试玩过程中编写的节点图不会被保存**」✓
2. **保存节点图**
3. **保存关卡**

★ 节点图**挂载对象不变** ✓ —— 还是**关卡实体** ✓（和结算那张图同一张、同一实体 ✓）

## 四 ★★ 验收（真机，4 条）

## 五 ★★ 六个坑（动手前知道）

| # | 坑 | 后果 |
|---|---|---|
| 1 | ★★ **`save` 5 参 / `restore` 4 参** | 把 `level_id` 也接到 `restore` 上 ⇒ 整条错位 ✗ |
| 2 | ★ **变量类型与参数类型不一致** | **静默不生效**，不报错 ✗ |
| 3 | ★ **漏掉 `murdoku_save_exists`** | 进关时双分支条件恒"否" ⇒ **永远不还原** ✗ |
| 4 | ★ **本地缓存 ≠ 存档** | `adapter:load` 只读**内存表** ✓ 别拿它当"跨会话"的证据 ✓ |
| 5 | ★ **试玩中写的节点图不保存** | 白干 ✓ |
| 6 | ★ **声明变量后改名字/类型** | 相关节点**无法执行** ✓ |

## 六 ★ 与结算那张图的关系

★ **可以就加在同一张节点图里** ✓ —— 不冲突 ✓
　 结算用的是「监听信号 ×2」✓ 存档用的是「监听信号 ×1 ＋ **实体创建时** ×1」✓
　 四个事件节点各自起链 ✓ 互不影响 ✓

| | 结算（已通 ✓）| 存档（本文）|
|---|---|---|
| 信号 | `murdoku/solved` / `murdoku/settle` | `murdoku/save` / ★ `murdoku/restore`（**反向**）|
| 服务端动作 | 设结算状态 ＋ 结算关卡 | **写变量 ＋ 读变量发信号** |
| 变量 | `solved_level` ×1 | ★ ×5 |
| 挂载 | 关卡实体 ✓ | ★ **同一个关卡实体** ✓ |
