### 条目 04-01 · 上机包里 67.3 %（906,668 B）是注释

| 项 | 值 |
|---|---|
| 类别 | **E**（冗余数据；不进执行路径，但进包、进内存、进存档） |
| 位置 | `tools/bundle_client_script.lua`（打包器，L115 起把源码整段拼进 `dist/`）；`dist/client_script.lua` 全文件 |
| 规模 | **906,668 B ≈ 0.9 MB**，占整包 **67.3 %** |
| 判据 | 注释不参与执行。`dist/` 是**生成物**，源码里的注释对维护有用，但**没必要跟着下发到设备** |
| 反向检查 | ① `lua/**` 源文件注释**不动**（维护要用）② 只在打包器里剥注释 ⇒ 源码可读性不变 ③ 但 `check_all` 2m（`check_actions.mjs`）与 `check_names.mjs` 读的是**源码**不是 dist ⇒ 不受影响 ④ `tools\lua53check` 编译 dist，剥前剥后都能编译（要实测） |
| 删除风险 | **P1**（改打包器 1 处 + 回归一轮；风险点是剥注释实现必须正确处理长注释 `--[[…]]` 与**字符串里的 `--`**） |
| 标签 | `[实测]`（字节构成实测）·「剥注释后行为不变」为 `[推断]`，需一次 `lua53check` + 33 套离线回归兑现 |

> 这是**单笔最大**的"不必要代码"（0.9 MB / 67 %），且**零逻辑风险**（不动任何一行源码语义）。
> 建议单独一批做，做完量一次包大小 + 跑 `tools\lua53check\check.cjs dist\client_script.lua --run`。

## 一 三份副本：谁是"必要"的

同一个脚本在仓库里有三份：

| # | 位置 | 是否必要 | 证据 |
|---|---|---|---|
| 1 | `lua/**`（14 个源文件，21,953 行） | **必要**（唯一可维护源） | `tools/bundle_client_script.lua` 从它生成 dist |
| 2 | `dist/client_script.lua`（1,347,962 B） | **必要**（打包产物，交付件） | 内嵌进 `.gil` 的就是它 |

### ⚠️ 顺带发现一个**闸门漏洞**（不是死代码，是"该跑没跑"）

`tests/` 共 **36 个 `.lua`** ＝ **33 套用例**（`fixtures.lua` / `old_case_001.lua` / `old_case_002.lua` 是被 require 的夹具，不算套）。
其中 `tools/check_all.ps1` 只跑 **7** 套（`selftest` `ui_math` `effects_wiring` `input_logic` `select_hit_visible` `settle_button` `entry_smoke`），
其余 **26 套**靠**每轮手工 `lua tests/*.lua` 逐套跑** —— 出处 `docs/回执-门墙居中格线-v265.md:79`「逐套 `lua tests/*.lua` ✅ 33 套全绿」。
⇒ 所以 `bound_rearm` / `dupe_dispatch` / `clue_hint` / `grid_cost` / `perframe_throttle` / `hide_safety` / `things_wiring` …
**不是"无人调用"，只是"不在自动闸门里"** ⇒ 一律**不得**按"没人调用"删掉。
正确处置：把 33 套接成一条自动步骤（另立议题，本轮不做）。这也解释了为什么 `tools/run_checks.ps1` 只跑 `selftest.lua` 一套。
