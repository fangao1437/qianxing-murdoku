## 六、阻塞项与下一步

1. **真机验证（唯一未闭环项）**：导入 `453-门墙居中格线-v265.gil` → 进第 2 关（6×6）看：
   竖墙是否压在格线上（左右各半 3.5px）、横墙同理、门是否与墙共线、四角是否有缺口。
   判据（截图可量）：若还有偏移，把"实测偏移量 / 方向"回传，`pitch` 与 `cw` 只有一个数要调。
2. **真机若仍偏，优先怀疑**（按可能性排序）：① 真机 `cell_geometry` 拿到的 `pitch` 与 UI 规划不同（会同时影响墙长）；
   ② 素材自身透明边距（墙/门各一份，可用 `records/shot-measure` 同一套脚本再量一次）。
   ⇒ 两者都能用**同一张截图**区分：墙长 92（=cw≈88+4）还是 95（=cw 91+4）。
3. **模拟器为什么本轮不作证**：`tools/sim/out/geom-final-1.log.txt` 里模拟器的 `边缘适配` 是
   `基准 80x20 → 目标 **108**x8` ⇒ 模拟器侧 `cw = 104`，而真机截图实测格子是 **91**（`cw≈91`）⇒
   **同一个公式在两个环境里喂进的 cw 不同**（模拟器的 `stage` 尺寸与真机不一致）⇒ 模拟器截图无法判定真机几何。
   记 `[模拟器]` 环境差异；真机才是裁判。
4. **待用户决定（视觉，不阻塞）**：设计图门长 = **44%×pitch**（71/162、59/136 两图一致），
   而代码 `door_length_ratio = 0.30` ⇒ 现在门只有设计的 **68% 长**。要不要按设计图改成 0.44？
   （改的话只动 `entry_client_script.lua` 一个数 + 重新打包/嵌档；`wall_overlap` 会同步改期望值。）
