## 二、问题定位（先证明离线可预测）

用 `离线渲染撕边651.mjs` 从 **650_优化版.gil 的磁盘记录**反解并绘制全部 720 个撕边图元，结果与实机截图的白边形状、鼓包、末端提前收细**逐像素吻合**。因此可以在本机离线迭代，不必反复导入游戏。

对照设计图，旧版两个结构性缺陷：

1. **转角缺口**：纸片由 166 段旋转长条拼成，折点处互相错位；白线是独立短矩形，段间只延长 2.5 设计 px。649 的 133 片局部盖板只向 board 侧加宽、650 的 ±2 段最大值滤波又把宽度骤增，于是转角出现方形台阶、黑色咬口，白边整体外移且明显过粗（设计图白线平均 5.5 设计 px，实机约 14~24 设计 px）。
2. **边缘白边缺失**：轨迹首尾没有沿切线出画面，左下陡降段后半与底边、右上右端白边提前收细消失；5 条 3px 桥接只能补 5 行，补不住整条边。

像素量化（白边 mask，画布 1600×900，仅撕边区域）：

| 区域 | 版本 | 设计图有白/渲染无白（缺失） | 渲染有白/设计图无白（溢出） | 合计误差 |
|---|---|---:|---:|---:|
| 左下 BL | 650 | 1,051 | 3,188 | 4,239 |
| 左下 BL | **651** | **209** | 1,262 | **1,471**（-65%） |
| 右上 TR | 650 | 322 | 2,540 | 2,862 |
| 右上 TR | **651** | **8** | 1,582 | **1,590**（-44%） |

## 三、做法：按设计图重建，不再叠补丁

从设计图逐列/逐行提取白边中心线（TR 206 点 `x1508→1918`，BL 123 点 `y836→1076`），首尾沿切线外推 **64 设计 px** 出画面，再按 7 设计 px 等弧长重采样；纸片与白边共用**同一条轮廓**：

1. **纸片**：3.5 设计 px 步长的实色扫描矩形（TR 141 / BL 79），轮廓内侧填实，折点不再靠旋转长条交叉 ⇒ 无黑楔、无方形台阶。
2. **白边**：8 设计 px 宽旋转矩形（TR 183 / BL 150 段），每段两端各延长 5 设计 px 形成重叠；颜色沿用 `#FFF6E6C4`，纸片沿用 `#FFB36E45`。
3. **折点接头**：角度差 >10° 的折点与首尾各放 11 设计 px 白色方块（38 个），消除 V 形黑缝。
4. **层序**：`art642.select.board` 子列表与全局记录表同序：纸片 → 白线 → 接头；board 组整体仍在 paper/thread 之前，红绳、便利贴、牛皮纸、节点、按钮、v12 资产层级一律不动。

删除 650 的 720 个旧撕边层（`art647/649/650.select.tear.*`），新增 591 个 `art651.select.tear.*`，净减 129 个控件。

## 五、效果与未做项

- `651_对比_转角放大.png`：用户指出的左下转角，中间一栏（651）已无黑色咬口与方形台阶，折角形状贴近设计图。
- `651_对比_左下撕边.png` / `651_对比_右上撕边.png`：四栏依次为 650 实机 / 650 旧离线 / **651 新离线** / 设计图；新档白边连续、两端贴到画面边缘。
- `651_整体预览.png`：把新撕边层叠到实机截图上的整屏效果（合成图里会残留一点旧白边，真机只有新层，不会叠加）。

**次要问题（控件在亮暗交界区没有过渡）本轮未处理**：那需要给每个跨界控件单独加渐变层或改渲染路径，会新增大量半透明图元、与 650 的减负目标冲突，按用户「实现困难可忽略」的口径保留现状。

**已知限制**：新档尚未在游戏内导入，需实机截图复核；离线渲染模型已用旧档证明与真机一致，但不能替代真机验收。白边取 8 设计 px，略宽于设计图均值 5.5 px，是给真机取整/抗锯齿留的余量；设计图的纸张纹理未复刻，沿用纯色纸片。

## 六、复现

```bash
cd "qianxing-murdoku/650_全面优化"
node 提取设计图白边轨迹.mjs            # 可选，重新从设计图提取轨迹
node 构建651_撕边修复.mjs               # 锁定 650_优化版 SHA，产出 651_撕边修复.gil + 审计 JSON
node 离线渲染撕边651.mjs 651_撕边修复.gil 651_撕边渲染.png --dark
```

构建器只写 `651_撕边修复.gil`，不碰 650 原档、仓库 lua 源、dist 或任何用户文件。
