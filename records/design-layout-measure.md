## 0 结论（先看这段）

1. **墙/门在设计图里"压在格线正中"，不允许偏进格子。** 23 根墙条 + 4 个门牌，垂直方向偏移 **全部 = 0.0 px**，
   沿边方向偏移也 **= 0.0 px**（门正好落在格边中点）。▸ 实机那 6.5px 右/下偏在设计图里是**没有依据**的。`[图片实测]`
2. **墙 = 11px 粗条，长度 = 整条格边（pitch−1）**；两侧各占格线一半 ⇒ 墙厚正好等于"两格内缩后留下的 10px 缝 + 两条 1px 描边"。`[图片实测]`
3. **门 = 17px 粗、长 0.43–0.44 格**的橙条，骑在墙上，垂直墙方向**冒出墙面各 3px**；另有一块 33×27px 的 `门` 字号牌居中贴在上面。`[图片实测]`
4. **编号基准没有差 1**：图的列/行标注与代码 `r/c` 完全同基准（1-based，行自上、列自左）。
   校准依据 = 人物答案摆位（D(1,3)/(2,4) 等 11 个棋子）＋家具标签，逐格对上。`[图片实测]`
5. **对账**：`case_001` 墙 9/9、门 3/3 **逐条一致**；`case_002` 墙 14/14 一致、**门图上 1 扇 vs 代码 3 扇**
   （`h,3,1`、`v,4,3` 是 2026-10-18 后加的，v5 图没重画 ⇒ **图陈旧，不是错位**）。`[图片实测]`+`[文档]`
6. 给界面用的比例（相对格边长）：**墙厚 7–8%、门长 43–44%、门厚 10–13%、格内缩 3–4%**。`[图片实测]`

## 7 对"墙该在哪"的直接结论（给坐标修复用）

- 墙 ≠ 格内元素：**墙的矩形中心必须落在格线上**（`rect.y/h` 或容器坐标要按"中心对齐格线"算，
  不是"贴到格子左上角再内缩"）。`[图片实测]`
- 门 = 格线 ∩ 格边中点的对称块：沿格线长 0.43–0.44 格，垂直格线厚 ≈1.5×墙厚（17 vs 11）。`[图片实测]`
- 换算到千星（Y 向上、原点左下）时**只需翻转 Y**；翻转不改变"居中/偏移"这一结论。`[推断]`
- 实机看到的"整体右偏下偏 ≈6.5 截图 px、方向恒定"，量级恰好是**一个墙厚**（001: 11px/162 = 6.8%）。
  若实机格宽约 90px，6.5px = 7.2% ≈ 墙厚 ⇒ 更像**把条状控件的左上角当成了中心**或**容器原点偏移一个墙厚**，
  而不是比例/缩放误差。`[推断]`（此条为推断，请以实机二次截图为准）
