## 2. 阻塞点：`things` 里现有 7 条不是"旧式模板引用控件"

v315 脚本 `Adapter:_furn_prefab_map()` 的读取方式是：
```lua
for ch in things:GetChildren() do
  local prefab = ch.referencedPrefabIndex   -- 读引用控件的"引用模板索引"
  if key_of(ch.name) and type(prefab)=="number" then map[key]=prefab end
end
-- 回退：cfg.furn_tpl_prefab（v315 里仍是旧 id 6900…6912，**这些记录已被编辑器删除**）
```
对照 520.1：
1. `things` 7 个子控件的**组件槽是 `[68/91]`（模板形态）**，不是引用控件的 `[66/89]`；
2. 它们**没有任何引用值**（旧式 `#505(66/89)/#503/#77/#501` 不存在；新版 `#505(68/91)/#503/79` 也是空消息）；
3. 无族号、无 `#14`、无 content ⇒ 它们既不像"引用控件"，也不像"完整模板"；
4. 唯一"编辑器刚建过、形状完整"的样本是 `cell.face`#7145/#1882 这一对（但也没有 content）；
5. v315 `cfg.furn_tpl_prefab` 仍是 6900…6912 —— **全部指向已被删除的记录**，所以即使回退也 instantiate 不了。

⇒ **"做法和 things 里其它 7 个完全一样"无法照抄**：没有可抄的"引用值"，也没有可抄的"带 3 层 content 的模板"。

## 3. 建议（需要 lead/用户选一个）

### 方案 A（推荐，最稳）：用户在编辑器里手动做 1 次 `furn.rug`，我们再填层
1. 编辑器 → 界面控件组管理 → 界面控件组库 → **客户端控件模板** →【添加客户端控件】→ 类型「容器节点」；
2. 命名 **`furn.rug`**，**存为模板**；
3. 在 `root/things` 的容器画布里新建一个「**模板引用控件**」→ 引用 `furn.rug` → 名字改 **`furn.rug`**；
4. 导出存档发我 → 我按导出后的**真实形态**把 3 层（L01 100001/0xFFB89A62/108×108，L02 0xFFDCC684/82.1×82.1，L03 0xFFC9B072/64.8×64.8，全居中、Stretch、无旋转）填进模板的 content（源/母本两份），并做四闸对账。
   > 这样既解决了"编辑器删手写模板"的根因，也顺便得到一个"带引用值的新版引用控件"样本——之后 7 个家具模板都能照此补齐（lead 的脚本/cfg 也能直接用真实 GUID）。

### 方案 B（可作为对比实验，但大概率被编辑器再次删除）
我按 520.1 里"编辑器新建的空模板"形态复制出 `furn.rug`（无父 + 族号 92 + 空 #14）+ things 里加一条同形态 `furn.rug`（无引用值），content/3 层按 `cell.face` 对 + `#7147` 形态猜写。**风险：编辑器保存时可能再次删除，且引用值仍无处可写。**

### 方案 C（不推荐）
重建我们 521 那套完整形态（源+母本+content+层+旧式引用控件）：已被实证会被编辑器整体删除。
