## 一、作用域 / 变量（**selene 抓得到** ✓）

### 1.1 漏写 `local` ⇒ 泄进引擎全局表 ✗
- **症状**：变量在**真机/模拟器共享的全局表**里 ✗（别的脚本可能看到、也可能踩 ✓）。更糟的是它**还能"正常工作"** ⇒ 不报错、不崩 ⇒ 极难发现 ✓
- **判据**：`selene` 的 `error[undefined_variable]` ✓
- **正确做法**：补 `local` ✓
- **实例**：`main.lua` 的 `v2` / `a2`（**且下一行直接拼接它们** ⇒ pcall 一失败就是 `.. nil ..` ⇒ **Lua 拼接 nil 会抛错** ⇒ 打断整帧 ✗）

### 1.2 ★★ 跨帧记忆**不能**放函数内局部 ✗（**最贵的一条** ✓）
- **症状**：把一个**需要跨调用存活**的缓存声明成函数内的 `local` ✗ ⇒ **每次进函数都被重置** ✗ ⇒ 缓存失效 ✗ ⇒ 性能**反而退化** ✓
- **判据**：**量出来**的每帧写次数 ✗（本项目实测**退化到 41.8 笔/帧**，比改之前还差 ✗）；单看测试是**绿的** ✓ 抓不到 ✗
- **正确做法**：★ **文件级 `local`** ✓ —— **既不是全局**（不污染 ✓）**又能跨帧存活** ✓✓
- **实例**：`main.lua` 的 `murdoku_vis_memo` / `murdoku_vis_force_to` / `murdoku_vis_key`
  · 第一版：没声明 ⇒ **全局** ✗（selene 报 3 条 ✓ 已修 ✓）
  · 第二版：**声明进 `on_update` 函数体** ✗ ⇒ 每帧重置 ⇒ 强压窗口每帧重开 ⇒ **稳态从 8.7 退化到 41.8 笔/帧** ✗✗
  · 第三版：**提到文件级 local（L41-42）** ✓✓ ⇒ 正解 ✓
- **一句话**：**"消除全局" ≠ "改成函数内局部"** ✗ —— 先问"它要不要跨调用活着" ✓

### 1.3 作用域断裂：一处声明、另一处使用 ✗
- **症状**：变量在 A 块声明、在 B 块使用 ⇒ B 块拿到 **nil** ✗
- **判据**：★ `selene` **同时**报两处 —— 声明处 `unused_variable` + 使用处 `undefined_variable` ✓✓（**两条告警互相印证** ⇒ 直接指出断裂 ✓）
- **实例**：`names` / `done` / `miss`（抽 helper 后调用处够不到 ✓）

## 二、结构 / 块配对（**`luac` 与 `check_nesting` 各管一半** ✓✓）

### 2.1 块配错位（数量对、位置错）✗
- **症状**：`end` 总数**配平** ✓ 但**位置错** ✗ ⇒ **整段代码被吞进上面的块** ⇒ **功能静默失效** ✗✓
- **判据**：★ **只有 `--depths`（逐行深度）能抓** ✓ —— **`luac -p` 改前改后都 exit 0** ✗（**它是"数量检查"** ✓）
- **正确做法**：用 `node tools/audit/check_nesting.mjs --depths=file:a-b` 看**每行深度** ✓ 别肉眼数 `end` ✗
- **实例**：
  · `apply_ruler_layout` / `diagnose_overlap` 被吞在 `apply_tray_layout` 里 ⇒ **加载期根本不存在** ⇒ `if x ~= nil` 守卫恒假 ⇒ **行标对齐、相交诊断从来没跑过** ✗✓（最贵的一个 ✓）
  · `%30` 被 `%300` 套住 ⇒ "每帧压住"实际**每 300 帧**才跑 ✗

### 2.2 增删 `end` 数量错 ✗
- **判据**：`luac -p`（**它是"数量检查"** ✓）+ `check_nesting` 的 `[不平衡]` ✓
- **⚠️ 两者不能互相替代** ✗ —— **四类坑需要四种判据** ✓（见 §五）

## 三、数据 / 结构（**`check_layout_dupes` / `prop_ledger` 抓** ✓）

### 3.1 同一 `id` 出现在多个计划节点 ✗
- **症状**：两个同 `id` 节点**每帧互相覆盖账目** ✗ ⇒ 每帧真写一次 `visible` ⇒ 又把"事件驱动的兜底隐藏"每帧点着 ✗✓
- **判据**：`lua tools/check_layout_dupes.lua`（**逐状态调 `build_layout()`** ✓）
- **⚠️ 陷阱**：**不能查 `layout-plan.json`** ✗ —— 那份产物**生成时已按 id 去重** ⇒ 结构上**看不到重复** ⇒ **必然假阴性** ✗✓（我栽过 ✓）
- **实例**：`home` / `select` 双 push（真凶 ✓）；`action.back` ×2（**用户的设计** ✓ 不动 ✓）；`root` ×2（**语义互补** ✓ 需合并但风险高 ✓）

### 3.2 假树/假引擎缺连接 ⇒ 计数结构性为 0 ✗
- **症状**：测试**恒红**或**恒绿** ⇒ 毫无防线价值 ✗
- **判据**：看**假树节点数**与 `find(...)` 是否可达 ✓
- **实例**：`perframe_throttle.lua` 假树**漏了 `attach(rt, st)`** ✗ ⇒ `stage` 子树（110 节点）不可达 ⇒ 4 条断言**永远红** ✗✓ ⇒ **补一行** ⇒ **4 红转 4 PASS** ✓✓
- **一句话**：**断言恒红 ≠ 代码有问题** ✗ —— 先怀疑**测试自己的脚手架** ✓

## 四、性能（**`grid_cost` / `probe_throttle_cost` 抓** ✓）

### 4.1 一条规则两个权威 ⇒ 互相拆台 ✗
- **症状**：两处代码写**同一个控件的同一个属性** ⇒ 白烧引擎写 ✗ + 互相抵消 ✗
- **实例**：
  · `selbar`：老的 `bar:SetVisible(on_select)`（**每帧无条件** ✗）与新的 `setv(...)`（**读回 + 记忆 + 窗口** ✓）并存 ⇒ **603 笔/600 帧** ✗ ⇒ 删掉老的 ⇒ **2 笔** ✓✓
  · `.ps1` 的 BOM：我的哨兵要"有 BOM" ✗、`normalize_encoding.ps1` 要"无 BOM" ✗ ⇒ 互相剥/加 ✗ ⇒ **必须留一个权威** ✓

### 4.2 "每帧"的判据是**调用点**，不是直觉 ✗
- **实例**：`apply_ruler_layout` 在 `Murdoku.render()` 里 ⇒ 看起来"每帧" ✗ 但 `render` 被 `dirty` 门控 ⇒ 实测 **1.10 次/秒** ✓（**我连续误判 3 次** ✗✓）

### 4.3 记"我写下去的值"不够，要**读回真实值** ✓
- **症状**：**别人也在写**同一个属性 ⇒ 记忆与真实值**分叉** ⇒ 每帧重写 ✗
- **正确做法**：★ **先读回 `c.visible`** ✓（**读便宜、写贵** ✓）；已等于目标 ⇒ **一笔都不写** ✓；读不到 ⇒ **退回写**（不许因为读不到就不压 ✗）
- **实例**：实测"光靠记忆"稳态 **602 笔/600 帧** ✗ ⇒ 读回后 **0 笔** ✓✓

### 4.4 节流要有"强压窗口"兜底 ✓
- **症状**：纯"变化才写"会被**外部复位**击穿 ✗（引擎/`ensure_widgets` 会把它设回去 ✗）
- **正确做法**：`(屏幕, 关卡)` 一变 ⇒ 开 **60 帧强压窗口** ✓；之后**变化才写** ✓
- **实例**：修好后实测 —— **外部抢成 `true` ⇒ 换屏回来 2 帧内被压回 `false`** ✓✓

### 4.5 日志也要节流（**修好一个功能反而引入负担** ✗）
- **症状**：某函数原来"从未运行" ✗ ⇒ 修好后它**第一次真的跑** ⇒ 里面"无条件打印"变成**每秒 2 行 / 7900 行每小时** ✗
- **正确做法**：把**会被打印的那些数**拼成签名 ✓；相同 ⇒ **整段跳过** ✓
- **⚠️ 两个坑**：① 签名里**不能塞没被打印的数** ✗（抖动会击穿节流 ✓）② `string.format` **占位符不能比参数多** ✗（否则 `bad argument #N to 'format'`，若在 pcall 里会被**静默吞掉** ✗）
- **实例**：实测 **6 次调用 → 2 次打印**（不节流 12 行 ✓）

### 4.6 `%d` 收到浮点会抛 ✗
- **症状**：`string.format("%d", 浮点)` ⇒ `number has no integer representation` ✗ ⇒ 若在 pcall 里**静默吞掉** ✓，否则**打断整帧** ✗
- **正确做法**：`%.0f` ✓
- **实例**：出现过 **3 次**（`main.lua` 的 `w or 0` ✗、探针 L355 ✗ …）

## 六、工具 / 流程

### 6.1 `edit` / `write` 工具**不写 BOM** ✗
- **规则是相反的** ✓：**`.lua` 必须【没有】BOM** ✓（Lua 引擎解析器）· **`.ps1` 必须【有】BOM** ✓（PS 5.1 靠它判编码；无 BOM 且含中文 ⇒ 按 **GBK** 解码 ⇒ **整份脚本解析失败** ✗）
- **症状**：用 `edit` 改完 `.ps1` ⇒ BOM **被悄悄剥掉** ✗ ⇒ 该脚本下次**根本跑不起来** ✗（**本项目栽过 4 次** ✓）
- **权威**：`.ps1` 的 BOM 归 **`tools/normalize_encoding.ps1`（`check_all` 步骤 2c）** ✓；`check_encoding.mjs` **只报告不判红** ✓（曾因两套规则互相抵消 ✗）

### 6.2 判据里的**行号会过期** ✗
- **正确做法**：每次动手前**重新取坐标** ✓（`--depths` / 哨兵输出 ✓）；**不要**沿用上一轮的数字 ✗
- **更稳**：脚本**按内容锚定** ✓ + **改前校验锚点内容** ✓ + **改后独立判据** ✓ + **失败自动回滚** ✓✓（这个模式救过我 4 次 ✓）

### 6.3 并发写盘时**警报会失真** ✗
- **症状**：收到"树坏了"的警报，但其实**已经修好了** ✗（或反过来 ✓）
- **正确做法**：**先自己复核**（`luac` + 结构 + 套件 ✓）再行动 ✓
- **纪律**：**同一文件同时只有一个写者** ✓（本项目为此吃过大亏：`git checkout` 抹掉过别人两次成功修改 ✗）

### 6.4 **打包/提交前先跑判据** ✗
- **实例**：曾从"改到一半的源"打包 ⇒ **整批测试崩** ✗（`board_bg 0/1` ✓）；也曾把**语法错误**提交进去 ✗（**"第一次运行的验证"与"提交"不能放在同一条命令里** ✗ —— 命令失败后 `git add -A && commit` 照样执行 ✓）

### 6.5 静态检查的价值：**默认关闭的路径只有它抓得到** ✓✓
- **实例**：selene 抓到的 **5 个真坑**里，**全部**在"离线测试测不到"的路径上 ✓（`btn_art` 路径 ✗、`v2`/`a2` ✗、跨帧记忆 ✗）
- **一句话**：**"离线测试全绿" ≠ 没问题** ✗ —— 默认关闭的路径需要**静态检查** ✓
