## 三、真正的缺口（这就是本轮的建设任务）

### 🔴 缺口 1 ★★★ `result` 弹窗的四键，只建出来一个

实测错误行（v214，点击结算后）：

```
[murdoku] 这些控件还没建（共 3 个，按类分组）：
[murdoku]   modal.*  ×3   modal.exit modal.home modal.settle
```

- 四个键在 `ui_controller.lua` L3457-3464 里**都 push 了**：
  `modal.next` / `modal.exit` / `modal.home` / `modal.settle`
- 但 `cfg.auto_create = false`，`auto_create_only` 白名单里**只有 `hex.*` / `hit.*` 14 个**
  ⇒ 这四个键**没有任何一条被造出来的路** ✗
- 结果：模拟器里 `modal.next` 有（存档里就有这个名字），**另外三个点不到** ✓

**⇒ 修法（不是补丁，是收口）**：

★★★ **2026-10-12 追加查证（重要，改了我第一版的判断）** ✗✓：
`entry_client_script.lua` L307-323 写着 —— **`auto_create_only` 白名单 2026-10-09 已整段删掉** ✓
（那 14 个 `hex.*`/`hit.*` 当时**搬进存档**了，`check_names` 的"脚本会自动建"从 14→0 ✓）
⇒ ★ **所以"加白名单"这条路【不存在了】** ✗ —— 白名单机制已被用户拍板取消 ✓

⇒ ★ **唯一符合项目既有约定的修法 = 与 `hex.*`/`hit.*` 同一条路：把四键【搬进存档】** ✓
　 工具：`tools/gil/gen_icons.mjs`（搬 14 个控件用的就是它 ✓）
　 步骤：`lua tools/dump_layout.lua` 重出 plan → 克隆原型 → 打补丁 → 登记子列表
　 → `tools/gil/roundtrip.mjs` 闸门 → **从磁盘重读断言** ✗（读内存不算 ✓）
　 ⚠️ 顺序纪律（照 `hex`/`hit` 那次）：**先建能渲染的、后建热区** ✓ 否则射线被图片控件吞掉 ✓

### 🔴 缺口 2 ★★ `modal.exit` 这一个 id 有两套几何（并集冲突）

同一个 `modal.exit` 在两个状态里被声明成不同位置：

| 状态 | 位置 |
|---|---|
| `exit_menu`（L3520） | `y = my + 50`（第一个键） |
| `result`（L3459） | `y = my + 146`（第二个键） |

而 `layout_plan()` 是**并集**、只留第一个 ⇒ 编辑器/存档侧只能有一套几何 ✗
（与本项目第 11 号历史 bug「自适应几何在并集里自相矛盾」**同形状** ✓）

**⇒ 修法**：`result` 四键改用**独立 id**（例如 `result.next/exit/home/settle`），
与 `exit_menu` 彻底分家 —— 两个界面本来就是两件事 ✓

### 🟡 缺口 3 ★★ 结算信号没有接收方

- 客户端：`main.lua` L362-370 `on_settle` ⇒ `adapter:signal_emit(SIGNALS.SETTLE, {level_id})` ✓

- 服务端：`serverLogic.rules = []` ⇒ **空** ✗

**⇒ 这是服务端节点图的活**（不在 Lua 客户端脚本里）。本轮给出接法规格；
真机上还要把 `murdoku/solved` / `murdoku/save` / `murdoku/settle` 三条一起接。

### 🟡 缺口 4 ★ 模拟器不实现 `RefreshItems` ⇒ 线索卡列表项建不出来

⇒ **后果**：模拟器里**点线索卡选人这条路验不了** ✓
⇒ 但**判定链不受影响**（本轮用 `hit.hint` 走通了）✓
⇒ 真机上列表项是引擎建的，所以**"点卡选人"只能等真机** ✓ —— 这条要如实标注。
