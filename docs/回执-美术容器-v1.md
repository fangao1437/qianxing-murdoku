## 6. 已知风险 / 边界

1. **号段只保证"与本文件不撞"**（E14）：`.gil` 只带当前关卡状态，编辑器工程侧索引占用不一定在文件里。
   `1073746100+` 在本档完全空（494 maxGuid=1073743994），且**刻意不复用**上一轮 495/496 的
   `1073746000–1073746003`（两份存档若同时留在工程里会同号撞，E11）。
   真机若仍报「控件 GUID 重复」⇒ `--guid-base=1073746200` 重跑（不要改结构）。
2. **6 层家具的图/色/几何不在 `.gil`**：本工具只加空的 obj2..obj6（imageId=100001 占位、与 obj 重叠）。
   美术数据由脚本模块 **`lua/furn_art.lua`** 给（lead 侧改）；若脚本没给某层，该层是占位色块。
   `things` 的 6 个 `obj.<kind>` 本轮**不写 palette**、保持原样 ✓。
3. **`labels` 初始 visible=false**：房间名要在运行时由脚本 `SetVisible(true)` 并 `SetText`；
   容器 `labels` 本身保持**可见**（父级隐藏会连坐，脚本再点不亮）。
4. **兄弟次序**：`labels` 在 `root` 里紧跟 `stage` ⇒ 画在棋盘之上，但仍在 `home / topbar / modal / teach`
   **之下**（这些菜单/HUD/教程本来就在 stage 之后）。若设计要求"房间名压住 HUD"，把 labels 在 root
   子列表里往后挪即可（改一行 ID 数组，工具可加 `--place-after=`，本轮未做）。
5. **文本属性字段是"文档+工具实测"结论、非本轮真机验证**：`#506`/`#502` 的默认语义来自
   `docs/转换器-gil到模拟器存档.md` §4.3；若真机发现 outline/adaptive 行为不符，改工具的常量重跑即可。
6. **visible/active 判据**：`visible` 用 `check_visible.mjs` 全档实测判据（隐藏 = `/503/14/17/503=1`）；
   `active` 本档 466 条基线里**没有** inactive 标记（`#14/#502`），故"不写 = 默认激活"。
   若真机发现 label 不显示，先查这两处。
7. **两份 content 都改了**（E6）：若之后在编辑器里重导出覆盖模板，需要对新基线重跑本工具。
8. `label.N` 的 `text` 为空、初始都在棋盘中心 (0,0) —— 运行时由脚本逐关摆位/写文案（lead 侧已定）。
