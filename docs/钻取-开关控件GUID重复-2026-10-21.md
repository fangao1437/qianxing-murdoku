### 2.3 控件登记模型：一条记录有 **7 处**自身 GUID + 3 个登记字段

以 `472` 的 `result.next`（1073742714，主档原生按钮）与 `479` 的 `tut.btn.close`（1074000025）为例：

```
记录（顶层字段列表）
├─ #501 = <自身 GUID>                    ① 顶层这份
├─ #502 = { #11 { #501=<自身 GUID> } #501=1 #502=5 }      ② 实例表那份（编辑器校验读这里）
├─ #502 = { #12 { #501=<模板族序号> } #501=2 #502=6 }     ③ 族序号
├─ #502 = { #13 { #501=<源控件 GUID> } #501=3 #502=? }    ④ 只在"母本记录"上出现
├─ #502 = { #14 { #501=<母本 GUID> } #501=4 #502=4 }      ⑤ 只在"实例记录"上出现
├─ #503 = <子控件 ID 列表（裸 varint）>                   ⑥ 父登记子
├─ #504 = <父控件 GUID>                                   ⑦ 子指回父

      #505[1] = { #12 { #501="控件名" } #501=2 #502=15 }   ← 控件名在这里（不是类型串）
```

## 三 真因判定

### A. 这条校验比对什么集合？

| 候选集合 | 结论 |
|---|---|
| 顶层 `#501` 的数值集合（旧口径 `probe_guid_collision` ①） | **不是它**：`479` 顶层 412 个 GUID 两两不同，`1074000025` 只有一条。`[实测]` |
| 全档所有 big-id 数值出现次数（`_probe_innergids` 口径） | **不是它**：父指针天然多对一、子列表每子一次、状态块 5 份自引用；`472` 也有 810 处 `#501` 大号却正常。`[实测]` |
| `#502 组件表` / `#505 状态块` 的**数值**结构 | **不是它**：`btn.close` 与 `btn.prev` 逐字段同构，`btn.prev` 没被点名。`[实测]` |
| **"界面控件登记关系"**：实例表那份 GUID ＋ `族号 #12 → 母本 #14` 的解析 ＋ 父子表 | ★ **最可能**：`479` 里有 24 条母本悬空 + 4 个族号带进"参考档没有的母本"；`472`（实机正常）这两项为 0，`475`（源骨架）母本链闭合。这是 479 与"跑得通的档"之间**唯一**的结构性差异。`[实测差异 + 推断机制]` |

**机制（`[推断]`，与库内既有档案 `docs/gil工具-总览与错误路径.md` §E4 同源）**：
一条带 `#502 组件 4` 的记录 = "我是某个客户端控件模板的实例"。编辑器载入时必须解析出母本；
解析不到时它会把这条实例**同时当成"新模板本体"和"界面树里的控件"**登记 ⇒ 同一个 GUID 在
"界面控件"和"控件模板表"里各出现一次 ⇒ 校验报「界面控件里的…控件GUID重复:<号>」。
这就是"文件里明明只有一条"却报"重复"的由来。

**`[UNKNOWN]`**：具体是哪一层（族表还是母本表）先触发、以及为什么报的是这一条而不是别的条，
离线证据不足。§六 给了 3 个能一次分清的真机实验。

### B. 为什么是「开关控件」和 `1074000025`

- 「开关控件」：**不是类型**（§2.10 两例反证）。
- `1074000025`：`[实测]` 它是 `tut.btn.close` 的自身 GUID；它在**族 30**。族 30 是 4 个悬空族里
  **唯一"主档本来就有同号族、且主档该族已有母本（1073742355）"** 的那一个（`[推断]` 唯一可能构成
  "同族两条母本"的族）；而 `1074000025` 是这批"族 30 且母本悬空"的 7 条记录里**文件顺序最靠前、
  GUID 最小**的一条。`[推断]` 校验器按族号处理、遇到第一个"登记两次"的就抛错 ⇒ 报到它。

  ⚠️ 这条只是**相关性**：`[实测]` 主档自己也有多母本族（70/73）却正常，所以"族内两条母本"不足以定罪，

## 七 附：本次新增的两个只读探针

两个文件都 **只读**，不写盘、不改任何 `.gil`，可以随时跑。

### `tools/gil/probe_top_subtrees.mjs`

```
node tools/gil/probe_top_subtrees.mjs <存档.gil> [更多...] [--json] [--limit=6]
```

- 外层头 / `/#1` 存档 id / `/#2` 名 / `/#52`；
- 每个顶层字段：线型、字节、**其下记录数**、`#501` 大号数、子列表段数与项数、文本样例；
- **控件记录住在哪个顶层字段**；记录按父级的分布（标出"父不是记录 ⇒ 引擎/模板容器"）。
- 用途：一句话回答"这个档的界面控件在哪个子树里、并入时有没有动到别处"。

### `tools/gil/probe_ui_registry.mjs`

```
node tools/gil/probe_ui_registry.mjs <存档.gil> [--base=<基线.gil>] [--id=] [--name=] [--verbose] [--json]
```

六段体检 + 一段 diff，退出码 `0` = 自洽 / `3` = 有硬问题：

| 段 | 查什么 |
|---|---|
| ① | 自身 GUID（顶层 `#501`）重复、唯一值数 |
| ② | 实例表那份（`#502[1]/#11/#501`）与 `#501` 是否一致（`472` 有 1 条例外，不算错） |
| ③ | **母本链**：有引用多少条 = 指向本档 / 空母本 / **悬空**（悬空判 FAIL） |
| ④ | **模板族序号**：每族成员数、母本集合、**一族多母本**、**与基线撞族**（带进基线没有的母本） |
| ⑤ | 父子表：子列表重复、登记了不存在的记录、与父指针不符 |
| ⑥ | **模板容器**：不是记录却收着记录的父级（472=`1073741844`，475/477=`1073742015`） |
| ⑦ | 与 `--base` 的记录级差异（多出/减少/同 id 但字段不同，字段路径级） |
