> 真正的根因与最终修复见 **`回执-教程家具可见-v358.md`**（存档 `579-教程家具可见-v358.gil`）。

## 1 现状链路（v356 的设计）

`lua/tutorial_ui.lua:_ensure_furniture()` 在教程 `init/open_ui` 时：
1. 找 `td.<tag>.board`（每关一套**共享棋盘底图**，静态控件）；
2. `adapter:_furn_prefab_map()` 从 `root/things` 拿 10 个模板源 GUID；
3. `game.InstantiateClientUIControl(prefab, board)` 创建 L1 8 件 / L2 12 件家具；
4. 设尺寸/位置/整树缩放，然后 **`SetSiblingIndex(地毯=1 / 家具=2)`**。

单测（v356）验证了"创建 20 件、挂到 board、缩放比例正确"，所以看起来都通过。

## 2 根因：`SetSiblingIndex(1/2)` 在教程里语义完全不同

- 正式关卡里 `1/2` 是 **格子 content 里的序号**：
  `0=face`、`1=地毯`、`2=家具`、`3+=墙/门/笔记/头像` —— 那里是"少量覆盖层"。
- 教程里 parent 是 `td.<tag>.board`，它是**存档静态底图**：v356 存档里
  `td.l1.board` 有 **27 个直接子控件**：
  - `svg.1`（428×428）、`svg.2`（381×381）——底图/边框；
  - `svg.3 ~ svg.27` —— **25 个格子底板（70×70，不透明房间色）**。
- 官方 API 语义：`SetSiblingIndex` 数值越大越靠上 ⇒ **把家具塞到 1/2 号位 = 落到 25 个格子底板之下**，
  运行时实例化了，但被底图完全盖住 ⇒ 真机/试玩"家具没出来"（用户说的"卡住"）。

## 3 修复（lua/tutorial_ui.lua）

1. **删除照搬来的 `SetSiblingIndex(1/2)`**；
2. 改为 **append 到父控件末尾（最上层）**：`SetAsLastSibling()`；没有该方法时退化为
   `SetSiblingIndex(#parent:GetChildren()-1)`；
3. **两遍创建**：先建地毯（`rug / rug_2 / rug_3`），再建其它家具
   ⇒ 后建的更靠上 ⇒ **棋盘底图 < 地毯 < 家具 < 页面提示层**（提示层在 page 根上，本来就高于 board）；
4. 加诊断日志：`[tutorial] 家具实例化 tag=l1 新建=8`（只打一次，真机可判读）；
5. 找不到 `board` / `things` 映射为空时也打日志（原来静默 return）。

## 4 回归

`tests/tutorial_ui.lua` 扩到 **28 条**，新增层序断言（27 个底板子控件模拟 v356 存档）：
- 所有家具实例都 `SetAsLastSibling`（不再被底板盖住）；
- 不再往 1/2 号位塞（旧行为会落到格子底板下方）；
- L1 先建 2 件地毯（`rug_2`×2）再建家具；L2 先建 3 件地毯（`rug/rug_2/rug_3`）再建家具；
- 原有：创建 20 件、挂 board、缩放比、重复打开不重复创建 —— 全过。

## 6 真机验收（重点）

1. 打开教程：
   - 首页：无家具（按设计）；
   - L1 第 1–8 页：棋盘上应有 **8 件**家具（2 桌、3 植物、2 地毯、2 椅，口径以 FURN 表为准）；
   - L2 第 1–4 页：应有 **12 件**（含雕像/书架/多格地毯）。
2. 层序：**格子底板 < 地毯 < 家具**；页面上的候选标记/红叉/金圈**仍在家具之上**。
3. 日志出现一次：`[tutorial] 家具实例化 tag=l1 新建=8` / `tag=l2 新建=12`；
   若为 `跳过 tag=…`，把那行发回来（说明 board 或 things 映射没找到）。
4. 若家具出现但位置/大小不对：把截图发我，按 `FURN` 表逐件调坐标（表在 `tutorial_ui.lua` 顶部）。
