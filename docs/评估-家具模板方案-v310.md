## 0. 结论（先给 lead 用）

| 问题 | 结论 |
|---|---|
| 模板本体（每个家具 = 1 个客户端控件模板，内含 9~12 层图片控件）能否**纯靠写 .gil** 造？ | **结构上可以**。模板 = **模板源 + 母本** 两条记录（各带一棵内容子树），我们上一轮已纯写 `tpl.prim` pair 并过全部离线闸门；仓内 `cell.1.1`/`tpl-container`/`hex` 都是这种 pair。 |
| 模板引用控件能否纯写？ | **可以**（克隆 `tpl.stage`：槽 `/505(501=66,502=89)`，引用值在 `/505/503/77/501 = 模板源 GUID`）。 |
| **需要用户在编辑器手动引用吗？** | **本轮结论：不需要。** cell 的实例化根本不经过引用控件 —— `cfg.cells.prefab` 直接就填**模板源 GUID**（1073741876）。模板引用控件只是"编辑器里的摆放/登记"工具。为保险，我会**顺带写 7 个引用控件**到隐藏容器，脚本可读 `referencedPrefabIndex` 兜底，但**用户无需动手**。 |
| 真机风险 | 纯写模板**尚未真机验证**（`tpl.prim` 当时也只做了离线校验）。若真机 `InstantiateClientUIControl` 返回 nil → 走 §4 的**最小手工回退**（用户只建 7 个空模板并"存为模板"，层次由我填）。 |

**记录预算（重要）**：模板 pair 有**两份内容拷贝**（实测 `cell.1.1` 的源 #1876 与母本 #1880 **各带一棵 content 子树**，各 26 个子控件）⇒ 7 模板共 **178 条新增**：
`7×(源+母本)=14` + `7×2×content=14` + `2×71 层=142` + `7 个模板引用控件` + `1 个容器` = **178**。

- 基于 **502（500 条）** ⇒ 514 = **678 条**（< 1000 ✓）
- 基于 **511（957 条）** ⇒ 1135 条（**超 1000 ✗**）
- ⇒ **建议 514 从 502 出**；模板方案取代"静态烘焙"路，烘焙的 457 条控件不再需要（若要保留回退则必超上限，二选一）。

## 1. 为什么判断"结构上可行"（依据）

1. 模板的 .gil 模型（`probe_ui_registry.mjs` / `docs/钻取-开关控件GUID重复-2026-10-21.md` §2.4 实测）：
   - **模板源**：无父、不在任何子列表（"仅存为模板"在 .gil 里的形态）、组件 `[1,2,4]`：`#502[2]/#12=族号`、`#502[4]/#14/#501=母本 GUID`；
   - **母本**：父 = `ClientUIPrototypeHierarchyRoot #1073741844`、组件 `[1,2,3]`：`#502[3]/#13/#501=源 GUID`；
   - **源与母本各有一棵内容子树**（两份拷贝，`cell.1.1` 实测：源 child=content#1888，母本 child=content#1886，各 26 个孩子）—— 写模板必须**两份都写、保持一致**。
2. 仓内已有 3 个可用模板 pair（`cell.1.1` / `tpl-container` / `hex`），其中 `cell.1.1` 就是"容器节点 + 26 个子控件"的**多层模板**——正是家具模板要的形状（只是层数 9~12、层是图片控件）。
3. 上一轮我已纯写 `tpl.prim` pair（模板源 + 母本），`writeGil` 四闸 + probe 登记自洽全部通过——**写入链路没有未知字段**。
4. 外来参考档 `_work/art-tools/.../templates/2D-ready.gil`（外部拼图网站导出）同样是"模板源 + 母本"结构，其 lua 用 `game.InstantiateClientUIControl(模板源 id, parent)` 逐件画——**说明实例化只用模板源 GUID**（`_work/art-research/artkit-*/**.lua` 的 `IMAGE_PREFAB_ID` 用法）。

**结论：模板 pair + 多层内容 = 纯记录结构，我们完全能写。唯一未验证的是"引擎是否接受手写模板被 Instantiate"。**

### 2.2 模板引用控件（可选、兜底）

| 项 | 值 |
|---|---|
| 名字 | `tpl.furn.chair` / `tpl.furn.plant` / …（7 个） |

### 2.3 实例化协议（照抄 cell 已真机验证的路径）

```lua
-- 每件家具每格实例化一次（父 = 新容器 root/fart.furn；容器在 labels 之后、home 之前）
local ctrl = game.InstantiateClientUIControl(cfg.furn_tpl[key], furnParent)
ctrl.name = "furn." .. level .. "." .. i          -- 唯一名，脚本记账用
ctrl:SetAnchorMin(0.5, 0.5); ctrl:SetAnchorMax(0.5, 0.5); ctrl:SetPivot(0.5, 0.5)
ctrl:SetSizeDelta(cell_size * span_c, cell_size * span_r)   -- span 来自 piece.span_c/span_r
ctrl:SetAnchoredPosition(x, y)   -- 锚点格中心相对 furnParent 中心（Y 向上）
ctrl:SetSiblingIndex(k)          -- 官方语义"数值越大越靠上"；按 anchor.r 递增（下排压上排）
```

- `key` 与 `FurnArt.layout().pieces[i]` 的映射：`pieces[i] = {kind, variant("1"/"h2"/"v2"), box, anchor, span_r, span_c}`；
  `cfg.furn_tpl` 建议键 = `chair` / `plant` / `statue` / `shelf` / `table`(单格) / `table_h2` / `table_v2`（或统一 `kind .. "_" .. variant`，脚本侧定）。
- 两关实际用到的组合已核对（`lua/levels/case_001.lua` §objects / `case_002.lua` §objects）：
  桌子=单格/横 2/竖 2 三种都有；椅子/植物/书架/雕塑都单格；地毯**不走模板**（保持现状，跨格连续图形）。**7 个模板刚好覆盖**，无缺口。

### 2.4 缩放口径（需要 lead 定，这是唯一的行为不确定点）

- 模板内容按 **108 画布 px = 1 格** 写死（规格数据原样，`dx` 向右、`y = -dy_down` 向上）。
- 5×5 时 `cell_size = 108` → 1:1，不用缩放；6×6 时 `cell_size ≈ 89.3`（f ≈ 0.827）。
- **模板内部图层不会自动随根控件 `SetSizeDelta` 缩放**（cell 模板里脚本也是显式缩 `face`/`x` 的，见 adapter L2392-2407）。
  ⇒ 推荐脚本在实例化后按 f = `cell_size / 108` 遍历实例子控件：`SetSizeDelta(w*f, h*f)` + `SetAnchoredPosition(dx*f, dy*f)`（层名我会起成 `L01`…`L12`，`GetChildren()` 即可遍历）。
  ⇒ 或者先只做 5×5（1:1），6×6 再调 —— 请 lead 定。

## 3. 模板内部结构（工具将按此写）

```
模板源 record（无父；组件[1,2,4]；族号 80~86；#14→母本）
 └ content（容器节点，108×108 或 216×108，pos(0,0)，锚点/中心 0.5；clear 后重建）
     ├ L01 … L12（图片控件：imageId=规格 id；imageColor=规格 color；imageType=Stretch；
     │             w×h=规格 w/h；pos=(dx, -dy_down)；锚点/中心 0.5；visible=true）
母本 record（父 1073741844；组件[1,2,3]；#13→源）——同样是上述内容的**第二份拷贝**（保持一致）
```

- 模板源/母本自身的 4 个状态块：`#504` 位置、`#505` 尺寸、`#502/#503` anchorMin/Max、`#506` pivot（模板画布/锚点字段就在这里）。
- 层顺序 = 规格 `order`（1 在下）；工具按 order 排 childList。

## 4. 若真机不支持纯写模板：最小手工回退（1/2/3/4）

1. 编辑器 → **界面控件组管理 → 界面控件组库 → 客户端控件模板 →【添加客户端控件】**，类型选「容器节点」；
2. 名字**精确**填 `furn.chair` / `furn.plant` / `furn.statue` / `furn.table.1` / `furn.table.h2` / `furn.table.v2` / `furn.shelf`（7 个，**不用摆任何子控件**）；
3. 每个点「**存为模板**」（保存后 .gil 会出现"源+母本"pair；此时母本里的内容子树可能与源不一致——没关系，下一步覆盖）；
4. 把这份存档给我：我用 514 工具 `--fill-existing` 模式（按名字找到 7 个 pair）**自动填 71 层（两份拷贝）、写 7 个引用控件**，其余结构不动。
   > 用户**不需要手摆任何图元、不需要手动引用**；唯一手工动作就是"建 7 个空模板 + 存为模板"。
