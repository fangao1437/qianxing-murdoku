## 一 根因（三条，全部有出处）

| # | 根因 | 位置 |
|---|---|---|
| 1 | **缩放用错手段**：模板实例的层是"内容根的孙子"，按画布 108 的绝对像素定位；`_furn_scale_layers` 只改**内容根的 sizeDelta** ⇒ 框变了、层没缩 ⇒ 家具偏大 1.21 倍、跨格件溢出 ✗ | `_furn_scale_layers`（v323） |
| 2 | **应用记录挂在控件对象上**：`inst.__murdoku_applied` 在真机读回来**永远是 nil**（控件不收自定义字段）⇒ 每趟 resync 都判定"参数变了" ⇒ **销毁→重建→再销毁**（闪、卡、日志刷屏）✗ —— 离线用例当时是绿的，因为假控件是 Lua 表、能存字段（假环境骗了一次） | `_spawn_furn_tpl` |

> 附带修掉：v323 的兜底 `ch:SetScale(avg, avg)` —— **官方没有这个方法**（只有 `SetLocalScale(x,y,z)` / `localScaleX/Y/Z` 字段），pcall 吞掉后等于没写。

## 二 改了什么

1. **缩放改成真变换**：`_furn_scale_layers` 现在依次尝试 `SetLocalScale(fx, fy, 1)` → `localScaleX/Y/Z` 字段 → 子内容根 `SetLocalScale`
   （`fx = 格子宽×跨格 / 模板画布宽`，画布取 `cfg.furn_tpl_canvas`）⇒ 整棵子树（含所有层）一起缩 ✓
   旧实现保留为 `_furn_scale_children`（只在完全没有 scale API 时兜底）；
2. **应用记录挪进适配器表** `self._furn_applied[inst_key]`（销毁/换格/换关三处一并清）⇒ resync 真幂等，不再重建；
3. **`_cell_size_of` 优先 `rects`**（布局算出的真实像素），读不到才退回 `sizeDelta`；两者不一致时打一行
   `[murdoku] 格子尺寸：cell=… rects=… sizeDelta=…（用 rects ✓）`（每格一次）；
4. 缩放方式打一行 `[murdoku] 家具缩放：比例=… 方式=SetLocalScale`（每种方式一次，失败会写明"三种写法都不行"）。
