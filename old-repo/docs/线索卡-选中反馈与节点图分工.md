## 一、选中反馈：现状 vs 设计图

### 现状（代码事实，`ui_controller.lua` 的 `focus_clue` 分支）

```lua
elseif a == "focus_clue" then
  if self.focused_clue == ci then self.focused_clue = nil   -- 再点一次 = 取消
  else                          self.focused_clue = ci  end
  self:fx("clue." .. tostring(ci), M.EFFECTS.CLUE_IN)        -- clue_box_pop：弹一下
```

| 项 | 现在 |
|---|---|
| 状态 | `self.focused_clue` = 第几条 ✅ 有 |
| **反馈** | **只有一次性的 `clue_box_pop` 动画** |
| **常驻高亮** | ❌ **没有**（松手动画播完，卡片外观和没选中一模一样）|

### 设计图要的（`docs/线索卡-设计图.png` 下半张）

**选中态 = 卡片外框从 1px `#46464a` 变成 3px 纯白**（外框尺寸不变）。

⇒ **这是当前缺的那一半**，而且**可以完全由脚本实现，不需要新素材**（见下）。

## 二、选中反馈怎么做（三个方案，按可行性排序）

| 方案 | 脚本能独立完成？ | 代价 | 评价 |
|---|---|---|---|
| **★ A. 白框垫片**：每张卡背后放一块**比卡片大 4px 的白色方块**，只有选中那张显示 | ✅ **能** | 5 个额外控件，各 1 次 `SetVisible` | **推荐** |
| B. 换底图：卡片底图在"普通/选中"两张之间切 | ✅ 能 | 需要**两张素材**（选中态那张要你出图）| 备选 |
| C. 染色 `imageColor` | ⚠️ **有坑** | — | 见下面的警告 |

### ★ 方案 A 的实现要点（全部是已验证过的技术）

```
每张卡 i：在 clues 下建一个 ring.i
   模板 = cfg.prefab_icon（纯图片模板，真机验证：能建、能设图）
   image_id = 100001（基础形状·正四边形，纯白 256×256）
   尺寸 = 卡片 + 4px（设计空间 → 画布 456×106 的卡 → 垫片 464×114）
   位置 = 卡片中心
   SetSiblingIndex(0)  ⇒ 压到所有卡**下面**（「底板压到最底层」用的就是这个，已验证）
   SetVisible(选中)    ⇒ 只有 focused_clue 那张是 true
```

露出的是卡片四周 **4px 白边**，视觉上就是设计图的"白框" ✅
（卡片本身是不透明的深色底，中间会盖住白块。）

**为什么放背后而不是前面**：放前面会盖住卡片的文字；放背后只露一圈边，且不用抠图。

### ⚠️ 方案 C 的警告（别走这条路）

真机日志（每次开局都会打）：

```
环境没有全局函数 `Color`，染色跳过（不影响玩法）。
官方文档里 ColorValue 由 `Color(r,g,b,a?)` 创建（0–255，a 可省略）。
```

⇒ **染色在当前环境是跳过的**。而且即使能写，`imageColor` 是**乘算**（乘白不变、乘深色压暗），
**压不出比素材更亮的颜色** ⇒ 用它做"高亮"方向就是错的。

## 三、外部素材（头像）怎么进来

**脚本不能直接引用你本地的图片文件** —— 它只能写 `SetImage(imageSource, imageId)`。
外部素材有自己的 `imageSource` 和 `imageId`，**这两个值脚本拿不到**，除非有人先把它摆进编辑器。

### 可行且已验证的做法：**调色板照抄**

```
编辑器里：
  assets（容器，可以放到画布外）
    ├─ portrait.A   图片控件，图配成嫌疑人 A 的头像
    ├─ portrait.B   ……
    └─ portrait.E
```

脚本运行时：

1. 找到 `assets` 下的 `portrait.X`（**按名字找**）
2. **读**它的 `imageSource` 与 `imageId`（图片控件的这两个字段是**只读可读**的）
3. **写**到线索卡的 `clue.N.face` 上（`SetImage(imageSource, imageId)`）

> 这条链子**已经在格子上跑通了**（`Adapter:_cells_stamp` 的注释原文：
> 「图片控件的 imageSource / imageId 是只读可读的（API 文档 1427~1434），
> `SetImage(imageSource, imageId)` 是写接口（1503），所以可以直接照抄。」）

⇒ **结论：外部素材可以用，但必须先在编辑器里摆一个"引用它的图片控件"当中间人。**
   名字就是引用键（`portrait.A`），脚本按名字取。

## 四、脚本**建不出来**的部分（这是硬边界）

脚本只能用**已存在的客户端模板**建控件，而三个可用模板的子树里**都没有文字控件**：

| 模板 | 索引 | 子树里有文字吗 |
|---|---|---|
| 格子（可点、可设图）| `1073741876` | ❌ 日志原话 `没有配的：text obj` |
| 纯图片 | `1073742357` | ❌ |
| 容器 | `1073742330` | ❌ |

而 `.gil` 里**所有**带 `label` 的记录，都在**编辑器摆的按钮**下面
（`home.select` / `home.continue` / `home.shop` / `home.bag` / `action.back`）。

⇒ **判据一句话**：

> **要显示文字的控件，只能编辑器摆；不显示文字的（纯图 / 容器 / 可点热区），脚本能建。**

### 分工表

| 部件 | 谁建 | 说明 |
|---|---|---|
| 卡片底（深色圆角 + 可点）| **脚本** ✅ | 格子模板 + `SetImage` 换底图 |
| **头像** `clue.N.face` | **脚本** ✅ | 纯图片模板 + 从 `assets` 照抄 `imageSource/imageId` |
| **选中白框** | **脚本** ✅ | 方案 A |
| ▲ / ▼ 滚动 | **脚本** ✅ | 用**箭头图片**素材建图片控件（不要用文字 ▲▼，那是文字 ⇒ 建不出来）|
| **角色名** `clue.N.who` | **编辑器** ❌ | 文字 |
| **线索正文** `clue.N.what` | **编辑器** ❌ | 文字 |
| **徽章字母** `clue.N.letter` | **编辑器** ❌ | 文字 |
| 徽章底 | 脚本 ✅ | 纯图 |
| `clues.count`（3/18）| **编辑器** ❌ | 文字 |

## 五、编辑器要摆的**最小节点图**（只有文字那几个）

```
root
└─ clues                    ← 容器（脚本会用，但摆一个更稳；尺寸 456×575 设计空间）
   ├─ clue.1                ← 卡片（可点，预设按钮；456×106 @ x=72, y=314）
   │   ├─ clue.1.who        ← ★文字：角色名        127×29  @ 相对卡片 (101, 26)
   │   ├─ clue.1.what       ← ★文字：线索正文      199×29  @ 相对卡片 (101, 58)
   │   └─ clue.1.letter     ← ★文字：徽章字母       35×30  @ 相对卡片 (404, 63)
   ├─ clue.2 … clue.5       ← 同上，y 依次 +118（432 / 550 / 668 / 786）
   └─ clues.count           ← ★文字：「3 / 18」（可省）
```

> **只摆这 5 张卡的 3 个文字子控件 + 计数 = 16 个控件。**
> 头像、卡片底、白框、▲▼ 全部由脚本负责 —— 这也正好配合你"头像以后换外部素材"的计划：
> 换素材时**只动 `assets` 里的 `portrait.X`**，脚本一个字都不用改。

### 摆的时候 4 个要点

1. **名字一字不差**（脚本按名字找）：`clue.1.who` / `clue.1.what` / `clue.1.letter`
2. **卡片本身要能收光标事件**（和 `home.select` 同类的预设按钮）——
   纯图片控件真机验证过**收不到点击**（日志：`控件 hex.* 不支持光标事件`）
3. **文字控件不要设固定文案**，留空即可（脚本每帧按关卡数据填）
4. **摆完不用"存为模板"** —— 脚本直接复用你摆的这 5 张，靠滚动换内容

## 六、待你确认的一点

方案 A 的**白框宽度**建议 **4px（设计空间）**，即"卡片四周各露 4px 白边"。
设计图上量到的是 3px（画布）= 3.6px（设计）⇒ 我按 **4** 来做，视觉上等价。
**如果你想要更粗/更细，说一个数就行**（这是唯一需要你拍板的参数）。
