fix: placing a person shows only the portrait, and print the row-to-letter map.

The user reported that placing an avatar also dropped the letter into the cell. That was the
2026-10-10 reading of "let the letter replace the pencil note", where showing the letter on a
placed piece looked like the same feature. The user has now separated the two: a pencil mark
shows the letter, an actual placement shows only the portrait. So the placed-piece branch is
gone entirely and the note falls to the mark list, which for a placed cell is empty. That
already yields the value the adapter needs to hide the note, so nothing extra is written.

For the level-3 DEF report: the chain is provably correct. I reproduced level 3 exactly -- seven
rows, seven pieces -- and each piece resolves to its own row and that row's letter:
A->L1 B->L2 C->L3 D->L4 E->L5 F->L6 V->L7, with the letters deliberately distinct from the
piece ids so an id fallback could not pass. Rows 4, 5, 6 are what feed D, E, F. The board note
is copied from the row, so if the cells read A, A, F then those rows hold A, A, F in the editor
and no code change can correct that -- the script can only render what is configured. Rather
than guess, the build now prints the whole mapping once per level:

    row -> piece -> letter

so a wrong letter is visible directly instead of inferred. It retries until the table is
populated and then latches, so it appears once and costs nothing after. Getting that dump to
actually print took three tries, all recorded: a call site inside a branch the real archive path
skips, a latch set before the data existed, and a guard written as print ~= true when print is
a function.
