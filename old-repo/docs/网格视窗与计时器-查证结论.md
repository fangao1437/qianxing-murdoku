## 二、计时器 —— **不能替代 `OnUpdate`**（明确结论）

| 问题 | 答案 | 依据 |
|---|---|---|
| Lua 能挂计时器吗 | ❌ **不能** | 官方客户端 API（2917 行）里 `Timer`/`Interval`/`Schedule`/`SetTimeout` **0 命中** |
| 「计时器」界面控件是什么 | **纯显示**（倒计时/正计时），**服务器控件** | `mhnrdor7uyra.txt:1-11` |
| 真正的计时器在哪 | 系统菜单 →**【计时器管理】**（全局计时器，上限 50，挂**关卡实体/玩家**才生效）| `mhn4bsi5lb58.txt:10` |
| 周期定时用哪个 | **【定时器】节点**（服务端）：`启动定时器` + 序列 `[0.5]` + `循环=是` | `mhr6jorjp77a.txt:163,176-178` |
| 能通知客户端脚本吗 | ⚠️ 只能绕：服务端【发送客户端脚本信号】→ `script:RegisterServerSignalHandler` —— **联机延迟最低 100ms** ✗ | `mhbgxf0nynww.txt:174-181` |
| `coroutine` / `wait` | ❌ **引擎禁用**（官方明列不可用）| `mhtakr07vej4.txt:82-102` |
| 能关掉 `OnUpdate` 吗 | ❌ **不能** —— 双击/长按/计时全靠 `dt` 累加；本工程已实测记档（`docs/真机搭建与运行指南.md:21`）| 同上 + `ui_controller.lua:1061` |

### ⇒ 对本项目的真实结论（**修正我之前的判断**）

我早前说"用 `os.clock()` 节流能把每帧开销降到 1/30" ✓ —— 但复核 `main.lua` 后：

- **每帧真正跑的**是 `adapter:on_tick(dt)` + `controller:tick(dt)` ⇒ **不能节流**（双击/长按/计时靠它 ✓）
- **大诊断块**早就是**换屏才打**（`main.lua:675-676` 的 `_dump_done_for` 门控 ✓）⇒ 它**本来就不是每帧** ✗

⇒ **`os.clock()` 节流对本项目的收益很小** ✗（我上一轮说"省 30 倍"是**没有核对代码**就说的 —— 更正）
⇒ **真正的性能收益在网格视窗的列表项复用** ✓（只加载可见项）+ **删掉那 ~319 行诊断块** ✓（早已列入待办）

### 4.3 ★ `RefreshItems` 的一个关键坑（实现时必须知道）

> 网格视窗滚动时**会反复触发回调**刷新列表项内容（官方：`列表发生滚动时：对列表项内容进行刷新(触发回调)`）

⇒ **回调会被重入**，同一批控件换内容 ⇒ **脚本必须"无状态地按 index 重填"**，不能"只填一次就撒手" ✗
（这也是它省性能的原因：**永远只有可见的那几项被实例化** ✓）

### 4.4 按键提示的 24 个键（枚举全覆盖 ✓）

`keyboardKeyCode`（`Enum.KeyboardKeyCode`）能表达项目现绑的全部 24 个键 ✓
- 方向 = `CraftspersonKey36..39`、选角色 = `CraftspersonKey1..10`、放置 = `InteractKey`、笔记 = `JumpKey`、
  划掉 = `DropKey`、返回 = `CraftspersonKey42`、换工具 = `OpenShortcutWheelKey`、橡皮 = `CharacterSkill1Key`、
  提交 = `CharacterSkill3Key`、撤销/重做/提示 = `CraftspersonKey12/13/15`
- ⚠️ `Enum.ControllerKeyCode` **没有** `CraftspersonKey36..39` ⇒ **方向键那 4 个没有手柄提示**，留 `None` ✓

### 5.2 ★「界面动效」不是"给控件挂动画"（别指望它替 `fx()`）

官方原文：**「选择界面动效：可以选中所需要展示在界面布局中的【特效资产】」** ⇒ 它承载的是**美术做的特效资产**，是一个**独立控件** ✗

⇒ **不能替代 `fx()` 的"控件自身弹跳"**，三条硬理由：
1. 动效**不挂在目标控件上**（位置不跟随 ✗）
2. **层级只有两级**（`AboveAllControls` / `BelowAllControls`）⇒ 会盖住别的 UI ✗
3. **没有"播完"回调**（API 无 `SetOnComplete` 之类）⇒ 脚本无法在播完后还原姿态 ✗（而本项目现在正是靠 Tween 的 `SetOnComplete` 写回基准姿态 ✓）

⇒ **但能替代另一件事**：「额外叠一层光效 + 音效」（落子炸光、结案闪白）✓ —— 编辑器里摆好，脚本 `ctrl:PlayAnimation()` 一行 ✓；`playSoundEffect = true` 顺手顶掉现在整张 nil 的 `M.SOUNDS` ✓
⚠️ **全屏界面动效**：API 里**一个方法都没列** ⇒ **不要假定它也有 `PlayAnimation()`** ✗（稳妥路径是节点图的【播放界面动效控件】，但那是服务端、≥100ms ✓）
