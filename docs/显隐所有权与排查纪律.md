# 显隐所有权与排查纪律

> 这份文档是 **2026-10-06** 那次"墙/门第一次进关不画"排查的产物。
> 它存在的唯一理由：**同一个 bug 我查了上百轮没查出来，突破口全是用户找到的。**
> 所以这里记的不是"结论"，而是**下次怎么不再犯**。

---

## 一、那次 bug 的完整因果（四层，每层各有一个"多余的负责人"）

| 层 | 谁在管 | 它做错了什么 |
|---|---|---|
| ① 屏幕层 `apply_screen_hide` | `PREFIX` 里的 `"cell."` | **单向藏**（只写 false ✗）+ 藏的是**格子根**（连坐全部子控件）|
| ② 规划 `layout_plan` | `cell.*` 的 `visible`（原本**没给** ✗） | 首次进关的格子**没人点亮** |
| ③ 适配层 `set_property` | `hide_kids(ctrl, 0)` | **单向递归**（只在隐藏时递归 ✗）⇒ 子控件永不恢复 |
| ④ 每帧 `_cells_paint` | `face` 的"每帧保持" ✓ | ★ **墙/门没有同等待遇** ✗（`face` 有 ✓ 它们没有 ✓）|

**为什么"只有第一关"坏** —— ★ 这一条是用户想到的 ✓：
- 真机日志：第一关「本次新建 **25** 个」✗ · 第二关「本次新建 **0** 个」✓
- 第一关的格子是**开局那一刻**建的 ⇒ 那时 `screen="home"` ⇒ 被①藏 ⇒ 被③递归藏子控件
- 其它关复用已存在的格子 ⇒ `cell.*` **没有 false→true 的过程** ⇒ **从不触发③** ⇒ 看起来正常
- ⇒ ★ **不是"第一关特别"，而是它的建格时机与后加的关卡不同** ✓
- ★ 用户原话：「第一关是项目最初的造物」✓「合并成一套」✓ —— **判断正确**

## 三、纪律（下次照这个做）

### 1. 问"性质问题"，不问"假设问题"

| ✗ 我做的 | ✓ 该做的 |
|---|---|
| "会不会是死句柄？" | **"谁写 `cell.*.visible`？"** |
| "会不会是素材？" | **"为什么只有第一关？"**（差异即线索）|
| "会不会是每帧没保持？" | **"同一件事有几个负责人在写？"** |

★★ 用户的每一句话都是**性质问题** ✓ —— 而性质问题**直接指向不变量** ✓
★ 假设问题只能在**自己的假设列表**里打转 ✓（★ 那次我错了四个假设 ✓）

### 2. 属性所有权表（**新写任何 `visible`/`enabled` 之前先查这张表**）

| 属性 | 唯一负责人 | 其他人不许动 |
|---|---|---|
| `cell.*.visible` | ★ **规划 `layout_plan`**（按 `screen` ✓ 双向 ✓）| 屏幕层 ✗ · 适配层 ✗ |
| `cell.*` 的子控件 `face` | ★ 每帧 `_cells_paint` | 适配层 `hide_kids` **只许藏、且必须对称恢复** ✓ |
| `cell.*` 的子控件 `wall.*`/`door.*` | ★ `_apply_edges` 记 `_edge_want` ✓ + `_cells_paint` 每帧重放 ✓ + **对称恢复** ✓ | — |
| `home`/`select` 及其子控件 | ★ 屏幕层 `apply_screen_hide` | 规划 ✗ |
| `clues`（容器）| ★ 屏幕层 | — |
| `clues.bg` | ★ **规划**（`visible = (self.screen == nil)` ✓）| — |
| `clues.grid` | ★ **规划**（`_grid_state ~= "off"` ✓ 且初值 `nil` ✓）| — |
| `hex.*` / `hit.*` | ★ **屏幕层管"藏"** ✓ · **状态层管"亮"** ✓（★ 两套来源 ✗ 谁都不许越权 ✗）| 屏幕层**不许**写 true ✗（曾造成白方块 ✗）|

### 3. 观测纪律（**这一轮被自己的诊断骗了三次** ✗）

1. ★ **先确认诊断自己能跑** ✗（`print_` 那次 ✗ —— 整条 `walls` 下发都抛错 ✓）
2. ★ **去重键要带全部维度** ✗（漏了 `prefix` ⇒ 看到"只有门没有墙" ✗ 假象 ✓）
3. ★ **读回必须在【正确的时刻】** ✗（在 `screen="home"` 那一刻读 `clues` ⇒ 假象 ✓）
4. ★★ **判据要写进日志本身** ✓（如 `want=` 与 `vis=` 并列 ✓ —— 一次就分清"没要"还是"没生效"✓）

### 4. 分块分步 + 多轮独立验证（用户提的）

- ★ **逐行审查要分块** ✗ —— 不要在一个 turn 里审 4000 行 ✓
- ★ **每个结论至少两种独立证据** ✓（★ 静态阅读 ✓ + 真机日志 ✓ + 离线探针 ✓）
- ★ **定期整合**（见下节 ✓）
