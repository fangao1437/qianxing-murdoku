## 一、根因（这轮才真正查到）

### ① 真元凶：`furn_anchor` 抬的是**整个格子**

`lua/engine_adapter_qianxing.lua` 的 `furn_anchor` 分支：

```lua
elseif key == "furn_anchor" then
  if value == true and ctrl ~= nil and ctrl.SetAsLastSibling ~= nil then
    pcall(function() ctrl:SetAsLastSibling() end)   -- ctrl = cell.<r>.<c>
```

跨格家具实例由 `_spawn_furn_tpl()` 挂在锚点格 `content/furn` 下，尺寸 = `span × 格`，**允许越出格线**。
整格被抬到 `stage` 内最上后，越界那半件家具连同一整格压到**邻格**之上 —— 邻格 `content/x` 自然被盖掉。
这是「**格子之间**」的 sibling 顺序，任何「格子内部」的层序表都管不到。

### ② 680 的修复为什么无效（重要更正）

680 在 `layer_order` 的 `obj12` 之后插入 `"rug_layer", "furn",`，本意是让家具容器排在 `x` 之下。
本轮提取 684 **内嵌** Lua 全文核对，发现：

```lua
function Adapter:enforce_layers(cell_id)
  return 0        -- ← 空壳！打包版本里没有排序循环
end
```

内嵌脚本（636,689 B）与 `lua/engine_adapter_qianxing.lua` 源码是**不同版本**；`layer_order` 表虽然带着 680 那两行，却**从未被运行时执行**。
格内层序实际由 `.gil` 的 `content` childList 静态决定（684 里顺序本来就是 `…furn, portrait, wall…, x, note`，`x` 已在 `furn` 之上）。
⇒ 680 补的那一行对真机**没有任何效果**，这也解释了为什么 684 里 X 仍被盖住。

> ★ 教训：**改 `.gil` 内嵌 Lua 前，先确认目标函数在打包版本里不是空壳**；源码改了不等于真机跑到了。

### ③ 历史同类问题

v283 插 `portrait`、v315/316 `SetSiblingIndex(地毯=1/家具=2)`、v327 按轴缩放、v301 家具扩到 12 层 —— 历史上全是**格子内层序 / 尺寸**问题。本轮是第一次处理**格子之间**的层序，索引第 24 条「680 残留风险」预判的正是这一条，本轮按「把 X 提到独立最上层容器」落地，并做成通用构造法。

## 二、通用构造法：三层不变式

```
root
 └ stage                            ← 棋盘舞台（layout_plan 有 id="stage"，home/select 时整体隐藏）
    ├ board.bg / board.floors / board.rugs
    ├ cell.1.1 … cell.n.n           ← 运行时实例化；furn_anchor 只在 stage 内部抬格
    │   └ content/furn               ← 跨格家具，尺寸 = span × 格，允许越出格线
    └ art685.mark.overlay   ★新增   ← stage 的【最后一个子控件】
        └ art685.mark.<r>.<c> ×64   ← X 标记（容器 + 2 枚 45°/-45° 笔画），默认隐藏
```

**不变式**：任何跨格家具的抬层作用域**严格限定在 stage 内部**；标记层是 stage 的最后一个子控件，且运行时恒被复位到末尾 ⇒ **绘制顺序上不存在「家具盖住 X」的可能**。

**为什么对将来任意多格家具都通用**：
- 与 `kind`、`span_r×span_c`、缩放系数、家具层数、以后新增多少种家具**完全无关**；
- 新增家具照常下发 `furn_tpl` / `furn_span` / `furn_offset` 即可，**不必再改 `layer_order`、格子模板或标记层**；
- 标记网格 8×8（覆盖 4/5/6/7/8 阶棋盘）；将来若出 >8 阶，只需把规格 `markLayer.maxBoard` 调大重跑构建。

### 运行时四处通用钩子（内嵌 Lua）

| 钩子 | 作用 |
|---|---|
| `Adapter:_mark_layer_raise()` | 把标记层 `SetAsLastSibling()` 复位到 stage 末尾。**`on_tick` 每帧无条件调用** ⇒ 未来任何新抬格代码自动被覆盖，无需配合 |
| `furn_anchor` | 抬格后立即复位 + `_mark_layer_guard()` 存在性自检（未来存档若漏了标记层会打日志） |
| `x_mark` | 镜像显隐到标记层；`_mark_ctrl()` 复用建格时记录的 `(x, y, size)` 零误差对齐；`_mark_scope()` 收起越出当前棋盘 n 的残留标记 |
| `_cells_ensure` | 记录 `_cell_pos[id]={x,y,cell_size}` 与 `_board_n=n`；建格完成后立即复位一次 |

**显隐三层开关**：真机「父容器 `SetVisible` 不保证级联到子控件」（v308 教训），所以标记容器 + 两枚笔画**都默认隐藏**，`_mark_set_visible()` 逐层开关。格内 `x` 的原有逻辑**保留作兜底**（同位同色不透明，叠加不产生可见差异）；即使某平台 `find()` 取不到标记层，X 仍按 684 行为显示。

**屏幕切换**：`stage` 在 `layout_plan` 里是正式节点（`seen["stage"]=true`），且 `MANAGED` 不含 `stage` ⇒ `hide_unlisted` 不会单独隐藏标记层；home/select 时整棵 `stage` 被隐藏，标记层随之隐藏，不会在首页浮出一排 X。

## 三、具体改动

### 六处内嵌 Lua 补丁

1. `helpers`（插在 `Adapter:enforce_layers` 前）：`_mark_layer_raise` / `_mark_layer_guard` / `_mark_ctrl` / `_mark_set_visible` / `_mark_scope`
2. `_cells_ensure` 坐标块：记录 `_cell_pos[id]` 与 `_board_n`
3. `_cells_ensure` 末尾：建格后 `_mark_layer_raise()`
4. `x_mark`：镜像显隐 + `_mark_scope()` + `_mark_layer_raise()`
5. `furn_anchor`：`_mark_layer_guard()` + 抬格后 `_mark_layer_raise()`
6. `on_tick`：每帧 `_mark_layer_raise()`

`luac -p` 对 684 内嵌、685 内嵌、`engine_adapter_qianxing.lua`、`entry_client_script.lua` 四份全部通过。

## 四、通用性验证（不是目测）

`多格家具通用构造685.mjs` 枚举：
**棋盘 n ∈ {4,5,6,7,8} × 8 种 kind（含 2 个虚构 `future.*`） × span_r/span_c ∈ {1,2,3,4} × scale ∈ {1,1.25,1.5,2} × 全部锚点位置 = 97,280 组**。
家具可达单元格按四向 `ceil(span×scale)` **保守外扩**（比真实 bbox 更宽松）：

- 最大外扩 **8 格**、单件最多覆盖 **64 格**；
- **未被 8×8 标记网格覆盖的单元格 = 0**；
- `685_通用性验证.json` → `verdict = true`，结构性检查全绿。

`685_对照_多格家具X覆盖.png` 用四种互异参数（1×2 横桌 / 2×1 竖桌 / 2×2 大地毯 / 1×3×1.25 加长桌）模拟真机绘制顺序：左列 684 的 X 全被盖住，右列 685 的 X 四组全部完整可见。

## 七、边界 / 真机待验

1. **本版未导入游戏**。需真机复核：`_mark_layer_raise()` 每帧 `SetAsLastSibling()` 的层序稳定性、64 组隐藏标记的逐层 `SetVisible` 开关、`find()` 能否按 `art685.mark.<r>.<c>` 取到控件、8×8 隐藏控件对 `GetClientUIRoots()` 深搜与 7826 条加载性能。
2. **`note`（数字/笔记标记）仍留在格内**，本轮只处理用户点名的 X；若将来 `note` 也被跨格家具盖住，把它按同一套 `art685.mark.*` 命名挂进标记层即可（构造法已通用，不必改层序）。
3. **格内 `x` 保留作兜底**：若真机上 `find()` 取不到标记层，X 会退回 684 行为（仍可能被盖），日志里会有 `mark:missing` 告警。
4. `dist/client_script.lua`（1,550,849 B）与内嵌脚本本就是不同版本，本轮**未重打包**；若将来重新 bundle，源码 `lua/engine_adapter_qianxing.lua` 已同步同样六处逻辑，构建后请重跑本轮全部闸门。
5. 标记网格上限 8×8；若新增 >8 阶关卡，把 `685_多格家具通用构造规格.json` 的 `markLayer.maxBoard` 调大后重跑构建与通用性验证。
