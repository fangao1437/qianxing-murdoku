## 一、网格纸没跟随下移：根因是运行时 Lua 覆盖父坐标

679 把 `art657.grid.reuse`（网格纸复用父容器）的 504 y 从 0 改成 −30，离线预览确实下移了 30。
但 **679 内嵌 Lua 的 `sync_art641()`** 在切屏时执行：

```lua
local gp = adapter:find("art657.grid.reuse")
if gp ~= nil then
  help_visible(gp, screen == "home" or screen == "game")
  local dx, dy = 0, 0
  if screen == "game" then dx, dy = 105, 46 end
  pcall(function() gp:SetAnchoredPosition(dx, dy) end)
end
```

⇒ 关卡内父容器坐标被**强制覆盖成 (105,46)**，改存档里的父层 504 完全失效 —— 这就是用户看到的现象。
（657 构建报告里已写明「挂在 `art657.grid.reuse` 下继承 `sync_art641()` 位移」，664 校验脚本也注明「真机 sync_art641() 对整组做 (105,−46) 位移」。）

### 修法（不改 Lua，靠子层相对偏移）
| 项 | 679 | **680** |
|---|---|---|
| `art657.grid.reuse` 父层 504 y | −30 | **0**（恢复） |
| 49 个子层 504 y | 原值 | **各 −30**（y 向上为正 ⇒ 下移 30） |
| x / w / h | — | **全部不变** |

子层相对父的偏移**不会被 `SetAnchoredPosition` 覆盖** ⇒ 真机与离线预览都稳定下移 30。
网格纸（斜格纹）、24 竖线、23 横线、`art656.home.paper.edge` 共 49 层整组一起动，无错位。

> ★ 教训：**离线预览读的是存档里的父坐标，真机跑的是 Lua 覆盖后的父坐标**。
> 今后凡涉及 `art657.grid.reuse`（以及任何被 `sync_art641()` 设坐标的容器），
> 位移必须落在**子层**上，不能只改父层；`渲染对照680.mjs` 已内置「模拟 Lua 覆盖」的口径。

## 二、桌子挡住 X 标记：查询历史后的通用修复

### 历史结论（逐条核对）
| 版本 | 用户反馈 | 修法 |
|---|---|---|
| **v283** | 「现在家具图层会盖在放置的头像上」 | 根因是 `layer_order` 层序；**插入 `portrait` 层**（obj 之上、wall 之下） |
| v315/v316 | 教程家具不可见 | 正式关卡 `SetSiblingIndex(地毯=1/家具=2)`；教程不能照搬，改两遍创建 + `SetAsLastSibling` |
| **v327** | 「多格地毯在控件层加长」「底座色块压到雕塑本体」 | 地毯按轴缩放铺满长边；底座 8 层画在身体**之前** |
| v301 | 「横桌竖桌明显需要分开做」 | 家具最多 12 层 `obj..obj12`，`layer_order` 同步扩到 12 |

⇒ 反复出现的**同一类根因 = 图层顺序**，历史标准解法就是**把新层插进 `cfg.cells.layer_order` 的正确位置**。

### 本轮根因
`layer_order`（从下到上）：
`face → hint → obj..obj12 → portrait → wall.* → door.* → x → note`

`enforce_layers()` **倒序**对列出的子控件调 `SetAsFirstSibling()` ⇒ 最终顺序＝order 正序；
**未列出的子控件留在最上层**。而格子模板 `content` 下还有 `rug_layer`（地毯）与 `furn`（家具实例容器）——
两者**都不在 `layer_order` 里** ⇒ 压在 `x` 之上 ⇒ 桌子/地毯挡住 X 标记。
（设计注释明确写着「x 划掉标记压住一切装饰」，说明这是层序配置漏项，不是设计意图。）

### 修法（历史 v283 同款，一次解决地毯 + 桌子）
在 `obj12` 之后、`portrait` 之前插入一行：

```lua
"obj7", ..., "obj12",
"rug_layer", "furn",     -- ★ 680：跨格家具容器必须排在 x 之下
"portrait",
...
"x",
```

- 内嵌 Lua：**只插入这一行**（`636,660 → 636,689 B`），反向替换后与 679 逐字节相同；
- 同步改 `lua/entry_client_script.lua` 源码（带注释），保证未来重新 bundle 时不丢；
- `dist/client_script.lua` 与内嵌本就是不同版本（1,550,849 B vs 636,660 B），本轮**不重打包**，避免夹带巨变。

断言：`layer_order` 内 `obj12 < rug_layer < furn < portrait < x` ✓

## 四、验收与剩余

- 对照图 `680_对照_网格纸跟随.png`：**模拟真机 `sync_art641()` 覆盖父坐标**后，
  ① 679 栏网格纸明显偏上（白底板上方露出一大块、底部几乎不露）；
  ② 680 栏网格纸与白底板一起下移、相对位置恢复，棋盘深色框/白板位置不变 ✓
- X 标记：`rug_layer` / `furn` 两个容器都排到 `x` 之下 ⇒ 桌子与地毯同格不再遮挡 X ✓

**仍需真机复核**：
1. 跨格家具（横桌/竖桌）的越界部分是否仍会盖住**相邻格**的 X —— `furn_anchor` 会把锚点格整体
   `SetAsLastSibling()` 抬到 stage 最上层，这是**格子之间**的层序，格子内的 `layer_order` 管不到。
   若真机仍见跨格遮挡，下一步应把 X 标记提到独立的最上层容器（或按 `F.rug_cell_els` 的历史做法
   把跨格家具按格切片），需要单独一轮。
2. `enforce_layers` 能否按名字取到 `rug_layer` / `furn`（模板里两者都在 `content` 下，
   `self:sub` 为递归查找）；真机日志 `layer_order` 排上几个子控件可验证。
3. 7431 条记录 + 636,689 B 脚本的加载性能。
