# 最小骨架控件清单（照着在编辑器里摆）

> ⚠️ **本文件已被取代，请优先看这两份：**
> - **`docs/真机搭建与运行指南.md`** —— 主操作指南（四道门控 / 建树顺序 / 验收清单 / 故障排查）
> - **`docs/控件坐标表-1600x900.md`** —— 自动生成的**完整 123 个控件**坐标表（本文件只是最早期的骨架版）
>
> 本文件保留作过程记录：里面的"设计分辨率 1920×1080"说的是**设计空间**，
> 真正的**画布是 1600×900**（换算见坐标表第 0 节）。

> 目标：**不用一次摆完**。按阶段一 → 二 → 三推进，每阶段都能跑起来验证。
> 脚本按**控件的 name 精确查找**（`game.GetClientUIRoots()` 后逐层 `GetChildren()` 深搜），
> 所以**名字必须一字不差**（全小写、点号分隔）。
>
> 设计分辨率 **1920×1080**（`ui_controller.lua` 的 `M.LAYOUT`）。坐标都可改，
> 只要控件名字对得上，脚本就能工作；`apply_rect` 默认 **false**，位置完全由编辑器决定。

## 0. 前置：两件事必须做对

1. **建客户端控件容器**：界面控件组管理 → 界面布局 → 添加界面控件 → **客户端控件容器**
   → 画布设置 → **前往编辑**。所有下面的控件都摆在**这个容器里**。
2. **容器必须「激活且可见」**：官方规则——容器隐藏或销毁时，里面的客户端控件全部销毁、
   脚本逻辑停止。这是"控件找不到"这类问题最常见的原因。

**阶段 0（只验证脚本能跑，摆 3 个控件就够）**

| 名字 | 类型 | 父级 | 说明 |
|---|---|---|---|
| `root` | 容器节点 | 容器 | 全屏根（也可以不用，脚本会跳过找不到的父级） |
| `board` | 容器节点 | `root` | 棋盘区 |
| `cell.1.1` | **预设按钮** | `board` | 第一个格子 |

进游戏看日志有没有 `[murdoku] OnInit done` 与 `[murdoku] started`。

> **先做这件事**：`lua tools/bundle_client_script.lua` 生成 `dist/client_script.lua`，
> 然后在「千星沙箱 → 客户端脚本资源管理器」新建**脚本映射**指向**这一个文件**，
> 再在任意客户端控件的「**脚本**」页签 → 添加脚本 → 选该映射。
> 官方只打包"建立了映射的 .lua"，多文件 require 不保证可用，所以必须走单文件产物。

## 1. 阶段一：最小可跑骨架（棋盘 + 头像 + 标题）

### 1.0 层级树（照这个摆）

```
客户端控件容器画布
└─ (默认容器节点)                     ← 容器自带，**不用你建**
   ├─ topbar                          容器节点
   │    ├─ hud.title                  文本框   (关卡名)
   │    ├─ hud.timer                  文本框   (计时)
   │    └─ hud.moves                  文本框   (步数)
   ├─ left                            容器节点
   │    └─ tray                       容器节点
   │         ├─ tray.A                预设按钮
   │         │    ├─ face             图片     ← 头像立绘
   │         │    └─ text             文本框   ← 角色名
   │         ├─ tray.B / tray.C / …   预设按钮 (每名嫌疑人一个)
   └─ board                           容器节点
        ├─ cell.1.1                   预设按钮
        │    ├─ face                  图片     ← 放置角色时换的就是它
        │    ├─ note                  文本框   (铅笔笔记)
        │    ├─ x                     图片     (X 标记)
        │    ├─ text                  文本框   (角色名)
        │    └─ wall.up/down/left/right、door.up/down/left/right   图片（可选）
        ├─ cell.1.2 … cell.1.5
        ├─ cell.2.1 … cell.2.5
        ├─ cell.3.1 … cell.3.5
        ├─ cell.4.1 … cell.4.5
        └─ cell.5.1 … cell.5.5
```

**三条硬规则**（违反就不生效）：

1. **不用建 `root`**。客户端控件容器画布**自带一个「默认容器节点」**（官方 API：
   `GetClientUIRoots()` = "实际显示的客户端控件容器画布中的**默认容器节点**"），
   `topbar` / `left` / `board` 直接挂在画布顶层即可。
2. **格子的子控件名固定**：`face` / `note` / `x` / `text` / `wall.*` / `door.*`，
   而且必须是**格子的直接子控件** —— 脚本用 `GetChild(name)` 取，**不递归**。
   （放角色时换的图就是 `face`；不建 `face` 就直接改格子自身的图。）
3. **预设按钮必须「引用」子控件才会显示**（官方《预设按钮》："预设按钮可以引用子层级中的
   客户端控件，作为不同状态节点的外显样式"）。
   做法：选中格子 →【基础】→ 按钮设置 → **按钮状态节点** → 单击【**默认**】节点 →
   在弹出的子控件列表里**把 `face`/`note`/`x`/`wall.*`/`door.*` 全部勾上**（可多选）。
   `悬停`/`按下`/`不可用` 同理（可以先只配 `默认`）。
   配好后**点状态节点的播放键**可在编辑器里直接预览。
   - ⚠️ 名称叫「图片」的子控件请**改名为 `face`**，否则脚本认不到它。

**位置/尺寸**（设计分辨率 1920×1080，都可改；脚本默认 `apply_rect=false`，位置由编辑器决定）：

| 名字 | 类型 | 父级 | 位置 (x, y) | 尺寸 (w, h) | 用途 |
|---|---|---|---|---|---|
| `topbar` | 容器节点 | 画布 | 0, 0 | 1920, 104 | 顶栏 |
| `hud.title` | 文本框 | `topbar` | 32, 18 | 520, 50 | 关卡名 |
| `hud.timer` | 文本框 | `topbar` | 520, 30 | 140, 46 | 计时 |
| `hud.moves` | 文本框 | `topbar` | 664, 30 | 150, 46 | 步数 |
| `left` | 容器节点 | 画布 | 24, 128 | 392, 880 | 左侧面板 |
| `tray` | 容器节点 | `left` | 40, 148 | 360, 300 | 头像卡区 |
| `tray.<角色id>` | **预设按钮** | `tray` | 见下方公式 | 176, 132 | 选中/放置状态 |
| `board` | 容器节点 | 画布 | 480, 176 | 880, 880 | 棋盘区 |
| `cell.<行>.<列>` | **预设按钮** | `board` | 见下方公式 | 160, 160 | 一个格子（5×5 → 25 个） |

**建议做法**：先把 `cell.1.1` **完整做对**（子控件 + 状态节点引用 + 光标射线 + 可交互），
再**复制粘贴 24 次**并改名字 —— 比一个一个摆快得多。

进游戏后应该能：**单击写笔记、双击放人、点头像选人、看到计时/步数**。

|---|---|---|---|---|---|

| `hud.title` | 文本框 | `topbar` | 32, 18 | 520, 50 | 关卡名 |
| `hud.timer` | 文本框 | `topbar` | 520, 30 | 140, 46 | 计时 |
| `hud.moves` | 文本框 | `topbar` | 664, 30 | 150, 46 | 步数 |
| `left` | 容器节点 | `root` | 24, 128 | 392, 880 | 左侧面板 |
| `tray` | 容器节点 | `left` | 40, 148 | 360, 300 | 头像卡区 |
| `tray.A` … `tray.<角色id>` | **预设按钮** | `tray` | 见下方公式 | 176, 132 | 选中/放置状态 |

**棋盘格坐标公式**（`r`、`c` 从 1 开始）：

```
x = 524 + (c - 1) * 164          # 524 = board.x + 44(ruler)
y = 220 + (r - 1) * 164          # 220 = board.y + 44(ruler)
宽高 = 160
```

5×5 时的 `cell.*` 名字（直接复制去命名）：

```
cell.1.1 cell.1.2 cell.1.3 cell.1.4 cell.1.5
cell.2.1 cell.2.2 cell.2.3 cell.2.4 cell.2.5
cell.3.1 cell.3.2 cell.3.3 cell.3.4 cell.3.5
cell.4.1 cell.4.2 cell.4.3 cell.4.4 cell.4.5
cell.5.1 cell.5.2 cell.5.3 cell.5.4 cell.5.5
```

**头像卡坐标公式**（两列排布，`i` 从 1 开始）：

```
col = (i - 1) % 2 ; row = 地板除((i - 1) / 2)
x = 40 + col * 188
y = 148 + row * 142
```

| 格子/头像要在编辑器里开的开关 | 为什么 |
|---|---|
| **可被光标射线检测**（`raycastTarget`） | 脚本靠 `AddCursorEventListener` 收点击；关掉就点不动 |
| **可交互**（`interactable`） | 脚本会按 `view.enabled` 切它（例如不可站人的格子） |
| 手柄导航（可选） | 只用键鼠/触屏可以先不开 |

**这一阶段跑通后你会看到**：点 `cell.1.1` 写小字、双击放置、`hud.timer` 每秒跳动。

## 4. 格子子控件约定（可选，但做了表现会好很多）

父级是 `cell.<行>.<列>`，**名字固定**，脚本按名字找；找不到就自动跳过（不会报错）：

| 子控件名 | 类型 | 脚本怎么用 |
|---|---|---|
| `face` | 图片 | 放置角色时 `SetImage`（不建则直接改格子自身的图） |
| `note` | 文本框 | 铅笔笔记（多个笔记用空格连接） |
| `x` | 图片 | 划掉这格的 X 标记（脚本切显隐） |
| `text` | 文本框 | 角色名（不建则写格子自身文本） |
| `wall.up` / `wall.down` / `wall.left` / `wall.right` | 图片 | 墙：脚本按 `levels.walls` 切显隐 |
| `door.up` / `door.down` / `door.left` / `door.right` | 图片 | **门径**：脚本按 `levels.doors` 切显隐 |

> 墙和门都是**逐格边**的标记，所以每个格子四个方向各一张图最省事。
> 也可以把墙直接画进格子底图，那就**不用**建 `wall.*`（脚本会跳过）。

## 6. 常见坑

| 现象 | 原因 | 处理 |
|---|---|---|
| 日志刷 `控件未找到：cell.1.1` | 名字不一致 / 不在容器里 / 容器未激活可见 | 对照第 5 节名字；确认容器激活且可见 |
| 点格子没反应 | 没开**可被光标射线检测**，或用了"文本框"这类不支持光标事件的控件 | 格子必须用**预设按钮**或**光标检测区域** |
| 双击没反应 | 两次点击间隔 > 0.35s | 正常双击节奏即可；该值在 `ui_controller.lua` 的 `DOUBLE_CLICK_SECONDS` |
| 笔记要等半秒才出现 | **双击方案的固有行为**（等过双击窗口才落笔记） | 属预期 |
| 中文/位置错乱 | 没配**锚点**，换分辨率后整体错位 | 给每个控件配锚点（脚本默认不接管位置） |
| 立绘/角色名看不到 | `tray.<id>` 里的图片/文本子控件没建 | 头像卡里放图片 + 文本框即可（脚本只改卡的选中/放置状态） |
| 提交按钮点了没反应 | 没摆满（脚本会置灰） | 属预期 |

## 7. 建议的推进顺序

1. **阶段 0**：容器 + `board` + `cell.1.1` → 看日志 `OnInit done` / `started`；
2. **阶段 1**：棋盘 25 格 + 头像卡 + 标题 → 验证单击/双击/选中；
3. **阶段 2**：线索 + 右侧信息栏 → 验证文案与区域推断面板；
4. **阶段 3**：按钮 + 弹窗（+ 教程）→ 验证提交流程与两段式指认；
5. 最后接节点图信号（`M.SIGNALS`）：`ready` / `save` / `restore` / `solved` 等。
