## 二、空间结构（R3 的定义层）

### 2.1 区域（房间）

- 由**墙**划分：`walls` 是逐格边的标记；同一区域内的格子四连通；**门不合并区域**。
- 区域编号由洪泛算法生成（引擎内部用，玩家看不到）。

### 2.2 门径（doors）

- 门开在**格边**上，与墙同粒度：`{"h", r, c}` 表示 `(r,c)` 与 `(r+1,c)` 之间有门；
  `{"v", r, c}` 表示 `(r,c)` 与 `(r,c+1)` 之间有门。
- 一条边可以**既是区域边界、又有门**（这正是"跨区域的通道"的常态）。
- 门不改变区域划分，只用来定义区域之间的可达关系。

### 2.3 区域相邻

> **区域 X 与 Y 相邻 ⟺ 存在一条门直接连通 X 与 Y 的相邻两格，不需要经过第三个区域。**

即：门边两侧的格子若分属不同区域，就为这两个区域建立一条相邻边。
一个区域可以与多个区域相邻；相邻关系是双向的、不传递的。

顺带解锁了原版就有的一条线索：**「门窗正对的两格」**（`in_front_of`）。

## 三、盗窃者定位（R3 的约束层）

对最终摆位 + 角色归属，以下都是**硬约束**：

```
Rv      = 受害者所在区域
Adj(Rv) = 与 Rv 由门直接连通的区域集合
inno(X) = 区域 X 内「既不是盗窃者也不是同伙」的人数
Rt      = 盗窃者所在区域
```

1. **`Rt ∈ Adj(Rv)`** —— 盗窃者（及同伙）必然在受害者的相邻区域。
2. **`inno(Rt) = max{ inno(X) : X ∈ Adj(Rv) }`** —— 盗窃者必然挑无辜人数最多的那个相邻区域。
3. 同伙（若存在）与盗窃者**同区**：`room(同伙) = Rt`。

**计数口径**（⚙️ 我定的默认，符合你的措辞）：

- 「无辜人士」= 除盗窃者与同伙之外的**所有角色**；
- 受害者必在 `Rv`，而 `Rt ≠ Rv`（相邻不含自身），所以"受害者算不算无辜"不影响判定；
- 同伙**不算**无辜 —— 这正是让"有没有同伙"继续参与推理的关键。

**并列处理**（⚙️ 按你的回答）：

- 默认 `rules.tie_policy = "forbid"`：若 `Adj(Rv)` 中有两个及以上区域的无辜人数并列最高，
  该关卡视为**非法**，校验器直接报错（逼你在设计上避开并列）。
- 特殊关卡可写 `rules.tie_policy = "allow"`：此时并列的多个区域都算合法，
  允许出现"盗窃者可能在 A 区也可能在 B 区"的多解设计。

## 四、同伙规则（R4，与 R3 叠加）

```
k = 受害者所在区域内的人数（含受害者）
```

| 情形 | 约束 |
|---|---|
| `k ≥ 2`（受害者与他人同区） | **必须存在同伙**，且同伙与盗窃者同区（即 `Rt`） |
| `k = 1`（受害者独处一区） | 同伙**可有可无**：有则仍须与盗窃者同区 |

- `k` 是**玩家摆完就能自己数出来的**可观测量 —— 所以"要不要找同伙"这件事部分可自验证。
- 因为 R3 要求 `Rt` 是 `Rv` 的相邻区域，`k≥2` 时那"其他人"是**旁观者**，不是罪犯。

## 五、线索与假话（R5 / R6）

### 5.1 假话规则

- **范围**：个人线索 + 全局线索**合计**，至多 1 条为假；
- **粒度**：以**整条线索**为单位（玩家看到的每一行文字就是一个单位）；
- **受害者线索同级**：受害者那句同样可能落在这唯一一次"假话"上；
- 关卡用 `meta.false_clue = <线索序号>` 声明是哪一条（不写 = 本关全是真话）。

### 5.2 玩家是否被告知

关卡可声明 `meta.announce`：

| 值 | 含义 | 界面上怎么表现 |
|---|---|---|
| `"none"` | 本关线索全部为真 | 顶部显示「线索全部为真」 |
| `"one"` | 本关线索中有一句是假的 | 顶部显示「线索中有一句假话」 |
| `"unknown"` | **不告诉**玩家 | 什么都不显示，玩家自己推断 |

> 用 `announce` 而不是把它做成一条线索，是为了避免自指悖论
> （"本关有一句假话"这句话本身若是那句假话，逻辑上会塌掉）。

### 5.3 判题反馈（R6）

- **硬性冲突**（同行/同列两人、放到不可站格）可以说 —— 这些玩家自己看得见；
- **哪条线索不成立**：**不说**，连"有几条不成立"也不说，只说"摆位还没成立"；
- 因此判题界面不会剧透那句假话。

### 5.4 引用"同伙"的线索在无同伙时的真值

**一律判"不成立"**。于是「同伙在书架旁边」这类线索天然变成二选一：

> 要么确实有同伙且他在书架旁，要么**这句就是那句唯一的假话**。

这正是"有时需要自主推断"的实现方式。

## 六、判胜流程（R7）

```
① 摆满全部角色（含受害者）
② 提交 → 只校验硬约束（同行/同列/站位），通过后进入指认
③ 指认「盗窃者」是谁
④ 声明「有没有同伙」：有 → 再指认同伙是谁；无 → 直接判定
⑤ 全对 → 破案结算；错 → 给出 "n/m 位置正确" 之类的反馈
```

## 七、线索类型增补

| 新增 | 说明 |
|---|---|
| **角色别名** | 任何线索的 `who/a/b` 都可以写 `@thief` / `@accomplice` / `@victim`，玩家看到的是"盗窃者/同伙/受害者"而不是名字 —— **身份推理的主要手段** |
| `in_front_of` | `a,b`：a 与 b 处于**门窗正对**的两格 |
| `is_role` / `not_role` | `who,role`：某角色（不）是盗窃者/同伙/受害者 —— 直接的身份线索 |

原有的 54 种线索全部保留，并且因为别名机制，**每一种都能指向角色**。

## 八、关卡必须通过的自检清单

1. `#suspects == rows == cols`（N×N）；
2. `roles.thief` 存在、`roles.thief ≠ victim`、`roles.accomplice ≠ thief/victim`；
3. 受害者所在区域**至少有一个门相邻区域**（否则 R3 无法成立）；
4. 按 `tie_policy` 检查无辜人数**无并列**；
5. 答案满足 R3/R4 全部结构约束；
6. 答案在"至多一条假话"前提下满足全部线索，且**恰好**等于 `meta.false_clue` 声明的那条数量；
7. **唯一解**：在 `(摆位 × 角色归属)` 的空间里，"至多一条线索不成立 + 结构约束"只有一组解
   （这同时保证盗窃者与同伙都是唯一确定的）；
8. 边长建议 ≤8（求解器是回溯 + 角色枚举，越大越慢）。
