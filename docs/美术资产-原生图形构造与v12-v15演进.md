# 警局场景美术资产：原生图形构造方法与 v12–v15 演进

> 整理日期 2026-11-11。适用范围：`assets/警局场景-2026-11-09*`、`assets/警局场景-2026-11-11-v1{3,4,5}/`。
> 目的：把近几轮实机反馈沉淀成可复用的构造口径，避免重复踩「细矩形锯齿 / 柔影方形暗角 / 三角形覆盖不足」的坑。

---

## 一、用户确立的构造原则（v14 起，务必遵守）

1. **倾斜形状用「矩形 + 旋转」就够**，不要用大量竖直小矩形去扫描斜边——后者每条顶边都是水平线，斜边必然出现台阶/锯齿。
2. **斜边可以用三角形**：把 `100003` 适当压缩拉伸后，让它的**一条边**贴目标斜边，其余部分用其它大块同色补色形状覆盖。
3. **不透明同色重叠是无缝的**：只要保证**外边界不溢出**，内部可以任意重叠；原生基本图形的边不会有锯齿。
4. 一句话：**每个图元都必须完全落在目标凸区域内（零溢出），内部随便叠**。凸性保证：只要三角形三个顶点都在凸多边形内，整个三角形就在内。

反面教材（已实测废弃）：

| 做法 | 结果 |
|---|---|
| 竖条扫描填充斜边（v10 100 条 / v11 110 条 / v12 310 条） | 斜边台阶、实机明显锯齿 |
| 逐格实色网格做暗角（20×30 / 25×45） | 方格色块、竖条纹，且控件数 1161 超 1000 上限 |
| `106056` 柔影多层堆角部暗角（v13/v14 24 层） | 柔影拉伸后中心大片恒定色 ⇒ **硬边方形块** |
| 细长/钝角三角形用 3 个等腰三角拼 | 覆盖率仅 94.84%，露出尖牙状三角洞 |

## 二、官方基础图元的实测几何模型

导出链路：scene JSON（`type=image` + `imageAssetId` + `imageType=stretch` + `imageTint=true`）→ `POST https://qx.070077.xyz/api/export/{gia,png}`。

| id | 形状 | 实测模型 |
|---|---|---|
| `100001` | 直角矩形 | `x,y` 为中心，`width×height`，`rotation=r` 时**长边屏幕角度 = −r**（视觉逆时针 r） |
| `100002` | 圆/椭圆 | 拉伸成椭圆；柔影/圆环不要用它堆渐晕 |
| `100003` | **等腰三角** | 先按 `w×h` 画「顶点上中 `(0,−h/2)`、底边 `y=+h/2` 长 `w`」，再按 `rotation=r` 视觉逆时针旋转；变换 `(x,y)→(x cos r + y sin r, −x sin r + y cos r)`。**顶点方向 = `(−sin r, −cos r)`**，故要让顶点指向内法线 `n` 时 `r = atan2(−n.x, −n.y)`；中心 = 底边中点 + `n·h/2`。`rot=±90` 时包围盒 w/h 交换 |
| `106056` | 柔光圆 | **白心不透明 → 向外窄带渐隐**，是「柔影」不是渐晕；拉伸后中心大片恒定色 ⇒ 硬边圆盘/方块。只适合做物件投影（v10 README §4.4：纯黑 op 0.26–0.28、尺寸 ×1.18、偏移 (+28,+32)） |
| `106058/106059/106060` | 官方径向渐晕 | **中心透明 → 四周渐暗**（凹形）。整幅暗角只能用这一类 |

补充：`100003` 只能做**等腰**三角（两腰恒等）；`w=2h` 时是等腰直角。历史 v5/v8 实测：两三个错开的等腰三角拼非等腰斜切四边形会得到 M 形山峰；`type=polygon/triangle/path` 与自定义 `points` 会被导出器忽略，仍渲染默认三角。

## 三、`fillConvex`：凸多边形的通用原生构造（v14 核心，可直接复用）

```
fillConvex(poly, color):
  if poly 是三角形: fillTri(poly)
  else:
    A. 对整条 poly 的每条边 e(a→b):
         内法线 n 指向 poly 重心
         二分最大深度 h，使 tip = mid(e) + n·h 仍在 poly 内
         放一个 100003：底边 = e（长 |e|），高 h，rot = atan2(−n.x, −n.y)
         center = mid(e) + n·h/2
    B. 扇形剖分 poly：tri_i = (p0, p_i, p_{i+1})
         对每个 tri 调 fillTri（三条边各一个等腰三角，tip 在 tri 内）
  全部同色不透明；A 提供大块覆盖，B 补尖角
```

`fillTri(A,B,C,color)` = 对三条边各放一个 `100003`，顶点在中垂线上最远内点（二分），`edgeTri(a,b,c)` 以 c 决定内法线。

**为什么必须 A+B 双保险**：只做扇形剖分时，每个等腰三角的顶点被限制在小三角形内，深度过小，实测覆盖仅 **92.5%**；只用 A（整幅每边）时 P4 尖角附近漏 1.4%。两者叠加后：DARK 三角 **100%**、拍立得补缝三角 **100%**、阴影补缝三角 **100%**。

**覆盖率自检**（离线，纯几何）：把生成的每个 `100003` 按上表模型还原三个顶点，在目标凸多边形内均匀采样，要求 `coverage ≥ 99.9%` 且每个三角三顶点都在多边形内。中途 v15 用它查出「细长钝角区覆盖 94.84%」，据此改成单个钝角三角。

**单图元钝角三角**（v15 新增技巧）：等腰三角在 `w >> h` 时顶角趋近 180°，本身就是钝角三角。`rot=90` 时底边是右竖线、顶点在左中，传 `w=底边长, h=高`。用它**一个图元**盖住细长楔形的所有洞，比拼三个等腰三角干净得多。

## 四、渐变类为什么仍保留分段

右侧压暗（52 条整高竖直矩形）与胶带橙黄过渡（72 段×2 旋转矩形）**不是**「用大量小矩形近似形状」：

- 渐变本身必须逐段配色；这些是**整条原生矩形**，边界是直线，不产生斜边锯齿。
- 实测减到 12 段会出现明显竖向色带，36 段有虚线状色带 → 保持 v12 密度。
- 参数与 v12 逐条一致，保证「右侧不变」；v15 换官方渐晕后按实测 alpha 剖面补偿：`C_new = C_old·(1−a_old)/(1−a_new)`。

## 五、官方圆形/凹形暗角（v10 → v12 → v15 定案）

权威出处：`assets/警局场景-2026-11-09/README.md` §4.5、`v10-params.json` 的 `vignette`、`v12/README.md`「为什么回到 v10 的 106060」。

```
底色 → v11 的 52 条右侧渐变条 → 官方 106060 径向渐晕（单层，1800×1040，染黑 op1）→ 阴影 → 上下黑边 → …
```

- **顺序是关键**：渐晕必须画在渐变条**之上**（放下面会在 x=1080 露竖直硬边），画在胶带/物件**之下**（胶带保持明亮）。
- `106060` 同组 `106055/106058`；`100006` 圆环单层放大有硬椭圆边，**不要叠加**。
- 四条边各放柔光椭圆 ⇒ 条形；四角各放柔光圆 ⇒ 中间露竖直亮带；四角各 50 层同心实心圆 ⇒ 四个孤立**凸**斑（用户更正过：设计图是**凹形**）。均已实测排除。
- 尺寸实测（`vig106060.cjs`，底色 182）：

| 尺寸 | 四角 | 边中 | 结论 |
|---|---|---|---|
| 1600×900 | ≈47–56 | 110–121 | 四角够暗但整体发灰 |
| **1800×1040** | **≈85** | **≈136** | **v10 官方配方，最柔和，v15 采用** |
| 2200×1100 | ≈113–116 | ≈162 | v12 为「右侧不变」采用，四角偏亮 |
| 2600×1400 op0.7 | — | — | MAE 更低但暗角偏淡 |

- **已知限制**：单层 `106060` 的 alpha 剖面无法同时满足设计图「四角≈52」与「边中≈180」。别再用 `106056` 堆层来强行压暗——那正是 v13/v14 方形暗角的来源。

## 七、复现与校验链路

1. 改 `build-vXX.cjs` 顶部常量或 `scene-vXX.json`；
2. `node build-vXX.cjs` → 拼图站 `/api/export/{gia,png}` 产出 text / notext 两份；
3. `node finalize-vXX.cjs` → 落地交付、48px 粗体文字模拟预览、版本对比图；
4. `node verify-vXX.cjs`：根层**无 `field 4`**、`units` 数、`.gia+4=2a05362e`、文本包含性；
5. `artkit.mjs check --kind=gia --file=<...>`：`ok=true / budgetExceeded=false / kind=3 / trailer 0x679`；
6. `.gia` 放 `BeyondLocal/Beyond_Local_Export` → 游戏内「导入外部资产 → 转存所选资产」。

**对齐口径**：实机截图 1604×960，白色标题栏到 y≈58 ⇒ 画布 `crop(4,58,1600,900)`；设计图 1920×1080 等比缩到 1600×900。**注意**存档的 `preview/police-v12.png` 是旧渲染器产物（左上 R=161），用当前 API 重渲染 `scene-v12.json` 得 R=116，与 v12 实机 117 逐点吻合；跨版本对比一律用同口径 API 重渲染基线。

## 八、已知限制 / 真机待验

- v13/v14/v15 **均未做真机导入验证**（v10 链路已验证可导入）。项目历史里 `100003` 在 `.gil` 图片控件的个别旋转角（rot −90）曾「真机不出图」；本轮是 `.gia` scene `image` 图元，预览渲染全部正常，仍需实机截图确认。若个别三角不出图，用「沿斜边共线的旋转矩形」替补，同样零锯齿。
- 官方 `106060` 1800×1040 的四角 85 / 边中 136 与设计图 52 / 180 仍有差（素材 alpha 剖面固有）。
- 档案袋底部浅橙折角、咖啡杯沿用 v10 起的范围未做。
- preview PNG 的文本框被导出器画成固定小字；`police-vXX-simulated.png` 才是 48px 粗体 + 旋转的近似真机效果。
