# 占位素材（先把界面弄"看得见"，之后再换真图）

> 由 `tools/make_placeholder_assets.ps1` 生成，**可随时重跑**（会覆盖同名文件）。
> 全部是 PNG 带透明通道、纯色 + 白色描边，颜色故意做得显眼，方便你确认位置对不对。

---

## 为什么需要它

官方硬规则（也是我们实测确认过的）：

| 控件 | 自己画东西吗 |
|---|---|
| 客户端控件容器 | ❌ 一块**透明画布**，唯一作用是让里面的客户端控件能显示 |
| 容器节点（root / board / left …） | ❌ **只是挂点**，什么都不画 |
| 预设按钮 | ❌ **外观来自它「状态节点」引用的子控件**（默认/悬停/按下/不可用） |
| 文本框 | ⚠️ 画字，但要**奇匠等级**解锁【自定义文本外显】 |
| 图片 | ✅ 一定画 |

所以：**一行图都不加的话，控件全都存在、脚本也全都能找到它们，
但屏幕上什么都看不见** —— 这会让你完全没法判断"搭对了没有"。

> 注意区分两件事：
> - **脚本跑不跑 / 计时走不走** → **完全不需要图片**，看日志就够了；
> - **能不能看见** → 需要至少给「格子」和「按钮」挂上底图。

---

## 对照表：哪张图放哪儿

### 必加（不加就看不见）

> 占位图都是**纯色**，所以「图片类型」**基础 / 拉伸 随便选，效果一样**（见上一节）。
> 尺寸列只是"够用就行"的参考 —— 因为总是铺满控件，**真正要盯的是长宽比**。

| 文件 | 尺寸 | 图片类型 | 放到哪 |
|---|---|---|---|
| `cell_face.png` | 256×256（1:1） | 基础或拉伸都行 | 每个 `cell.r.c` 的 **`face`** 子控件；再把 `face` **拖到格子的「默认」状态节点**上 |
| `cell_hover.png` | 256×256 | 同上 | 同上，拖到 **「悬停」** 节点（可选，但体验好很多） |
| `cell_pressed.png` | 256×256 | 同上 | 同上，拖到 **「按下」** 节点（可选） |
| `cell_disabled.png` | 256×256 | 同上 | 同上，拖到 **「不可用」** 节点（可选） |
| `btn_default.png` | 256×96（≈ 按钮长宽比） | 同上 | **每个预设按钮**的 `text`（或 `face`）子控件。**所有按钮可共用这一张** |
| `x_mark.png` | 88×88（1:1） | 只能基础 | 每个 `cell.r.c` 的 **`x`** 子控件，初始**隐藏**（脚本运行时才显示） |

### 建议加（加了才知道分区）

| 文件 | 尺寸 | 放到哪 |
|---|---|---|
| `card_face.png` | 160×200（≈ 卡片 3:4） | 每张 `tray.X` 的 **`face`** 子控件（头像卡底） |
| `portrait_A/B/C/D/E/F/V.png` | 64×64 | 各角色头像（不同颜色，方便分辨谁是谁） |
| `panel_topbar.png` | 512×64 | `topbar` 里放一个图片子控件当底板 |
| `panel_side.png` | 512×512 | `left` / `right` 里各放一个当底板 |
| `bg_screen.png` | 1600×900 | 最外层放一张当整屏背景（可选） |

> **换成真美术时**：纯色占位图怎么缩放都不难看，但真实美术**长宽比不对就会被拉变形**。
> 例如头像卡是 68×87（≈3:4），头像素材就该按 3:4 出，而不是正方形。
> 有圆角/边框的底图再把它做成**九宫格**并选**拉伸**。

> 图省事的话：**`card_face.png` / 面板底图 / 背景可以全部先跳过**，
> 只加「格子」和「按钮」两类就能看清主体（棋盘 + 按钮条 + 头像卡位置）。

## 角色头像那一块，有个坑要先说清楚

脚本更新头像是这么做的（`engine_adapter_qianxing.lua`）：

```lua
target:SetImage(target.imageSource, imageId)   -- 沿用编辑器里配好的"来源"，只换 id
```

也就是说 **`imageSource`（图片来源）必须在编辑器里先配好**，脚本不负责配来源。

`imageSource` 的取值类型有 StaticReference / Item / Equipment / Prefab 等好几种，
**具体哪种能让你"一个来源切换多张头像"我没在真机上验过**。所以占位阶段建议：

- **每张头像卡各自把图片配死**（`tray.A` 的 `face` 直接用 `portrait_A.png`，依此类推）；
- 这样即使脚本的 `SetImage` 在真机上换不了图，**玩法完全不受影响** ——
  因为玩家是靠卡片上的**名字文字**认人的，头像只是锦上添花。

等你确认了 `imageSource` 的正确用法，再回来把头像改成动态的。

## 状态节点怎么挂（这一步不做，按钮就是透明的）

官方原话：**预设按钮的外观来自它状态节点引用的子控件**。

做法（二选一）：

1. **拖**：在层级里把子控件（`face` / `text`）**拖到** 按钮的「默认」状态节点上；
2. **勾**：**单击**「默认」状态节点，在弹出的列表里**勾选**那个子控件。

按钮设置入口：选中按钮 →【基础】→ 按钮设置 → 按钮状态节点。
四个状态：**默认 / 悬停 / 按下 / 不可用**。配好后点状态节点的**播放键**可以在编辑器里预览。

> 血泪教训：只改**按钮自己**的尺寸/图片，画面上**完全看不出来**。
> 我们为此白测过一整天 —— 一定要改**子控件**。

## 图片类型在哪设、要选哪个

**位置：选中那个图片控件 → 「图片设置」面板 → 把「图片源」设为【静态引用】→ 这时才会出现「图片类型」。**

依据：官方《图片控件》文档（`mh2oih9jou22`）「二、图片的编辑 → 2.图片设置」。
它的参数表是这么组织的：

| 配置参数 | 说明 |
|---|---|
| **图片源** | 枚举：静态引用 / 动态引用 / 道具 / 状态 / 技能 / 单位状态（**选不同的会决定下面出现哪些参数**） |
| **（1）当图片源 = 静态引用时** | 引用素材资产 / 填充颜色 / **图片类型** / 图片属性 |
| （2）当图片源 = 其他类型时 | 只支持配自定义变量作为图片标识 |
| （3）颜色配置 | 所有图片源类型都支持 |

> ⚠️ **「图片类型」只在「图片源 = 静态引用」时才出现。**
> 所以**找不到「图片类型」几乎一定是「图片源」没设成静态引用**。

### 关于「图片类型」：基础 / 拉伸 —— **结论已更正**

> **真机实验（2026-09-26）**：**基础 和 拉伸 都会随图片控件的大小变化（总是填满控件本身）。**
> 所以"不能用拉伸就会按原始尺寸画、会溢出控件"是**错的**。

官方文档里其实是**两个不同的概念**，很容易读混：

| 概念 | 归属 | 取值 |
|---|---|---|
| **图片类型** | **控件**上的设置 | `基础` / `拉伸` |
| **图片属性** | **素材自己**的属性（在图片资产库里筛） | `普通` / `三宫格` / `九宫格` |

「拉伸」= "**启用该素材的拉伸属性**"。所以真正的区别只在素材是**三宫格 / 九宫格**时才显现：

| 素材的图片属性 | **基础 vs 拉伸 有区别吗** |
|---|---|
| **普通** | ❌ **完全一样** —— 两者都铺满控件、四角都跟着形变 |
| 三宫格 | ✅ 拉伸保住那一对边；基础会压扁 |
| 九宫格 | ✅ 拉伸保住四角（圆角不糊）；基础把圆角压扁 |

**所以规矩很简单**：

| 场景 | 怎么做 |
|---|---|
| 纯色 / 纯图案（占位图、色块） | 基础 / 拉伸 **随便选** |
| **有圆角 / 边框**（按钮、面板、卡片底图） | 素材做成 **九宫格**，图片类型选 **拉伸** |
| 尺寸怎么定 | **不看尺寸，看长宽比** —— 总是铺满控件，长宽比不对才会被拉变形 |

> 因此下面表里的尺寸**不是约束**，只是"够用就行"的参考。
> 真正要盯的是**长宽比 ≈ 控件长宽比**（例如头像卡 68×87 ≈ 3:4，头像素材就该是 3:4）。
>
> 完整的更正记录见 `docs/环境问题-诊断记录.md` 第 12 节。

## 换成真图时怎么替换

1. 用同名文件覆盖 `assets/placeholder/` 里的图（**尺寸可以不同，但长宽比尽量接近**）；
2. 或者在编辑器里直接把图片控件的来源指向你的新图；
3. 界面坐标系是**画布空间（原点左下，中心点绝对坐标）**，跟图片本身无关 ——
   换图**不需要**改任何坐标。
