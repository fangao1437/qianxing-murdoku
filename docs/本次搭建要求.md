## 三之二、**一个模板怎么给不同格子配不同美术？**

> 格子都由同一张模板生成，但每格要长得不一样 —— 这不矛盾，
> **模板负责"结构"，美术在运行时按格设置**。三条机制，全部有官方依据：

| # | 机制 | 官方依据 | 解决什么 |
|---|---|---|---|
| ① | **换图**：`SetImage(imageSource, imageId)` | `imageId`/`imageSource` 字段**只读**，但有 SetImage 方法 | 不同房型底图、物件图标、角色头像 |
| ② | **染色**：`face.imageColor = Color(r,g,b,a?)` | `imageColor` 是 `ColorValue`、**读写**、Tweenable | 同底图不同色区分房间 → **零额外素材** |
| ③ | **墙/门**：`wall.<边>` / `door.<边>` 子控件 + `SetVisible(bool)` | `SetVisible(visible)`「仅设置可见性」 | 每格四边不同（墙、门）→ **不用为每种墙型做模板** |

> 由脚本按每格数据 `SetVisible(true)` 打开。

#### ⚠️⚠️ 四个状态节点**全部**要引用 `content`（否则鼠标一悬停就出"缺口"）

用户 2026-09-27 04:26 实测现象：**鼠标放到某个格子上时，那一格的内容消失了**（看起来像缺口）。

原因：预设按钮有四个状态节点 —— **默认 / 悬停 / 按下 / 不可用**。
只给「默认」配了引用时，**鼠标一悬停就切到「悬停」状态**，而那个状态什么都没引用
→ 按钮按该状态渲染 → **内容整个消失**。

官方原文明确允许四个状态引用同一个控件：

> 按钮状态节点：按钮在四种状态下的显示引用，**每个节点可引用相同或不同**的子控件。

| 状态 | 必须引用 | 说明 |
|---|---|---|
| **默认** | ✅ `content` | 无交互状态 |
| **悬停** | ✅ `content` | **漏了它 → 鼠标一放上去格子就空** |
| **按下** | ✅ `content` | 漏了它 → 按下瞬间格子空 |
| **不可用** | ✅ `content` | 本工程按钮始终可用，但一并配上省事 |

**四个都拖成同一个 `content` 即可**（官方允许"相同"）。

#### ⚠️⚠️⚠️ 中间容器必须**允许点击穿透**，否则"点格子没反应"

用户 2026-09-27 05:13：悬停不再消失 ✅，但**点击无反馈** ❌。

原因在官方 API 的 `ClientUIContainerControl` 字段里 ——

| 字段 | 说明 |
|---|---|
| `isolateNavigation` | 是否隔离手柄导航 |
| `disableKeyEventPassthrough` | 是否屏蔽按键事件穿透 |
| **`disableCursorEventPassthrough`** | **是否屏蔽区域内点击事件穿透** ← 就是它 |
| `showCursor` | 是否显示常驻光标 |

方案 A 下 `content`（容器节点）**整块压在按钮 `cell` 上面**。
只要它"屏蔽区域内点击事件穿透"，鼠标点击就**到不了按钮** ——
表现为"点格子完全没反应"，而**体检一切正常**（按钮自己的 raycastTarget 照样是 true）。

| 谁处理 | 怎么处理 |
|---|---|
| **脚本自动** | 把这个字段**关掉**（它是**读写**的），并顺手开 `showCursor`、放开按键穿透。不用你逐个容器去取消勾选 |
| 你（若脚本改不动） | 脚本读不到该字段时会明确提示，请在编辑器里**取消勾选「屏蔽区域内点击事件穿透」** |

> 另外脚本加了一行**判定输出**：点击真的到达脚本时会打
> 「`[murdoku] 收到点击 → 控件 `cell.r.c`（第 N 次）`」（前 8 次）。
> **看得到** = 点击通了，问题在后面；**看不到** = 点击根本没到，就是这个穿透开关。

#### ⚠️ 四个方向的墙要**各自一个**子控件

关卡数据里，墙/门是**按边**记的（`v` 竖边 / `h` 横边），一面 5×5 的棋盘四边都可能出现墙。
所以 `wall.up` / `wall.down` / `wall.left` / `wall.right` **四个都要配** ——
**只配 `wall.up`，竖墙就永远画不出来**（用户 2026-09-27 就是这种情况：
关卡里 `v:4:3`/`v:5:3` 是竖墙，但模板只有 `wall.up`）。

> 脚本会**自己对账**并在日志里报出来：
> 「⚠️ 本关需要这些边，但模板里没有对应的子控件（所以画不出来）：wall.left wall.right」。
> 所以不用靠看截图发现问题 —— 试玩一次就知道缺哪个。

### 素材调色板：解决「`SetImage` 要整数 ID，而你不能手抄数字」

`imageId` 是**只读**字段，所以脚本没法把"图片名字"变成 ID。做法：

```
assets                ← 一个容器（名字可配：cfg.assets.palette）
├─ room.kitchen       ← 一个图片控件，图在编辑器里配好；控件名就是引用键
├─ room.hall
├─ floor.wood
├─ portrait.A
└─ obj.cashier
```

脚本运行时**读这些控件的 `imageSource` + `imageId`**，之后就能按名字套到任意格子。

| 好处 |
|---|
| 一个模板 + 一张调色板 = **任意多种外观**，不用为每种外观做模板 |
| 换图只在编辑器里改调色板，**代码一个字都不用动** |
| **不用手抄任何数字 ID** |

`assets` 容器会被 `hide_unlisted` 自动隐藏（它不在关卡布局里），放哪都行。

关卡数据里凡是配图的地方现在**两种写法都行**：

```lua
portrait = 106053          -- 整数 ID（老写法，兼容）
portrait = "portrait.A"    -- 调色板里的素材名（推荐）
```
