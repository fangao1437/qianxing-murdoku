## 一、三条必须记住的

### 1. 内存断言过 ≠ 落盘复读过 ⇒ **写盘后必须重新解析再断言一次**

第四轮的实测：

| 阶段 | 结果 |
|---|---|
| `--probe` 内存断言（插入逻辑正确性） | **4/4 全过**（`路径差=0`、图对 `4281536672/100108`、子列表第 1 位、兄弟顺序） |
| 写盘后 `readGil(OUT)` 复读断言 | **3/4**（其中一个按钮不过） |
| `check_childlist_top` / 其余闸门 | 由复读结果决定 |

⇒ **结论**：内存里的树是对的，不代表**编码 → 重新解析**这条往返是对的。
凡是"改记录数组 / 动字段顺序"的工具，**必须在写盘后 `readGil` 一次并在新树上再断言**，
断言不过就 `exit != 0` 并且**不要把文件留在交付路径上**。

（这条已经写进 `tools/gil/gen_modal_art3.mjs`：写盘后 `readGil(OUT)` 复读四个按钮，不过则 exit 6。）

### 2. "同一轮里混【删除】+【插入】"是高风险动作

`readGil()` 给出的 `rec.index` 是**读入时**在 holder 里的下标：

- 删掉一条 ⇒ 它**后面**的记录下标全部 −1；
- 插入一条 ⇒ 它**后面**的记录下标全部 +1。

于是"边算边改"时，后续记录的 `splice(rec.index + 1, …)` 会落到**别的记录内部**，
把记录劈开 —— 表现是"文件还能解析，但某条记录的顶层 `#503` 没了/子控件丢了"，
**`check_childlist_top` 会立刻报 exit 1**（这条闸门两次都在第一时间抓到）。

**优先级（从安全到危险）**：

1. ✅ **只改值**（几何、名字、图对）——不动数组，零风险；
2. ✅ **只追加**（`holder.push(新记录)`）——不动任何已有下标；
   摘除旧引用只改**子列表 ID 数组**，不要删记录（旧记录变成"不在任何子列表里"的孤立记录，不渲染）；
3. ⚠️ **一次性收集 + 降序应用**（`sort((a,b) => b.at - a.at)`，且 `at` 必须**当场用 `indexOf` 重算**）
   —— 只有在**不混删除**时才安全；
4. ❌ **边遍历边增删** —— 已连错两轮，禁止。

### 3. 附带的坑（同轮踩到，一并记）

- **字段对象自己就带 `.field`（字段号，是数字）**，而记录对象带 `.field`（是对象）。
  写"兼容两种入参"的辅助函数时用 `x.field ? …` 会**静默走错分支**（实测：clone 的图对打印成 `null/null`）。
  正确写法：`typeof x.field === 'object'`。
- **`byName` 按"记录自己的名字"索引**：`home.select.bg` 这条记录的 `name` 其实是 `bg`
  （父才是 `home.select`）⇒ 必须按 `父名/子名` 两级查，不能按点号路径查。
- **引擎属性名 ↔ `.gil` 字段号全项目无记录**（`client_script.lua:8656` 还写过"这个引擎根本没有
  `raycastTarget` 字段"）。判不了的属性**不要猜着写字段**，正确做法是**整份克隆一个已知能用的同类控件**。
