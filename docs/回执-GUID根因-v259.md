# 回执 —— GUID 撞号的**根因**与修复（v259 / 2026-10-18）

> 用户判断（正确）：「**建控件正常来说没问题**，按仓库工具不该出问题；这是**首次**出撞 id」
> 并指出：**`things` 交给脚本对以后换素材很麻烦** —— 本版把 `things` **恢复**了。

## 〇 根因（一句话）

**`.gil` 里一条控件的 GUID 存了不止一份**；我建 `things` / `content/obj` 时用的是"克隆母本 + 只改顶层 `#501`"，
**其余几处仍指着母本** ⇒ 编辑器看到**两个控件同一个 GUID** ✗

`_probe_innergids.mjs` 实测（`402`，改前）：

| 号 | 被谁用着 | 路径 |
|---|---|---|
| `1073741889` | `face` **＋ `obj` ＋ `obj.table/plant/carpet/chair/shelf/statue`** | `/#501`、`/#502/#11/#501`、`/#505/#503/#504/#4` |
| `1073742330` | `tpl-container`、`tpl.stage`、`win`（★ 原档就有，属"模板引用"✓） | 同上 |
| `1073741876` | `cell.1.1`、`content`（★ 父指针 ✓） | 同上 |

⇒ 我把 `face` 克隆成 `content/obj` 时只改了 `/#501`，**`/#502/#11/#501` 与 `/#505/#503/#504/#4` 还写着 `face` 的号** —— 那正是编辑器校验读的位置 ✓
⇒ 所以：**395 干净**（一个控件都没克隆）、**396 起出错**（第一次克隆新建），而按顶层 `#501` 查永远是 0 个重复（我的旧探针只看那一处）✓
⇒ 这也解释了「**首次试玩不触发**」：校验走的是实例化后的控件表，第一次跑还没建那份缓存 ✓

## 一 修复

```
node tools/gil/remap_ids.mjs --in=402-高段GUID-v257.gil --out=404-GUID修根-v259底.gil \
  --names=obj,obj.table,obj.plant,obj.carpet,obj.chair,obj.shelf,obj.statue,things
```

- 对每个克隆控件：把"仍等于**母本 GUID**"的所有 varint 改成**它自己的 GUID**
  （本次扫到并改写 **62 处**；9 个控件：`content/obj` ×2、`things`、6 个 `obj.*`）
- 断言：每个克隆体里**母本号不再出现**；`writeGil` 自带重读 + 往返

★ 这一条以后**所有**克隆类工具都要走（`remap_ids` 已入库 ✓）。
