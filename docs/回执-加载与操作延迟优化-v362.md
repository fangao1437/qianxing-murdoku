# 回执：加载时间与关键操作延迟优化（v362，基于 583）

- 交付存档：`584-加载与操作延迟优化-v362.gil`（= 583 + 内嵌 v362 脚本；控件树与 583 逐字节相同，`diff_fields` 只差内嵌脚本这一处）
- 脚本：构建标记 `v362`；改动集中在 `lua/engine_adapter_qianxing.lua`、`lua/ui_controller.lua`、`lua/main.lua`、`lua/entry_client_script.lua`、`lua/tutorial_ui.lua`、`lua/tut_verify.lua`
- 量测工具：`tools/perf_faithful/`（真实控件树假引擎 + 场景 + 对比；用法见其 README）

## 一、结论

同一场景（开局 → 选关 → 第一关全流程到结算 → 第二关 → 第三关 → 首页），v358（583 内嵌）对 v362：

| 阶段 | 引擎调用 v358 | v362 | 变化 | 实例化节点 v358 → v362 |
|---|---:|---:|---:|---|
| 开局 OnInit+OnStart | 797,319 | 81,731 | −90% | 1,310 → 415 |
| 开局后 30 帧 | 2,972,133 | 48,213 | −98% | 2,125 → 0 |
| 进选关 | 661,703 | 20,585 | −97% | — |
| 进第一关 | 1,785,732 | 92,332 | −95% | 904 → 904 |
| 进第二关 | 2,711,938 | 253,347 | −91% | 4,859 → 1,467 |
| 进第三关 | 1,469,149 | 176,772 | −88% | 1,359 → 31 |
| 关卡内稳态（每帧） | ~607 | ~328 | −46% | — |
| 点格子 / 选人 / 撤销 / 翻教程 | 658 / 1,140 / 1,145 / 593 | 276 / 582 / 587 / 314 | −47%～−58% | — |
| **合计** | **12,424,249** | **1,325,868** | **−89%** | **10,557 → 4,942** |

- **界面结果不变**：最终 5,254 个控件的 路径+兄弟序号 / 显隐 / 激活 / 尺寸 / 位置 / 文字 / 图片 / 缩放 逐行相同（Lua 5.3、5.4 各跑，多次运行均为 0 处不同）。
- **回归**：47 套 `tests/*.lua` 结果与 v358 逐项相同（5 套原本就红的见第四节，未因本次改变）。`furn_newarch` F6/F7 改成"钉结果"（见第二节第 ⑥ 条），新断言在 v358 上同样全绿。
- ⚠️ 以上是**次数**，不是毫秒。毫秒与帧率只有真机能给，请按第五节实机验收。

## 二、改了什么（每条都不碰《关键功能清单与性能优化禁区》）

1. **`Adapter:find` 名字索引**（禁区 3 允许的"优化遍历方式 / 同帧缓存"）。
   根因：583 的 `root` 下 2,467 个节点里，教程三棵树 `td.l2/td.l1/td.home` 占 1,867 个，且排在 `home/modal/hex.back/select.*/things/hit.*` **前面** ⇒ 每一代每个名字第一次查找都要先走完 ~1,900 个教程节点，原来是一个名字走一趟。
   改法：一趟走树、按与 `find_in` **同样的先序与限深**记下每个名字第一次出现的控件（重名结果不变）。索引只在**建它的那一帧**内回答命中，命中先校验 `ctrl.name`；未命中照旧当场重走一遍（"搜空"的代价与语义与原来相同）；随 `invalidate_lookups` 整代作废。`cfg.find_index = false` 回到逐名深搜。
2. **按名单预取 `Adapter:prefetch`**：只用在"连着按名取、中间不改树"的三处——`ensure_cells`（格子 + 三个模板名）、`enable_cursor`（11 个容器）、教程触发判据（5 个名字）。一趟走树后对名单原样跑 `find`（命中 / 负缓存 / TTL / path_map 全照旧）⇒ 与逐个 `find` 逐字相同。进新关时格子全未建：原来每格整树搜空一趟（OnInit 25 趟、进 6×6 关 11 趟），现在 1 趟。
3. **`tut_verify` 重名计数一趟数完**：原来 62 条期望 × 三套 × 每条整树一遍 ≈ 100 万次 `GetChildren`，全压在开局前几帧；现在每套一趟。自检结论（`OK 62/62`）不变。
4. **教程家具空闲预热**：`tutorial_ui:init()` 不再在开局实例化 l1/l2 的 20 件家具（2,125 个模板节点）；开局稳定 60 帧后由入口每帧补一件（与原来同一建造顺序 ⇒ 兄弟次序相同），打开时仍会当场补齐。`opts.eager_furniture = true` 恢复旧行为。
5. **家具实例化按 render 批次收口**：一趟 `Controller:render` 里，`furn_tpl / furn_span / furn_offset / furn_level=true` 只记愿望与脏格，趟末（同一帧、规划全部下发完）按**最终**愿望每格造一次；`on_tick` 兜底。批次外（测试 / 直接调用）照旧立即造。`cfg.furn_batch = false` 关掉。
6. **同一模板只改尺寸 / 跨格 / 偏移 ⇒ 就地重缩放**，不再销毁重建（缩放本来就是 `SetLocalScale` 绝对值、几何本来每次都写 ⇒ 结果与新建相同）。进第二关时格子尺寸 108 → 89 → 91 逐步到位，原来每件家具被造 3 次（雕塑一件 383 个节点）。没有应用记录 / 模板键不同时仍按原来销毁重建；`cfg.furn_rebuild_on_resize = true` 恢复旧行为。
7. **关卡外不造家具**：另外三条补造路径（格子建好后的补造、`furn_tpl/span/offset` 即时补造、`on_tick` 每 0.5 秒重对齐）补上与 `_apply_furn_level` / 重试**同一个前提** `_furn_level ~= false`。那时造出来的件是隐藏的，下一次 `furn_level=true` 会被全部销毁重建 ⇒ 纯白造（首页阶段把第一关 8 件家具白造一遍、换关时把上一关整套家具再造一遍）。
8. **`_palette_child` 同帧缓存**（禁区 3 允许）：网格视窗每帧重进 5 个列表项回调，每项都从 `GetClientUIRoots()` 重新找 `assets` 再读 18 个名字；现在每帧只找一次、读一次（重名取最后一个，与原循环一致），换帧作废。
9. **`main.lua` 选关条**：`selbar` / `selbtn.*` 的查找只在 `on_select` 时做（循环体本来只在 `on_select` 时有动作；`widgets = false` 时它们根本不存在，原来每一代整树搜空 7 次）。

## 四、发现但**没有改**的（需要你拍板）

1. **`enable_cursor` 永不收敛**：收敛条件要求 `CURSOR_CONTAINERS` 里 11 个容器**全部**找到，而 583 里 `left / tray / board / actions / select` 不存在 ⇒ 每 20 帧重扫一次、永不停。属禁区 2.4-④（门控）⇒ 只做了预取降成本，没改收敛条件。建议：改成"找到的全部为 true 且连续 3 趟不变"即收敛。
2. **存档里的旧教程 `teach.*` 共 334 个控件已不再使用**（新教程是 `td.*`），占运行时控件树的 13.5%：开局要实例化它们，每次走树也要多走这一截。建议在下一版存档里删掉（同时把 `tut_verify` 的期望清单换成 `td.*`）。删存档控件属于设计决定，本次未动。
3. **内嵌脚本 62% 是注释**（1.55 MB → 剥注释后约 0.58 MB，`tools/audit/proto_strip_comments.mjs` 已验证可编译执行）。编译时间只省约 11%，主要收益是存档小约 0.95 MB（−19%）；但会让"内嵌脚本 == dist"这道闸门与真机报错行号的对照方式改变，未启用。
4. **5 套原本就红的测试**（v358 上同样红，本次未改变）：`btn_art_gate`、`perframe_throttle`（都在找已按设计删除的 `apply_tray_layout` 等）、`grid_cost`（2 条：卡片高亮已不走 `style = clue.focus`）、`ui_math`（6 条：`board/tray/legend` 容器已删除）、`selftest`（1 条：副标题已删除）——断言是按旧设计写的，建议按现设计更新。
5. `_read_control_text` 调的 `root:FindChild(slot)` 不在官方 API 里（pcall 吞掉后走广度优先兜底，结果正确，只是多走几步）。

## 五、实机验收（请按顺序）

1. 导入 `584-加载与操作延迟优化-v362.gil`，**重启客户端**。日志首屏应有 `构建标记 v362`。
2. 计时（秒表即可）：从进入游玩到首页可点；首页 → 选关；选关 → 第一关 / 第二关 / 第三关首帧出现完整棋盘。与 583 对比。
3. 功能抽查：
   - 左上角 ↰ 返回 → 确认条 → 能退出关卡（禁区 1）。
   - 第一关 / 第二关**首次进入**自动弹教程，翻页、关闭正常，教程棋盘家具都在。
   - 第二关家具位置、大小、地毯长度与 583 一致，没有残留第一关的家具。
   - 选人 → 点格子放置、灰白、长按、撤销 / 重做、提交 → 指认 → 结算。
4. 日志里应看到 `[tutorial] 家具实例化 tag=l1 新建=8` 与 `tag=l2 新建=12`，出现在开局约 1 秒之后，而不是开局第一帧。
5. 若某处异常，可按开关逐项回退定位：适配器 cfg（`entry_client_script.lua` 建适配器的那张配置表）加 `find_index = false` / `prefetch = false` / `furn_batch = false` / `furn_rebuild_on_resize = true`；教程家具回到开局即建：在 `tutorial_instance` 里给 `mod.new(...)` 的参数表加 `eager_furniture = true`。
