# 关卡数据格式（把设计好的关卡编入框架的入口）

框架是"引擎 + 数据"结构：**规则逻辑在 `lua/murdoku_core.lua`，关卡内容是一个 Lua table**。
你只需要按本文格式写关卡数据，不需要改任何代码。

---

## 1. 最小可用关卡

```lua
return {
  id   = "case_001",
  name = "第一案：雨夜书房",
  size = { rows = 5, cols = 5 },

  suspects = {
    { id = "A", name = "管家" },
    { id = "B", name = "医生" },
    { id = "C", name = "歌女" },
    { id = "D", name = "伯爵" },
  },

  solution = {
    A = { r = 1, c = 1 },
    B = { r = 2, c = 3 },
    C = { r = 3, c = 5 },
    D = { r = 4, c = 2 },
  },

  clues = {
    { type = "corner", who = "A" },
    { type = "at",     who = "B", r = 2, c = 3 },
    { type = "in_col", who = "C", c = 5 },
  },
}
```

复制 `lua/levels/template.lua` 改成你自己的即可。

## 2. 字段总表

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `id` | ✅ | string | 关卡唯一标识（存档、信号都用它） |
| `name` | ✅ | string | 关卡标题 |
| `subtitle` | | string | 副标题 |
| `difficulty` | | string | `easy` / `normal` / `hard` / 自定义 |
| `size` | ✅ | `{rows=,cols=}` 或 `"5x5"` | 棋盘行数、列数 |
| `rules` | | table | 见第 3 节；不写则用默认值 |
| `walls` | | table | 见第 4 节；决定"房间"的划分 |
| `objects` | | table | 家具/物体，见第 4.5 节；`occupiable=false` 的家具所在格**不能站人** |
| `blocked` | | array | 额外禁止站人的格子：`{ {r,c}, ... }`（家具之外的手工限制） |
| `water` | | array | 水域格子：`{ {r,c}, ... }`（用于"没有人在水里"这类线索） |
| `suspects` | ✅ | array | `{ id, name, portrait, gender }`；`id` 用短字符串（首字母会当分享码符号） |
| `victim` | | `{id=...}` 或 `{r,c}` | 受害者也**要摆上棋盘**：推荐 `victim = { id = "V" }` 并把它列进 `suspects` |
| `murderer` | | string | 凶手 id（用于 `is_murderer` 线索） |
| `solution` | ✅ | table | 正确答案，两种写法见第 5 节 |
| `clues` | | array | 线索列表，见第 6 节 |

## 3. `rules`（Murdoku 的"数独"约束）

```lua
rules = {
  one_per_row  = true,    -- 每行最多 1 人：一行放 2 个即判违规（默认 true）
  one_per_col  = true,    -- 每列最多 1 人（默认 true）
  one_per_room = false,   -- 每个房间最多 1 人（默认 false，按设计决定）
  place_all    = true,    -- 必须把全部嫌疑人都放上才算破案（默认 true）
}
```

> ⚠️ 这几条是**可配置**的，因为 Murdoku 官方的精确约束集需要按你的关卡策划确定：
> 如果采用"每行每列各 1 人"的排列式布局，那么 `adjacent` / `same_row` / `left_of`
> 这类线索在数学上恒为假，别写进关卡；反之若允许同行同列，就把两项设为 `false`。

## 4. `walls`（墙 / 房间）

三种写法任选（可混用）：

```lua
-- 写法 A：数组
walls = { {"v", 1, 2}, {"h", 3, 3} }

-- 写法 B：按方向分组
walls = { v = { {"1","2"} }, h = { {"3","3"} } }

-- 写法 C：字符串
walls = { v = { "1:2" }, h = { "3:3" } }
```

含义：

- `{"v", r, c}` = 单元格 `(r,c)` 与 `(r,c+1)` 之间**竖着的墙**（挡住左右相通）
- `{"h", r, c}` = 单元格 `(r,c)` 与 `(r+1,c)` 之间**横着的墙**（挡住上下相通）

房间不是手写的，框架用洪泛算法从墙推出来，房间号从 1 开始；
`same_room` / `different_room` / `alone_in_room` / `room_has` 这些线索都基于它。
房间号可以用 `core:view().cells[r][c].room` 在调试时打出来确认。

### 4.5 `objects`（家具 / 物体）与可站性

Murdoku 的棋盘是"格坐标系 + 美术场景"，**能不能站人是由家具决定的**：

```lua
objects = {
  -- 完整写法：可以标 occupiable
  ["书架"] = { cells = { { r = 1, c = 5 } }, occupiable = false },   -- 不能站人
  ["桌子"] = { cells = { { r = 3, c = 3 } }, occupiable = false },
  ["地毯"] = { cells = { { r = 2, c = 2 }, { r = 2, c = 4 } } },     -- 不写就是可站
  -- 简写：直接给格子，等价于可站
  ["椅子"] = { { r = 4, c = 4 } },
}
```

- `occupiable = false` 的家具会把所在格自动标记为「不可站人」，玩家放不上去，
  `core:view().cells[r][c].occupiable` 也会是 `false`（界面照这个显示/禁用）。
- 多格大件（船、车）就写多个坐标格；Murdoku 官方说法是"大件占多格，但人只占其中一格"。
> ⚠️ **Lua 的标识符只能是 ASCII**，所以中文家具名必须写成 `["书架"] = {...}` 这种**字符串键**；
> 直接写 `书架 = {...}` 会报 `unexpected symbol near '<\228>'`（这是本次实测踩到的坑）。
> 线索里引用家具时用的是**字符串值**，照常写 `object = "书架"` 即可。

- 线索里引用的是**家具名**（写成字符串值，见 `beside_object` / `on_object` 等）。

## 5. `solution`（正确答案）

两种写法都支持：

```lua
-- 1) 按嫌疑人 id
solution = { A = { r = 1, c = 1 }, B = { r = 2, c = 3 } }

-- 2) 按格
solution = { { who = "A", r = 1, c = 1 }, { who = "B", r = 2, c = 3 } }
```

还可以用紧凑字面量（`.` = 空，字母 = 嫌疑人 id）：

```lua
local M = require("murdoku_core")
solution = M.solution_from_grid_literal([[
A....
..B..
....C
.D...
...E.
]])
```

## 6. 线索类型全表（54 种，开箱即用）

> 类型名沿用 Murdoku 的英文原子名，方便和官方关键词表对照。

### 位置类

| type | 参数 | 语义 |
|---|---|---|
| `at` / `not_at` | `who,r,c` | `who`（不）正好在 (r,c) |
| `in_row` / `in_col` | `who,r` / `who,c` | `who` 在第 r 行 / 第 c 列 |
| `in_room` / `not_in_room` | `who,room` | `who`（不）在第 room 号房间 |
| `corner` | `who` | 棋盘四角之一 |
| `edge` | `who` | 贴棋盘边（含角落） |
| `inner` | `who` | 不贴边 |

### 房间 / 独处类

| type | 参数 | 语义 |
|---|---|---|
| `alone_in_room` / `alone` | `who` | `who` 独自待在所在房间（受害者也算"人"） |
| `with` | `a,b` | a 与 b 同处一室 |
| `with_only` / `alone_with` | `a,b` | a 与 b 单独共处一室（房间内只有他们两人） |
| `alone_with_victim` | `who` | `who` 与受害者单独共处一室（**破案判定**用的就是这条） |
| `room_has` | `room,n` | 第 room 号房间恰好 n 人 |
| `room_size_hint` | `room,n` | 第 room 号房间有 n 格（信息型） |
| `same_room` / `different_room` | `a,b` | 同一房间 / 不同房间 |

### "旁边"与关系类

`beside` = **上下左右四邻且同一房间**（隔着墙不算），这是 Murdoku 的核心语义。

| type | 参数 | 语义 |
|---|---|---|
| `beside` / `not_beside` | `a,b` | a（不）在 b 旁边 |
| `left_of` / `right_of` | `a,b` | 同行，a 在 b 的左/右 |
| `above` / `below` | `a,b` | 同列，a 在 b 的上/下 |
| `between` | `who,a,b` | `who` 夹在 a、b 之间 |
| `distance` | `a,b,d` | 曼哈顿距离正好 d |
| `offset` | `who,other,dr,dc` | 精确位移（dr 负=北，dc 负=西） |
| `row_offset` / `col_offset` | `who,other,d` | "正好在 X 北/南边 d 行"、"西/东边 d 列" |
| `compass` | `who,other,dir` | 斜对角方位，`dir` = `ne`/`nw`/`se`/`sw` |
| `gender_in_room` | `who` | 所在房间内没有异性（需 `suspects[i].gender`） |

### 绝对行列 / 角落 / 贴墙

| type | 参数 | 语义 |
|---|---|---|
| `abs_row_from` | `who,n,from` | `from`=`top`（默认）/`bottom`/`middle` |
| `abs_col_from` | `who,n,from` | `from`=`left`（默认）/`right`/`middle` |
| `corner_room` / `not_corner` | `who` | 是否在**房间**的墙角（一横一竖两面墙相交） |
| `border` | `who` | 贴着场景外框 |
| `wall_edge` | `who` | 贴着任意一面墙 |

### 家具 / 物体类

| type | 参数 | 语义 |
|---|---|---|
| `beside_object` / `not_beside_object` | `who,object` | `who`（不）在名为 object 的家具旁边 |
| `on_object` | `who,object` | `who` 站在该家具上 |
| `only_on_object` | `who,object` | 只有 `who` 站在这件家具上 |
| `only_beside` | `who,object` | 只有 `who` 在这件家具旁边 |
| `same_room_as_object` | `who,object` | `who` 与该家具在同一房间 |

### 格子 / 全局统计类

| type | 参数 | 语义 |
|---|---|---|
| `cell_empty` | `r,c` | (r,c) 没有人 |
| `only_one_in_row` | `r` | 第 r 行只有 1 人 |
| `no_empty_room` | — | 没有任何空房间 |
| `one_empty_room` / `two_empty_rooms` | — | 恰好 1 / 2 个空房间 |
| `one_on_object` / `n_on_object` | `object` / `object,n` | 恰好 1 / n 个人在这件家具上 |
| `nobody_in_water` | — | 没有人在水里（需要 `water` 列表） |

### 案件类

| type | 参数 | 语义 |
|---|---|---|
| `is_murderer` | `who` | `who` 是关卡登记的凶手 |
| `with_victim` | `who` | `who` 与受害者**同格**（摆位阶段用；破案判定请用 `alone_with_victim`） |

### 自己加一种线索（不用改引擎）

在任意初始化脚本里注册即可，引擎的校验、判定、文本全都会自动用上：

```lua
local M = require("murdoku_core")

M.clues["next_to_door"] = {
  params = { "who" },
  validate = function(ctx, clue)
    local p = ctx.pos(clue.who)
    return p ~= nil and ctx.room_of(p.r, p.c) == ctx.level.door_room
  end,
  text = function(ctx, clue)
    return ctx.name(clue.who) .. " 在门厅里"
  end,
}
```

`validate` 拿到的 `ctx` 提供：
`ctx.pos(id)`、`ctx.solution_pos(id)`、`ctx.name(id)`、`ctx.gender_of(id)`、
`ctx.room_of(r,c)`、`ctx.room_is_empty(room)`、`ctx.room_size(room)`、
`ctx.is_corner(r,c)`、`ctx.is_room_corner(r,c)`、`ctx.is_edge(r,c)`、`ctx.is_border(r,c)`、
`ctx.is_wall_edge(r,c)`、`ctx.is_water(r,c)`、`ctx.is_blocked(r,c)`、
`ctx.is_neighbor(a,b)`、`ctx.is_beside(a,b)`、`ctx.is_left_of(a,b)`、`ctx.is_above(a,b)`、
`ctx.same_room(a,b)`、`ctx.count_in_room(room)`、`ctx.count_in_row(r)`、`ctx.count_in_col(c)`、
`ctx.object_cells(name)`、`ctx.object_at(r,c)`、`ctx.count_on_object(name)`、
`ctx.count_beside_object(name)`、`ctx.victim_pos()`、`ctx.victim_id()`，
以及 `ctx.rows/cols/level/wall_set/room/room_count`。

## 7. 线索文案

每条线索的显示文本由线索类型自己出（`text` 函数），框架的 `core:view()` 里直接给出：

```lua
for _, clue in ipairs(core:view().clues) do
  print(clue.index, clue.text, clue.satisfied)

```

想做多语言，就在 `text` 里读一个全局语言变量，或自己包一层覆盖。

## 8. 自检（强烈建议写关卡后跑一遍）

```lua
local M    = require("murdoku_core")
local lv   = require("levels.case_001")

-- 1) 格式校验
local ok, errors = M.validate_level(lv)
for _, e in ipairs(errors or {}) do print("关卡错误: " .. e) end

-- 2) 答案是否满足全部线索 + 约束
local core = assert(M.new(lv))
for id, p in pairs(core.solution) do
  core:select_suspect(id)
  core:tap_cell(p.r, p.c)
end
local res = core:submit()
print("答案自洽:", res.solved, res.message)

-- 3) 是否唯一解（可选，慢；limit 传 2 表示最多找 2 个解）
local sols = core:solve(2)
print("解的数量(上限2):", #sols)
```

- 第 2 步必须为 `true`，否则关卡无解。
- 第 3 步若返回 2，说明线索太少、答案不唯一，玩家可以蒙对。

## 9. 棋盘规模与棋子数（N×N 规则）

Murdoku 的棋盘是 **N×N 正方形**，且 **N = 棋子总数（含受害者）**：

- `rules.one_per_row = true` 时，每行恰好 1 人 → 棋子数必须等于边长。
- 所以：`#suspects == size.rows == size.cols`，5×5 就是 5 枚棋子（例如 4 嫌疑人 + 1 受害者）。
- 官方线上关卡出现过 5/6/7/8/9/10/12/16 等边长，本框架不限制（引擎里 `solve()` 是回溯法，
  边长越大越慢，建议 ≤10）。

## 10. 分享码（把棋局发给别人）

`core:encode_state()` 会把整盘状态压成一个短字符串（和 murdoku 的分享棋局同思路）：

| 内容 | token |
|---|---|
| 已放置 | 该角色的**大写符号**（`id` 首字母，可在关卡里用 `symbol` 覆盖） |
| 单个笔记 | 小写符号 |
| 多个笔记 | `!` + 排序后的小写符号 + `?` |
| X 标记 | `X` |
| 空格 | `-` |

连续相同的 token 会压成「数量 + token」。往返验证：

```lua
local code = core:encode_state()
local clone = assert(Core.new(level))
assert(clone:decode_state(code))
```

## 11. 计分、提交与指认流程

照 murdoku 的三段式：

```lua
core:submit()        -- 校验：硬约束 + 全部线索 + 是否摆满
local got, total = core:score()   -- {n} of {m} correct
core:accuse("D")     -- 指认凶手；对了就破案，错了给出 "n/m 位置正确"
```

- 未摆满时 `submit().ok = false`（界面上"提交"按钮此时是禁用的）。
- 偷窃版里 `submit()` **只校验硬约束**，不揭晓任何线索层面的对错（规格 5.3）。
- 结案用 `core:accuse_verdict(盗窃者, 有没有同伙, 同伙)`（见第 12 节）。

## 12. 偷窃版新增字段（规则规格见 `docs/规则规格-偷窃版.md`）

### 12.1 `doors`（门径）与区域相邻

```lua
doors = {
  { "h", 3, 1 },   -- (3,1) 与 (4,1) 之间有门
  { "v", 4, 3 },   -- (4,3) 与 (4,4) 之间有门
}
```

- 写法与 `walls` 完全一致，同样开在**格边**上；
- 门**不改变区域划分**（区域只看墙），只用来建立**区域相邻图**；
- **区域 X 与 Y 相邻 ⟺ 有一条门直接连通 X 与 Y 的相邻两格，不经过第三个区域**；
- 一个区域可以和多个区域相邻；玩家看到的"相邻区域"就是这张图。

### 12.2 `roles`（角色归属，必填）

```lua
roles = {
  thief = "D",        -- 必有且只有 1 人，且不能是受害者
  accomplice = "C",   -- 0 或 1 人；不写 = 本案没有同伙
}
```

引擎据 R3/R4 校验答案：

- 盗窃者与同伙必须都在**受害者所在区域的门相邻区域**里；
- 盗窃者所在区域必须是这些相邻区域里**无辜人数最多**的（无辜 = 除盗窃者与同伙之外的角色）；
- 同伙必须与盗窃者**同区**；
- `k = 受害者所在区域人数`：`k ≥ 2` → **必须有同伙**；`k = 1` → 可有可无。

### 12.3 `meta`（假话声明）

```lua
meta = {
  false_clue = 7,        -- 第 7 条线索是假的；不写 = 本关全是真话
  announce   = "one",    -- none | one | unknown（unknown = 不告诉玩家）
}
```

- 粒度 = **整条线索**，范围 = **个人线索 + 全局线索合计，至多 1 条**；
- 受害者那句线索同级，一样可能是那句假话；
- **引用 `@accomplice` 的线索在"没有同伙"时一律判不成立** ——
  所以这类线索天然是"要么真有同伙，要么这句就是那句假话"。

### 12.4 `rules.tie_policy`（并列策略）

```lua
rules = { tie_policy = "forbid" }   -- 默认；相邻区域无辜人数并列时判为非法关卡
rules = { tie_policy = "allow" }    -- 特殊关卡：允许并列（多解设计）
```

### 12.5 角色别名（写线索的主要手段）

任何线索的 `who / a / b` 都可以写三个别名：

| 别名 | 指向 |
|---|---|
| `@thief` | 盗窃者 |
| `@accomplice` | 同伙（无同伙时该线索不成立） |
| `@victim` | 受害者 |

```lua
{ type = "in_row", who = "@thief", r = 1 },        -- 盗窃者在第 1 行
{ type = "in_col", who = "@accomplice", c = 5 },   -- 同伙在第 5 列
```

玩家看到的是"盗窃者/同伙"而不是名字 —— **身份推理就靠这个**：
先用位置线索把摆位压下来，再从"第 4 列是谁""谁在书桌旁"这样的描述里反推身份。

### 12.6 新增线索原子

| type | 参数 | 语义 |
|---|---|---|
| `in_front_of` | `a,b` | a 与 b 站在**同一扇门**的两侧（原版就有、现在终于有数据支撑） |
| `is_role` | `who,role` | `who` 就是盗窃者/同伙/受害者 |
| `not_role` | `who,role` | `who` 不是某个角色 |

### 12.7 自检（写关卡后必跑）

```bash
lua tools/validate_levels.lua
```

它会检查：格式（含新字段）→ 结构约束 R3/R4 → 假话声明与实际是否一致 →
**唯一解（摆位 × 角色归属）**。三项里有任何一项不过，关卡就不能发。
