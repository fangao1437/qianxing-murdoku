# 715 UI 自适应修订 v12：恢复设计坐标与选关底色原生拉伸

日期：2026-11-18。基于用户本轮三张1280×576实机截图，对照v3与v11，从原始715重新构建。v12为待实机验收的修复候选。

## 证据与修复

1. 四端存档确认：v3将服务器背景置为零缩放，v11恢复绘制并满拉伸。v12恢复停绘，消除客户端边缘出现第二套服务器装饰的可能来源。没有实机运行日志，不能把它宣称为唯一根因。
2. v11直接以API宽高计算侧栏偏移；v3普通控件以1600宽设计口径定位。v12采用w=1600、h=1600×API高/API宽，根控件保留原生变换，不再每次重写根。相同比例不同数值应得到同一设计布局。
3. v12不恢复v3的“移动端固定720高”兜底。4:3设计高度为1200，16:10为1000；背景与火漆使用max(1,h/900)等比覆盖，兼顾上下。
4. v11会将选关底色尺寸改为(API宽+4)/cover、(API高+4)/cover，API与宿主口径不同时可能缩窄原始底色。v12将art647.select.bg.base从静态背景组移到root背景层，锚点0,0至1,1、尺寸差4×4，依赖实际父容器拉伸，按选关页面显隐。常驻底色仍在更下层。
5. 选关底纹独立cover；便签纸、连线、衬纸、白框与动态内容共用cardScale=min(cover,1600/1120,h/600)。避免只限制卡片倍率而纸张继续放大。
6. 保留原有撕边fit等比缩放与角部定位、返回旗处理、动态卡片布局补丁及保护区域。未修改棋盘玩法、线索和身份规则。

## 已执行验证

- 从原始715构建v12：8300→8430条记录；父子链接、磁盘回读、往返编码、保护子树、静态祖先变换、玩法模块一致性通过。
- 绘制顺序只允许已有撕边置顶与本次底色移至root背景层的变化；服务器背景四端停绘、选关底色四端满拉伸通过断言。
- Lua 5.3编译通过：813786字符、17355行。
- 运行时回归直接执行导出Lua中的适配函数，并读取GIL真实四端父链。模型采用1600宽宿主，API输入宽分别为1280、1600、1920，高度按比例生成。
- 12组配置×3档输入×4次页面状态（home→select→game→select），共144场景、924项检查。相同模型下v11失败84项，v12失败0项。
- 检查背景底色叶层世界边界、纸与卡框倍率、完整背景显隐、重复刷新不累乘、同比例布局一致和控件代际刷新。
- 测试只检查了动态卡片控件存在，未执行完整控制器的动态缩略图与命中生成；不能由此宣称实际点击已验证。

## 验证边界与实机观察

本轮没有操作游戏、没有导入实机。1600宽映射参考v3代码与用户截图，但没有日志确认真实宿主尺寸；模型通过不等于实机漏边已消失。若API固定返回16:9，不能据此推断真实设备比例，本版不伪造移动端高度。模型也不模拟引擎裁剪、原生安全区、字体栅格化和实际触控。

导入v12后重点看：选关左右是否仍出现异页背景；关卡笔记本与火漆是否恢复接近v3的构图；4:3与16:10上下是否完整；纸、卡框、缩略图与文字是否同步；返回选关后有无残留及点击错位。若仍异常，应结合运行日志的reported_ui、layout、cover、root几何定位，而非继续凭截图添加固定放大系数。
