## 一、整体机制（概念章）

| 项 | 结论 |
|---|---|
| 服务器控件 | 7.1 之前所有界面控件，受**服务器节点图**控制 |
| **客户端控件** | **不受节点图控制，只受客户端脚本控制**；必须搭配客户端脚本 |
| **挂载位置** | 客户端控件**必须放在「客户端控件容器」内**；容器本身是**服务器控件** |
| 生效条件 | 容器**处于激活且可见**时，控件与脚本才正常运行；容器隐藏/销毁 → 客户端控件销毁 |
| 编辑入口 | ①界面控件组管理 → 界面控件组库 → **客户端控件模板**；②界面控件组管理 → 界面布局 → 添加界面控件 → **客户端控件容器** → 画布设置 → 前往编辑 |
| 脚本入口 | **千星沙箱 → 客户端脚本资源管理器 → 脚本映射文件夹** |
| 脚本关联 | 脚本要挂在**具体客户端控件的「脚本」页签**上（添加脚本）；只有**建立了脚本映射**的 .lua 才会被打包上传 |
| 断线/传送 | **传送、断线重连会销毁所有客户端控件并回到初始状态**（界面恢复要自己做） |
| 信号延迟 | 联机时服务器发信号**最低 100ms 延迟** |
| 按键事件 | 按控件**渲染顺序**传递，层级/排序靠前的优先；用 `AddKeyEventListener` 控制 |
| 本地化 | 多语言文本管理 → **脚本文本变量**；脚本里用 `game.GetText(textMapId)` |
| 音频 | `game.PlayAudio2D(audioId)` |
| 日志 | 日志面板勾选「客户端脚本」；若出现**循环调用**导致卡死，正常日志不报，要看**本地日志 `ErrorLog.txt`**（与客户端脚本储存路径相同） |
| 能力范围 | 「客户端脚本可以实现**绝大多数 2D 玩法**，以及界面的动态效果」 |

### 脚本调用控件的两种 ID

| ID | 用途 | 接口 |
|---|---|---|
| **控件模板索引**（编辑期可见） | 动态创建控件 | `game.InstantiateClientUIControl(prefabIndex, parent)` |
| **运行时 ID**（运行时生成） | 查已存在的控件 | `game.GetClientUIControl(controlId)`、`control.id` |

- 只有**存为模板的客户端控件的父节点**能用 `ClientUIBaseControl` 被动态创建；
- 主屏里的客户端控件、以及模板控件的**子节点**，**不支持**脚本动态创建（→ 我的方案：**控件全部在编辑器里摆好并按名字查找**，见第三节）。

## 二、脚本生命周期（运行时按固定名字查找并调用）

```lua
function OnInit()    end   -- 脚本初始化
function OnStart()   end   -- 脚本启动
function OnEnable()  end   -- 脚本启用
function OnDisable() end   -- 脚本停用
function OnUpdate(dt)      end   -- 逐帧；dt: number；**不受关卡时停影响**
function OnLevelUpdate(dt) end   -- 关卡逐帧；**受关卡时停影响**
function OnDestroy() end   -- 脚本销毁
```

- `script:EnableUpdate(enabled: boolean)` 控制本脚本 Tick 开关（省性能）。
- **没有 `os`/`io`**：计时必须靠 `dt` 自己累加（我的适配层就是这么做的）。
- `debug.*` 除 `debug.traceback` 外**不可用**；额外提供 `math.isnan(n)` / `math.isinf(n)`。

### 全局对象

| 名称 | 说明 |
|---|---|
| `script` | 当前脚本实例（`Script`） |
| `Enum` | 枚举表 |
| `print(...)` / `printerr(...)` | 普通/错误级日志，**不阻断运行** |
| `typeof(value) -> string` | 运行时类型名 |
| `Color(r,g,b,a?)` `Color.FromRGB/RGBA` | 0–255 构造颜色；`ColorValue` 可 `:GetRGBA()` 拆分 |

### `script`（冒号调用）

| 成员 | 说明 |
|---|---|
| `script.alive` / `.scriptMappingId` / `.object` / `.path` / `.enabled` | 字段（`alive` 只读，销毁后要检查） |
| `script:GetParam(paramName)` | 读**编辑期配置的脚本变量**（相当于"本地初始状态"） |
| `script:Invoke(funcName, ...)` | 调用同脚本内的全局函数 |
| `script:RegisterServerSignalHandler(name, cb(name, params[]))` | 收服务器信号 |
| `script:UnregisterServerSignalHandler(name)` | 注销 |
| `script:RegisterCustomVariableChangedHandler(entityType, varName, cb)` | 监听全局自定义变量变化（值要用 `game.GetGlobalCustomVariableValue` 读） |

### 4.2.2 图片控件的字段访问权（官方 API 文档原文，`mhtakr07vej4`）

| 字段 | 类型 | 访问 | 备注 |
|---|---|---|---|
| `imageSource` | `ImageSource` | **只读** | 图片来源 —— **脚本改不了**，必须在编辑器里配 |
| `imageId` | `integer` | **只读** | 图片 ID |
| `imageColor` | `ColorValue` | **读写** | 而且是 `Tweenable`（能做补间） |
| **`imageType`** | `ImageType` | **读写** | 「基础 或 拉伸类型」——**脚本可以设** |
| `enableMask` / `reverseMaskArea` | boolean | 读写 | 遮罩 / 遮罩区域反转 |
| `enableSoftEdge` / `softEdgeMode` / `softEdgeWidthX,Y` | — | 读写 | 边缘羽化（宽度是 `Tweenable`） |
| `fillType` / `fillAmount` 等 | — | 读写 | 按进度填充（`fillAmount` 是 `Tweenable`） |

方法：**`SetImage(imageSource, imageId)`** 设置图片来源与 ID；
`SetFill*` 系列设置各种填充；`SetSoftEdgeWidth`。

相关枚举：

```lua
Enum.ImageType   = Basic(基础) | Stretch(拉伸)          -- imageType 用，读写
Enum.ImageSource = StaticReference(静态引用) | Item(道具) | Equipment(装备)
                 | Skill(技能) | UnitStatus(单位状态) | Faction(阵营)
                 | Currency(货币) | Prefab(元件)          -- imageSource 用，只读
```

> **注意两个易混点**：
> 1. **「基础 / 拉伸」的区别只在素材是三宫格/九宫格时才显现**（真机实验 + 官方文档结构确认）：
>    素材的**图片属性**是 `普通` 时，基础 和 拉伸 **表现完全一样**（都铺满控件、四角都形变）；
>    只有素材是 `三宫格 / 九宫格` 时，选 `拉伸` 才会保住边/角，选基础会把圆角压扁。
>    **所以"基础也会铺满控件"，不会导致内容溢出。**
> 2. 「图片类型」是 **`基础 / 拉伸`** 二选一（`Enum.ImageType`）；官方《图片控件》里另有
>    一张 `普通 / 三宫格 / 九宫格` 表，那是**素材资产自己的属性**（「图片属性」），
>    不是 `imageType` 的取值。更正记录见 `docs/环境问题-诊断记录.md` 第 12 节。

> **三点由此得出的实践结论**：
>
> 1. **不要用 `kind` 判断控件类型** —— 真机读不到。用**接口是否存在**
>    （`c.AddCursorEventListener ~= nil`）来判断，这也是体检里用的办法。
> 2. **基础模板索引不能实例化**：`cell.1.1.prefabIndex` 读出来是「预设按钮」的
>    基础模板（这台机器 `1073741848`），`InstantiateClientUIControl(1073741848, board)`
>    **返回 nil 且不报错**。
>
>    正确做法（2026-09-26 真机实测，**已修正**）：**右键【另存为模板】不行** ——
>    那个索引（`1073741864`）照样返回 nil。必须走：
>
>    ① 界面控件组管理 → 界面控件组库 → **客户端控件模板** →【添加客户端控件】→ 存为模板；
>    ② 新建一个「**模板引用控件**」去**引用**那张模板（**不能**用模板"新建控件"）；
>    ③ 读它的 **`referencedPrefabIndex`**（模板引用控件**只有这一个**自有字段；
>       `prefabIndex` 是基类字段 = **控件自身**的索引），填进 `cfg.cells.prefab`。
>
>    实测结果：`格子模板索引 1073741876 可用；缺 25 个格子，开始补建` /
>    `棋盘格子：25 / 25 存在（本次新建 25 个）`。
>    详见 `docs/真机-cell.1.1-逐步指南.md` 第 6 步与 `docs/本次搭建要求.md`。
> 3. **素材尺寸不重要，长宽比才重要** —— 因为总是铺满控件，长宽比不对就会被拉变形。
>    有圆角/边框的美术做成**九宫格**再选**拉伸**。

### 4.3 光标事件（**点击交互的唯一途径**）

`Enum.CursorEventType`：`CursorDown`（按下）`CursorUp`（抬起）`CursorEnter` `CursorExit`
`CursorDrag` `CursorBeginDrag` `CursorEndDrag` `CursorClick`（完成点击）

`CursorEventData`：字段 `dragging` `touchId`；方法 `GetUIPos()` `GetPressUIPos()` `GetUIPosDelta()`

> ⚠️ **官方没有"长按"事件**，只有 Down / Up / Click / Drag 四种。
> 本工程因此**不用长按**，改为「**单击 = 铅笔笔记 / 双击 = 放置**」：
> 适配层只把 `CursorClick` 转成框架事件，双击判定与"待定单击延后落地"
> 由 `ui_controller` 用 `OnUpdate(dt)` 累加的时钟完成（沙箱没有 `os` 库）。
> 好处：不必自造长按阈值，玩家也更容易知道"怎么才算放下"。

## 五、补间与信号（手感与联机的两块拼图）

### `Tween`

```lua
local t = game.Tween(ctrl, { localScaleX = 1.1, localScaleY = 1.1 }, 0.2)
t:SetEase(Enum.EaseType.xxx):SetRelative(false):SetLoops(1)
t:SetOnComplete(function() end)
t:Play()          -- Pause / Resume / Restart / Complete / Kill(complete)
```

- `Tweenable` 字段就是基类里那些位置/缩放/锚点/尺寸，以及控件的 `imageColor`、`fontColor`、
  `fontSize`、`bgColor`、`outlineColor`、`fillAmount`、`softEdgeWidth*` 等。

### `TweenSequence`（多步动画）

`Append(tween)` `AppendInterval(sec)` `AppendCallback(fn)` `Join(tween)` `Insert(time, tween)`
`InsertCallback(time, fn)` `Play/Pause/Resume/Restart/Complete/Kill` `SetOnComplete` `SetLoops`

### `ServerSignal`（与节点图/服务器通信）

```lua
local s = game.ServerSignal("murdoku/solved")
s:AddString("case_001"):AddInt(123)   -- 也支持 AddFloat/AddBool/AddIntList/StringList/BoolList/Vector3/Guid/Entity...
s:SendSignal()
```

- **参数要有序添加**（服务器侧按顺序取）→ 本工程约定用**数组**传参，见适配层。
- 收：`script:RegisterServerSignalHandler(name, function(sigName, params) ... end)`
- 服务器侧发送入口：服务器节点 **【发送客户端脚本信号】**。

## 六、对"局内存档"的影响（重要）

客户端脚本**没有**读写局内存档的接口，也没有本地持久化：
可用的是 `script:GetParam()`（编辑期配置的脚本变量）与 `game.GetGlobalCustomVariableValue`（**只读**）。

所以**存档必须走信号**：客户端 → `ServerSignal` → 服务器节点图 → 局内存档（写入）；
回来时服务器用【发送客户端脚本信号】把存档推给脚本 → 脚本 `decode_state` 还原。
本工程的 `Murdoku.save_now()` / `Murdoku.restore()` 就是这么接的。
