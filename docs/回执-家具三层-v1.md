## 3. 工具 `tools/gil/gen_obj_art.mjs`

### 用法

```bash
# 占位 palette（本次产物）
node tools/gil/gen_obj_art.mjs --in=494-教程teach-v298.gil \
  --out=495-一二关美术-obj3层.gil --palette=<palette.json>

# 只预测不写盘
node tools/gil/gen_obj_art.mjs --in=494-… --out=… --palette=… --dry

# palette 也可以用内联 JSON（值以 { 开头）
node tools/gil/gen_obj_art.mjs --in=494-… --out=… \
  --palette='{"table":{"id":100001,"color":"0xFF4A3524"}}'
```

### palette JSON 格式（本方案只给第 1 层）

```json
{
  "table":  {"id":100001,"color":"0xFFB07946"},
  "plant":  {"id":100001,"color":"0xFF4CAF50"},
  "carpet": {"id":100001,"color":"0xFFD9C8A6"},
  "chair":  {"id":100001,"color":"0xFFE0A040"},
  "shelf":  {"id":100001,"color":"0xFF7A5230"},
  "statue": {"id":100001,"color":"0xFFB8B8C0"}
}
```

- 键 = `kind`（**不是控件名**，别写 `obj.table`）；值 = `{id, color}` 或 `null`；**缺的 kind 不动**。
- 上面这个 JSON 是**占位 palette**（=`495` 用的，色 = `gen_things_obj` 当年的占位色）；**正式 palette（`496` 用的）见 §5**。
- 颜色一律写成 **`"0xAARRGGBB"` 8 位十六进制**（或 32 位整数），落盘为 32 位整数。
- 旧方案的数组形式（写 `things` 的 `obj2./obj3.`）已取消 ⇒ 传数组会**报错并说明**，不会静默写错。
- 写字段路径（与 `gen_palette.mjs` 的 `imgIdsOf` 同源，已实测）：
  `imageId = /505/503/84/#503`，`imageColor = /505/503/84/#502`。

### 两段写盘（为什么分两次 `writeGil`）

`diff_fields`/`writeGil` 的字段 diff 是**按位置**比的（E10）。如果"加 4 条记录"和"改调色板叶子"混在一次写里，
`expectDiffs` 就说不清"到底改了 N 个叶子还是 N+结构"。所以：

1. **第一段**：只加结构 ⇒ `expectRecs: 470`、`expectDiffs: 3`（1 处记录数组条数 488→492 + 2 处子列表 payload 70B→80B）；
2. **第二段**：只写调色板 ⇒ `expectDiffs: N`（由实际新旧值逐字段算出来；占位 palette 全同 ⇒ N=0，第二段不写、
   直接沿用第一段已由 `writeGil` 校验的文件）。

中间文件在系统临时目录，成功即删（不落仓库）。新记录**追加到 `g.recHolder` 末尾**（`gen_modal_art3.mjs`
的先例："新记录一律 holder.push()，零下标运算"），这样基线→输出的字段 diff 只剩可解释的 3 处结构差异；
**子控件次序**（谁盖谁）才是必须插对地方的 ⇒ 改的是 `content` 的子列表 ID 数组，`obj` 之后立即插 `obj2`、`obj3`。

### 幂等

- 已存在的层/控件跳过（不重复加）；palette 值相同不写。
- 实测：对 `495` 再跑一次（`--in=495`）⇒ "已存在、本次跳过 4 条"、+0 条、0 处差异，产出与 `495`
  **SHA256 完全相同**（`E6B3C1AE…4633`）。

## 7. 已知风险 / 边界

1. **号段只保证"与本文件不撞"**（E14）：`.gil` 只带当前关卡状态，编辑器工程侧的索引占用不一定在文件里。
   1073746000+ 段目前在本档完全空（基线 maxGuid=1073743994），且避开了被占过的 1074000000+。
   真机若仍报「控件 GUID 重复」⇒ 换号即可：`--guid-base=1073746100` 重跑，**别改结构**。
2. **两份 `content` 都改了**（E6）：若之后在编辑器里重新导出覆盖了模板，需要对新基线重跑本工具。
3. **新记录追加在记录数组末尾**（不是紧挨原型）：这是为了让"基线→输出"字段 diff 可审计（E10）；
   层级只由父指针 `#504` + 子列表决定，与记录在数组里的先后无关（仓内 `gen_modal_art3.mjs` 同款做法）。
   若编辑器出现异常表现，可改为"插在原型后面"再验证，但那样 `diff_fields` 会报大量位移差异（属预期）。
4. **layer2/3 的图/色/几何不在 `.gil`**：本工具只加空的 `obj2`/`obj3` 层（imageId=100001 占位、
   与 obj 重叠），运行时由 lua `cfg.obj_art` 的 layers 逐层 `SetImage` / 缩放。若 lua 侧没给
   layers，这两层会是白色/占位图 —— **需确认 lua v299 的 `cfg.obj_art` 已带 2/3 层**（lua 由 Lead 侧改）。
5. **palette 只支持对象形式**（旧数组形式已随方案取消，会明确报错）；`null`/缺 kind = 不动，
   所以正式 palette 若漏了某个 kind，那个家具会保留现在的占位色 —— 跑完看输出里"未提供 ⇒ 不动"那几行即可。
6. 占位 palette（`495`）的 id 全是 `100001`、色 = `gen_things_obj` 当年的占位色，**不是真实美术**；
   `495` 只用于结构对照，**交付用 `496`**（正式 palette：106053 圆角方板 / 100002 圆形 / 100001 矩形）。
7. `things` 的 6 个 `obj.<kind>` 图/色由 `--palette` 写；**lua `read_palette` 只收 `imageId > 0` 的控件**
   （v282 定案），所以正式 palette 的 id 必须是有效素材 id（>0），不能填 0。
8. **正式 palette 里的素材 id 是否已在用户工程素材表里**不在 `.gil` 的校验范围内（本工具只按 palette 写整数）；
   若编辑器里显示缺图，是素材 id 未导入/未解锁，不是本工具写错 —— 与 `495` 的结构对照 + `diff_fields 495 496`
   恰好 8 处即可区分"写错"与"素材问题"。
