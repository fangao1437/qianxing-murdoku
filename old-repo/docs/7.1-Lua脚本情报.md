## 0. 一句话结论

7.1（「月之八」）**确实在创作者体验服上线了「客户端控件与脚本」**，脚本能力包含
**输入、本地状态、补间动画、动画序列**，并通过**信号**与节点图/服务器交换数据；
但**截至调研时官方综合指南还没有脚本章节**，具体函数名/命名空间没有公开文档，
只能在 7.1 编辑器内的「帮助」文档里查到。因此本工程的 Lua 框架刻意做成了
「纯逻辑 + 单文件绑定层」，绑定层的钩子名留空待填。

## 4. 由上述事实推出的工程结论

1. **Lua 侧该干什么**：控件交互、本地状态、补间/动画序列、纯计算。
   本工程的规则引擎、线索判定、状态机、布局规格全部放在 Lua 侧，完全可行。
2. **Lua 侧不该硬扛什么**：多人同步、排行榜、成就、结算上报、云存档 ——
   这些官方有现成的**外围系统**（排行榜 `mho2rt9ir6ay`、成就 `mh65jrr2yj3i`、
   关卡结算 `mhx1du08nhwo`、局内存档 `mhzcw29qjjma`、奇域任务 `mhv1zh9x9nbe`），
   走节点图/外围系统比在 Lua 里造轮子稳。
3. **交付方式**：整套奇域可以用 `.gil` 存档导出/导入分发；
   你的关卡数据（本工程的 `levels/*.lua`）是纯文本，方便版本管理与批量改。
4. **风险与兜底**：函数名未知 → 绑定层 `M.API` 集中留空 + 能力探测 + 降级，
   `M.report()` 会打印"还缺哪些钩子"。7.1 正式上线后照编辑器内「帮助」文档把名字填上即可，
   上层逻辑一行都不用改。

## 5. 还没确认、你需要去编辑器里核对的点

- [ ] 脚本的**挂载位置**：是挂在客户端控件容器的脚本槽，还是独立脚本资产再被容器引用？
- [ ] 脚本的**生命周期回调名**：初始化 / 每帧 / 控件点击 / 容器显隐。
- [ ] 控件句柄的**获取方式**：按名字查找？按层级路径？还是拖引用？
- [ ] **信号** API 名与参数形态（本工程约定见 `M.SIGNALS`，可整体改名）。
- [ ] **本地状态**的读写 API；是否区分"本机"与"房间"作用域。
- [ ] 补间/动画序列的参数形态（属性名、时长、缓动枚举）。
- [ ] 是否允许脚本直接读改**场景实体**（控件以外的东西）。
- [ ] 脚本的**负载/性能预算**（风险检查功能 `mh0xm3ryh9hq`、负载计算 `mho2hirgodxi`）。

把答案填进 `lua/engine_adapter_qianxing.lua` 的 `M.API`，然后跑
`Murdoku.validate_all()` 与 `tests/selftest.lua` 即可验证。
