## 一 先定口径：什么才算「控件 GUID 重复」

编辑器报的那条，**只有一个原因**：**两条记录的"自身 GUID"相同**。而一条记录的自身 GUID 在 `.gil` 里存了**两处**：

| 位置 | 含义 |
|---|---|
| `/#501` | 自身 GUID（顶层） |
| `/#502/#11/#501` | 自身 GUID（实例表里那份，**编辑器校验读这里**） |

以下三类**不是**撞号，别拿它们的数量当判据（见 §三 E2）：

| 现象 | 为什么合法 |
|---|---|
| 同一个 id 出现在很多记录的 `/#504` | 那是**父指针**：N 个子指向同一个父，天然多对一 |
| 同一 id 出现在父的 `/#505/#503/#504/#4` | 那是**子列表**里登记的子 id，每个子一次 |
| `4294967295 / 16777215 / 858993459` 这类大数 | 那是**颜色常量**（0xFFFFFFFF / 0xFFFFFF / 0x33333333），根本不是 id |

> ★ 本工程 GUID 取值区间：`[1073741824, 1073800000)`；用它把颜色排除掉。

### 判定工具（★ 本轮新增，替代"数多属号"）

```bash
node tools/gil/probe_guid_collision.mjs <存档.gil> [--verbose]
# 退出码 0 = 干净；3 = 有真撞号（① 或 ②）
```

输出四段：① 真撞号（自身 GUID 重复，**这条才是编辑器报的**）② 自身 GUID 两处是否一致
③ 父子表一致性（子列表登记的都存在且父指针指回父）④ 悬空父指针（模板层常见，只提示）。

### 本轮实测（2026-10-21，**已按用户实机反馈修正口径**）

| 存档 | ① 顶层撞号 | ② 自身 GUID 两处 | 实机 | 结论 |
|---|---|---|---|---|
| `472-头像层-v283.gil` | ✅ **0** | 1 条 `hud.subtitle` | ★ **用户实机跑过、不报错** | ★ **干净**；② 那条**不是**编辑器判据 |
| `471-头像层-v283.gil` | ✅ 0 | 1 条（同上） | — | 干净 |
| `473 / 474-教程UI系统骨架-v1/v2` | ✅ **0** | ✅ | ★ 用户报「473 以后报错」 | ★ **文件本身没有撞号**（见 E11） |
| `475-教程UI系统骨架-v3.gil` | ✅ 0 | ✅ | 同上 | 文件本身干净 |
| ★ `477-教程UI骨架-独立号段.gil` | ✅ **0** | ✅ | 待验 | ★ **整份换到 1074000000+ 新号段** ⇒ 与主界面、与历史副本都不可能同号 |

> ★★ **两条重要更正**（都是被实机证据推翻的）：
> 1. `#502/#11/#501` 与 `#501` 不一致 **不是**编辑器判"GUID 重复"的依据 ——
>    `472` 就带着这一条，用户实机**不报错**。⇒ 探针里 ② 降级为提示，只有 ① 判 FAIL。
> 2. `473/474/475` 三个文件**内部都没有撞号**（顶层唯一、父子表一致、往返一致）⇒
>    用户在 473 之后看到的报错，**不是文件里的 GUID 同一性**，最可能是 E11（同一资产导入了多次）。

## 二 工具总览（按"你要干什么"分组）

### 2.1 只读探针（先跑这些，别急着写）

| 工具 | 用途 |
|---|---|
| `inspect_gil.mjs` | 总览：记录数 / 最大 id / 结构 |
| `list_names.mjs <gil> [过滤]` | **精确**列控件名（按记录解析，不用字节 Contains） |
| `probe_guid_collision.mjs` | ★ **GUID 撞号分类审计**（§一） |
| `_probe_dupids.mjs` | 顶层 id 重复（只看一处，**不够**） |
| `_probe_innergids.mjs` | 同一 id 被多条记录使用（**含三类合法情况，只看数量会误判**） |
| `_probe_childlists.mjs` / `_probe_flattable.mjs` / `_probe_idrefs.mjs` | 子列表 / 扁平表 / id 引用排查 |
| `_probe_select_geom.mjs` | 选关屏：父级 / 位置 / 尺寸 / 是否超出父级 |
| `_probe_texts.mjs` | 文本字段里到底存了什么（★ 控件名、颜色都在这） |
| `_probe_diffnames.mjs <A> <B>` | 两个存档的**名字差集**（插入/删除记录的安全比对） |
| `check_visible.mjs` | 初始可见性（存档里存隐藏的控件清单） |
| `roundtrip.mjs` | ★ 往返闸门：解析→重编码是否逐字节一致 |
| `diff_fields.mjs <A> <B>` | 字段级 diff（**按位置比**：有插入/删除时会连带报一堆，见 E10） |

### 2.2 写入类（全部走 `writeGil`，自带重读 + 往返 + 字段 diff 断言）

| 工具 | 用途 | 关键参数 |
|---|---|---|
| `embed_script.mjs` | 把 `dist/client_script.lua` 写进存档内嵌脚本字段 | `--expect-marker=vNNN`（★ 独立事实，不是"复制成功"） |

| `set_positions.mjs` / `set_button_rect.mjs` / `set_control_size.mjs` | 批量几何（★ 几何归编辑器后，慎用） | — |
| `reparent.mjs` / `move_child_order.mjs` / `reorder_children.mjs` | 改父子与同级次序（★ 次序在前景/背景两套里是反的） | — |

## 三 错误路径清单（每条都是我们真踩过的）

> 格式：**症状 → 真因 → 以后怎么做**。新工具/新文档里请沿用这套编号（E1…），便于相互引用。

### E1 ★ 克隆控件只改顶层 `#501` ⇒ 编辑器报「控件 GUID 重复」

- **症状**：编辑器报撞号，但按顶层 `#501` 查是 0 个重复。
- **真因**：自身 GUID 有**两处**（`/#501` 与 `/#502/#11/#501`），克隆时只改了第一处；
  有的克隆体还在 `/#505/#503/#504/#4` 带着母本号。
- **实证**：v259 的 `face → obj` / `tpl-container → things` 克隆；**本轮又抓到一次**
  `hud.title → hud.subtitle`（`472`/`471`：`#502/#11/#501` 仍是 `1073741923`）。
- **以后**：任何克隆**必须**跑 `remap_ids.mjs --names=<克隆体>`，再用 `probe_guid_collision` 收口。

### E2 ★ 拿"多属号数量"当判据 ⇒ 误判（473/474 就被误标成"撞号勿用"）

- **症状**：`_probe_innergids` 报 28（或 82、85…），看起来"没修干净"；其实干净。
- **真因**：那个数字混了父指针、子列表、颜色常量三类合法情况（§一）。
- **后果**：本轮实测 `473`/`474` 与干净的 `475` **数字完全相同（28）**，文件名里的
  "GUID撞号勿用"是**假警报**——差点让人白删重建一遍。
- **以后**：只用 `probe_guid_collision.mjs` 的 ① / ② 下结论；`_probe_innergids` 只当"有没有变化"的旁证。

### E3 ★ 整块替换 `#505` ⇒ 控件名变 null（`rebuild_things` 第一版）

- **症状**：重建后记录还在，但 `name == null`；`list_names` 少一个名字。
- **真因**：**控件名存在 `#505` 块里的 `#12 → #501` 文本**。把 `#505` 整组换成另一份
  （为了搬几何）会连名字一起换掉。
- **以后**：搬几何只写**第一块状态块**里的 `#504`（位置）/`#505`（尺寸）两个 pair，别换整块。

### E4 ★ 克隆"模板引用控件"当普通容器 ⇒ 每次加载多一份

- **症状**：`things` 每次运行都被"克隆一遍"（用户实测）；脚本里根本没有任何创建它的代码。
- **真因**：`things` 是克隆 `tpl-container`（模板引用控件）来的，组件表是 `1,2,4`，
  而真正的普通容器只有 `1` ⇒ 引擎把它当可实例化的东西。
- **以后**：
  1. **容器要用容器母本**（`assets` / `root` 这种组件 `== [1]` 的），不要用 `tpl-container`；
  2. 建完跑一次组件核对（`rebuild_things.mjs` 的断言就是这条）。

### E5 改 `tree[].parentId` 不生效

- **症状**：改了父子关系，进游戏没变。
- **真因**：加载器读的是 `root.children` 与**父记录里的子列表**（`#505/#503/...`），
  `tree[]` 只是派生摘要。
- **以后**：改父子 = ①改子记录 `#504` ②改父记录的子列表 ③（可选）同步 `tree[]` 让人看得懂。

### E6 同一原型有**两份**记录（模板层 / 场景层）⇒ 只改一份会被覆盖回去

- **症状**：改完在模拟器对、真机不对；或用户再导出一次又变回去。
- **真因**：`content` 子树等成对出现（一份顶层无父 = 运行时源，一份原型层级根下 = 编辑器看到的）。
- **以后**：写类工具**两份都改**，断言里逐个读回（`fix_cell_layers.mjs` 就是这么写的）。

### E7 只改磁盘 `.lua` 不同步内嵌源码 ⇒ 跑的还是旧代码

- **症状**：改了 `lua/*.lua` 但试玩行为没变。
- **真因**：存档里 `scripts[].source` 非空时**运行内嵌源码**，磁盘文件只是备份。
- **以后**：`bundle_client_script.lua` → `embed_script.mjs --expect-marker=vNNN`；
  标记号是**独立事实**，能证明"进去的是这一版"。

### E8 用"规划值"猜位置，而不是读存档 ⇒ 整块被拖走

- **症状**：四张选卡叠成一张；卡片"看不见了"。
- **真因**：v255/v256 给 `image`/`tint` 分支加的"贴格"钩子对**任何**带 rect 的控件都跑，
  卡片没有 `face` ⇒ `target` 落到卡片自己 ⇒ `SetAnchoredPosition(0,0)` ⇒ 全钉到父级中心。
- **以后**：位置类钩子**必须按 id 形态加闸门**（`^cell%.%d+%.%d+$`）；几何归编辑器。

### E9 用字节 `Contains` 找控件名 / imageId ⇒ 假命中

- **症状**：探针说"存档里有 `tray.A` ×5"，其实一张都没有。
- **真因**：短名是长名的前缀（`tray.A` ⊂ `tray.A1`…），字节搜索不认边界。
- **以后**：只信 `list_names.mjs` / `gilread.mjs` 的**记录级**解析。

### E10 记录数变了还用"diff 条数"判成败

- **症状**：加 4 条记录，`diff_fields` 报 3780 处差异，看起来全坏了。
- **真因**：`diff_fields` 是**按位置**比的，插入/删除会让后面全体位移。
- **以后**：新增/删除记录 → 用**记录数 + 结构断言**（子列表、父指针、名字、id）判定；
  `diff_fields` 只用于"只改几个值"的场景，并断言差异条数**恰好**等于预期。

### E11 ★★ 同一资产**导入多次** ⇒ 工程里两份同号（文件本身是干净的）

- **症状**：某份 `.gil` 单看完全干净（`probe_guid_collision` 全 0、往返一致），
  但导入编辑器后报「控件 GUID 重复」；换一个空工程导同一份就不报。
- **真因**：**上一份还留在工程里**。第二次导入的是同一批 GUID ⇒ 工程里两份同号。
  （`473`/`474`/`475` 三个文件内部都干净，却都在 473 之后报错 —— 与这条完全吻合。）
- **以后**：
  1. 同一个资产**只导一次**；要换版本先**把旧的整套删掉**再导；
  2. 或者把新版**整份换号**再导（这样即使旧副本还在也不会撞）：
     ```bash
     node tools/gil/renumber_all.mjs --in=存档/475-教程UI系统骨架-v3.gil \
       --out=477-教程UI骨架-独立号段.gil --base=1074000000
     ```
     ★ 新号段必须落在 `[1073741824, 1074200000)` 里（读档器/引擎认的窗口），
     且**画布头 1073741825–1073741842 与引擎内置模板索引（1073741848 / 1073741864 / 1073742014 / 1073742015）不能改**。
- **本轮产物**：`477-教程UI骨架-独立号段.gil`（63 条记录、自身 GUID 63 个唯一、与主档 `472` 零交集、
  父子表一致、往返逐字节一致）—— 这份**即使旧副本还在工程里也不会撞号**。

### E12 ★★ 把**别的存档**的记录整段搬进主档 ⇒ 反复被编辑器挡下（v286 的真因）

- **症状**：目标文件"内部完全干净"（撞号 0、自身 GUID 一致、父子表一致、往返一致），
  但实机导入/试玩仍报「界面控件设置错误 / 界面控件里的开关控件GUID重复:<我方某个号>」；
  **换号段也没用**（1074000000 → 1074199900 换了三次仍然报）。
- **真因（本轮判断）**：并入的记录**来自另一套工程形态**（教程资产 `.gia` 解码出来的独立存档）。
  记录里的组件块 / 状态块 / 引用关系是那个工程长出来的；编辑器在"界面控件"这一层重建时，
  会把它们当成"又一个同号控件"。⇒ 这类失败**不在号上，在记录来源上**。
- **实证**：`472`（全部记录本工程原生）实机正常；`473`–`481`（并入外来记录）连续失败；
  `479` 相对 `472` 的差异只有"多了 43 条记录 + `root` 子列表长 5 字节"（字段 diff 2 处）。
- **以后**：★ **新控件一律"从本档母本克隆"**，只写"号 / 名字 / 父级 / 几何"。
  合档工具：`tools/gil/gen_tutorial_native.mjs`（断言"新记录内部只允许自己/父/子的号"）。
  要并入外来记录前，先问一句：**这条记录的组件形态，本工程里有同款母本吗？** 没有就别并。

### E13 ★ 用"文本猜控件类型" ⇒ 认错类型 / 改错名字

- **症状**：以为某条记录的"类型名"被改坏了（例如 `tut.全屏界面动效`），或者把默认名当成类型名。
- **真因**：类型**不是**记录里的短文本；`gilread.mjs` 的 `KNOWN_TYPES` 只用来判"哪个短文本是实例名"，
  名字其实是"组件 `#501=2` → `#12` → `#501` 的文本"（默认名常常就是类型名，看着像类型而已）。
  真正区分类型的是**组件指纹** = 记录顶层各 `#505` 组件块的 `#501` 值集合：
  容器 `1.2.4.63.67.68`、按钮 `1.2.4.63.67.70`、文本 `1.2.4.63.64.67`、图片 `1.2.4.63.67.73.74`、
  全屏动效 `1.2.4.63.67.76`。
- **以后**：认类型用指纹（`_work/gilx/sig.mjs` 的思路），改名字只改"组件 `#501=2` 里那段文本"。

### E14 ★ 号段：文件里的"空档" ≠ 编辑器没占用的号

- **症状**：明明挑的是 `472` 里的空档（例如 1073742041 落在一个 176 宽的洞里），实机仍报撞号。
- **真因**：`.gil` 只带**当前关卡的状态**；编辑器侧的索引占用（历史分配、其它界面布局/控件组的登记）
  不一定在文件里。⇒ 只能保证"与本档不撞"，不能保证"与编辑器全工程不撞"。
- **以后**：
  1. 先用 `gen_tutorial_native --dry` 让它自己断言"与基线全档零交集"；
  2. 号段挑**基线最大 id 之上的第一段空档**（现在 = `1073742811` 起）；
  3. 真机若仍报撞号，**换号只要一条命令**：`--id-base=<新起点>`，别改结构；
  4. 1074000000+ 段已被证明被编辑器自己占用（479 的 `1074000025`），默认避开。

## 四 标准作业流程（SOP，改存档一律照这个走）
```
1) 只读体检：inspect_gil → probe_guid_collision → list_names/<专项 probe>
2) 写工具：默认 --dry；先备份；只做一件事；能断言就断言
3) 落盘：writeGil（自带重读 + 往返 + 字段 diff + expectRecs）
4) 收口：probe_guid_collision（① ② 必须 0）+ roundtrip + 名字对账
5) 交付：embed_script --expect-marker → 再跑一次 4)
6) 回归：离线 tests（当前基线 34 套）→ 需要时模拟器 → 真机
```

★ 三条硬规矩：

1. **克隆必 remap**（E1）；
2. **断言必读回**（不看"工具返回成功"，不看"往返字节相等"当生效证明）；
3. **数字变了不等于坏、数字没变不等于好**（E2/E10）。
