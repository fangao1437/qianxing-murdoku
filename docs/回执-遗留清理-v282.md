## 二 逐条判据（怎么验的）

### 1–3 死码

| 项 | 判据 |
|---|---|
| 1 `pending_click` | 全仓 `grep pending_click`：删前只剩"置 nil"与注释；`flush_pending_note` 的首行是 `if p == nil then return end` ⇒ 永不执行。它还是 v279 那个"一次按键两次 `tap_cell`"的元凶。删后全量 35 套 0 失败 |
| 2 橡皮擦长按 | 两条不变量：`set_mode(ERASE)` 会 `selected = nil`；`select_suspect(id)` 在 ERASE 下会把模式切回 PLACE ⇒ `mode==eraser` ⇒ `selected==nil` ⇒ `hold_cell` 上一行就 return。**新增 `tests/rule_guards.lua` R5（6 条断言）钉住这个不变量本身**，以后谁改联动立刻红。`Core:clear_all()` 本体保留（`tests/gray_unplace.lua` 在用） |
| 3 share 双分支 | 前一支**只有注释没有代码**（空支），后一支才是渲染。`selene` 唯一的 `Error`（`ifs_same_cond`）报的就是它。合并后 share 弹窗仍可被"别处构造"渲染出来（链路保留），只是不再有"点不出东西"的雷 |

### 4–5 调色板

| 项 | 判据 |
|---|---|
| 4 `id <= 0` | `type(0) == "number"` 为真 ⇒ 旧代码把"图还没配"的控件收进调色板，`SetImage(src, 0)` = 没图；而且 `cfg.obj_art` 因"键已存在"被跳过 ⇒ **配了脚本素材也不生效、完全静默**。用例 `things_wiring §⑧.1`：`obj.table` 的 `imageId=0` ⇒ 必须回落到 `cfg.obj_art` 的 100001 |
| 5 空调色板 | 与 v281 那个 bug 同一族（**首帧读太早**）。用例 `§⑧.2`：树里暂时没有 `things/assets` ⇒ 空表**不缓存**；素材区就绪后能读到 |

### 6 `SYNC_STATE`

服务端同步来的动作以前 `select_suspect` / `tap_cell` 两个返回值都丢掉 ⇒ 被规则拒绝（越界/已有人/障碍格/同行同列）时玩家与服务端都只看到"盘面没变"。现在拒绝原因走同一个 `_refuse` 出口（自带同类去重，最多 3 条）。

### 7 PERF-1 注释

旧注释原文：「**触发**：`_cells_paint` 由 L2071 每帧调用」。事实：它只在 `create_control` / `ensure_cells` 里被调，**没有每帧调用者**。v280 照这句把家具重放挂上去 ⇒ 离线全绿、真机无效（用例自己手动调了那个函数，替被测代码补了关键一步）。现在注释写清三处字段的真实位置，并把这条教训写进 `技术架构.md` §7.6。

### 8–9 工具与标记

- `bump_build_marker.mjs`：新正则以 **Lua 引号**收尾说明（不再要求尾部 `=====`），写回时把可能存在的尾巴**原样保留**；「标记必须存在」这条**没有放松**（整行对不上仍 exit 1）。我这边实测：`--check` 前后从 exit 1（复现 bug）到 **exit 0**；并用它自己把标记 v281 → **v282**（dogfood）。
- 标记行：v240→v270 之间"版本说明"越写越长（单行 ≈4.5KB），既让解析脆，也让真机日志首行淹没在历史里。已搬到 `docs/构建标记历史.md`（14 段，原文逐字），标记行现在 **266 字符**。

### 10–13 编码与仓储

- `powershell -File tools\normalize_encoding.ps1` → fixed 2（`docs/回执-门墙居中格线-v265.md`、`tests/edge_center.lua`）；`-Check` → **all files OK**。
- 另外 **9 个 `.mjs`** 的 BOM 由我逐字节剥（`copy_state_floats.mjs` + `tools/sim/_*.mjs` ×8），`check_encoding` 从 13 项 → **✓ 全过（760 文件）**。8 个 `_*.mjs` 剥完 `node --check` 全部通过。
- `tools/_wip/`：删掉 14 个一次性产物（`base_v27*.gil`、`out_v27*.gil`、`lua53.out.txt`、`append_*.mjs`、`v28*-*.md`）＋ 我自己那几个临时脚本。

## 三 明确**不动**的（附判据，免得下一轮重新纠结）

| # | 项 | 为什么不动 |
|---|---|---|
| A | **关卡内 toast 没有出口** | 是**产品缺口**不是 bug：`hud.toast` / `hud.subtitle` 已按美术结论删除，要补得**新开控件位**（编辑器建控件 + plan + `check_names`），不是清理任务 |
| B | **模拟器不实例化 `cell.*`** | 平台能力缺口（无"可实例化的客户端控件模板"）⇒ 环境差异，写进真机清单 |
| C | **`tools/gil/copy_state_floats.mjs` 在 HEAD 就是坏的** | 它的中文注释是一整片 mojibake，**乱码把换行和引号吃掉了** ⇒ 5 处语法损坏（`// … function floats_(blk) {`、`console.error('…` 引号失踪…）。我试过按行修，发现是"整个文件被 GBK 管线写过一次"，逐字恢复等于重写并反推原文 ⇒ **超出机械清理范围**。本轮只做了 gate 要求的"剥 BOM"（与 HEAD 的差异**只有 BOM 那 1 行**，`git diff` 可验）。**它本来就跑不了，不是本轮造成的**（HEAD 版本 `node --check` 同样失败）。建议：以后单独一轮按用途重写（输入/输出契约看 `--help` 段注释与调用处） |
| D | **`note`/`x`/`hint` 的意图重放** | 与 v281 同族，但开局为空 ⇒ 无症状、无真机证据。扩展点写在 `回执-首关家具不画-v281.md` §六。**先有症状再动** |
| E | **`tools/lua53check/node_modules/**` 约 130 个文件被入库** | 与 selene 报告同类（`node_modules/` 规则管不到已入库文件）。但它是**依赖副本**，摘索引需要一次专门操作 + 确认离线环境仍能跑 `lua53check` ⇒ 单独立项 |
| F | **大量注释里的旧行号** | 只改了**行为性**的那几条（"每帧调用"这类会误导修法的）。纯行号引用不影响执行，且每轮都在漂，机械重编成本不划算 |
