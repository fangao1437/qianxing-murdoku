## §1 日志定位到的真因（v312 为什么一件家具都没实例化）

关键三行：
```
[murdoku] 模板化家具：关卡=true（实例缓存已清）          ← furn_level 到了，且 =true
[murdoku] 属性补发 3 次仍未送达，已停止补发：`cell.1.1.furn_tpl`（…）
（此后没有任何一条 "家具模板：cell=…" 成功/失败日志）
```
- cell 的 `furn_tpl / furn_span / furn_offset` **先于** root 的 `furn_level` 送达；
- 当时适配层 `_furn_tpl_ok` 还是 nil ⇒ 三个分支都返回 **false**；
- 通用"属性补发"机制把 false 当"没送达"，**重试 3 次后丢弃**；
- 等 `furn_level` 到了，这些属性已经没人再发 ⇒ **永远不实例化**。

## §2 v313 修法（三处）

| # | 改动 | 作用 |
|---|---|---|
| ① | `furn_tpl/span/offset` 分支**一律返回 true**（"已受理"），值先缓存 | 不再触发补发/丢弃，**不依赖投递顺序** |
| ② | 新增 `_furn_try_all()`：`furn_level` 置真后，按缓存把"该有家具的格子"**统一补造一遍** | 属性先到后到都能收敛 |
| ③ | `furn_tpl == false`（该格没家具 / 切关旧值）时**销毁**该格缓存实例 | 切关不残留上一关家具 |
| ④ | `furn`（手搭层）分支：只要 cfg 配了模板表就**一律跳过绘制** | 避免"先画手搭、模板后叠上来"的两代同屏（第二关异常可能与此有关） |

## §3 离线验证（不花真机时间）

用 `_work/art-work/probe_tpl_instantiate.lua` 复现真机投递顺序：

- 结果：cell 属性 → `true`（缓存）；furn_level 到达 → 自动补造：
```

[murdoku] 模板化家具：本轮补造 1 格（缓存里共 1 格有家具）
```
⇒ 顺序问题已消除。
