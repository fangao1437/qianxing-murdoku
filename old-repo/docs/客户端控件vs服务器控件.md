# 客户端控件 vs 服务器控件（**外部资产图片只能走服务器控件**）

> 2026-10-03 由用户纠正后补写的。**这一天我在同一个坑里栽了三次**，把它写清楚，别再犯。

## 一、官方定义（原文）

> 除**客户端控件容器画布中的客户端控件**以及**客户端控件模板中的控件**外，
> 其他控件均为**服务器控件**，**服务器控件的模板索引无法被客户端脚本调用**。
> —— 《客户端控件和客户端脚本的定义》

## 二、两类东西怎么认

| | **客户端控件** | **服务器控件** |
|---|---|---|
| **怎么创建** | 界面控件组管理 → 界面控件组库 → **客户端控件模板** → 添加客户端控件 → 存为模板 | 直接在**界面布局**里摆；或右键控件 → **另存为模板** |
| **挂在哪** | **必须放在「客户端控件容器」内**（容器本身是服务器控件） | 布局树里任意位置 |
| **脚本能否按索引实例化** | ✅ **能**（`game.InstantiateClientUIControl(索引, 父控件)`） | ❌ **不能**（官方明说调不动） |
| **本项目实例** | **格子模板 `1073741876`** —— 真机日志「模板索引 1073741876 验证通过（试造成功）」 | **`m` 的 `1073742380`**、历史上的 `1073741864`、`murdoku-btn-hex` 的 `1073742333`、**`1073742356`** |

## 二·五、★★★ **「另存为模板」的判定规则（2026-10-03 用户实测总结）**

> 用户原话：
> **「其实另存为模板不会影响客户端模板的创建，现在我理解了，关键是要在**客户端控件里面**另存，
> 直接在 root 下另存会被默认创建为**服务器控件**，所以官方才给了一条不会出错的路径」**

**⇒ 也就是说，右键「另存为模板」本身没问题，出问题的是**你在哪一层另存****：

| 你在哪另存 | 得到 | 实测结果 |
|---|---|---|
| **在「客户端控件容器」里面**选中控件 → 另存为模板 | **客户端控件模板** | ✅ 能被脚本实例化 |
| **在 `root` 下**（普通布局树）→ 另存为模板 | **服务器控件模板** | ❌ `InstantiateClientUIControl` 返回 **nil** |

**⇒ 这条规则把本项目**每一次失败**都对上了**：

| 索引 | 怎么来的 | 实测 |
|---|---|---|
| **格子 `1073741876`** | **在客户端控件容器里做的** | ✅ **25/25 建成功** |
| **`m` 的 `1073742380`** | **在 root 下另存** | ❌ **nil** |
| **`1073742356`**（用户后来新建的那个）| **在 root 下另存** | ❌ **nil**（日志 `err=nil`）|
| **`1073742321` / `1073742333`** | **素材记录**（不是模板）| ❌ **nil** |

**⇒ 官方给「界面控件组管理 → 界面控件组库 → **客户端控件模板** →【添加客户端控件】」这条路，
就是为了**保证你在客户端那一侧创建** —— 不用你去记"我这一层是客户端还是服务器"。**

**⇒ 反过来也说明**：**只要入口选对，模板怎么建都行**（新建、另存、克隆都可以）；
**入口选错（在 root 下另存），再干净的空壳模板也没用。**


## 三、★ 由此得出的**硬结论**

1. **外部资产的图片**（我们转存的 `murdoku-btn-hex` 等）
   ⇒ **只能在服务器控件上显示** ⇒ **必须在编辑器里摆**，脚本生成不了。
2. **`InstantiateClientUIControl(服务器控件的索引, …)` 一定返回 `nil`**
   —— 真机实测过三次：`1073742321`、`1073742333`、预期中的 `1073742380`。
3. **脚本能管的只有"客户端控件"那一套**（客户端控件容器里的、以及客户端控件模板实例化出来的），
   本项目里 = **棋盘格子**、以及**脚本当场创建的那些按钮/文本**。

## 五、那"图片底图"这件事到底该怎么做

**⇒ 只能在编辑器里摆**（每个位置一个服务器控件）：

```
1. 在编辑器里放一个「图片」控件（或任何能设图片的服务器控件）
2. 图片 → 静态引用 → 选中导入的资产（例如 murdoku-btn-hex）
3. 调整它的位置/尺寸 —— ⚠️ **尺寸在这一步就定死了**（用户实测第 ① 条）
4. 它**必须放在客户端容器之外**（用户实测第 ② 条）
```

**⇒ 需要几个就摆几个**（按钮 3 个就摆 3 个），**分别命名**（例如 `hex.back` / `hex.redo` / `hex.hint`），
脚本**不去创建它们**，只负责按屏显隐（`SetVisible`）和摆位置 —— **这两件事对服务器控件是有效的**。

## 六、摆放清单（脚本会按这些名字去认）

| 控件名 | 用途 | 建议位置（画布 1600×900，Y 向上） |
|---|---|---|
| `hex.back` | 「返回列表」的六边形底图 | 盖在 `action.back` 上 |
| `hex.redo` | 「重置关卡」的六边形底图 | 盖在 `action.redo` 上 |
| `hex.hint` | 「放大镜」的六边形底图 | 盖在 `action.hint` 上 |
