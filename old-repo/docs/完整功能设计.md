## 二、四个问题的根因（都已定位到代码）

### 问题 2 与 4 是**同一个根因**：调色板不存在 → 所有换图静默失效

**证据链**：

1. 落子时脚本发的是**素材名**（不是数字 ID）：
   `ui_controller` → `image = portrait_of(...) or cd.object`
2. 适配器换图前必须解析这个名字：
   ```lua
   function Adapter:resolve_asset(value)
     local n = tonumber(value)
     if n ~= nil then return { source = nil, id = n } end   -- 数字：直接用
     local map = self:read_palette()                        -- 否则查调色板
     local hit = map[tostring(value)]
     if hit ~= nil then return hit end
     self:warn_once("asset:missing:"…, "调色板里没有素材「…」")   -- ← 查不到就 return nil
     return nil
   end
   ```
3. **调色板的来源是编辑器里一个叫 `assets` 的容器**（里面每个素材放一个图片控件，控件名 = 引用键）。
   **我们生成的界面里没有这个容器** → 调色板是空的。

⇒ **每一个"按名字换图"的调用都解析失败 → 图片一张都不换。**

而**放置**走的正是这条路：换了名字解析不出来，`face` 保持默认图不变，所以**看起来毫无反馈**（缩放动效太轻，几乎注意不到）。

**这是一个"沉默失败"** —— 代码里有 `warn_once`，但当前日志里没看到，说明连这条路都没走到或已被去重。**修完后我会加一条"本局共换图 N 次 / 失败 M 次"的汇总行**，避免再出现沉默失败。

**修法（两条路，见第四节）**：
- **A. 生成调色板容器**：我在 `.gil` 里生成一个 `assets` 容器，每个素材一个图片控件，图与 ID 由你给我（或我在编辑器素材库里挑）
- **B. 关卡数据直接用整数 ID**：绕开调色板。缺点是 ID 只能手抄，不推荐

### 问题 1：双击有时让格子"消失" —— 是**多出来的那一次点击 + vanish 动效**

**证据链**：

1. 双击的判定是"两次点击落在同一格且间隔 ≤ `DOUBLE_CLICK_SECONDS`"：
   ```lua
   if (not occupied) and mode == "place" then
     if last and last.r == r and last.c == c and (now - last.t) <= DOUBLE_CLICK_SECONDS then
       self:do_place(r, c); return
     end
     self.last_click = { r = r, c = c, t = now }
   end
   ```
2. **放置之后格子变成"已占"**，而"已占格"的单击是**立即生效**的：
   ```lua
   if occupied or mode == "x" or mode == "eraser" or mode == "note" then
     local ok, why = core:tap_cell(r, c)          -- 已占格 → 拿起棋子
     if ok then self:fx(self:cell_id(r, c), M.EFFECTS.ERASE) end   -- ← 注意这里
   ```
3. `ERASE = "vanish"`，而动效定义是 **`vanish`：缩放 1.00 → **0.00****
   ```lua
   vanish = { dur = 0.20, ease = "InQuad", ch = "scale",
              keys = { { 0.00, 1.00 }, { 1.00, 0.00 } } },
   ```
   适配器里有一句注释恰好印证这个坑：
   > 「动完把姿态还原（**vanish 那种会缩到 0，不还原下次就"消失"了**）」

⇒ **双击 → 放置成功；若系统多派发一次点击（或玩家手抖连点三下），那一次落在"已占格"上 → 拿起棋子 + 把整个格子缩到 0 → 看上去"格子消失了"。**

**修法**：
- `erases` 动效**不要作用在格子本身**，改成作用在 `face` 子控件上（或换成不缩到 0 的动效）
- 放置后加一个**短的"防重入窗口"**，窗口内的同格点击忽略
- 还原姿态时**强制写回 scale=1**（不依赖动效结束回调）

### 问题 3：X 标记"出现"仍有 bug —— 需要你的具体现象

**我查到的事实**（链路本身是通的）：
- 数据层：`view()` 里 `x = self.x_marks[r][c] == true`，**每格都发**（不会漏）
- 界面层：`ui_controller:963` → `x_mark = cd.x`
- 适配器：`elseif key == "x_mark" then local c = self:sub(id,"x"); c:SetVisible(value and true or false)`
- 层级：`layer_order` 里 `x` 在 `wall.*`/`door.*` **之上**、`note` 之下

**所以链路是通的，bug 在细节**。我列几种可能，**请你在旁边标一下是哪种**：

| # | 现象 | 我的猜测 |
|---|---|---|
| a | X 该消失时不消失（取消 X 后还在） | 增量渲染没把 `x_mark=false` 推下去 |
| b | X 出现在**不该出现**的格子上 | 索引错位（行列颠倒？） |
| c | X 出现了但**看不清**（太小/被挡） | `x` 的图是 `imageType=Basic`（**按原始像素画**，不填充）→ 图比格子小 |
| d | 双击/X 工具切换后 X 行为不一致 | `set_mode` 里 `MODE_X` 会清 `selected`，交互耦合 |

> **c 有强证据**：日志里 `x` 是 `imageType=Enum.ImageType.Basic imageId=100101`，而 `face` 是 `Stretch`。
> **Basic = 按素材原始尺寸画，不填充控件** —— 所以 X 的图很可能**只占格子一小块**。这条我已经有把握。
