# 脚本侧检查 —— 教程控件（`tut.*`）运行期自检 · 2026-10-21

> 一句话：`lua/tut_verify.lua` 在运行期把「教程控件树应该长什么样」逐条核对，
> 用**一行 `[tut] 自检 …` 日志**喊出结论。**只读、零创建**（不建/不改任何控件），
> 离线测试在 `tests/tut_verify.lua`（42 断言全绿）。
>
> 本轮只新增三个文件，**没动** `lua/tutorial_ui.lua` / `entry_client_script.lua` /
> `bundle_client_script.lua` / `tests/tutorial_ui.lua` / 存档 —— 接线按 §六 三步由 Lead 执行。

## 一 它治的是哪几种"静默失败"

| # | 失败形态 | 玩家侧症状（以前） | 自检现在会说 |
|---|---|---|---|
| 1 | 控件**没进树** | `find` 拿到 nil ⇒ pcall 降级 ⇒ 少一块 / 全空 | `[tut] 自检 FAIL 1 项: tut.btn.close=缺失` |
| 2 | **重名**（同名多条，编辑器报「开关控件GUID重复」同源） | `find` 取到哪一条看遍历顺序 ⇒ 表现飘 | `…: tut.btn.close=重名(2 条)` |
| 3 | **父级挂错** | 控件在，被父级的 0×0 / 隐藏 / 裁剪吃掉 | `…: tut.hud.title=父不对(期望 tut.screen.demo 实际 tut.page.p1)` |
| 4 | **尺寸 0**（477 骨架把整片教程裁没的那个坑） | 界面在、就是画不出来 | `…: tut.app.root=尺寸 0(0x900)` |
| 5 | 尺寸**小于下限**（可选判据） | 文字挤没 / 只露半块 | `…: tut.page.p1=尺寸不足(120x40 < 1200x600)` |
| 6 | **该显示却没显示** | `open_ui()` 调过了，画面还是空 | `…: tut.screen.demo=不可见` |
| 7 | 控件自己可见但**祖先被关** | 同上（本项目"主页整个消失"就是这一层） | `…: tut.btn.close=不可见(祖先 tut.app.root 隐藏)` |

反向的两条也钉着：**该藏没藏**只是警告；**读不到接口**（没有 `visible` / `GetSizeDelta`）
只警告不判红 —— 不同控件类型暴露的字段不一样，凭这个报错会变成假警报。

## 二 模块 API

文件：`lua/tut_verify.lua`（Lua 5.3 语法；不 require、不用 io/os/debug、不读 `game`）

```lua
local TutVerify = require("tut_verify")

TutVerify.VERSION            -- "v1-2026-10-21"
TutVerify.TUTORIAL_EXPECT    -- 内置期望清单（14 条 tut.*），§五
TutVerify.run(opts)  -> res  -- 纯计算：不打日志、不产生副作用
TutVerify.log(res)   -> line -- 打**一行**结论（print），返回这行原文
TutVerify.check(opts)-> res  -- run + log；有警告时再补一行"警告 N 条"
```

### `opts`（注入）

```lua
{
  find   = function(name) -> ctrl|nil,      -- 必填。也接受"带 :find(name) 的对象"，例如适配器
  all    = function(name) -> {ctrl, ...},    -- 可选。同名**全部**控件（判重名最准，能报精确条数）
  roots  = function() -> {root, ...},        -- 可选。客户端控件树根表；没给 all 时用它自己走树数名字
  expect = { { name = ..., parent = ..., visible = ..., min_size = ... }, ... },
                                             -- 可选。**省略 ⇒ 用内置 TUTORIAL_EXPECT**
}
```

三种注入能力的关系（判重名用）：`all`（最准）> `roots`（自己走全树）> 只给 `find`
（只剩"查同级"兜底，并会打一条 `(配置)=重名只查同级` 警告 —— 不静默降级）。

### `expect` 条目（除 `name` 都可选）

| 字段 | 类型 | 语义 |
|---|---|---|
| `name` | string | 控件名，**必须与存档逐字一致** |
| `parent` | string | 期望父控件名（比对 `ctrl.parent` 字段 / `ctrl:GetParent()` 的 `name`） |
| `visible` | boolean | `true` ⇒ 必须可见（含祖先链）；`false` ⇒ 必须隐藏（不满足只算警告） |
| `min_size` | number 或 `{w=,h=}` | 最小尺寸下限（不写也照样查"尺寸 0"） |

### `res`

```lua
{
  ok      = boolean,                    -- 没有 error 就 true（警告不影响）
  errors  = { { name=, kind=, text= }, ... },   -- 每条都带控件名，text 就是日志片段
  warnings= { { name=, kind=, text= }, ... },
  found   = number,                     -- 找得到的期望条目数（重名也算找到）
  total   = number,                     -- 期望清单条目数
}
```

**空清单 / 没注入 `find` 都判红**（`kind="配置错误"`）—— `0/0 的绿`是假绿，自检最忌讳报平安。

## 三 注入方式示例

### 3.1 真机（适配器就是 `find` 能力）

```lua
local TutVerify = require("tut_verify")

pcall(TutVerify.check, {
  find  = adapter,                                       -- 适配器自带 find(name)
  roots = function() return game.GetClientUIRoots() end,  -- 判重名时走全树
  -- expect 省略 ⇒ 用内置的 14 条 TUTORIAL_EXPECT
})
```

> 也支持写成 `find = function(name) return adapter:find(name) end`（普通函数形态），两者等价。
> `roots` 不注入也能跑：`tut.*` 的重名如果只是**同级两份**，靠 `find` 兜底也能抓到（会附警告）。

### 3.2 离线（假树，`tests/tut_verify.lua` 的做法）

```lua
local finder = {}
function finder:find(name)  return find_in(self._root, name) end   -- 假树的 DFS
function finder:all(name)   return all_in(self._root, name) end
function finder:roots()     return { self._root } end

local res = TutVerify.run({ find = finder, all = finder, expect = MINI_EXPECT })
```

## 四 日志格式（只用 `print`，一行）

通过（`found/total`）：

```
[tut] 自检 OK 14/14
```

失败（`N 项` = error 条数；一条 = 一个判据，同一控件可能同时报两条）：

```
[tut] 自检 FAIL 3 项: tut.btn.close=缺失; tut.hud.title=父不对(期望 tut.screen.demo 实际 tut.page.p1); tut.app.root=尺寸 0(0x900)
```

* 最多列 **8** 条，再多就追加 `…另有 N 项`（真机日志一行太长会被截断）；
* 细节里的换行会被压成空格、超过 80 字截断并加 `…` —— **保证结论永远在一行里**；
* 警告不判红，由 `check` 单独打一行（最多列 3 条）：
  `[tut] 自检 警告 1 条: (配置)=重名只查同级(注入 all(名)->列表 或 roots()->根表 才能查全树的重名)`

## 五 内置清单 `TUTORIAL_EXPECT`（14 条）

| 控件 | 期望父 | 条数 |
|---|---|---|
| `tut.app.root` | `root` | 1 |
| `tut.screen.demo` | `tut.app.root` | 1 |
| `tut.hud.title` / `tut.hud.pager` | `tut.screen.demo` | 2 |
| `tut.tab.p1` / `p2` / `p3` | `tut.screen.demo` | 3 |
| `tut.btn.prev` / `next` / `reset` / `close` | `tut.screen.demo` | 4 |
| `tut.page.p1` / `p2` / `p3` | `tut.screen.demo` | 3 |

来源（两个独立来源互相对上了）：

1. `lua/tutorial_ui.lua` 头部那张控件表 —— 模块实际按这些名字取控件；
2. 存档记录：`node tools/gil/ancestry.mjs 481-教程UI并入-v285.gil tut.app.root tut.screen.demo …`
   ⇒ 14 条名字全在，`parentId` 指向的父记录名与上表一致（`tut.app.root` 的父 = `root`，其余 = `tut.screen.demo`）。

**故意不写 `visible` / `min_size`**：显隐随运行时状态（open/close/翻页/页签选中态）变；
尺寸以编辑器实测为准，写死会在换画布/换分辨率时变成假警报。要加就在调用处传自己的清单。

### 第 2 步：entry 接线（`lua/entry_client_script.lua` 922–946 行整段替换）

`tick_tutorial` 现在是这样（922–946 行）：模块懒加载 → `init` → 开局弹一次。
把 **922–946 行**整段换成下面这版（只多了自检：一个一次开关 + 一个兜底计数 + 一个本地函数）：

```lua
local tutorial = nil
local tutorial_opened_once = false
local tutorial_verified = false      -- ★ 教程控件自检只跑一次
local tutorial_wait = 0              -- ★ init 还没成功时的帧计数（自检兜底）

-- ★ 2026-10-21 教程控件自检：只读、不创建控件；失败也只打一行日志，不影响玩法。
--   `tut_verify` 的清单就是存档里那 14 个 `tut.*`（见 docs/脚本侧检查-教程控件-2026-10-21.md）。
local function verify_tutorial_once()
  if tutorial_verified then return end
  tutorial_verified = true
  local okv, mod = pcall(require, "tut_verify")
  if not okv or type(mod) ~= "table" or type(mod.check) ~= "function" then
    if printerr then printerr("[murdoku] 教程自检模块没加载上：" .. tostring(mod)) end
    return
  end
  pcall(mod.check, {
    find  = adapter,                                       -- 适配器本身就是 find(name)
    roots = function() return game.GetClientUIRoots() end,  -- 判重名时走全树
    -- expect 省略 ⇒ 用模块内置的 TUTORIAL_EXPECT（14 条 tut.*）
  })
end

local function tick_tutorial()
  if adapter == nil then return end
  if tutorial == nil then
    local ok, mod = pcall(require, "tutorial_ui")
    if not ok or type(mod) ~= "table" or type(mod.new) ~= "function" then
      if printerr then printerr("[murdoku] 教程模块没加载上：" .. tostring(mod)) end
      tutorial = false          -- 用 false 记"试过了"，避免每帧重试刷屏
      return
    end
    tutorial = mod.new(adapter)
    if Murdoku ~= nil then Murdoku.tutorial = tutorial end
  end
  if tutorial == false then return end
  if not tutorial.inited then
    tutorial:init()             -- 控件没进树时自己会早退，下一帧再来
    if not tutorial.inited then
      -- ★ init 一直起不来（最典型：根容器压根没进树）也要喊一次 —— 原来这条路是纯静默的
      tutorial_wait = tutorial_wait + 1
      if tutorial_wait >= 120 then verify_tutorial_once() end   -- ≈2 秒（60fps）
      return
    end
  end
  verify_tutorial_once()        -- ★ init 成功后跑一次：一行 `[tut] 自检 OK 14/14`
  if not tutorial_opened_once and started then
    tutorial_opened_once = true
    pcall(function() tutorial:open_ui() end)   -- 开局弹一次「玩法说明」
  end
end
```

要点：

* **为什么放 `init` 之后**：`init` 是"控件树已经就绪"的唯一现成信号（根容器找不到它会一直早退）；
* **为什么还要 `tutorial_wait` 兜底**：`init` 起不来的那种失败，恰恰是最该被喊出来的，
  但它原来**一个字都不打** —— 等满 ≈2 秒再跑一次自检，日志就会说"14 条全缺失"；
* 自检失败**不会**影响教程本身（`pcall` + 只打日志），也不会重试刷屏（`tutorial_verified`）；
* 阈值 120 帧只影响"喊话时机"，不影响判据，真机日志嫌早/晚改这一个数即可。

## 七 明确没覆盖的（别指望它）

| 没覆盖 | 原因 / 现行做法 |
|---|---|
| `tut.bg` / `tut.label` / `state.sel` / `state.off` 这些**子控件** | `label` 全档有 27 个、`state.*` 每页签各一份 ⇒ 按名字 `find` 会取错；`tutorial_ui` 用 `sub(父, 子)` 取，要靠"父名+子名"的新判据才能查（不在本轮范围） |
| 文字内容 / 图片 / 颜色 / `active` | 本轮判据只有：名字、父名、显隐、尺寸 |
| 双画布（4 套容器）的**归属** | 只按名字核对。若 `GetClientUIRoots()` 返回多套且 `tut.*` 被复制进多套，**重名判据会报出来** —— 那本身就是问题（脚本 `find` 取到哪一套不确定） |
| 运行时创建控件 | **永不做**：自检若能造控件，就会把"缺控件"验成"通过"（假绿发生器）。测试 ⑦ 用"一调就记错"的假 `game.InstantiateClientUIControl` 钉着 = **0 次** |
| 改控件 | **永不做**：只读，所以可以随时反复跑，无副作用 |
