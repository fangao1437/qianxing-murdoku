# 715 UI 自适应修订 v11：选关背景纸与卡片统一覆盖

日期：2026-11-18。

## 本轮修复

v10 已恢复固定内容的原生尺寸，但选关背景纸使用 `cover`，选项卡衬纸和白框仍按 1 倍处理，导致不同画布比例下背景与卡片构图脱节。本版从原始 715 存档重新构建，统一以下层的运行时变换：

- `art642.select.backdrop`、`art642.select.paper`、`art642.select.thread`：选关背景链；
- `art642.select.lighting`、`art642.select.frames`：四张卡片衬纸与白框；
- 动态缩略图、标题、成绩文字和点击区：沿用同一个 `cardScale`；
- 选关背景继续使用 `cover = max(canvas_w / 1600, canvas_h / 900)`，保证宽屏补左右、高屏补上下。

`cardScale` 以 `cover` 为基础，并受卡片组可用矩形 `1120×600` 的上限约束：

```text
cardScale = min(cover, canvas_w / 1120, canvas_h / 600)
```

因此 4:3、16:10 等高画布不会因为背景覆盖而把卡片组无限放大；21:9 等宽画布则不会让卡片停留在旧倍率而与背景纸分离。撕边继续使用等比 `fit`，玩法根、棋盘、线索规则和固定保护区域保持原有处理。

## 比例回归

构建器执行了 12 个比例配置、每个配置 1280/1600/1920 三档画布，共 36 个离线几何案例：

- 官方 10 组：PC 16:9、21:9；触屏 16:9、19.5:9、4:3；主机手柄 16:9、21:9；移动手柄 16:9、19.5:9、4:3；
- 额外校验：16:10、20:9。

每个案例都断言：背景同时覆盖画布宽高、卡片组不越出可用矩形、倍率为有效正数。v3/v5 中 21:9 只有离线模型验证，没有实机验证；v11 仍不能代替真实设备导入验收。

## 实机边界

本轮没有操作游戏进行真实渲染验收。导入后优先观察：

1. 移动端和 4:3 是否不再漏左右或上下底层背景；
2. 选项卡衬纸、白框、缩略图和文字是否与背景纸同步放缩；
3. PC/主机 21:9 是否保持边缘完整；
4. 长屏与高屏下返回、翻页、结算按钮和点击区是否仍可触达；
5. 页面切换后背景、撕边和卡片是否没有残留或重复缩放。
