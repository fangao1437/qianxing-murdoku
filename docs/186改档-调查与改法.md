## 二、★ 字段定位（`dumpone.mjs` 逐字节摊开得出，非推断）

### 1）图片来源与 id —— 在 `#84` 块里

**参照物**：`board.bg`（字节 63815..64570）的 `#84` 块：

```
@ 64405  #84 msg[12] @64408 {
  @ 64408  #502 = 4280097563      ← imageSource（内置素材库的 source）
  @ 64415  #503 = 100001          ← imageId
}
```

**而 backrop 现在是"空"的**（这就是"没图"的原因）：

```
@ 82405  #84 msg[7] @82408 {
  @ 82408  #502 = 4294967295      ← 没有配图（4294967295 = 0xFFFFFFFF）
}                                  ← ★ 连 #503 都没有
```

⇒ **要做的**：把每个 backrop 的 `#84` 块改成
`#502 = 4280097563` + **新增 `#503 = 100001`**（msg[7] → msg[12]，块长 +5，**父级链上的长度字段要一起重算**）。

### 2）调色（填充颜色）—— 每个**状态块**里 3 个 float

`dumpone` 里每个 backrop 有 **4 个状态块**（预设按钮的 4 态），每块里都有：

```
@ 81926  #501 msg[93] @81929 {
  @ 81932  #501 msg[15] @81935 {
    @ 81935  #1 float = 1        ← R
    @ 81940  #2 float = 1        ← G
    @ 81945  #3 float = 1        ← B
  }
```

⇒ 当前是**(1,1,1) 纯白**；**4 个状态块都要改**（只改一个的话，悬停/按下会跳回白色）。

**要写的值**（8 位色 / 255）：

| 控件 | 目标色 | R | G | B |
|---|---|---|---|---|
| `clue.i.backrop1`（描边）| `#56565E` | 0.337255 | 0.337255 | 0.368627 |
| `clue.i.backrop2`（填充）| `#26262E` | 0.149020 | 0.149020 | 0.180392 |

> 用户原话「图你选用 100001 加调色就好」⇒ 两张都用 **100001**（基础形状-正四边形），
> 靠 **尺寸差（360×96 vs 354×90 = 四周 3px）** 做出描边 ✓

## 三、改法（下一步执行，共 3 件事）

1. **10 个 backrop 的 `#84`**：`#502` → 4280097563；插入 `#503 = 100001`
   （≈ 可用现成的 `tools/gil/retint.mjs`：它正是"改子控件的 source+id、并重算长度"的工具
   ⇒ `--names=clue.1,clue.2,clue.3,clue.4,clue.5 --child=backrop1 --src=4280097563 --id=100001`，backrop2 同理再来一次）
2. **10 个 backrop × 4 个状态块 × 3 个 float**：按上表写 RGB（共 120 个数）
3. **`clue.2.backrop2` 高 96 → 90**（改状态块里的尺寸 float，四态一起）

**收尾必做**：`node tools/gil/roundtrip.mjs 186.gil`（逐字节一致性）+ 逐项回读核对。

## 四、⚠️ 一条必须提前说的风险

真机日志每次开局都打：

```
环境没有全局函数 `Color`，染色跳过（不影响玩法）。
```

⇒ **"调色"在实机可能被跳过**（那是**脚本侧** `SetImage/imageColor` 的路径）。
**但编辑器里"填充颜色"写进 `.gil` 的这 3 个 float 是存档数据，属于另一条路** —— 大概率有效，
**但没验证过**。所以改完要**进游戏看一眼**：如果两张图都显示成**白色**（= 调色没生效），
回退方案是**换成两张本来就是目标色的素材**（素材库「底板-单色 106001–106096」里挑），
用 id 区分而不是靠调色。
