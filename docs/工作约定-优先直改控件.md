# 工作约定：**能直改控件的事，不要用脚本做**

> 来源：用户 2026-09-29 的要求。
> 原话：「你既然有能力直接编辑控件，有些能直接通过编辑控件完成的工作就不必靠脚本执行了，
> 就像添加文本、删除控件这类问题，直接调整控件就能轻易完成，从脚本执行却需要大量环节……
> 这是效率和稳定性都不高的操作方式」

---

## 一、为什么

我这边有两条改动通路：

| 通路 | 我怎么做 | 生效环节 |
|---|---|---|
| **A. 直改控件** | 用 `tools/gil/*.mjs` 直接读写 `.gil` 的控件记录 | **1 步**：改文件 → 你在编辑器里导入 |
| **B. 改脚本** | 改 Lua → 打包 → 内嵌进 `.gil` → 同步沙箱 | **N 步**：脚本加载 → 找控件 → 设属性 → 每帧渲染维持 |

**B 的每一环都可能出错**，而且错了以后症状往往不在出错的地方。

### 这次的真实教训（删三个工具按钮）

我走的是 B，结果连踩四轮：

1. 把三个按钮**从布局表里不 push** → 按钮**还在屏幕上**
   （渲染的差集逻辑**只隐藏"曾经显示过"的控件**，从没进过计划的不会被隐藏）
2. 改成 `visible = false` 留在计划里 → 才藏掉
3. 你手动把控件删了 → 脚本 `sub(id,"label")` **找不到子控件** →
   真机日志刷出 16 条"读回 nil"（**不是写入失败，是控件不存在**）
4. 再把布局表里的声明删掉 → 才真正一致

**同一件事，A 通路只需要"删掉记录"一步。**

## 二、判定表：这类事走 A，那类事走 B

### ✅ 走 A（直改控件）

| 事情 | 做法 |
|---|---|
| **删控件** | 删记录 + 从父控件的子列表里摘掉（`tools/gil/` 现成工具） |
| **加控件** | 克隆一个已知可见的原型 + 改名 + 改父子关系 |
| **改位置 / 尺寸** | 直接改记录的几何字段（或你在编辑器里拖） |
| **改图片** | 成对改 `imageSource` + `imageId`（**只改 id 会"属性变了画面没变"**） |
| **改层级** | 改父控件子列表里的顺序 |
| **改子控件顺序 / 归组** | 同上 |

### ⚠️ 走 B（必须脚本）

| 事情 | 为什么不能走 A |
|---|---|
| **文字内容** | 存档里**读不到文字**（`ruler.c.1` 显示 "C1"、`hud.title` 显示标题，但记录里只有控件自己的名字）。目前**只能运行时由脚本写**。 |
| **运行时生成的东西** | 格子（`cell.r.c`）是按模板在运行时建的，存档里没有 |
| **随状态变化的显示** | 头像换图、✗ 显隐、墙门显隐、进度文字 |
| **按人数自适应** | 头像卡列数、行标列标对齐 |
| **交互逻辑** | 点击/双击/长按/键盘 |

### 🤝 两者都能做时，默认选 A

例如"按钮该显示什么文字"：**文字内容走 B**（存档存不了），
但**字号 / 位置 / 对齐 / 尺寸走 A**（你在编辑器里调，脚本不许覆盖）。

> 这正是 `cfg.respect_editor_rect`（默认 `true`）的由来：
> **存档里已有的控件保持编辑器几何，脚本只摆自己运行时生成的控件。**

---

## 三、走 A 时的纪律

1. **先备份**（`git` 提交，或 `tools/restore_backup.ps1` 快照）
2. **改完立刻回读验证** —— 不要只看"写成功了"，要**重新解析文件**确认结构没坏
3. **尾标记 `0x00000679` 必须在**（`tools/gil/*.mjs` 一般会检查）
4. **别拿"运行时状态为假"的控件当克隆原型**
   （例如墙/门在存档里是 `visible=false`，克隆出来的副本也是隐藏的）
5. **图片必须成对改** `source` + `id`

---

## 四、走 B 时的纪律（仍然适用）

1. **改完必须重打包 + 重内嵌**，否则你跑的是旧脚本
2. **脚本不要再"接管"编辑器里已有的几何**
3. 给脚本加开关时放在 **`cfg` 顶层**（不是 `cfg.cells` 里）
4. 断言要锁**用户可感知的行为**，不要锁**内部机制**
   （本项目已经因此红过三次：`erases`、`pending_click`、`action.q.x`）

---

## 五、给未来的我：动手前先问一句

> **这件事，能不能只改 `.gil` 就完成？**

如果能 —— **就只改 `.gil`**，别去动 Lua。
脚本的职责是**运行时才成立的东西**，不是静态布局。
