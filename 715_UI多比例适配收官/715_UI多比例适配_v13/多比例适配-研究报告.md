# 715 UI 多比例适配 v13
2026 年 11 月 19 日。交付物为基于 v12 游戏侧保存件构建的独立 GIL。底色随宿主延展到四边，主画按原比例居中完整显示。宽高比不同于原画时，新增区域显示页面底色。

## 依据与取舍
本地三个仓库的提交分别为 qianxing-murdoku 的 dc96981、qianxing-murdoku-tool 的 4114275、murdoku-project 的 ffd967d。第二轮《715_背景漏边与黑底深度调研》定位到控制器先将根写成 1600×900，随后适配函数因根没有满拉伸而提前退出。报告中的 v2 高窗口与 v3 长窗口观察作为历史对照。Unity 的多分辨率指南说明锚点相对父矩形生效[14]。具体千星宿主可见范围仍需客户端测量。

仓内 v12 与最近的游戏侧保存件各有 8430 条控件记录，ID 集合和内嵌 Lua 一致，1562 条控件的编码有差异。选择游戏侧保存件作为输入，以保留这些差异。v13 写出后逐记录回读，8430 条控件与该输入一致，整棵数据树仅内嵌 Lua 字段变化。GIL 大小 7613869 字节，SHA-256 为 8c31341a86b597f2c9e847f13272489b7ac9ba76d72d6fe0ae89bab2a5886f5f。

## 不同比例下的画面
运行时沿用项目的设计宽 1600，按画布 API 的宽高比换算设计高度 H。主画倍率取 min(1, H/900)，火漆沿用同一倍率。根布局交给存档四边锚点，控制器跳过根矩形写入。独立底色铺满根，纸张、连线、卡框与动态内容沿用 v12 的共同倍率。页面显隐先于画布尺寸检查执行，切回主页时即关闭选关深色层。

|窗口比例|模型中的主画与边缘|
|---|---|
|16:9|1600×900 主画显示原构图|
|4:3|设计高度 1200，主画上下各留 150 个单位，由底色填充|
|21:9|设计高度约 686，主画宽约 1219，左右各约 190 个单位由底色填充|

## 验证与实机放行条件
整份导出 Lua 在本机 Lua 5.4.6 编译通过。回归从交付 GIL 提取实际矩形写入与适配函数，使用控件替身，保持实例并切换尺寸。项目 10 组设备配置加 16:10、20:9 两组，分别用 1280 和 1920 宽，按首页→选关→首页→关卡执行，共 96 个场景通过。另通过两次 API 尺寸为零时的即时切页。核查了四端底色锚点、649 个背景子控件的显隐、场景等比边界、卡框与纸张倍率，以及卡片和热区在相同输入矩形下的位置与尺寸。

本次未在游戏内导入。测试未运行完整控制器、原生渲染与输入链。真实可见宿主与 API 比例的关系、设备安全区、动态卡片最终布局和实际点击仍待实机确认。优先用 4:3 看上下边缘，21:9 或 19.5:9 看左右边缘。在同一窗口切换首页→选关→首页，确认警局画面恢复、边缘只出现预期底色，最后点选最外侧卡片并检查棋盘四角。
