# 操作模式 · 纯 2D 平面 + PC 键鼠 / 移动端触屏双端

> 这份是**操作层的唯一规格**。任何"要不要加 3D""要不要做镜头""移动端能不能玩"的
> 问题，答案都在这里，不用再讨论。
> 对应代码：`lua/ui_controller.lua`（手势与状态机）、`lua/engine_adapter_qianxing.lua`（设备识别与事件绑定）。

---

## 一、铁律：这是 2D 平面解谜，不是 3D 玩法

**参考原作 murdoku.com/play/ 的形态**：一屏 N×N 网格，左边一列角色卡、左边一列线索文字，
玩家用"把角色放到格子里"来表达推理。**玩法 100% 发生在 2D 平面上。**

| 有 | 没有 |
|---|---|
| 一张 N×N 网格（N = 5 / 6 / 7） | ❌ 3D 移动、走位、跳跃 |
| 2D 光标拾取（点哪个格子就是哪个格子） | ❌ 自由镜头、旋转、缩放视角 |
| 2D 头像卡 → 2D 格子的"放置"动作 | ❌ 角色实体、寻路、碰撞体 |
| 2D 弹窗/面板/开屏教程 | ❌ 第三人称/第一人称角色控制 |
| 2D 坐标系下的自适应排版（5×5/6×6/7×7 共用一套） | ❌ 世界坐标 / 场景物件摆放 |

**因此这份设计里不出现任何 `game.GetLocalPlayer()` 位移类 API、不出现相机 API、
不出现 `SetPosition` 类世界坐标操作。** 全部界面用**客户端控件**表达，
全部逻辑跑在**客户端脚本**里（`lua/entry_client_script.lua` 挂到控件上）。

### 坐标系（唯一转换点）

| 项 | 值 |
|---|---|
| 设计空间 | `1920 × 1080`，原点**左上**，Y 向下 |
| 真机画布 | `1600 × 900`，原点**左下**，Y 向上（真机日志已确认 `画布 1600.00×900.00`） |
| 缩放 | `M.SCALE = 5/6` |
| 控件「位置」语义 | 控件**中心点**的**画布绝对坐标**；**跟父级无关**、锚点/pivot 不参与计算 |
| 转换点 | 只有一个：`M.to_canvas(rect)`，在 `lua/ui_controller.lua` |

> ⚠️ 唯一容易踩的：控件「位置」不是"相对父级的偏移"，是**中心点绝对坐标**。
> 所以**嵌套多深都不影响**，这反而让编辑器和脚本容易对齐。
> 自检在 `tests/ui_math.lua`（47 项，含 5×5/6×6/7×7 的编辑器值 vs 运行时值比对）。

## 二、一套界面，两种操作：PC 键鼠 + 移动端触屏

**同一份脚本、同一套编辑器控件、同一个布局，两种设备都能完整通关。**
不是"两套 UI 各做一份"——那样维护量翻倍，而且移动端那份永远落后。

### 2.1 设备识别

```lua
game.GetDevice()  →  Enum.Device
```

`Adapter:device()` 拿原值，`Adapter:input_profile()` 归一成三档：

| `Enum.Device` | `input_profile` | 用途 |
|---|---|---|
| `KeyboardAndMouse` | `"pc"` | PC 键鼠 |
| `Mobile` / `MobileController` | `"touch"` | **移动端触屏**（含接了手柄的手机） |
| `Controller` | `"gamepad"` | 纯手柄（兜底，见 §2.6） |
| 取不到 / 枚举缺失 | `"pc"` | 安全兜底 |

界面层只依赖 `input_profile` 这三个字符串，**不直接调 `GetDevice()`**，
这样真机枚举一旦改名/缺失也不会连锁炸掉。

### 2.2 交互语义（两端共用一套动作）

| 动作 | 语义 | 为什么 |
|---|---|---|
| **单击 / 轻触** | 铅笔**笔记**（写候选） | 移动端也能精确单击 |
| **双击**（≤0.35s 内两下） | **放置**角色 | PC 上的自然操作 |
| **长按**（按住 ≥0.45s 不动） | **放置**角色（与双击同效） | **移动端主入口**：手指没有"双击"这种可靠操作，长按更稳 |
| 拖拽（位移 > 24px） | 取消，不算点击 | 防手指滑动误判成落子 |
| 单击「橡皮擦」工具 | 清掉这一格 | |
| 双击 / 长按「橡皮擦」工具 | **清全盘** | |

判定参数（`lua/ui_controller.lua` 顶部，集中一处，要调只改这里）：

```lua
local DOUBLE_CLICK_SECONDS = 0.35   -- 双击窗口
local LONG_PRESS_SECONDS   = 0.45   -- 长按门槛
local TAP_MOVE_TOLERANCE   = 24     -- 超过这个像素位移就不算"点击"
```

**时间从哪来？** 没有 `os` 库，`dt` 全靠 `OnUpdate(dt)` 累加进 `Adapter.clock`；
界面层读 `self.now`。所以**门控③（`script:EnableUpdate(true)`）不过，
长按和双击都会失效** —— 这也是为什么它被列为硬门控。

### 2.3 长按、拖拽与尾随点击的冲突处理

**① 尾随点击**：移动端一次长按，系统会先给 `CursorDown`，长按到点后放手指还会**再给一个 `CursorClick`**。
不处理的话就是"放好了又被笔记盖掉"。做法：

1. `on_cell_down` 记下按下时刻与坐标；
2. `OnUpdate` 里超时 → 触发落子，并置 `self._suppress_click = true`；
3. 随后的 `CursorClick` 看到标志位 → **直接吞掉**，然后清标志。

**② 按住时移动（拖拽）= 当场取消，不等抬起**：官方枚举里有
`CursorBeginDrag / CursorDrag / CursorEndDrag`，我们**只绑 `CursorDrag`**：

| 事件 | 绑不绑 | 为什么 |
|---|---|---|
| `CursorDrag` | ✅ 绑，收到就比坐标位移，超 24px 立刻撤销待判定的长按 | 语义是"已经在移动"；提前取消 → 玩家按住想微调时不会一松手就落子 |
| `CursorBeginDrag` | ❌ **不绑** | 它的语义是"开始可能成为拖动"，**有些实现一按下就发**。接成"取消长按"会让真机上长按彻底失效，而且模拟器发不出 drag、这个错查不出来 |
| `CursorEndDrag` | ❌ 不绑 | 与 `CursorUp` 重复 |

**③ 双保险**：即使 `CursorDrag` 因为实现差异没派发，`on_cell_up` 里还会**再比一次**
按下/抬起的坐标位移 —— 所以"划动不落子"这条至少有一条路径保得住。
两条路径都拿不到坐标时**宁可退回"只看时长"**，也不误取消。

`tools/sim/probe_input.mjs` 有专门一条断言验长按后抑制尾随点击；
但**模拟器的 `pointer` 只有 `down`/`up`、没有 `move`**，所以 ② 这条分支在模拟器里
永远走不到 —— 它由纯 Lua 的 `tests/input_logic.lua`（36 断言）直接调
`on_cell_down / on_cell_drag / on_cell_up` 覆盖。

### 2.4 PC 键鼠：键盘是加分项，鼠标是主路径

**鼠标**：走光标事件（`CursorClick` / `CursorDown` / `CursorUp`），跟触屏同一条路径，
所以鼠标玩家天然能用双击/长按那一套。

**键盘**（可选，绑不上不影响玩）：绑定在**控件**上而不是 `script` 上
（`AddKeyEventListener` 是**控件**方法，这是踩过的坑），目标控件由 `cfg.key_control`
决定，默认 `"root"`。`entry_client_script.lua` 里绑 30 个键：

```
方向键 ×4 · W A S D · Space · Return · NumpadEnter · Tab · Escape
Z · Y · H · Digit1..7 · Alpha1..7
```

| 键 | 作用 |
|---|---|
| `↑ ↓ ← →`（**只用方向键**，WASD 不参与移动） | 移动**键盘光标**（棋盘上高亮的那一格） |
| `Space` | 在光标格写/删笔记 |
| `Return` / `Enter` / `NumpadEnter` | 在光标格**放置**当前选中角色 |
| `1`..`7` / `Digit1..7` / `Alpha1..7` | 选中第 i 张头像卡 |
| `Tab` | 循环切换工具：放置 → 笔记 → X → 橡皮擦 |
| `Z` / `Y` | 撤销 / 重做 |
| `H` | 提示 |
| `S`（仅键盘光标已激活时） | 提交 |
| `Esc` | 有弹窗 → 关弹窗；没弹窗 → 打开**选关面板** |

> **为什么方向键和 WASD 里只用方向键移动？** `W/A/S/D` 要留给别的快捷键
> （`S` = 提交），混在一起必然误触。绑定列表里留着 WASD 只是为了将来扩展，
> 移动只认方向键（`KB_DELTA` 表里只有四个方向键）。

**键盘光标可见性**：`kb_active` 为真时，棋盘上对应格子套 `style = "cell.cursor"`，
玩家能看见"键盘现在指在哪"。用鼠标点一下就会切回鼠标路径。

### 2.5 图例文案按设备换

同一块图例控件（`left/legend`），三种文案，玩家不用自己试：

| profile | 文案要点 |
|---|---|
| `touch` | 「轻触=铅笔笔记　**长按=放置**　X工具=划掉这格」 |
| `pc` | 「单击=笔记　双击/长按=放置 …」**并追加一行键盘说明**（方向键/空格/回车/Tab/数字） |
| `gamepad` | 「确认=笔记　按住=放置　肩键切换工具（手柄为兜底方案，推荐用键鼠或触屏）」 |

代码在 `lua/ui_controller.lua` 渲染 `legend` 的那一段（约 716 行）。

### 2.6 手柄：兜底，不承诺

`Controller` 单独归成 `"gamepad"`，文案上**明说这是兜底**。
原因：奇域的手柄光标事件我们**没有在真机上验过**（只验过键鼠与触屏路径），
不想给你一个"看起来支持、实际点不动"的承诺。要正式支持手柄得先补一次真机验证。

## 四、真机上还必须满足的前置条件（跟操作模式强相关）

1. **容器「显示常驻光标」必须开** —— 不开则**任何**点击/触摸都收不到。
   脚本会自己开（`Adapter:enable_cursor()`，真机日志会打
   `已由脚本打开 N 个容器的「显示常驻光标」`）；若真机不开放该字段，手动勾。
2. **`script:EnableUpdate(true)`** —— 不开则 `OnUpdate` 一次都不跑 →
   双击/长按/计时器**全部失效**（只剩光标事件）。
3. **控件类型必须是「预设按钮」或「光标检测区域」** —— 普通容器/文本**不接受**
   `AddCursorEventListener`。脚本遇到会打一条明确的警告而不是静默失败。
4. **界面布局必须被「职业」引用** —— 不引用则编辑器和模拟器都对，一进游玩什么都没有。
