# 千星关卡存档（`.gil`）格式 —— 逆向记录

> 起因（2026-09-27）：用户发现千星有**「导入存档」**功能，问能不能**直接生成存档文件**，
> 省掉手搭 101 个控件的活。
>
> **结论：技术上可行，且已通过字节级往返验证。** 但"生成完整布局"还没做，见文末【下一步】。
>
> 本文里的每一条都标了**已验证**还是**推断**——请按标注采信。

## 一、它是什么：两种格式，别混

| 扩展名 | 是什么 | 入口 | 官方文档 |
|---|---|---|---|
| **`.gil`** | **整个关卡存档**（含界面布局、节点图、地形…） | 存档页面 → 导出/导入存档 | 《1.4存档导入与导出》`mhjuwpiubrh0` |
| `.gia` | **资产**（元件/实体/技能/道具/节点图） | 系统菜单 → 资产导入导出工具 | 《资产导入导出》`mhxbd59urbfu` |

我们要的是 **`.gil`**。

### 导入路径（官方原文）

- **从原神游戏内**：派蒙菜单 →【我的奇遇】→ 存档界面 → 右下角【**导入存档**】→ 选文件
- **从编辑器内**：局内编辑器 ESC → 左侧面板 → 存档页面 →【导入存档】

> 官方还给了个现成样例：课程《关卡导出》`mhg94h90x3oq` 的附件 **「建成我的第一个奇域.gil」（217.1 KB）**，
> 可以下载来当第二个参照样本。

## 三、文件结构（**已验证：字节级往返一致**）

### 3.1 外层头（20 字节 + 4 字节尾）

```
偏移 0   u32BE  文件大小 − 4          （实测 249247，文件 249251）
偏移 4   u32BE  1
偏移 8   u32BE  806                   （版本号？实测固定）
偏移 12  u32BE  2
偏移 16  u32BE  体长度                 （实测 249227 = 文件大小 − 24）
偏移 20  protobuf 体（长度 = 上面那个）
末尾 4   u32BE  尾部标记               （实测 0x00000679，含义未知，**必须原样保留**）
```

> ⚠️ 体的**结束位置**要用头里给的长度（`20 + 体长度`），**不能**用文件长度 ——
> 末尾还有 4 字节尾。

### 3.2 体是一棵**单消息**树

`node tools/gil/roundtrip.mjs` 的实测结果：

```
试 [20, 249251)：❌ 失败        ← 用文件长度当结束位置就解析不了
试 [20, 249247)：✅ 解析出 45 个字段
重新编码：249227 字节（原体 249227 字节）
★★★ 往返成功：重新编码与原始体逐字节完全一致
```

**往返逐字节一致**说明：字段顺序、类型、长度前缀都被完整还原了 ⇒ **模型是完整的**，
可以安全地改字段、加记录、重算长度。

## 四、控件记录的字段含义（**推断，但有大量旁证**）

从 `cell.1.1` 所在的区域（`tools/gil/grow.mjs` 向上生长得到的 43716 字节记录）解出来：

```
#501 bytes[95]                     ← 一串 varint：1073741868 1073741897 1073741898 1073741899 …
                                     看着像**子控件 ID 列表（有序）**
#502 msg  ← 重复出现，**每个控件一条**：
  #501 = 1073741868                ← 控件 ID（唯一）
  #502 { #11 { #501 = <id> } #501 = 1 #502 = 5 }     ← 分类/类型标记
  #502 { #12 { #501 = 1 }   #501 = 2 #502 = 6 }      ← 次序
  #502 { #14 …              #501 = 4 #502 = 4 }
  #505 { #12 { #501 str = "客户端控件容器" } … }      ← ★ 控件类型名（中文）
  #505 { … #503 { #13 { #12 msg[6] {
        #501 msg  ← **重复 4 次 = 四个状态节点**
          #501 = 0 / 1 / 2 / 3                        ← 状态号（默认/悬停/按下/不可用）
          #502 {
            #501 { #1=1 #2=1 #3=1 }                   ← 锚点相关
            #502 { #501=0.5 #502=0.5 }                 ← 锚点 min（或 max）
            #503 { #501=0.5 #502=0.5 }                 ← 锚点 max
            #504 { #501=-320.0 #502=-274.0 }           ← ★ 位置 (x, y)
            #505 { #501=64   #502=64    }              ← ★ 尺寸 (w, h)
            #506 { #501=0.5  #502=0.5   }              ← ★ 中心 pivot
            #508 bytes[0]
          }
        } #502 = 24 / 1 / 3      ← 状态个数？
          #504 = 1 }
        #501 = 2 }
      #501 = 4 #502 = 12 #503 = 1
      #504 { #2 = 1 #3 = 8 #4 = <id> } }               ← 引用/回指
  #505 { #72/#17/#19/#16 … }        ← **各控件类型特有的属性块**
```

### 已确认能读出来的东西

| 项 | 证据 |
|---|---|
| **控件类型名（中文）** | UTF-8 字符串：`客户端控件容器`、`容器节点`、`交互按钮`、`文本框`、`图片` |
| **每个控件的数值 ID** | 见「四之二」的精确布局 |
| **父控件 ID** | 记录内 `#504 = <父ID>`（**显式**） |
| **实例名** | 记录内**唯一**的短字符串（如 `"board"`、`"cell.1.1"`） |
| **位置 / 尺寸** | fixed32 浮点：`420.0 / 380.0`、`680.0 × 680.0` |
| **四套状态几何** | 同一结构重复 4 次（状态号 0 隐式，其余 1/2/3）→ 对应预设按钮的**四个状态节点** |

### 还没确认的（生成前必须补上）

1. **`#501 bytes[]` 那串 ID 是不是"子控件列表"** —— 若是，加控件时要同步更新它。
2. **新 ID 的分配上限**：ID 连续递增，但最大值之后能否直接用？有没有别处需要登记。
3. 各类型专有属性块（`#72`/`#73`/`#17`/`#19`…）里哪些**必填**。**克隆时原样保留最安全**。
4. 尾部 4 字节 `0x00000679`（校验？版本？）—— 先**原样保留**。
5. 同一文件里还有另外 44 个顶层字段（节点图/地形/关卡设置），**必须原样保留**。
6. 存档里有 **4 套画布**（`客户端控件容器` ×4，各带一份 `board`/`cell.1.1`）——

7. ★★ **几何编码形状随记录而变**（2026-09-27 生成器第一版实测）：
   · `board`（活动容器画布里的容器）用的是 `#504{#501 float,#502 float}` = 位置、
     `#505{…}` = 尺寸；
   · 而**模板画布**里的 `容器节点`/`交互按钮`/`文本框` 原型，按同一判据找出来
     **pos 组数 = 0** —— 位置存在别的字段里，**尚未解出**。
   ⇒ 所以**不能跨画布拿原型**；克隆原型必须取自**目标画布自己那套**。
   这也是"直接生成布局"目前唯一剩下的拦路点（其余都已验证）。   要确认**当前生效的是哪一套**，只改那一套最安全。

## 四之二、控件记录的**精确字节布局**（**已验证**）

`node tools/gil/records.mjs` 找到 **54 条控件记录**，全部连续、可定位（图谱存
`tools/gil/out/records.txt`）。用 `node tools/gil/dumpone.mjs <起> <止>` 摊开单条：

### 原型清单（生成器就靠这几条克隆）

| 原型 | 记录序号 | 字节区间 | 长度 | 控件 ID |
|---|---|---|---|---|
| `客户端控件容器`（画布） | 1 | 9765..10394 | 629 | 1073741868 |
| **`交互按钮`（按钮）** | 2 | 10394..11041 | 647 | 1073741897 |
| **`文本框`** | 4 | 11690..12347 | 657 | 1073741899 |
| **`图片`** | 6 | 12984..13803 | 819 | 1073741904 |
| **`容器节点`（容器）** | 7 | 13803..14488 | 685 | 1073741960 |
| **`cell.1.1`（模板引用控件）** | 8 | 14488..15309 | 821 | 1073742132 |

### 以 `board`（区间 43551..44115，564 字节）为例的字段位置

| 偏移 | 内容 | 含义 |
|---|---|---|
| @43551 | `#502 msg[560]` | 记录外层 |
| **@43555** | `#501 = 1073742977` | **控件 ID**（本记录内共出现 **7 次**，还有 1 次是紧凑字节形式） |
| @43580 | `#503 bytes[5] = 82 89 80 80 04` | 同一个 ID 的 varint 紧凑形式 |
| **@43588** | `#504 = 1073742976` | **父控件 ID** ← **父子关系是显式的** |
| **@43600** | `#501 str = "board"` | **实例名**（整条记录里**只有这一个**短字符串） |
| @43658 | `#4 = 1073742977` | 自引用 ID |
| @43691..43964 | `#501 msg` ×**4** | **四个状态**：第一个不带状态号（=0），其余 `#501 = 1 / 2 / 3` |
| **@43724 / @43730** | float 420.0 / 380.0 | **位置 (x, y)** |
| **@43739 / @43745** | float 680.0 / 680.0 | **尺寸 (w, h)** |
| @43700 / @43705 / @43710 | float 1.0 / 1.0 / 1.0 | 锚点相关（`#1 #2 #3`） |
| @43751 / @43754 | 空 bytes | `#506` / `#508` |
| @43985 / @44025 / @44065 / @44105 | `#4 = 1073742977` | 自引用 ID ×4（每个状态一份） |
| @43995 / @44035 / @44075 | `#505 { #73/#78/#77 … }` | **该控件类型专有的属性块**（容器节点特有），克隆时**原样保留** |

### 由此确定的三条生成规则

1. **ID 可以自己发号**：同一层级里 ID 连续递增（`1073742976 → …977 → …978 → …979`，
   对应 `容器节点 → board → cell.1.1 → face`）。新控件取"当前最大值 + 1"即可。
   varint 字节长度在 `1073741824` 这个量级是固定的 5 字节，**替换 ID 不会改变记录长度**。
2. **父子关系靠 `#504 = <父ID>` 显式表达**，不需要去猜子控件列表。
3. **几何是固定 4 字节浮点**（`#504 {#501=x, #502=y}` 与 `#505 {#501=w, #502=h}`，每状态各一套），
   所以改坐标/尺寸也**不改变记录长度** —— 这让"克隆 + 打补丁"变得非常可控。

> 唯一会改变记录长度的是**实例名**（字符串）。但我们的重编码器能正确重算所有长度前缀
> （roundtrip 已验证），所以不是问题。

## 四之四、**导入前对账**（离线就能抓出"脚本找不到控件"）

`node tools/gil/check_names.mjs [存档.gil]` —— 把"脚本按名字要用的控件"和"存档里实际有的"对一遍。
Lua 全靠名字找控件，名字对不上在离线是看不出来的，所以这一步必须在导入前跑。

**2026-09-27 首跑就抓到两个真问题**（都在 `tpl.cell` 模板里）：

| 缺失 | 证据 | 影响 |
|---|---|---|
| **`text`** | `ui_controller` 的格子 push 带 `text = text`；`engine_adapter:2091` 是 `if ctrl.text ~= nil then … else c = sub(id,"text")`。而**预设按钮没有 `text` 属性**（只有 `interactable`/`clickAudioId`/`raycastTarget`） | ⚠️ **格子上的文字静默不显示** |
| `obj` | `engine_adapter:1913` 的 `layer_order` 里列了它；`enforce_layers` 是 `if sub ~= nil` 容错 | 物件图标层缺失（可选） |

**原因**：重建模板（用 `content` 把子控件包起来那版）时漏掉了这两个。
**修法**：`node tools/gil/gen_template_subs.mjs` —— 克隆 `face` 得到 `obj`、克隆 `proto.text` 得到 `text`，
挂到模板的 `content` 下并登记子列表。

> ⚠️ 踩坑：存档里有**两套**模板（各一份 `cell.1.1 → content → 子控件`）。
> 按名字取会取到错的那套（`Map` 只留最后一个）——**必须按 `cfg.cells.prefab` 的索引**
> （默认 `1073741876`）定位 `tpl.cell` 真正引用的那一套。

## 四之五、**写入路径的决定性验证**：我写的文件 vs 引擎导入后重存的文件

截图读数字会看错（我就在 519.60/599.60 上错过一次），所以改用**字节级对比**：

```powershell
node tools/gil/compare_controls.mjs 测试3控件.gil <游戏目录>\1073741829\1073741829.gil
```

> `1073741829.gil` 是**用户导入我生成的文件后、游戏自己保存出来的**存档。

结果：

```
两边同名控件 21 个
  ✅ board / cell.1.1 / content / door.* / face / note / proto.* / tpl.cell / wall.* / x
  ✅ test.box   位置(0,0)    尺寸(420x260)
  ✅ test.btn   位置(0,60)   尺寸(200x70)
  ✅ test.label 位置(0,-60)  尺寸(360x60)
一致 20 个，不一致 0 个
★ 引擎原样接受了写入（无归一化/重算）
```

**结论：引擎逐字段原样接受我的写入**，不做任何归一化或重算。

### ⚠️ 过程中踩到的坑：**零值不等于"没有"**

第一次跑对比时报了 3 个"不一致"，看上去像"引擎丢了我的位置"。深挖后发现是**我的验证工具有 bug**：

- 引擎重存 `test.label` 时，位置 (0, −60) 只写了 `#502 = −60`，
  **把值为 0 的 `#501` 省掉了**（protobuf 稀疏编码：零值不写）。
  当 `#501 = 0` 是 `#504` 唯一子字段时，整个 `#504` 退化成空消息。
- 而我的 `pairValue` 要求"**必须恰好两个浮点**"，于是把 `(0,−60)` 读成"空" → **误报**。

这与第四之二节那条"位置为 (0,0) 时 `#504` 是空消息"是**同一个规律**，只是发生在**分量**级别。
修法：`pairValue` 改成"缺哪个分量，哪个就是 0；整个字段缺失就是 (0,0)"。

> 教训：**"看起来引擎改了数据"时，先怀疑自己的读取代码**。这次若直接按差量去"校准"生成器，
> 就会把本来正确的坐标改坏。
