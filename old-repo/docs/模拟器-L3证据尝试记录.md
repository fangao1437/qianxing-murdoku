## 3. 格式边界（`.gil` / `.gia` 到底吃不吃）

### 3.1 导入入口白名单（插件 v2.0.2 实际代码）

Web 编辑器导入按钮的判定：

```
r = name.endsWith(".gia") ? "gia" : name.endsWith(".json") ? "json" : name.endsWith(".lua") ? "lua" : ""
if (!r) { 报「仅支持 .json、.gia 或 .lua 文件」 }
```

⇒ **`.gil` 连入口都进不去** ✓（这就是为什么 `.gil` 报的是别的错，而不是被当成 GIA 解析）。

### 3.2 项目 `.gia` 为什么进不去 —— 实测字段

模拟器的 GIA v1 校验（`ci()`）读的是：

```
u32@4  === 1        ← 版本标记，项目的文件都对 ✓
u32@8  === 806      ← 项目文件是 806，模拟器期望的常量【未能确认】是多少
u32@12 === 3        ← 项目文件是 3，`.gil` 是 2，模拟器期望的常量【未能确认】
u32@16 === len-20   ← payload 长度自洽 ✓
```

实测：项目所有 `.gia` 都在 `u32@12` 这一关被刷掉（报 UTF-8 错是**解码失败的表象**，根因是长度/常量校验不过 ⇒ 返回 false ⇒ 落到通用解码路径）。

★★ **反过来是通的**：用模拟器自己导出的 GIA，用 `importData('gia', base64文本, 文件名)` 能**无损往返**：

```
[EXPORT] gia → 未命名存档 · 服务器控件模板.gia 820382B
   [REIMPORT OK] asset=server-control-template tree=1049 templates=5 scripts=0
[EXPORT] gia-combined → 未命名存档 · 整合包.gia 1680297B
   [REIMPORT OK] asset=server-control-template tree=1049 templates=1 scripts=1
   warn=["整合包已拆回「UI控件-服务端」与「UI控件-客户端」；客户端模板边界已保留。"]
```

⇒ 想送进真机编辑器时，**应当从模拟器导出 GIA**（顶栏"导出"），而不是把项目的 `.gil` 喂进模拟器 ✗。

## 4. ★ 运行时发现（L3 真正值钱的部分）

### 4.1 ③ 的定案方向：**墙/门在模拟器里是"缺件"，脚本自己在日志里说了**

`walk-03-level.json`（`click select.card.1` 之后）里的**原话**：

```
⚠️ **本关需要这些边，但模板里没有对应的子控件**（所以画不出来）：door.left door.up wall.down wall.left wall.right wall.up
   补法：在模板的 `content` 里加同名图片子控件（`wall.up`/`wall.down`/`wall.left`/`wall.right`、`door.*`），**四个方向的墙要各自一个子控件**，不能只配一个。
  没有配的：wall.up wall.down wall.left wall.right door.up door.down door.left door.right
  wall.up  兄弟索引=?  （取不到这个子控件）
属性补发 3 次仍未送达，已停止补发：`cell.1.1.walls`（控件在、但适配层说这次没写进去（子控件没就绪？））
```

运行树实测（同一份 `walk-03-level.json`）：

```
cell.* 名称命中 49 个（cell.1.1 … cell.7.7）
wall* 名称命中 0 个
door* 名称命中 0 个
cell.1.1.children = ["text","note","x","obj","face"]     ← 没有 wall.up/down/left/right，也没有 door.*
```

**判定**：在**这一版模拟器存档**里，③ **不可复现** —— 不是"脚本没设上"，而是**控件根本不存在**，没东西可设。
**但这条日志本身就是最有价值的 L3 证据**：它把 ③ 的**候选根因**从"引擎/顺序/性能"收窄到**一个可验证的建模问题**——
**真机上的 `cell` 模板里到底有没有 `wall.up`/`wall.down`/`wall.left`/`wall.right`/`door.*` 这 8 个同名图片子控件？**

- 若有 ⇒ ③ 是"设了但被盖住/没画出来"（层序或尺寸问题）；
- 若没有 ⇒ ③ 就是**编辑器侧漏建子控件**，脚本无论如何都画不出来，与性能修复无关。

⇒ **下一步只需要人在编辑器里看一眼 `cell` 模板的子控件清单**（或用 `.gil` 只读解析数一遍 `wall.` 前缀），不需要再跑模拟器。

### 4.2 网格视窗：`itemPrefabIndex` 在模拟器里不存在

`walk-03-level.json`：

```
网格视窗：失败（设 itemPrefabIndex 失败：cannot set itemPrefabIndex, no such field）⇒ 退回老路径（手写滚动：▲▼ + 滚动条 + clue.N 卡片）
```

## 6. 需要用户做什么（按优先级）

1. ★★ **在编辑器里打开 `cell` 模板，数一下它有没有 `wall.up`/`wall.down`/`wall.left`/`wall.right`/`door.up`/`door.down`/`door.left`/`door.right` 这 8 个图片子控件**（四个方向各自一个，不能只有一个）。

   - 顺带确认这些子控件的**兄弟顺序**是否在 `face` **之前**（引擎：索引大的画在上面 ⇒ `face` 若在墙之后，白底会盖住墙）。

3. **若想让模拟器直接吃你的工程**：目前**没有**这条路 ✗ —— 要么按 §1-C 用公开 API 重建（已可跑通），要么等插件支持 `.gil`。想给真机编辑器送资产时，**从模拟器导出 GIA**（那条路已验证能往返 ✓）。
