# 724 存档与节点图成果总结

更新日期：2026-11-22

## 本轮成果

v724 的存档功能基于已验证的选关续局版本继续完善，主要覆盖多关独立记录、通关结果恢复、教程一次性显示和恢复后的线索卡刷新。

### 多关独立存档

客户端将多关记录编码在局面字符串中，记录容器以 `M724` 开头，并保留教程位掩码。每条关卡记录包含关卡 ID、棋盘局面、用时、步数、失败次数、通关状态、结果类型、错误数和结果用时。

读取时按当前关卡 ID 选择对应记录，因此第一关和第二关可以同时保存，切换关卡不会覆盖其他关卡的记录。旧版 `M723` 单关记录仍保留解析兼容路径。

### 通关记录

通关后将当前关卡的结果合并回对应记录。结果包含通关状态、结果类型、错误数和用时。重新进入已通关关卡时恢复红绿圈完成态，并跳过通关弹窗，避免把已完成关卡再次当作首次结算。

### 选关与续局

首页继续和选关入口都等待玩家存档查询结果。直接从选关界面进入最近保存的关卡时，若记录匹配当前关卡，则恢复棋盘和线索状态。没有有效记录时才创建新局。

恢复操作会清空线索网格的旧缓存，强制下一次渲染按恢复后的棋盘状态重新填充卡片、人物字母和选中高亮，避免必须额外点击一次才能看到线索卡状态。

### 教程记忆

首页、第一关和第二关教程分别使用位掩码记录是否已经弹出。位掩码与局面码一起保存，恢复后重新应用到教程模块。旧存档没有该字段时按未记录处理，首次升级可能再次显示一次教程。

### 日志降噪

重复的家具实例化、家具状态复述和输入诊断日志已收敛为状态变化时输出。存档回读一致、恢复成功、空档、关键校验和画布异常仍保留，便于定位真实运行问题。

## 客户端接口

保存信号使用五个参数，顺序固定为：

```text
level_id   字符串
state_code 字符串
moves      整数
elapsed    整数
solved     布尔
```

恢复信号使用四个参数，顺序固定为：

```text
state_code 字符串
moves      整数
elapsed    整数
solved     布尔
```

`state_code` 的尾部元数据采用以下形式：

```text
<棋盘局面>|murdoku_meta:<教程位掩码>
```

解析时先拆出教程位掩码，再把纯棋盘码交给棋盘核心解码，兼容没有元数据的旧局面码。

## 本地验证范围

已完成以下离线或文件层检查：

- 多关编码和解码。
- 两关记录同时存在且互不覆盖。
- 旧 `M723` 单关档兼容。
- 通关结果、错误数和用时字段。
- 恢复后线索状态刷新路径。
- Lua 语法检查。
- `.gil` 重新读取和编码往返。
- 注入前后字段差异检查，确认节点图与存档模板未被无关改动替换。

这些检查能证明数据协议、客户端逻辑和文件结构的一致性，不能替代正式发布环境的玩家实体持久化验收。

## 正式发布前必须验证

1. 同一账号在正式入口分别保存两关，重新进入时两关记录互不覆盖。
2. 从首页继续和直接选关进入都能恢复对应关卡。
3. 通关后完全离开，再进入已通关关卡时红绿圈保留且不弹通关窗口。
4. 更新版本后旧版 `M723` 玩家记录仍能被正式环境带入。
5. 编辑器中的“下次试玩自动填充保存数据”只作为试玩配置单独验证，不把它当作正式服玩家存档证据。

在上述验证完成前，候选 `.gil` 只作为测试版本保存，不应直接覆盖正式发布版本。

## 关联代码

- `lua/main.lua`：存档编码、恢复、教程位掩码、选关续局和恢复后 UI 刷新。
- `lua/entry_client_script.lua`：教程模块与位掩码接口连接。
- `lua/murdoku_core.lua`：棋盘局面编码和解码。
- `tests/grid_cost.lua`：线索列表回收、事件监听去重和载荷刷新夹具。
- `dist/client_script.lua`：供存档内嵌使用的客户端构建产物。
