# 686 · X 标记离场收起 · 变更与验收

> 基准 **685**（`685_多格家具通用层.gil`，7826 条，SHA `b8fdbc9a…4cdd`），**保留未改**。
> 交付 **686**（`686_X标记离场收起.gil`），7826 条，SHA `b5efd319…d8f8`，可直接导入千星奇域。
> 用户判词：「现在 x 标记离开关卡后会残留」（附真机截图：橙黄结算/选关界面上浮着约 8 个蓝灰 X 叉）。

---

## 一、根因：685 的一个错误判断

685 把 X 标记层挂在 `stage` 下，并在验收文档第七节写道：「home/select 时整棵 `stage` 被隐藏，标记层随之隐藏」。
**这个判断是错的**：项目里 v308 早就记录过「真机上父容器隐藏**不保证级联**到子控件」，685 自己也在显隐实现里写了这条注释，却在「随父隐藏」上又踩了一次。

具体链路（读 685 内嵌 Lua 实证）：

| 事实 | 证据 |
|---|---|
| `stage` 的 `visible` **恒为 true** | `layout_plan` 7432 的 stage 节点无 `visible` 字段；7387 `if n.visible == nil then n.visible = true end` ⇒ 切屏时不会下发 false |
| `cell.r.c` 的 visible 随屏幕变化 | `layout_plan` 8105/8139：cell 节点带 `visible = (self.screen == nil)` |
| 离开关卡时 cell 一定收到 `visible=false` | 内嵌 12878-12892：`for id in pairs(self._shown) do if not seen[id] ... _set_prop(..., "visible", false)` |
| **标记层控件不在 nodes 表里** | 8×8 组标记是 `.gil` 静态控件，Controller 的 `_shown` 差异下发 / `hide_unlisted(keep)` 都不会给它们下发 visible |
| 项目已有同类范式 | 内嵌 20009-20019：`set_property` 的 visible 分支在 `id == stage` 时**显式切** `board.floors` / `board.rugs` |

⇒ 关卡外没有人给 192 个标记控件关灯，加上父隐藏不级联 ⇒ X 全部残留。

---

## 二、修法：沿用项目既有范式，逐层关灯 + 屏幕门控

**685 的三层不变式完全保留**（stage 末尾标记层 / 8×8 组 X / 每帧 `_mark_layer_raise`），只补「离场收起」：

| 机制 | 作用 |
|---|---|
| `_mark_all_ctrls()` / `_mark_hide_all()` | 遍历 `8×8×3 = 192` 个控件逐个 `SetVisible(false)`；控件列表缓存，`#t < 192`（树未就绪）时不缓存，下次重建 |
| `_mark_screen_on` 门控 | 关卡外为 `false` 时，`_mark_set_visible(rc, true)` 一律降级为 false ⇒ 切屏瞬间即使 `x_mark` 抢先下发也不会点亮 |
| `set_property` 的 visible 分支 | `stage` 收到 `visible=false` ⇒ `_mark_hide_all()`；`cell.r.c` 收到 `visible=false` ⇒ 置门控并逐组收起；`visible=true` ⇒ 门控恢复（不自动点亮，由 `x_mark` 决定） |
| `hide_unlisted(keep)` 兜底 | `keep`（layout_plan 的 `seen`）里没有任何 `cell.*` ⇒ 当前不在关卡内 ⇒ `_mark_hide_all()`；兜住首帧 / `_shown` 重建等没有 cell visible 下发的路径 |

**通用性**：只依赖「cell 节点是否可见」这一既有布局事实，不依赖关卡、棋盘阶数、X 数量、家具种类或尺寸。将来新增任意家具/标记类型，只要沿用 `art685.mark.*` 命名并走 `_mark_set_visible`，离场收起自动生效。

## 六、边界 / 真机待验

1. **本版未导入游戏**。需真机确认：离开关卡后 X 全部消失、重新进入关卡时 X 按 `x_mark` 正常点亮、`_mark_all_ctrls()` 首次调用能取到全部 192 个控件（取不到时会打印 `mark:missing` 并退回 685 行为）。
2. 若真机上 `cell.r.c` 的 `visible=false` 因属性去重**没有下发**，仍由 `hide_unlisted(keep)` 兜底；但两者都依赖 Controller 正常 render。极端情况下可在 `on_tick` 里再加一次屏幕态检查，本轮未加（避免每帧遍历 192 个控件）。
3. `note`（数字/笔记标记）仍留在格内；若将来也移到标记层，需同样走 `_mark_set_visible` 才会自动获得离场收起。
4. `dist/client_script.lua` 未重打包；源码已同步，将来重新 bundle 请重跑本轮全部闸门。
