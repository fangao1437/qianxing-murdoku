# 669 恢复旧高亮方案：变更与验收

**基准**：`668_线索卡染色.gil`（SHA `2f6c1ac8…7b3`，6,976 条），保留未改
**产物**：`669_旧高亮方案.gil`（SHA `567a1045…5d55d`，6,976 条，可直接导入）

## 一、控件位置核对（两套模板完全一致，模板局部坐标）

| 控件 | 668 实测 cx,cy | 尺寸 | 668 颜色 | 669 角色 |
|---|---|---|---|---|
| `backrop1` | 800, 450 | **330×85.4** | `#00FFFFFF` 透明 | **染色区**，脚本写 `imageColor`，放最下面 |
| `backrop2` | 800, 450 | **324×79.4** | `#00FFFFFF` 透明 | **红色卡面底色** |
| `art658.clueN.bg` + `art661.clueN.*` 28 层 | 800, 450 | **330×85.4** | 红色阶梯渐变 | **红色渐变素材** |
| `art658.clueN.rule` | 800, 410 | 330×5 | `#FDFAF5` | 白线 |
| `who` / `what` / `letter` | — | — | `#FFFFFFFF` | 白字（保持） |
| `gen.backrop`（隐藏） | 800, 450 | 330×79.4 | `#FFFFFFFF` `img=107133` | 通用提示卡，未动 |

**关键发现**：红色渐变原本是 **330×85.4，和 `backrop1` 一样大**。原样放上去会把染色区完全盖住 —— 这正是前几轮「描边/高亮失效」的几何根因。所以红色必须按 **`backrop2` 的 324×79.4** 来放，`backrop1` 才能露出上下左右各 3px。

## 二、本轮改动

### ① 缩放红色渐变到 backrop2 尺寸

对两套模板各 30 层（`art658.clueN.bg` + `art661.clueN.*` 28 层 + `rule` 白线）做仿射缩放：

- `SX = 324/330 = 0.981818`、`SY = 79.4/85.4 = 0.929742`
- 中心相对 (800,450) 的偏移同比例缩放，`rot` 保持不变
- 结果：渐变组 324×79.4，与 `backrop2` 完全对齐；白线一并缩放

### ② 层序重排（recTop 与 childList 同步）

```
backrop1 (染色区 #FF56565E, 330×85.4)
  → backrop2 (#FF611F23 渐变最暗底色, 324×79.4)
  → art658.clueN.bg + 28 层阶梯渐变 (324×79.4)
  → rule 白线 → who / what / letter
```

实测两套模板的层序索引均为 `[23, 24, 25]`（backrop1 → backrop2 → bg），childList 同序。

### ③ 颜色

| 控件 | 668 | 669 |
|---|---|---|
| `backrop1` | `#00FFFFFF` | **`#FF56565E`**（5xx 旧档普通态描边色 / 染色区） |
| `backrop2` | `#00FFFFFF` | **`#FF611F23`**（渐变最暗底色，垫住缩放后可能的微小缝隙） |
| 白字 / 白色底板 / Lua | 不变 | 不变 |

**效果**：普通态 = 红阶梯渐变卡 + 3px 描边 + 白字；选中态 `Controller:_grid_paint_highlight()` 给 `backrop1` 写 `HIGHLIGHT_TINT = 0xFFFFD44B`，**只有露出的 3px 一圈变黄，卡面红渐变不变** —— 即 515/523/544 的旧高亮方案，也符合《线索卡-设计规格》「选中态只改描边，外框尺寸不变」。

## 四、范围与未验证项

- **本轮未进行游戏内导入与真实渲染验证**；离线模拟只画静态层 + 5 行模板实例，文字为占位说明。
