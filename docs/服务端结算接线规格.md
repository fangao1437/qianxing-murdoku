## 二、真机侧：官方节点图怎么接（**这是交付项** ✓）

四条信号各自在服务端建一个**「收到客户端脚本信号」**触发器 + 动作：

### ① `murdoku/ready` —— 开局登记
- 动作：**设置自定义变量**（`Level`域）`ready_level = 参数0`、`ready_rows = 参数1`…
- 用途：服务端能知道玩家开的是哪一关（例如做排行榜/校验）

### ② `murdoku/solved` —— ★ 结案判定成功
- 动作：**设置自定义变量** `Level.solved_level = 参数0`
- ⇒ 这是"这一局推理成立"的**唯一服务端凭据** ✓

### ③ `murdoku/save` —— 存档点
- 动作：按需落库（本作目前只用客户端本地存档 ⇒ **可先不接** ✓）

### ④ ★★★ `murdoku/settle` —— 第 4 键「存档并结算」
- ★ 动作：**设置玩家结算成功状态**（服务端节点，枚举 **未定 / 胜利 / 失败**）⇒ 选 **胜利**
- 官方口径（本项目已核对过）：**「结算成功状态」决定合法退出时的结果** ✓
  （出处：`docs/编辑器搭建指南.md` L498、`docs/社区资料-交付包/验证报告.md` L420
   —— 与《关卡结算》文档"仅当逃跑合法性为『是』，该字段才有意义"一致 ✓）
- ⇒ ★ **这才是"结算"两个字的落点** ✓ 也就是说：
  **第 4 键按下去 → 客户端存档 + 发 `murdoku/settle` → 服务端把本局判为「胜利」** ✓

## 三、模拟器侧：先在本地把规则跑起来（便于回归）

模拟器没有官方节点图，但插件提供 `qxqy_studio_patch` 的 **`setServerLogic`** 作为**薄模拟**
（⚠️ 它是**模拟器存档格式，不是官方节点图**，别混为一谈 ✓）：

```json
{
  "op": "setServerLogic",
  "expectedRevision": 7862,
  "logic": {
    "rules": [
      {
        "id": "murdoku-solved",
        "signalName": "murdoku/solved",
        "actions": [
          { "kind": "setCustomVariable", "entityType": "Level",
            "name": "solved_level", "value": { "fromSignalParam": 0 } }
        ]
      },
      {
        "id": "murdoku-settle",
        "signalName": "murdoku/settle",
        "actions": [
          { "kind": "setCustomVariable", "entityType": "Level",
            "name": "settle_level", "value": { "fromSignalParam": 0 } },
          { "kind": "setCustomVariable", "entityType": "PlayerSelf",
            "name": "settle_win", "value": true }
        ]
      }
    ]
  }
}
```

用法：`fromSignalParam` **从 0 开始**，指"监听信号的第一个参数" ✓

### 接上之后怎么验（可复跑）
```
qxqy_studio_play { action: "serverGet", args: { entityType: "Level", name: "settle_level" } }
```
- 打通 ⇒ 回读 `"selftest_theft_5x5"` ✓
- 没打通 ⇒ 变量不存在（未定义变量的 Get 返回 nil）✗

## 四、这条为什么**必须**在真机上再验一次

| 理由 | 说明 |
|---|---|
| ★ 模拟器的 `setServerLogic` **不是**官方节点图 | 它只证明"信号发得出去、参数对"✓，**不证明节点图接对了** ✗ |
| ★ 官方「设置玩家结算成功状态」的**枚举名**与**生效时机** | 《关卡结算》写了"仅当逃跑合法性为『是』该字段才有意义" ⇒ **中途退出**那一支要一起验 ✓ |
| ★ `murdoku/solved` 的占位参数 | 真机上是否也恒为 0，要读一次真机日志确认 ✓ |

⇒ 真机验收三问（照抄进真机清单）：
1. 通关后服务端变量 `solved_level` / `settle_level` **有没有值**？
2. 点第 4 键「存档并结算」后，本局在服务端是否被记为 **胜利**？
3. **中途退出**（不点第 4 键）时，结算状态是否仍为 **未定**（不被误判）？
