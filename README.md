## 3. 怎么把设计好的关卡编进去（你唯一要做的事）

### 3.1 推荐：用生成器（会把最容易翻车的空间结构算给你看）

```powershell
$lua = "$env:LOCALAPPDATA\Programs\Lua\bin\lua.exe"

# ① 画一张纯文本图（答案 + 墙 + 门），先干跑看 R3/R4 自不自洽
& $lua tools\new_level.lua tools\examples\level_grid_example.txt --thief=D --victim=V --dry

# ② 填线索，然后校验（必须看到「唯一解: OK」）
& $lua tools\validate_levels.lua 3
```

全流程与图文件格式见 **`docs/关卡生成器用法.md`**。

### 3.2 手动：复制模板

1. 复制 `lua/levels/template.lua` → `lua/levels/case_00N.lua`
2. 填 `size / walls / doors / suspects / objects / victim / roles / solution / clues`
3. 在 `lua/levels/init.lua` 的 `LIST` 里加一行（**顺序 = 游戏里的关卡顺序**）
4. `& $lua tools\validate_levels.lua 3` —— 格式 / 结构 R3R4 / 假话 / 唯一解 全绿才算过

**六条设计要点**（都是踩坑得出的）：

- **`#suspects` 必须等于 rows 也等于 cols**（5×5 就 5 枚棋子，6×6 就 6 枚）。
- 受害者所在区域里**有没有别人**决定要不要同伙：k=1 → 可以没有；k≥2 → **必须有且仅有 1 个**。
- 相邻区域（由 `doors` 定义）里的**无辜人数不能并列**（`tie_policy = "forbid"`），
  否则盗窃者不唯一，校验器会直接报错。
- **`left_of / right_of / above / below` 在本作里恒为假**（它们要求同行/同列，
  而本作开了 one_per_row + one_per_col），别用它们表达"谁在谁左边"；
  用 `col_offset` / `row_offset` / `compass` / `distance`。
- **要用角色别名** `@thief` / `@accomplice` / `@victim` 承担身份推理，
  否则把每个人的坐标直接报出来，玩家没得可推。
- **`meta.false_clue = N` 的 N 要等于实际不成立的那条序号**；校验器会核对。
  **反镜像**：别名把位置钉住时，补一条实名身份线索（如
  `{ type = "not_role", who = "D", role = "accomplice" }`），否则会出现两个解。

**界面容量硬限制**（`tests/ui_math.lua` 会自动查）：
**线索条数 ≤ 18**（超出的线索不会生成控件，玩家看不到）、**棋盘 N ≤ 7**（8×8 是 16 亿摆位）。

界面是**自适应**的：格子边长 = 可用边长 ÷ N，编辑器按最大 N 建一次即可，
5×5 / 6×6 / 7×7 共用同一套控件。

自查（强烈建议）：

```lua
local Core = require("murdoku_core")
local lv   = require("levels.case_001")
local core = assert(Core.new(lv))          -- 1) 格式与参数校验
for id, p in pairs(core.solution) do       -- 2) 答案必须满足全部线索
  core:select_suspect(id); core:tap_cell(p.r, p.c)
end
print(core:submit().ok)                    -- 必须 true
print(#core:solve(2))                      -- 3) 等于 1 才是唯一解
```

字段与 **54 种线索**的完整说明见 `docs/关卡数据格式.md`。
想加自定义线索，往 `M.clues` 里注册一个 `validate + text` 就行，引擎不用动。
想不出来线索时可以用 `lua tools/find_clues.lua lua/levels/xxx.lua` 暴力搜（慢，当兜底）。

`docs/控件坐标表-1600x900.md`）：

```
┌───────────────────────────────────────────────────────────────┐

├───────────────────────┬───────────────────────┬───────────────┤
│ 左侧面板               │ 中央棋盘               │ 右侧信息栏     │
│ · 嫌疑人头像卡（选中/  │ · C1..Cn / R1..Rn 坐标 │ · 已放置 n/N   │
│   已放置两种状态）     │   尺                   │ · 位置正确 n/N │
│ · 线索卡（逐条带满足   │ · 格子（墙/家具/受害者 │ · 硬性冲突列表 │
│   状态，失败抖动）     │   /X 标记/笔记）       │ · 分享码       │

```

**交互状态机**（照 murdoku 实证规格的手感）：

| 操作 | 结果 |
|---|---|
| 点头像卡 | 选中/取消选中（已放置的卡片下沉 2px） |
| **单击 / 轻触格子** | 写/删**铅笔小字笔记**（不占位；延迟 0.35s 判定，避免抢在第二次点击前） |
| **双击格子**（≤0.35s） | **放置**该角色，并清空选中 —— **鼠标/PC 主路径** |
| **长按格子**（≥0.45s 不动） | **放置**该角色 —— **移动端主路径**（手指没有可靠的"双击"）；长按后**抑制**尾随的那次点击 |
| 按住后划走（>24px） | 取消，不算点击（防手指滑动误判） |
| X 工具 | 该格**不可能**（X 标记，可与笔记互斥） |
| 橡皮擦 | 单击清该格；**双击 / 长按橡皮擦工具清空全盘** |
| **键盘（PC 可选）** | 方向键移动光标、`Space` 笔记、`Enter` 放置、`1..7` 选人、`Tab` 换工具、`Z/Y` 撤销重做、`H` 提示、`Esc` 选关 |
| 撤销 / 重做 | 逐步回退（放置、笔记、X、擦除都在栈里） |
| 提交 | 未摆满时按钮禁用；摆满后校验硬约束 + 逐条线索，失败线索抖动 |
| 摆位成立 | 弹出「谁是盗窃者」（两段式：先盗窃者 → 再有没有同伙 → 有则指认同伙） |
| 指认正确 | 破案结算（用时/步数/误指认次数/位置正确数） |
| 分享 | 生成棋局分享码（可用 `decode_state` 还原） |
| 开屏教程 | 5 页：怎么破案 / 每行每列一人 / beside 的含义 / 单击写字双击放置 / 提交判题 |

> 为什么只用**方向键**移动键盘光标、不用 WASD？`W/A/S/D` 要留给别的快捷键（`S` = 提交），
> 混在一起必然误触。`KB_DELTA` 表里只有四个方向键。
>
> 图例会**按设备换文案**（`touch` 说"轻触/长按"，`pc` 追加一行键盘说明，`gamepad` 说明是兜底方案）。
> 完整规格（手势判定参数、设备分档、两端验收清单）见 **`docs/操作模式-2D双端输入.md`**。

**特效**沿用 murdoku 的动画语义（`M.EFFECTS`，**12 条**）：`pop_tile` 落子弹入、`sel_pop_glow` 选中脉冲、
`note_pop` 笔记、`pulse` X 脉冲、`vanish` 橡皮擦消失、`undo_flash`、`submit_nudge`、
`clue_box_pop` 线索卡刷出、`solved_flash` 破案闪光、`portrait_slide_up` 受害者头像顶出、
`roomwall` 区域墙（备用）、`shake` 指认错误。

## 5. 规则对齐说明（重要）

> **本工程已按用户需求改成「偷窃版」规则**：主题=盗窃、角色=盗窃者 + 可选同伙、
> 区域相邻由**门径**定义、盗窃者选**无辜人数最多**的相邻区域、线索**至多一句假话**。
> 完整规格见 `docs/规则规格-偷窃版.md`。下表是**与 Murdoku 原规则一致**的部分。

框架按 murdoku 官方规则实现，而**不是**按"数独"的直觉：

| 规则 | 实现 |
|---|---|
| 棋盘是 **N×N**，N = 棋子总数（含受害者） | `#suspects == size.rows == size.cols` |
| 每行、每列恰好 1 人 | `rules.one_per_row / one_per_col`（默认开） |
| 受害者也要摆上棋盘 | `victim = { id = "V" }` 并把它列进 `suspects`（`{r=,c=}` 写法也支持，视为固定格） |
| "旁边(beside)"= 四邻且**同一房间** | `beside` 线索；跨墙的相邻不算 |
| 能不能站人由**家具**决定 | `objects` 里 `occupiable = false` 的家具所在格自动不可站；也可用 `blocked` 手工限制 |
| 线索可以引用家具物体 | `beside_object / on_object / only_on_object / only_beside / same_room_as_object` |
| 有"空房间/水里/椅子上的人数"这类全局线索 | `no_empty_room / one_empty_room / nobody_in_water / one_on_object / n_on_object` |
| ~~凶手 = 与受害者单独共处一室的人~~ | **已改**：盗窃者 + 可选同伙，规则见规格 R2–R4；结案走 `core:accuse_verdict(盗窃者, 有无同伙, 同伙)` |
| 每房间最多 1 人 | `rules.one_per_room`（默认关，按你的关卡设计开） |

> 因为"每行每列恰好 1 人"，`left_of / same_row / adjacent` 这类同排线索在数学上恒为假，
> 设计关卡时别用；**房间类、家具类、绝对行列类、斜对角(compass)类**才是主力。
> 完整 54 种线索见 `docs/关卡数据格式.md` 第 6 节。
