# 玩法三条新规则 —— 契约、实现与证据（v279 · 2026-10-20）

> 本文只讲这一轮新增的三条规则：**它们各自管什么、管到哪、怎么验证、哪些还没验证**。
> 运行/维护手册仍看 [`技术架构.md`](技术架构.md)（本文末尾"§七"那节是本次结构性改动的登记）。
> 用例在 `tests/rule_guards.lua`（99 断言）＋ `tests/cases/v279-rules.json`（模拟器用例）。

## 一 用户原话 → 契约

| # | 用户原话（2026-10-20） | 落成的契约 | 代号 |
|---|---|---|---|
| 1 | 「**已经放置的人物的同行同列内不能再放置其它人物**」 | 交互层拒绝：目标行或列上**已有别人**时，放置不生效、盘面不变、给原因 | **P** |
| 2 | 「**x 标记和 note 标记互斥**，通过**任何方式**出现的 x 标记都会擦掉对应位置的所有 note，在 x 标记上标记 note 时也会**在标记的同时**擦除 x」 | 状态不变量：一格**不允许**同时有 ✗ 与笔记；两条方向都要成立，且**所有**产生 ✗ 的路径都要擦笔记 | **X** |
| 3 | 「**不可放置人物的障碍物上也不可进行 note 标记**」 | `blocked` 格拒绝铅笔笔记（✗ 仍然可以打） | **B** |

## 二 规则 P：同行同列不可再放别人

### 2.1 判定口径（两个容易误伤的点，都写进用例了）

| 情形 | 结果 | 为什么 |
|---|---|---|
| 第 2 行已有 A，把 B 放到第 2 行空格 | **拒绝** | 用户要的就是这条 |
| 第 3 列已有 A，把 B 放到第 3 列空格 | **拒绝** | 同上 |
| **A 从 (2,2) 挪到 (2,4)**（同一行内换位） | **允许** | 判据是「**其它**人物」；同一个人换位等价于"撤销后重新放置"，拦了就没法调位置 |
| 把 B 放到 A **所站的同一格** | **允许** | 目标格的旧人**会离场**（换人站同一格），终局仍是"一行一人" |
| 关卡 `rules.one_per_row = false` | 同行不拦（同列仍拦） | 沿用 `Core:rules()` 的开关；`tests/selftest.lua` 有这个形状的探针关 |
| 双击（预放置） | **同样拦** | 用户口径是"不能再放置"，没区分正式/预放置 |
| `hint()` / `decode_state()` / `deserialize()` | **不拦** | 见 2.3 |

### 2.2 拒绝文案（会进日志 / `_refuse` / 真机抖动）

```
第1行已经有值班保安了，同一行只能站一个人
第3列已经有值班保安了，同一列只能站一个人
```
由 `Core:row_col_conflict(r, c, id)` 生成，`text` 字段既是界面提示也是断言串。

### 2.3 为什么守卫**不在** `do_place` 里（关键决策）

`do_place` 还被 **`Core:hint()` / `Core:decode_state()` / `Core:deserialize()`** 以 `record = false` 调用。
把守卫塞进去的后果是：**载入一份"同行两人"的旧存档 = 静默丢子**（数据被改而作者不知道），
分享码解码也会半途失败。⇒ 守卫只放在**交互入口**（`hold_cell` / `pre_place`），恢复路径不受影响。

⚠️ 还有一个顺序陷阱（没踩到，但要记住）：`hold_cell` / `pre_place` 都是**先**
`move_piece_if_needed`（把这个人从旧格拿走）**再** `do_place`。
若守卫写在 `do_place` 里、拒绝时角色**已经离开旧格且没落到新格** ⇒ **人凭空消失**。
现在守卫前置在 `move_piece_if_needed` **之前**，所以拒绝时盘面一个字节都没动（用例 P1 钉住这条）。

## 三 规则 X：✗ 与铅笔笔记互斥

### 3.1 不变量

> **一个格子任意时刻不允许"既有 ✗ 又有笔记"**；冲突时 **✗ 赢**（因为 ✗ 是"这格排除掉"的强结论）。

### 3.2 「任何方式出现的 ✗」= 下面**四条路**，四条都要擦笔记

| ✗ 的来源 | 代码位置 | 擦笔记 | 可撤销还原 |
|---|---|---|---|
| ① 手动点亮 ✗（单击空格 / X 键 / 右键 / `MODE_X`） | `Core:toggle_x` | ✅ | ✅ `prev_notes` |
| ② **放置派生的自动 ✗**（同行同列） | `do_place` 内的 `auto_x()` | ✅（本轮新增） | ✅ `auto.x_notes` |
| ③ 读档（脏存档 / 旧存档） | `Core:deserialize` | ✅ 清洗 | —（载入即事实） |
| ④ 分享码解码 | `Core:decode_state` | ✅ 拒绝写笔记 | — |

另外 `Core:serialize` 在**写出前**再收一次口（✗ 优先、障碍格不写笔记），保证存档往返不会产出脏格。

### 3.3 反方向：在 ✗ 上打笔记 ⇒ **同一个动作**里擦 ✗

`toggle_note` 里做两件事（擦 ✗ + 落笔记），并记进**同一条历史**（不拆成两条，否则撤销要点两下）。
历史条目新增两个字段：`on`（这一击是加还是去）、`was_x`（顺带擦掉的 ✗）——
`Core:undo` / `Core:redo` 都按它们**精确反演**，不再靠"翻转当前值"猜。

### 3.4 撤销语义（**新增**：被 ✗ 擦掉的笔记要还回去）

| 撤销的动作 | 结果 |
|---|---|
| 打 ✗ | ✗ 撤掉，**被它擦掉的笔记恢复**（`prev_notes`） |
| 在 ✗ 上打笔记 | 笔记撤掉，**✗ 恢复**（`was_x`） |
| 放置 | 棋子撤下，自动 ✗ 撤掉，**被自动 ✗ 擦掉的笔记恢复**（`auto.x_notes`） |
| 拿起棋子（单击已占格） | 同上（走同一个 `revert_auto`，不是第三条路） |

⚠️ **仍然不还原**的一样东西（2026-09-28 用户定过，别好心改回去）：
`auto.notes` = **正式放置时擦掉的"该人物自己的草稿"**。定案后的猜想不该复活。

### 3.5 顺手做的重构（为什么值得记）

"还原一次放置派生出来的改动"原来在 `do_clear` / `restore_auto_of` / `Core:undo` **三处各写一遍**
（本文件自己的注释都记着"同一个概念散在三处实现，就一定会漏一处"，上一轮就漏过"直接拿起"那条路）。
本轮规则 X 又要多还原一样东西 ⇒ 收成 **`revert_auto(self, auto)` 一个函数，三处都调它**。

## 四 规则 B：障碍格不可打笔记

| 动作 | 障碍格（`occupiable = false`） | 普通格 |
|---|---|---|
| 打 / 擦 **✗** | ✅ 允许（**保持** 2026-09-29 的解禁） | ✅ |
| **铅笔笔记** | ❌ 拒绝：「这格是障碍物，站不了人，也不能打笔记」 | ✅ |
| 放人 | ❌ 拒绝（旧行为） | ✅ |

### ⚠️ 与旧结论的冲突（如实记录，别把旧注释当依据）

`murdoku_core.lua` 里 2026-09-29 那段注释写着"**去掉 `blocked` 门控**……正是那种格子最需要能打笔记"，
依据是用户当时报「R1C5 不能做铅笔笔记」。**本轮用户改主意了**（原话见 §一 #3）。
现在的口径是**一开一关**：✗ 开着、笔记关掉。
⇒ 代码里两处旧注释都保留了原文并**追加**了"2026-10-20 用户改主意"的说明，
   `tests/selftest.lua` 的旧断言「不可站人的格子**能**打 X」**保留**（它仍然成立），
   并**补了 3 条新断言**（障碍格不能打笔记 / 拒绝带原因 / 被拒后仍无笔记）。

## 五 用例映射（`tests/rule_guards.lua`，99 断言 / 0 失败）

| 节 | 钉住什么 |

| B4 | 普通格打笔记照旧（对照组） |
| B5 | 脏存档把笔记塞进障碍格 ⇒ 载入清洗 |
| R1–R4 | 回归：拿起还原自动 ✗ / 正式放置后禁打该人笔记 / 笔记与 ✗ 不计步（历史 kind 不变）/ 全盘不变量 |

## 七 已知限制 / 真机核验清单

1. **模拟器看不到棋盘**：24 个 `cell.*` 要由 `game.InstantiateClientUIControl` 运行时生成，
   而模拟器里没有"可实例化"的客户端控件模板 ⇒ 日志「有 24 个格子还没建…**全部实例化失败**」。
   ⇒ **模拟器截图不能用来证明盘面显示**（这是环境限制，不是规则缺陷；真机有模板层）。
   ⇒ 本轮模拟器证据全部走**日志**（`_refuse` + 放置分辨），并用**键盘**驱动（不依赖格子控件）。
2. **`_refuse` 的抖动反馈**（`M.EFFECTS.FAIL = "shake"`）在 2.0.8 模拟器里是**空操作**
   （平台事实：动画播放不生效）⇒ **只能真机看**。真机验收：对同行/同列格子长按，格子应抖一下。
3. **关卡内仍然没有 toast 出口**（`hud.toast` / `hud.subtitle` 已按美术结论删除）。
   拒绝原因目前只进：日志 + 抖动 + `self.toast`（关卡内无出口，主页才有）。
   ⇒ 若要"文字提示上屏"，那是**新增控件位**的活，不是这一轮的范围。
4. 真机要确认的三件：① 长按同行格 → 不落子且抖一下；② 障碍格长按/点击 → 不出笔记；
   ③ 打 ✗ 后同行同列的字母确实消失、撤销能回来。
