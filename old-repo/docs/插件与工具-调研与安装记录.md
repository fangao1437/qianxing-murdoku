## 0. 先搞清：DSH 的插件是怎么装的

这一节是后面所有安装动作的依据，全部由**读本机文件**得到，不是猜的。

| 事实 | 依据 |
|---|---|
| Harness home = `C:\Users\18182\.dsh` | 环境变量 `DSH_HOME` |
| profile 目录 = `C:\Users\18182\.dsh\profiles\desktop` | 环境变量 `DSH_PROFILE_DIR` |
| 插件装在这个 profile 目录里，装法 = `pnpm add` + 往 `package.json` 的 `dsh.profile.bundles` 追加一行 | `@deepseek-ai/dsh/lib/plugin-DkYIj96-.js`（`runPlugin` → `runPluginCommand`） |
| 一个插件包的 `package.json` 用 `dsh.bundle.patch` 声明自己的 patch 层文件 | `dsh-community-market/package.json`、`dsh-plugin-miliastra-toolbox/package.json` |
| `dsh plugin --profile desktop …` 被 CLI **硬拒**：`error: profile "desktop" is managed exclusively by the Electron application` | `@deepseek-ai/dsh/lib/bin.js:36` |

| `dsh.cmd` 依赖 `DSH_DESKTOP_APP_EXECUTABLE` / `DSH_DESKTOP_DSH_BOOTSTRAP` 两个变量，本 shell 里没有 ⇒ 直接用 `desktop-cli.js` 等价调用 | `%APPDATA%\DSH Desktop\cli\<gen>\bin\dsh.cmd` |

**本文使用的等价调用（复现用）**：


## 3. selene 首轮就抓到的东西（**只报告，未改动 `lua/**`**）

配置：`tools/lua-tooling/selene.toml`（`std = "lua53+qianxing"`）。
**调参前 1110 条 → 调参后 60 条**，减少的 1050 条全是本工程有意为之的风格类，见表格下方说明。

| 类别 | 条数 | 说明 |
|---|---|---|
| `unused_variable` | 46 | 多为刻意（占位/只用于打印），噪音为主 |
| `undefined_variable` | 6 | 真问题（见下） |
| `unscoped_variables` | 5 | **真问题**：漏写 `local`，变量会泄进引擎全局表 |
| `empty_if` | 2 | **真问题**：条件写了、分支没写 |
| `parse_error` | 1 | **真问题**：文件开头有 BOM |

具体位置（值得逐个看）：

| 位置 | 类别 | 判断 |
|---|---|---|
| `lua/entry_client_script.lua:1:1` | `parse_error` `unexpected character` | **文件开头有 UTF-8 BOM**。工程的 `tools/normalize_encoding.ps1 -Check` **独立确认**了同一件事。后果：打包成单文件后 Lua 5.3 报 `unexpected symbol near '<\239>'` 且行号指向文件末尾（见 `check_all.ps1` 2c 步的注释）。⚠️ **16:5x 之后这个 BOM 已被清掉**（不是我清的 —— 见 §5），现在 `lua/` 下已无 BOM 文件，`parse_error` 从报告里消失 |
| `lua/main.lua:872:23` / `:873:23` | `unscoped_variables` `v2` / `a2` | **漏写 `local`** ⇒ 泄进引擎全局表。且第 875 行直接 `.. v2 ..`/`.. a2 ..` 拼接 —— 上面的 `pcall` 一旦抛错，这两个还是 `nil`，**拼接会报错**（潜在真机崩溃，尽管在诊断分支里） |
| `lua/murdoku_core.lua:1168:6` | `empty_if` | 条件写了、`if` 块是空的 |
| `lua/murdoku_core.lua:2107:6` | `empty_if`（elseif） | 同上 |
| `lua/engine_adapter_qianxing.lua:2532,2533,2562` | `undefined_variable` `names` / `done` / `miss` | ⚠️ **见 §5：这些行是本次会话进行中被改出来的** |
| `lua/engine_adapter_qianxing.lua:2547,2548,2559` | `unscoped_variables` `done` / `miss` | 同上 |

> 条数是**会漂的** —— 并发写入期间实测到过 40 / 60 / 70 三个值。以
> `tools/lua-tooling/out/selene-report.txt`（每次运行覆盖）为准。

**为什么把 1050 条关掉了**（这条很重要，不关就白装）：

| 关掉的规则 | 条数 | 理由 |
|---|---|---|
| `multiple_statements` | 953 | 本工程大量 `if x then y end` / `x = 1 y = 2` 单行写法，是**有意**的紧凑风格 |
| `if_same_then_else` | 2 | **误报**：selene 只比较块体是否相同、不看条件。`main.lua:631` 那处是「① 旧结构 board/cell.1.1 → ready=true」和「② 新结构 stage/home → ready=true」，块体相同但语义完全不同 |
| `shadowing` | 10 | `local self = self` 这类适配层刻意写法 |

> 这正是「噪音淹没信号」的现实样本：不调参时 **1110 条里真问题只有 8 条**（0.7%）。

**stylua 体检**：13 个 lua 文件里 12 个会被重排 ⇒ 本工程是手写对齐风格。
所以 `lua_lint.ps1` **只跑 `--check`**，并且 `check_all` 里那一步**只报告不判失败**。

## 4. 没法装 / 不适用，以及原因

### 4.1 `luacheck` —— 未能安装（缺 C 编译器）

```
> luarocks install luacheck
Installing https://luarocks.org/luacheck-1.2.0-1.src.rock
luacheck 1.2.0-1 depends on argparse >= 0.6.0 (not installed)
Installing https://luarocks.org/argparse-0.7.2-1.src.rock
argparse 0.7.2-1 is now installed in C:\Users\18182\AppData\Roaming/luarocks (license: MIT)
luacheck 1.2.0-1 depends on luafilesystem >= 1.6.3 (not installed)
Installing https://luarocks.org/luafilesystem-1.9.0-1.src.rock
x86_64-w64-mingw32-gcc -O2 -c -o src/lfs.o -I…\Lua/include src/lfs.c
Error: Failed installing dependency: https://luarocks.org/luafilesystem-1.9.0-1.src.rock
       - Build error: Failed compiling object src/lfs.o
```

**根因**：`luacheck` 依赖 `luafilesystem`（C 扩展），本机**没有任何 C 编译器**
（`cl` / `gcc` / `clang` / `make` / `nmake` / `mingw32-make` 全部 not found；
`Program Files\Microsoft Visual Studio`、`LLVM`、`mingw64` 目录均不存在）。
`luarocks` 本身可用（用户级，装在 `%APPDATA%\luarocks`），装**纯 Lua** 的 rock 没问题
（`argparse` 就是这么装上的）。

**替代方案（按推荐顺序）**：

1. **用 `selene` 顶替**（已装·可用）。它覆盖同一类检查（未定义全局 / 漏写 local / 空分支 / 未用变量），
   且是预编译二进制，**零编译依赖**。本次就是走这条路。
2. 用 `lua-language-server --check`（已装）。诊断规则更细（`undefined-global`、`unused-local`、
   `redundant-parameter`、`need-check-nil` …），代价是要写 `.luarc.json` 且跑得慢。
3. 真要用 `luacheck`：先装一个**便携 MinGW**（如 `w64devkit` / `winlibs` 的 x86_64 包）解到用户目录，
   把这个 `bin` 加进 `PATH`，再 `luarocks install luacheck`。
   ⚠️ 本次**没有**执行这一步 —— 官方 release 只有 `w64devkit-x64-*.7z.exe`（自解压 7z，本机无 7z 可解）
   或 `winlibs-*.zip`（260 MB）。代价（~100–260 MB 下载 + 一个未审计的自解压 exe）与收益
   （多一个和 selene 重叠的 linter）不成比例，所以**主动放弃**，不是失败。

### 4.2 `busted` —— 不适用

- 同因：依赖链含 C 扩展（`luasystem`），没有编译器装不上。
- 更关键的是**没必要**：本工程已有自研测试件 `tests/*.lua`（`selftest` / `ui_math` /
  `effects_wiring` / `input_logic` / `entry_smoke` / `grid_cost` / `perframe_throttle` /
  `prop_ledger` / `hide_safety` / `board_bg`），直接用 `lua.exe` 跑，共 300+ 条断言，
  且**已经逐条接进 `tools/check_all.ps1`**（1/2/2b/2d/5b 步）。
  换成 busted 要把这些断言全部改写，纯亏。

## 7. 对我们最有价值的 3 件

### ① `dsh-plugin-beyond-simulator`（模拟器）
本工程的**整个验证闭环都压在模拟器上**（`tools/sim/` 有 24 个自研 `.mjs`，
`check_all` 的 8~15 步全是它）。而这个插件给的是**上游维护的**同一条能力，
并且多了我们现在**没有**的东西：GIA 导入导出、编辑器/试玩两侧截图、
多设备画布与多玩家视角、录制回放用例、以及实机 Lua 目录同步（`qxqy_script_sync`）。
它不是替换 `tools/sim/*.mjs`，而是把「模拟器这一侧」从自研变成有上游兜底 ——
以后 `.gil`/试玩行为变了，是上游跟着改，不是我们跟着改。

### ② `dsh-plugin-miliastra-toolbox`（知识库）
本工程现在对官方 API 的全部认知，来自 `docs/api-cache/*.txt` ——
那是一次性**手工抓取**的快照，必然过期，而且没有「按节点名反查归属端」的能力。
装上之后同一份语料变成**在线可查的 6 个工具**，且实测返回的 10 篇客户端文档
与本工程已缓存的 `mh*.txt` **一一对应**（互相印证语料是同一份）。
它直接对准本工程反复吃亏的那个病：**「我代码里的假设」和「官方文档」会漂**
（`check_all` 的 2e/2f「四方对照」就是为这个病写的；现在文档那一方有了活的数据源）。
成本几乎为零：不用装依赖、不用起服务、包只有 27 KB。

### ③ `selene` + 为这个代码库调过的配置
**投入最小、回报最快**：装完指向 `lua/` 几分钟内就报出 3 类真问题
（BOM 导致 `parse_error`、`main.lua` 两处漏写 `local` 且有潜在拼接崩溃、
`murdoku_core.lua` 两处空分支）。
真正值钱的不是 selene 本身，而是**那份把 1110 条压到 60 条的配置**：
`multiple_statements` / `if_same_then_else` / `shadowing` 三条按本工程现状关掉，
剩下的每一条都值得看一眼。没有这一步，装了也只是多一个刷屏的东西。
