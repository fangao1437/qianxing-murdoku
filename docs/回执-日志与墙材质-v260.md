## 一 ④ 选关卡片：为什么要再要一份日志

我这边能查到的只有"**存档里四张卡是分开的**"（`-374 / -125 / +125 / +375`），
而真机画面是"只有一张" ⇒ 说明**运行时**四张卡被摆到了一起（或三张不可见）。
模拟器里那套控件是脚本建的、读数与真机不一致，**验不了**这条 ⇒ 只能靠真机日志。

所以本版加了一行诊断（**每张卡只打一次**，不会刷屏）：

```
[murdoku] 选关卡框 select.card.1：w=208.98 h=291.6 pos=(-374.2,-4.5)
[murdoku] 选关卡框 select.card.2：…
```

判据：

| 日志形状 | 结论 | 我的下一步 |
|---|---|---|
| 四条 **pos 各不相同** | 编辑器里是分开的 ⇒ 叠的原因是**父级/层级**换算 | 改"按规划格重排 + 显式 pos_runtime" |
| 四条 **pos 完全相同** | 编辑器里就是叠着的（之前导入的副作用） | 同上，用规划格把它们撑开 |
| 只有 **1~2 条** | 另外几张卡**读不到**（没进树） | 查"控件不存在"分支 |
