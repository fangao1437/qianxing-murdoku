### 2.3 抽样方法

**方法 = 分层抽样（按域名分层）+ 层内等距抽样**

```powershell
foreach ($g in ($rows | Group-Object D)) {
  $list = @($g.Group | ForEach-Object { $_.U } | Sort-Object)      # 层内先排序 ⇒ 可复现
  $n = $list.Count
  $k = [Math]::Min($n, [Math]::Max(3, [Math]::Min(16, [int][Math]::Ceiling($n/70.0))))
  for ($i=0; $i -lt $k; $i++) {
    $idx = if ($k -eq 1) { 0 } else { [int][Math]::Round($i*($n-1)/($k-1.0)) }   # 等距，含首尾
    $sample.Add(@{D=$g.Name; U=$list[$idx]})
  }
}
```

- **为什么分层**：域名分布极度倾斜（前 2 个域名占 96.1%）。**纯随机抽样会几乎全抽到 `act-webstatic` 的图片**，等于只测了 1 个站。
- **层内配额**：`k = clamp(ceil(n/70), 3, min(16, n))` —— 大层封顶 16、小层保底 3、不足则全取。
- **层内等距**：排序后取等间隔下标（含首尾各 1 条），保证覆盖层内不同区段。

| 其中 `act-webstatic` | 16 |
| 其中 `act.mihoyo.com` | 11 |

```powershell
$req = [System.Net.HttpWebRequest]::Create($u); $req.Method='GET'; $req.Timeout=20000
$req.AllowAutoRedirect=$true; $req.AddRange(0,2047); $resp = $req.GetResponse()
```

### 2.5 ★ 方法自纠：第一轮抽样作废（记录在案）

1. **GET 兜底其实没生效**：PowerShell 5.1 里 `-Headers @{Range='bytes=0-1023'}` 被拒 —— 报错原文：
   `必须使用适当的属性或方法修改"Range"标头。 参数名: name`。

2. **`\n` 粘连**：链接总表 25.2% 的 URL 尾部粘了字面量 `\ndescription` / `\nsourceURL`。样本内 8 条命中，**全部落在 `act.mihoyo.com`**，而该域名的 200 不可信（§2.4）⇒ 这 8 条**判定为"无法证实"**，不并入可达数。

## 3. ③ 两个讲义是什么关系 + 15 MB 装了什么

### 3.1 `正文.txt` 是不是 `HTML` 的子集？—— **是，它就是 HTML 的纯文本转储**

方法：把 HTML 去掉 `<style>`/`<script>`/base64 与所有标签、解码 HTML 实体；把 TXT 按不可逆替换字符切成片段，逐段在 HTML 文本里找**逐字出现**。

```powershell
$htmlN = ($text -replace '[\s\u3000]','')
$segs  = ($t -split '\ufffd') | ForEach-Object { $_ -replace '[\s\u3000]','' } | Where-Object { $_.Length -ge 12 }
$in = @($segs | Where-Object { $htmlN.Contains($_) }).Count
```

**实测读数**

| 指标 | HTML | TXT |
|---|---:|---:|
| 原始字节 | 15,318,226 | 37,822 |
| 去标签后文本（去空白） | **7,463 字符** | **7,200 字符**（已剔除 442 个损坏符） |
| TXT 干净片段（≥12 字符） | — | **173 段** |
| 逐字出现在 HTML 中的片段 | — | **170 / 173 = 98.3%** |
| 逐字覆盖的字符数 | — | **6,424 / 6,641 = 96.7%** |

**3 段"未命中"全部是 HTML 实体差异**，不是内容差异：
```
拟合&amp;GIA转换工          ← TXT 保留了字面量 "&amp;"，HTML 里已是 "&"
提供。04【1】通过Agent+模拟器制作奇域常见问题&amp;更新指南…
```
⇒ **结论：两个文件是同一份材料的两种序列化**（HTML = 图文版；TXT = 文本转储，且**保留了 `&amp;` 实体**）。
⇒ **不是两份互补资料，是同一份的两份拷贝** —— 入库时保留其一即可，**不存在"两份都要"的理由**。

### 3.3 ★ 15 MB 的 HTML 适不适合进 git？—— **不适合，三个独立理由**

1. **它已损坏**（§1.2）：打开即乱码，`<title>` 都是 `åæå¥å…`。**入库一个打不开的文件没有意义。**
2. **体积/版本控制**：98.2% 是 base64 文本，而 base64 **每 3 字节膨胀成 4 字符**，且**行内大块 base64 几乎无法被 git 增量压缩**。任何一次"重新抓取"都会让整个 15 MB 全量进入 `.git` 历史，**不可回收**。
3. **它与 37 KB 的 TXT 内容重复**（§3.1，98.3% 逐字重合）——留下来是**纯冗余**。

**替代方案（按推荐顺序）**：

| 方案 | 做法 | 代价 |
|---|---|---|
| **A（推荐）** | **只留链接，不留正文**：索引里记 `https://ppt.070077.xyz/beyond-ai/index.html`。**同时解决 ③ 和 ⑥（版权）** | 0 字节 |
