## 2. 为什么 `tpl.prim` 是两条记录（模板模型，实测依据）

仓内 `probe_ui_registry.mjs` / `docs/钻取-开关控件GUID重复-2026-10-21.md` §2.4 实测的**模板对**：

```
模板源（★ lua 的 prefabIndex 用它）
  · 无父（顶层没有 #504）、不在任何子列表里 —— "仅存为模板"在 .gil 里的样子
  · 组件号 [1,2,4]： #502[2]/#12 = 模板族号； #502[4]/#14/#501 = 指向母本 GUID
  · 本档真机可用例：cell.1.1#1073741876（cfg.cells.prefab）、tpl-container#1073742330（stage.prefab）
母本（master）
  · 父 = ClientUIPrototypeHierarchyRoot (#1073741844，不是记录节点)
  · 组件号 [1,2,3]： #502[3]/#13/#501 = 指回模板源 GUID
  · 本档例：cell.1.1#1073741880、tpl-container#1073742355、hex#1073742356
```

- 官方原文：「**仅存为模板**的客户端控件的父节点，支持通过接口 `ClientUIBaseControl` 被动态创建」；
  「除**客户端控件容器画布中的客户端控件**以及**客户端控件模板中的控件**外，其他控件均为服务器控件，
  服务器控件的模板索引无法被客户端脚本调用」。
- `docs/API-四方对照.md` §17：用户真机实验，只有"模板引用控件/模板"这条链让
  `InstantiateClientUIControl` 成功，且**传的是模板源记录的 GUID**（1073741876）。
- ⇒ 本工具按**本档自己的 `hex` 模板对**（源 `hex#1073742357` ↔ 母本 `hex#1073742356`，族号 53）克隆，
  换新号/新名/新族号 78，不引入任何外来记录（E12：外来记录会反复被编辑器挡）。

### `tpl.prim` 两条记录逐项

| | **模板源（= prefabIndex）** | **母本（master）** |
|---|---|---|
| 记录 GUID | **`1073746302`** | **`1073746303`** |
| 父 | **无（`#504` 缺失，孤儿）** | **`1073741844`**（ClientUIPrototypeHierarchyRoot） |
| 组件号 | [1,2,4]；`#14` → 母本 6303 | [1,2,3]；`#13` → 源 6302 |
| 模板族号 `#12` | **78**（全档原用 13…77，未撞） | **78** |
| 名字 | `tpl.prim` | `tpl.prim`（与源同名，仓内惯例） |
| 尺寸 / 锚点 | 1×1，锚点/中心 0.5（4 个状态块） | 1×1，同 |
| imageId / imageColor / imageType | **100001 / 0xFFFFFFFF / 1（Stretch）** | 同 |
| 初始可见性 | **false（隐藏）** | false |
| 遮罩/羽化 | `#505/503/84` 节点只有 `#502/#503/#504` 三个叶子，**无 `enableMask`/`softEdge` 字段**（= 关闭） | 同 |

- **imageSource**：`.gil` 里**没有独立字段**（`gen_tutorial_teach.mjs` v291 实测结论：图片槽只有
  `#502` 染色 / `#503` imageId / `#504` 类型；模拟器侧统一 `StaticReference`）⇒ 克隆自本档模板即 `StaticReference`。
- **"关闭模板遮罩/烘焙"**：我们克隆的是**本档已是模板的 `hex` 模板对**，其图片槽上没有遮罩/羽化叶子；
  烘焙是编辑器"存为模板"时的动作选项，`.gil` 记录里没有对应字段 ⇒ 从既有关闭状态的模板克隆即可；
  本工具断言 `#84` 下没有 `#508/#509…#516` 这些遮罩/羽化族叶子。

## 7. 已知风险 / 边界

1. **模板源 GUID 的可用性**：`prefabIndex=1073746302` 是按仓内**已真机验证**的模板模型复刻的
   （与 1073741876 / 1073742330 同构）；但**本轮没有真机验证**新模板能否实例化。真机若返回 nil：
   ① 确认模板源仍是"孤儿"（不在任何子列表）；② 换号重跑；③ 退路：直接用本档已验证的
   `cell.1.1#1073741876` 当宿主模板不可行（那是容器），可改用 `tpl-container#1073742330`（容器）
   —— 图片图元必须用图片模板，所以还是需要本模板。
2. **模板族号 78**：全档原来 13…77；新族独立，不污染旧族。真机若报族冲突 ⇒ `--family=79` 重跑。
3. **号段只保证与本档不撞**（E14）：1073746300–6303；真机若报 GUID 重复 ⇒ `--guid-base=1073746400` 重跑。
4. **本轮只做结构**：`furn` 是空容器（无子控件）；`tpl.prim` 是模板源+母本，不挂在 root/任何画布上；
   运行时由 lua 在 `furn` 下逐个 `Instantiate` 图元。`things` 不写 palette。
5. **`furn` 初始可见=true**：父级隐藏会连坐子控件，脚本再点不亮；故保持可见（容器本身无图，不挡画面）。
6. **两份 content 都改了**（E6）：编辑器重导出覆盖后需对新基线重跑（工具幂等，`--in=<新基线>` 即可）。
7. `list_names tpl.prim` = 2 是**预期**（模板源+母本同名）；接线只用 `父=null` 那条（1073746302）。
