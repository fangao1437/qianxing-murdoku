## 二、A/D 互换：为什么「卡序对调」不能做，「姓名对调」可以

用户质疑「仅换内容顺序不应该会改变谜题结构，为什么不能直接换」。实测（第4关，v15 现状 vs A/D 两卡整句对调）：

| 项 | v15 现状 | A/D 整句对调 |
|---|---|---|
| 真假向量 | `[1,1,1,1,0,1]` | **完全相同** |
| 全真摆法 / 盗窃者 / 严格审计唯一性 | `0 / E / True` | **完全相同** |
| 各人物「假设其口供为假」的解数 | `[0,0,0,0,1]` | **完全相同** |
| 摘掉后严格题仍唯一 | 无 | **第 1 卡 → 变冗余** |
| 28 项闸门 | PASS | **FAIL（仅「删卡非冗余」一项）** |

结论：**用户对「谜题结构不变」的判断是对的** —— 解、真假、身份全不变。挂掉的是 34 关标准里那条「**删卡非冗余**」：验证引擎把「第 h 张卡」当作「人物 h 的口供」来摘，摘掉谁的口供、看还能不能定案。整句一换，A 名下挂的是讲 A/D 相对位置那句，摘掉它 A 仍能被其余 5 句定位，这张卡就不再是必需的了。即**卡序与人物身份是绑定**的（这也是 688 每个候选顺序都要重跑闸门的原因）。全 6! 枚举中满足「槽1=原卡4 且 槽4=原卡1」且通过全部闸门的顺序为 **0 个**。

因此按确认口径只做**姓名对调 + 卡面重渲染**：谓词、卡序、几何、答案、真假向量一个字不动，28/28 全通过。第4关卡面变化示例：

## 五、三格地毯：独立新建素材 + 完整引用路线

### 为什么是两套
两关的「三格地毯」都是 **L 形三连、bbox 2×2**，但朝向互为镜像：
- 第3关 `(3,2)(3,3)(4,2)` → 缺**右下** → `furn.rug.4` / `L3a`
- 第7关 `(2,3)(2,4)(3,4)` → 缺**左下** → `furn.rug.5` / `L3b`

各建独立素材而非拉伸/翻转，避免 691 记录的「2×2 bbox 回退 h2 双格模板、压扁、双绘」问题。

### 素材结构（与 `furn.rug.2` 完全同构，克隆而非拉伸）
每套 **23 条记录**：源（parent=null，150×150）＋母本（parent=`ClientUIPrototypeHierarchyRoot`，150×150）＋`things` 引用控件（80×80，`referencedPrefabIndex` → 新源 ID）＋2 份 `content`（**216×216**）＋**9 层 × 2**（3 个格位 × 3 圈：外框 108、内面 82.08、内框 64.80；格位中心 x/y = ±54；颜色 `0xFFB89A62 / 0xFFDCC684 / 0xFFC9B072`；图元 100001；零溢出；未静态隐藏）。

### 引用链（全部补齐，与现有家具一致）
```
源/母本/引用三件套 → things.childList (11 → 13)
→ path_map["furn.rug.4"|"furn.rug.5"]
→ cfg.furn_tpl_prefab.rug_4/rug_5 (新源 ID 1073760711 / 1073760734)
→ cfg.furn_tpl_canvas {216,216}、furn_scale_axis_by_kind {x=1,y=1}（等比 1:1，不缩放）
→ F.layout 识别「3 格 + 2×2 bbox」→ variant L3a/L3b（并停止逐格 els，避免双绘）
→ build_layout 采用 p.variant → TPL_KEY.carpet.L3a/L3b → furn_tpl
→ _spawn_furn_tpl 放行新 ckey（地毯隐藏分支排除 rug_4/5，is_rug 纳入 rug_4/5）
→ InstantiateClientUIControl + SetSizeDelta(2格×2格)
```
`objects` 数据**未改**（仍是 `kind="carpet"`、3 个 cells），保持谜题与 691 的几何语义。其余地毯（第4/5/6 关的单格、横双、非连片块）继续走 691 的逐格 `rug_cell_els` 路线，行为级验证已确认未被破坏。

示意图：`692_示意_三格地毯.png`（层/颜色/尺寸从 692 .gil 实读，右栏为被否决的拉伸做法）。
