# 真机问题：选关页点不动 —— 定位过程与修法

> 2026-10-02 凌晨。**结论：真正的原因是 `home` / `select` 这两个"容器"是用「预设按钮」原型做的**，
> 铺满屏幕之后就是一个**全屏按钮**，把整个界面的点击（以及你听到的点击音）全吃了。
> **修法在编辑器里，不在脚本里。**

---

## 一、你提供的四条观察（每条都推翻了我一个错误假设）

| 你说的话 | 它证明了什么 |
|---|---|
| **「新控件可见」** | 运行时新建的能显示、编辑器里已有的不能 ⇒ 问题在**编辑器已有控件**的几何上（而不是渲染层）|
| **「选关页点哪里都有音效，主页点空白没有」** | 选关页上有一个**铺满全屏、能发出点击音**的东西在吃射线 |
| **「消失的是选关界面该有的按钮，而不是那个不该有的按钮」** | 把容器缩成 1×1 之后按钮消失 ⇒ **引擎会按父级矩形裁剪** ⇒ 容器**不能缩** |
| **「现在依旧处处有音效」** | 那个吃点击的东西**不是** `home` / `select` 本身（它们已经 1×1 了）—— **当时我这么以为，后来被你下一条否掉** |
| **「全是我在编辑器里做的（卡片/标题/返回键）」** | **游戏没有自己的选关界面** ⇒ 吃点击的只能是**脚本自己的控件** ⇒ 回到 `home` / `select` |

**⇒ 最后两条合起来**：那个全屏按钮**就是 `select` 容器**（缩小之后它不吃点击了 ——
所以"依旧有音效"那条实际上是**在缩小版上**观察到的，而缩小版把按钮裁掉了，
你看到的是**被裁之后残留的东西**）。

## 二、为什么它是"按钮"

**⇒ 这正好命中我在《工作约定-优先直改控件》里自己记过的一条**：

> **容器要克隆真正的容器原型（不能用按钮原型）**

**⇒ 而日志里那条自相矛盾的结果也解释得通**：

```
容器 select 字段： raycastTarget=nil  disableCursorEventPassthrough=false
                   interactable=nil   blockRaycast=nil   showCursor=false
可接收光标=false
```

**⇒ `raycastTarget` 这个字段在这个引擎里**根本不存在**（`nil`）** ⇒ 我前两版改它全是白改；
**"可接收光标=false"** 说的是**没有挂事件监听**（`AddCursorEventListener == nil`），
**不等于"不参与射线"** —— 一个按钮原型**即使不挂监听，也会吃掉射线、并播出它自带的点击音**。

## 三、修法（**在编辑器里，5 分钟**）

1. 在千星奇域编辑器里打开这个奇域
2. 找到 `home` 和 `select` 这两个控件（它们是**顶层**的，就在 `root` 下）
3. **看它们的类型** —— 如果是「**预设按钮**」/「交互按钮」，那就是问题所在
4. **把它们换成「容器节点」/「客户端控件容器」原型**：
   - 最干净：删掉它们，用「容器节点」新建两个，改名回 `home` / `select`
     （尺寸随意，脚本每帧会把它们设成全屏；子控件由脚本重建/重新挂）
   - 或者：保留它们，但**在编辑器里把它们的"点击/音效"关掉**
     （如果编辑器里能取消勾选「可点击」「播放点击音」之类）
5. 重新打包导入

**⇒ 判断有没有改对的最快办法**：改完进选关页，**点空白处** ——
**没有点击音效**就说明那个全屏按钮没了 ✅；有音效就说明还没改掉 ❌。

## 五、我这一夜的教训（写给以后的自己）

**⇒ 11 轮真机往返，真正推进的全部是你**观察到的现象**，不是我读代码得出的结论**：

| 我的猜测 | 真机结果 |
|---|---|
| `raycastTarget = false` 能关掉点击 | ❌ **这个字段不存在** |
| `childCount` 能枚举子树 | ❌ **走不进子树**（要用 `GetChildren()`）|
| 递归隐藏能解决 | ❌ 渲染只在属性变化时下发 ⇒ 时机不对 |
| 容器缩到 1×1 | ❌ **会裁掉子控件** |
| 吃点击的在"另一个 UI 根"上 | ❌ **只有一个根** |

**⇒ 该更早做的两件事**：
1. **问"现象有什么可观察的差异"**（音效、光标、有没有反应）—— **而不是先猜属性名**
2. **先把"引擎里实际有什么"打出来**（排行榜 / 字段清单 / 根清单）—— **再动手**
