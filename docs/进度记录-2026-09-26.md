| bug | 后果 | 防线 |
|---|---|---|
| `check_canvas` 用 `%d` 格式化**浮点**画布尺寸 | 抛错 → **整个 OnInit 中断** → 配置全没生效，日志表现成一大串"控件未找到" | `tests/entry_smoke.lua`（假游戏环境故意返回浮点） |

| 头像卡溢出容器 / 线索行数上限 12 | 压住线索 / 18 条线索只显示 12 条 | `tests/ui_math.lua` 的容量与重叠断言 |
| `destroy_control` 真销毁手摆控件 | 弹窗第二次永远出不来 | 区分"脚本生成"与"编辑器手摆" |
| 节点缺 `visible` 字段 | 弹窗逻辑对但一直隐藏 | `push` 补显式 visible |
| `on_update` 只在整秒变化时重绘 | 单击笔记要等下一个整秒才画出来 | 增加 `or controller.dirty` |

另外两个**工具链陷阱**（都已加自动防线）：
- **UTF-8 BOM**：PowerShell `Out-File -Encoding UTF8` 会写 BOM，拼进单文件后 Lua 5.3 报
  `unexpected symbol near '<\239>'`。打包器现在自动去 BOM。
- **`$Args` 是 PowerShell 自动变量**：拿它当函数参数名会让 lua 收到空参数 → 跑成 REPL →
  **"退出码 0"假绿**。已改名并给自检加了依赖跳过。

### 这一轮又抓到的一个真 bug（第 12 个）

## 七、真机续做：把「另存为模板」那条路做成免配置 + 可诊断（2026-09-26 11:xx）

昨天试模板生成失败，原因已经定位清楚：`cell.1.1.prefabIndex` 读出来是
**`1073741848`，那是「预设按钮」的基础模板** —— **读得到，但拿去 `InstantiateClientUIControl`
会静默返回 `nil`**（不报错）。所以"读到就用"是错的做法。

### 改法：候选 + 实测

`Adapter:_cells_prefabs()` 现在返回**候选索引列表**（自动去重）：

| 顺序 | 来源 |
|---|---|
| ① | `cfg.cells.prefab`（显式填的数字，最优先） |
| ② | `cfg.cells.probe`，默认 `cell.1.1` |
| ③ | 约定名 `tpl.cell` / `cell.tpl` / `cell.prefab` |

`ensure_cells` 挨个**真的试着造一个格子**，第一个造得出来的才算数
（试造出来的那个**不浪费** —— 直接当成第一个缺的格子收下）。
这样你**不用抄任何索引数字、不用改代码**：

1. 把 `cell.1.1` 做对（底图 + `face`/`note`/`x` + 拖到「默认」状态节点）
2. 右键 `cell.1.1` →【另存为模板】
3. 从该模板**新建一个控件**放到 `board` 下，改名 **`tpl.cell`**（位置随意）
4. 试玩

`tpl.cell` 不用管 —— 它不在布局里，`hide_unlisted` 会自动把它藏起来。

### 诊断能力同步补上

`dump_names` 现在把**每个控件的模板索引**也打出来（`tpl=` 那一栏）：

```
[murdoku]   - cell.1.1  [presetButton vis=true act=true tpl=1073741848]
[murdoku]   - tpl.cell  [presetButton vis=true act=true tpl=1073741961]
```

一眼就能看出哪个索引能用。**模拟器里没有 `InstantiateClientUIControl`**
（`full-project.json` 里那两处命中只是打包进去的脚本文本），
所以这条路**只能真机验**，离线回归只能保证"不回归"、证明不了"能生成"。
