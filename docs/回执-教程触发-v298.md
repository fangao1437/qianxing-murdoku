## §2 新判据（顺序即优先级；可见性取不到一律按"不可见"）

```
① home 可见                        ⇒ "home"
② select.card.1（退而 select.title）可见 ⇒ **选关页 ⇒ nil（不弹）**
③ clues 或 board 可见               ⇒ 才认为在关卡里 ⇒ tostring(cur.level.id)
④ 其它（过渡态 / 未知屏）           ⇒ nil
```

实现（`lua/entry_client_script.lua`）：

| 函数 | 行 | 作用 |
|---|---|---|
| `tut_visible(name)` | 1031 | `adapter:find(name)`（**按控件名精确 DFS**）+ `pcall` 读 `.visible`；取不到 = `false` |
| `tut_key_and_probe()` | 1054 | 同一帧把 home / card1 / clues / board / scr / id 各读**一次**，返回 `(key, probe)` |
| `current_tut_key()` | 1092 | **唯一入口**（把快照存进 `tut_last_probe` 后返回 key）；本文件里只有这一处定义 |
| 诊断日志 | 1142 | `tick_tutorial` 里触发键**一变**就打一行；**首次评估（哪怕 key=nil）也打一行** |

日志样子（真机上按这三行就能定位）：

```
[tutorial] 触发键 -> home  (home=true card1=false clues=false board=false scr=nil)
[tutorial] 触发键 -> nil   (home=false card1=true clues=false board=false scr=nil)   ← 选关页：不弹
[tutorial] 触发键 -> case_001  (home=false card1=false clues=true board=true scr=nil)  ← 关卡内
```

> ★ 值全部来自**运行时读到的**可见性/字段；`probe` 与"实际用来判的"是**同一份快照**（不为日志二次读）。

### 顺带清掉一个真陷阱

`lua/entry_client_script.lua` 里原来有**两份** `current_tut_key()`（v289 的"只看 cur.screen"版排在前面，
v295 版在后面）。`local function` 后定义者盖掉先定义者 ⇒ 前面那份是**死代码**，
**照着它的位置改，运行时一点效果都没有** —— 这正是"连续两版改错方向"的现成陷阱。v298 已删掉那份，
并留注释说明"本文件里 current_tut_key 只允许一处定义"（现在 grep 只有 1092 一处）。

## §6 真机上要看的（一次定位）

日志首屏应依次出现三行 `[tutorial] 触发键 -> …`：

1. **首页**：`home=true`、`card1=false`、`clues=false`、`board=false` ⇒ 触发键 `home` ⇒ 弹首页那套；点关闭后不再自动弹。
2. **选关页**：`home=false`、**`card1=true`** ⇒ 触发键 `nil` ⇒ **不弹任何教程**（这就是 v296 的病根所在）。
3. **进关卡**：`card1=false`、**`clues=true` 或 `board=true`** ⇒ 触发键 = 关卡 id ⇒ 弹对应那套。

⚠️ 如果第 3 步打出的是 `触发键 -> nil (… clues=false board=false …)`，说明该屏 `clues`/`board` 都**不可见** ——
那就还缺一个"关卡内独有且可见"的信号，**下一条日志会直接告诉我们**（不用再猜）。备选信号（本项目现成的）：
`stage` 子项、`cell.1.1`、`hex`（都是进关卡后由脚本建出来的）。
