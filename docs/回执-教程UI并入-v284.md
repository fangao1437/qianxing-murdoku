### 2.1 并入时的三条硬处理

| # | 处理 | 为什么 |
|---|---|---|
| 1 | **全部加 `tut.` 前缀**（41 条） | 实测骨架与主档**同名**：`hud.title`（主档是顶栏标题）、`bg`（14 个）、`label`（27 个）。`find` 按名字取 ⇒ 不加前缀必串 |
| 2 | `tut.app.root` → **1600×900 / (0,0)** | 骨架里它是 **0×0**；真机实测过"容器缩到 1×1 子控件会被裁掉" |
| 3 | **只搬场景层**（41 条），模板原型（父 = 内置模板容器 1073742015）**一条不搬** | 我们的教程控件是**静态写进存档**的，不在运行时实例化 ⇒ 模板层纯属多余，还是撞号/不一致的来源 |

### 2.2 教程逻辑（`lua/tutorial_ui.lua`）

- 三页正文：**目标 / 操作 / 区域与门窗**（`.gil` 存不下文字 ⇒ 由模块运行时写进 `tut.page.pN.label`）；
- 翻页：`tut.btn.prev / next / reset / close` + 三个页签 `tut.tab.p1..3`（选中态 `state.sel` / `state.off`）；
- 页码：`tut.hud.pager` → 「第 N / 3 页」；标题：`tut.hud.title`；
- 默认收起，**开局弹一次**；`close` 收起；页签/翻页按钮回调**每控件只绑一次**（控件换代后对象变了才重绑，与适配器 `bound` 同一套语义）；
- ★ **不创建控件**：用例里挂了一个假 `game.InstantiateClientUIControl`，一被调用就判红（实测 0 次）。
