# 650 全面优化审计与交付说明

基准：用户指定的 `650.gil`。产物：`650_优化版.gil`。本轮直接以650内嵌脚本和控件为依据，没有用仓库旧版dist覆盖。650原档、仓库lua、dist和其他存档均未修改。

## 已落实的控件与脚本清理

1. 删除旧 `teach` 完整子树334个控件，控件记录约263,390字节。最初按teach名称前缀仅统计到316个；沿父子关系补齐后实际是334个，因此删除的是完整子树，不是只删同名前缀。
2. 新教程使用 `td.home / td.l1 / td.l2`；原脚本初始化时会主动隐藏旧teach。结构引用扫描只发现root对子树根的挂载，没有发现其他外部整数或packed ID引用。本次同时移除root中的旧teach引用。
3. 删除专门验证旧teach的 `tut_verify` 模块、调用入口和记账；删除旧teach隐藏查找与显隐豁免。新td教程、翻页、家具、首次触发和手动重开路径保留。
4. 删除配置 `tpl_probe=false` 下不运行的模板探针及其逐帧入口。此项取消的是发行脚本中的开发探针；优化构建器保留完整修改依据。
5. 删除零调用的旧 `sync_art642` 函数及其专用状态。现行647/648/649美术同步保持。
6. 删除一个每300帧执行、只读控件属性但已无输出的诊断块。相邻的格子face点亮、x比例、显隐强压窗口和功能同步保持。
7. 词法剥离注释：所有短字符串、长字符串及换行保留；剥离前后非注释token序列完全一致。本次注释处理减少927,975字节。由于还清除了旧模块和死代码，原脚本与最终脚本的全局行号不能一一对应；精简前后换行保持仅针对剥注释这一步。

## 已落实的高频流程优化

### 素材容器定位

650里 `assets` 只有一份，直接挂在root下。原来素材查找从 `GetClientUIRoots()` 深度优先遍历，先穿过大量教程和美术层，热点阶段每帧约有1,268笔GetChildren。

优化后仍每次从最新的 `GetClientUIRoots()` 出发，确认根名为root，使用 `GetChild("assets")` 并回读名称；取不到、类型异常或校验失败时立刻回原DFS。没有跨帧缓存根句柄，也没有改为依赖可能过期的Adapter缓存。素材容器内按名映射、重名取最后一份的规则保留。

### 重复属性写入

- 遮罩、教程显隐：先回读visible，只有不同才写。需要激活时单独回读active；读不到时仍走原写入。
- 结算美术、倒计时透明字、选关箭头颜色：每帧继续判断目标值，先回读实际颜色，只有不同才写；读不到时保留原写入。没有仅凭跨帧记忆省略必要重放。
- 常驻光标：showCursor已经为true时不重复写。原扫描对象、重试频率、停止条件、换屏重新武装逻辑不变。

重要限制：若真实引擎不开放某属性回读，此类守卫会退回原写入，仍保证功能，但该项实机负载收益可能小于离线读写模型。属性读写计数也不代表它们具有相同耗时。

## 验证结果和边界

### 存档与脚本

- 原650的编码往返一致。
- 新档通过writeGil落盘、磁盘重读、重编码一致性校验。
- 6,452个保留控件记录逐字节不变：包括图层几何、文本、颜色、图片、状态块、模板索引和各自子列表。剩余的root记录仅修改旧teach的子引用，保留子控件相对顺序。
- 控件和脚本区之外的顶层字段逐字节不变，文件尾部不变。
- 新记录数6,453；子列表无缺失目标；旧teach外部引用检查通过。
- 优化脚本通过Lua 5.3编译及顶层chunk执行，生命周期函数存在。完整流程量测使用电脑现有Lua 5.4离线模型，因此不是Lua 5.3真实引擎全流程验收。

### 固定输入的离线运行对比

采用项目原有perf_faithful假引擎，输入树来自650/优化版实际记录。导出顺序以顶层子列表为准，几何使用稀疏分量读取。固定随机种子和业务表遍历顺序，并将列表回调顺序固定为控件原顺序。此测试专门用于两版对比，未修改游戏运行逻辑。

34个阶段涵盖初始化、首页、选关、四关切换、教程前后翻页与关闭、卡片点击、人物选择、格子点击、撤销、返回确认、提交与指认、结算解锁等路径调用。每阶段保存保留控件路径和层序、显隐、激活、位置、尺寸、文字、图片、颜色、光标、射线、交互和缩放等模型状态。

结果：222,030行阶段记录，原版与优化版有序快照完全相同，差异0。比较时排除已删除旧teach子树，并归一化该子树移除后root层的兄弟序号，不掩盖保留兄弟的相对顺序变化。

| 离线指标 | 原650 | 优化版 | 降幅 |
|---|---:|---:|---:|
| 全流程引擎访问次数 | 3,548,709 | 1,963,598 | 44.67% |
| GetChildren / GetChild访问 | 1,630,232 | 840,847 | 48.42% |
| SetVisible调用 | 30,862 | 20,127 | 34.78% |
| 实例化节点 | 5,101 | 5,101 | 相同 |
| 第一关稳态60帧引擎访问 | 174,044 | 22,004 | 87.36% |
| 第一关稳态60帧GetChildren/GetChild | 79,291 | 3,271 | 95.87% |
| 首页稳态60帧SetVisible | 840 | 0 | 该场景无重复显隐写入 |

这些是离线模型的访问次数，不是实机帧率、加载秒数、显存或CPU占用，不能据此承诺实机快44.67%或87.36%。实例化节点数相同也说明本轮保留了当前功能所需的家具和列表实例化，没有以删画面换取指标。

假引擎原版和优化版均有43条警告。忽略脚本文件名与行号后，警告类别和数量完全一致：36条content穿透字段读不到，1条face图片信息诊断，1条缺少环形填充枚举，5条portrait素材不可读。34阶段未出现阶段函数抛错，但不能把这些警告说成全部检查通过。

特别说明：测试调用了填写答案、提交、指认和返回首页等路径，但第一关最终状态仍为filled，原/新一致；因此不把这份老测试场景表述为“已完成解谜到成功结算”的端到端证明。它能支持保留状态等价与调用量对比，不能替代所有玩法成功结果、实际命中和真实渲染的验证。假引擎并未完整还原全部图片、字体、裁剪、模板引用和原神事件行为。

## 用户补充：分类整理控件到不同父级是否有效

有效，但要和限定查找范围一起做。

| 做法 | 对遍历的影响 | 对650的建议 |
|---|---|---|
| 只把控件放入分类父级，仍从root递归全树 | 扫描节点基本不减，可能多几层父级 | 不作为独立性能方案 |
| 已知用途后直接进入对应父级查找 | 可跳过其他页面和美术树 | assets直达路径已落实 |
| 页面根负责统一显隐 | 可减少逐个子节点的显隐写入 | 必须核对当前显隐所有权和点击遮罩 |
| 按控件类别索引，使用同帧有效缓存 | 可合并多次重复扫描 | 可继续优化，但需保留首命中和失效规则 |
| 隐藏其他页面后仍递归搜索 | 隐藏通常不会阻止脚本遍历 | 不能把隐藏等同于零遍历 |
| 搜索时无条件跳过隐藏树 | 可能找不到隐藏的模板、素材和待显示UI | 不直接采用 |

适合后续分组：稳定的页面根home/select/game、教程td三套、素材assets、模板things、独立弹窗和遮罩。当前assets、td等已经有分组，真正收益点在于利用它们限定搜索，而不是再加空容器。

大范围重新挂父级会改变局部坐标、anchor/pivot继承、裁剪、缩放、可见性、层序和射线命中，不能仅凭名称批量移动。若继续做，应先保存每个控件的有效位置与状态，逐页面迁移，同时修改查找范围，并在游戏内检查。本轮保留当前美术层级，仅删除已废弃旧教程。

## 审计后保留或延后的项目

- td教程及大量无名图片不是自动判定的冗余；它们构成实际视觉和家具层，保留。
- 647/649/650分层美术、字体图形和阴影不合并、不减层。
- 线索末次单射、格子face点亮、x的70%比例、返回确认、长按阈值、raycast、各pcall容错保留。
- 光标扫描全名单缺失时停止条件难以满足，本轮不放宽条件，避免造成迟到控件无法点击。已减少重复写，后续应结合实机重建事件再优化停止条件。
- 家具批量实例化、同模板缩放复用、关卡外不造家具、空闲预热等既有v362优化已存在，保留，未重复引入另一套实现。
- 选关页每帧从opts.levels取列表的代码仍保留：当前生产传入表，不必为假设中的函数输入额外引入长期缓存。
- 未修改仓库原lua源文件或dist，避免混入落后于650的旧源。以后如果重新按原仓库源码打包，可能覆盖这轮优化；要同步时应以本次优化脚本和构建器为依据。

## 尚需实机验收

本轮未导入或操作游戏窗口，没有实机截图或逐像素对比。虽然保留控件字节一致、离线状态等价，仍不能保证所有真实引擎时序和视觉情况已经覆盖。

建议实机重点对比：初次首页、选关两态箭头、结算倒计时前后颜色；四关首次和再次进入；两关教程全部页面及家具；手动重开教程；提示菜单和提示结果；返回确认及遮罩；人物选择、长按、撤销/重做、提交、指认、结算；隐藏再显示和客户端重建后的资源定位。记录首屏时间、切关时间和稳态帧率后，才能量化实际设备收益。

## 交付与复现

- `650_优化版.gil`：本轮优化存档。
- `650_client_优化.lua`：与优化存档内嵌字节相同的脚本。
- `优化650.mjs`：基于锁定650哈希的可复现构建器，使用项目现有gilread/gilwrite，不联网、不装依赖。
- `优化审计数据.json`：改动项、哈希、大小、控件ID及构建断言。
- `650_离线验证数据.json`：逐阶段调用统计、对比口径和警告限制。

在本工作区内运行构建器可重新生成同名优化产物。它校验输入哈希和修改点数量，异常立即停止。构建器不是独立于项目的通用gil工具，需现有tools/gil模块。

本轮未关闭程序、未改系统设置、未改游戏安装数据、未向第三方发送文件、未删除原档或其他用户文件。工作目录以外仅使用本次任务临时目录存放分析和量测文件。
