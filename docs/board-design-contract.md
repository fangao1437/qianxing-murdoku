## 2 门墙的设计语义（核心）

> **墙 = 两格之间那条边界线上的粗条**（中心线=边界线，厚度骑线两侧各一半）；
> **门 = 同一条线上的中段短标记**，与墙**共线**、**压在墙上面** —— 所以门那一段「墙线」仍然连着，只是中段被橙条盖住。

## 6 与「墙门错位」直接相关的代码线索

### 6.1 公式把边钉在「格子内侧」，设计要「骑格线」⇒ 固定偏 6 画布 px

`engine_adapter_qianxing.lua:4279-4283`（`_apply_edges` 贴边段）：

```lua
if s == "up"    then y =  (ch - tthick) / 2
elseif s == "down"  then y = -((ch - tthick) / 2)
elseif s == "left"  then x = -((cw - tthick) / 2)
else x = ((cw - tthick) / 2) end
```

中心离格心 `(格子−厚度)/2` ⇒ 墙**外表面与格边齐平、整体朝格心内缩**；契约要求中心在**边界线**
= `pitch/2 = (格子+缝)/2`：

| | 现有 | 契约 | 差 |
|---|---|---|---|
| 5×5（cell 108、gap 4、pitch 112、厚 8） | 50 | **56** | **+6 画布 px** |
| 6×6（cell 89、gap 4、pitch 93、厚 8） | 40.5 | **46.5** | **+6 画布 px** |

叠加 §3.1 的归属规则，偏差方向 = **横墙偏下 + 竖墙偏右、量级 6 画布 px**
⇒ 与用户报的「整体偏右偏下约 6.5 截图 px」**同量级同方向** [推断，算式如上；1600×900 画布与截图近 1:1]。

### 6.2 `door_nudge=6` 是对同一个 6px 的手工补偿，只对一半

`engine_adapter:4290-4294`：竖门 `x−=6`、横门 `y+=6`。代入 §6.1：内部竖门（`left` 画、本偏右 6）→ −6
正好落回格线；内部横门（`up` 画、本偏下 6）→ +6 也落回；**但边框 `down`/`right` 两侧方向相反 ⇒ 误差放大到 12**。
⇒ 中心线公式修好后 `door_nudge` **必须归零**。 [推断]

### 6.3 同一条边有**两处**写坐标，`cw` 来源不同

| 处 | 何时跑 | `cw/ch` 取自 |
|---|---|---|
| `_apply_edges` | 每帧渲染 | `self:cell_geometry(n)` → 读 **`cfg.cells.parent="stage"`** 尺寸（stage=1600×900 ⇒ avail=900 ⇒ pitch 175/cell 171；读不到回落 733/cell 137——**都不是真格 108**）；`engine_adapter:4184-4188,1101-1109`、`entry_client_script:526` |
| `set_property("walls"/"doors")` | 每次属性下发 | `self.rects[id]` = 界面层真发下去的格子矩形（**108/89 ✔**）；`engine_adapter:5190-5204` |

两处公式相同、`cw` 不同 ⇒ 后跑者覆盖前者。**修之前先定「谁是真源」**（推荐 `self.rects[id]`，或让
`cell_geometry` 读棋盘容器而非全屏 `stage`）。这是比 ±6 更可能的**量级放大器**，须用真机日志核对。 [推断]

### 6.4 `content` 归位那段用了作用域外的 `cw/ch`（= nil）

`engine_adapter:4074-4089`（2026-10-18 加的 content 归位）在函数**前段**引用 `cw, ch`，而
`local cw = …` 到 **4185 行**才声明 ⇒ 读到全局 nil；`content:SetSizeDelta(nil,nil)` 被 `pcall` 吞掉 ⇒
**content 尺寸没被钉住**，只有锚点/轴心/位置被改了。若模板 content 是 135×135（v256 记录），
锚点/轴心改成 0.5 后整组边会随 content 实际盒子偏移。[代码] 事实 + [推断] 影响

### 6.5 别重复走的两条

- v257 已定「横墙不完整」根因 = `imageType=Basic`，改 Stretch 才整条贯通（`回执-选关与门墙-v257:18-19`）；同条还说「布局不像设计图 = 横墙短一截、竖墙位置偏」——**位置偏要单独修，Stretch 救不了**。v264 的 `edge_overlap=4` 只让墙**长**到 `cell+4=pitch`（顺手填角缝），**不改中心线**，与本次错位无关。

## 7 修法建议（供 Lead 取舍）

1. **中心线**：四个式子改成 `±(cw + gap)/2`（= 边界线，gap 与 ui 同源）⇒ 墙/门自然骑格线，`edge_overlap` 可留（长 = pitch 正好贯通）。
2. **边框**：若要照设计（13px、在格外），四侧中心改 `±(cw/2 + ruler/2)`、厚度用 `ruler`；不区分也可接受（与格边齐平，薄 1px 观感）。
3. **门长**：`door_length_ratio` 是**乘 cell** 的 ⇒ 照设计应取 **0.44×112/108 ≈ 0.456**；想保守取 0.35~0.40。
4. **`door_nudge`**：公式修好后设 **0**，等真机只看素材自身偏心再微调这一个数。
5. **唯一真源 + content**：§6.3 两处写坐标合并、`cw` 统一 `self.rects[id]`；顺手修 §6.4 的 nil。
