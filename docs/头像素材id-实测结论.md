## 2. 关键事实（先量出来，再谈匹配）

1. **头像框位置**：每张线索卡左侧有一个 **108×108** 的方框，s1 在 `x=127`，行间距 123 px
   → 四行 `y=340 / 463 / 586 / 709`。s2 在 `x=133`（面板整体右移），框 107×107。
   （工具：`find_slots.ps1`，靠"框内底色偏蓝紫 `b-r ≥ 4`"找出连通带。）
2. **框内底色**：几乎纯色 **#272528 左右**（JPEG 噪声 ±3），而且**和卡片底色 #2C251D 不是同一个颜色**。
   → 说明头像框自己有一层底色，不是卡片渐变。
3. **素材 PNG 是带透明通道的**（`112042.png`、`105104.png` 等都是透明底）。
   → 屏幕 = 「纯色底 + 素材图」，**不是**素材图直接贴上去。
4. **素材被缩放**：素材原生 247–256 px，屏幕上只有约 **94 px**
   → 实际是"等比 contain 放进一个 ~94 px 的框、居中"（`112042` 缩放系数 0.367，`105104` 0.381）。
   **不是**塞满 108 px。

这 4 条决定了正确的比对模型：

```
模型图 = 先填 #272528 一类的纯色底，再把候选素材等比 contain 放进 ~94px 的框并居中（+ 亚像素偏移）
差异   = 模型图 与 屏幕真实像素 的 逐像素 |ΔR|+|ΔG|+|ΔB| / 3 的全框平均（0–255）
```

## 3. 为什么敢下结论（不只是"最像的那个"）

### 3.1 四个互相独立的指标，结论完全一致

`verify_final.ps1` 对每个字母重新拟合一遍，同时给出 4 个残差（越小越像）：

- `fullDiff` — 整个 108×108 框
- `insetDiff` — 去掉最外 8 px（排除卡片描边干扰）
- `maskedDiff` — 只统计"素材不透明"的像素（完全不依赖底色模型）
- `interiorDiff` — 只统计"素材不透明**且**其 3×3 邻域也全部不透明"的像素

`interiorDiff` 是关键：它把剪影边缘整圈剔掉，**重采样 / 抗锯齿 / JPEG 振铃都无法影响它**。
若屏幕真的是这张素材，其**内部平色区必须几乎完全一致**。

### 3.4 看差异热图（证据图第 3 格）

4 张 `evidence-*.png` 的差异热图（×4 放大）**只在轮廓线/内部描边上发亮，平色区全黑**。
这正是"**同一张图被重采样**"的特征：
- 若是**别的图** → 热图会在色块内部大面积发白；
- 若是**被调色/被遮罩** → 热图会成片发亮而不是只剩细边。

**结论：4 个头像都是素材的直接副本（等比缩放 + 居中），没有被调色、没有被遮罩裁剪。**
唯一的例外细节：A 那张卡在屏幕上是"被选中"状态，卡片高亮描边压到了头像框左/下边缘，
所以在 A 的热图里能看到左、下两条亮边——这是卡片描边，不是素材差异。

## 7. 踩到的坑（写给后面的人）

1. **本机 `powershell` 是 Windows PowerShell 5.1**，读**没有 BOM 的 .ps1 会按 GBK 解码**。
   我第一版脚本里写了中文路径字面量，结果脚本在 `D:\` 下创建了一个乱码目录
   `D:\鏂板缓鏂囦欢澶筡miHoYo Launcher\...`（已删除）。
   → 最终做法：**所有 .ps1 一律 ASCII-only**，仓库根路径用 `$PSScriptRoot` 反推，绝不写中文字面量。
   这样 BOM 有没有都无所谓。
2. **PowerShell 的逗号比 `-` 优先级高**：`@($a-1,$b-1)` 会被解析成 `$a - (1, $b-1)`，
   报 `[System.Object[]] does not contain a method named 'op_Subtraction'`。
   同一个坑还会伪装成 `New-Object System.Drawing.Rectangle(2+3,5,10,1)` 失败。
   → 一律写成 `@(($a-1),($b-1))`，或用 `[System.Drawing.Rectangle]::new(...)`。
3. **PowerShell 变量名大小写不敏感**：`$W` 和 `$w` 是同一个变量，`$H`/`$h` 同理。
   我因此把证据图的画布尺寸写成了素材缩放后的尺寸（图片只有 94×94）。→ 变量名必须真正不同。
4. `[System.Drawing.Drawing2D.PixelOffsetMode]::High` **在 .NET Framework 4.8 不存在**，要用 `HighQuality`。
5. **`Diff` 是 `Compare-Object` 的内置别名**，自定义函数不能叫 `Diff`（旧脚本踩过）。
6. 比对时必须**处理 alpha**：素材是透明 PNG，直接 `DrawImage` 到新 Bitmap 上，透明处会变黑，
   和屏幕上的纯色底差 40+ —— 旧脚本 `match_avatar2.ps1` 给出的"差异 37~49"就是这么来的，
   所以它"没命中任何已知 id"。**必须先把底色填好再贴素材**，或只比对不透明像素。
