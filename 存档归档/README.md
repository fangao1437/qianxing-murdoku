# `存档归档/` —— `.gil` 存档的归档目录

> 建立说明：2026-10-09（用户指示：「顺手把**旧脚本、旧存档**分别归档进 `versions` 和 `存档归档`」）

## 约定

| 位置 | 放什么 | 为什么 |
|---|---|---|
| **工程根目录** | ★ **只有【当前交付】的那一份 `.gil`** ✓ | 用户导入时用根目录路径 ✓ 只有一个候选就不会导错 ✓ |
| **`存档归档/`**（本目录） | 其余**全部历史 `.gil`** ✓ | 回退、对照、追查都要用 ✓ 但不该干扰"该导入哪一个" ✓ |
| **`versions/`** | **每一版的脚本快照**（`lua/*.lua` ＋ `dist/client_script.lua` ＋ 配套 `.gil` ＋ `MANIFEST.txt`）| 脚本与存档**成对**保存 ⇒ 回退时不会配错版本 ✓ |

## 怎么用

**要回退到某一版** ⇒ 去 `versions/<编号>-<说明>-vNNN/` ✓：
1. 把那份 `lua/*.lua` 拷回 `lua/` ✓
2. 跑 `node tools/bundle_client_script.lua` ✓
3. 导入它同名的那份 `.gil`（若该目录里有 ✓）
   或从本目录按编号/名字取 ✓

**要查某个历史存档** ⇒ 在本目录按**编号**找 ✓ —— 两套命名并存：

| 命名 | 时期 | 例 |
|---|---|---|
| `完整界面NNN-说明.gil` | 早期（1–~190） | `完整界面186-撤销键按下反馈.gil` |
| `NNN-说明.gil` | 接手之后 | `238-四键真因修复-v101.gil` |

★ **两套名字里的编号不连续、也不完全按时间** ✗ —— 早期那套是"界面版本号"，接手后那套是"**交付序号**" ✓
⇒ 要确定先后请用文件时间或 `git log` ✓，**别只看编号** ✓

## ⚠️ 一条已知的坑：**脚本内嵌在 `.gil` 里**

导入 `.gil` 时，编辑器会把它**内嵌的那份脚本副本**解到新关卡目录 ✓ ——
⇒ ★ **`.gil` 老 = 真机跑的脚本也老** ✗（实测踩过：导入带 v075 的存档 ⇒ 真机跑 v075，而当时最新是 v093 ✗）

⇒ 所以：
- **交付用的 `.gil` 必须用 `node tools/gil/embed_script.mjs` 把最新 `dist` 嵌进去** ✓
- 判断一份 `.gil` 里嵌的是哪版 ⇒ `node tools/gil/find_script.mjs <文件>` ✓（看字节数）
- 沙箱里被覆盖掉的旧脚本会自动备份到 `_backup/sandbox-scripts/` ✓

## 归档时的纪律（写在这里免得下次忘）

1. ★ **移动前先查撞名** ✓（同名会覆盖历史 ✗）
2. ★ **移动后必须复跑闸门** ✓ ——
   `node tools/check_encoding.mjs` ＋ 全 Lua 回归 ＋ 至少一个 `.gil` 工具（如 `list_names`）
3. ★ **保留根目录那一份** ✓（用户的导入路径依赖它 ✓）
4. 归档**不删** ✓ —— 这个目录只增不减 ✓
