## 0. 照着填就行（三条规则）

1. **画布 1600×900，原点在左下角，Y 轴向上。**
2. 每个控件的**锚点**选「自定义」，Min = Max = `0.5, 0.5`，**中心(pivot) = `0.5, 0.5`**。
3. 于是「位置 X, Y」= 控件**中心点**的绝对坐标，**跟父级无关**，
   下表「位置(中心)」那一列**直接照抄**即可。子控件也不用换算，同样是绝对坐标。

> 官方 API 文档（`mhtakr07vej4` 1317~1322 行）另有一套语义：
> `Get/SetAnchoredPosition` 在没有父层级时以画布左下为原点，**有父层级时是与父层级中心的相对偏移**。
> 那是**脚本运行时**用的，跟编辑器「位置」输入框不是一回事。
> 本工程的脚本用的就是运行时那套（见 `engine_adapter_qianxing.lua` 的 `cell_offset`）。

## 1. 三道必开的门控（少一道就"什么都没发生"）

### 门控 ① 客户端控件容器：**激活 + 可见**
客户端控件必须放进「客户端控件容器」里。容器没激活或没可见 → 控件销毁、脚本停。
官方原文（4 篇教程都有这句）：*客户端控件容器需要处于激活且可见状态*。

### 门控 ② 容器要打开**「显示常驻光标」**
这是 2026-09-26 在模拟器实现里挖出来、并在真机症状上对得上的一条：
模拟器的派发条件是

```js
cursorEventsEnabled(t) {
  for (let i = t; i; i = i.parent)
    if (i.kind === "container" && i.showCursor === true) return true;
  return false;
}
```

也就是：**控件只要有一个祖先容器打开了 `showCursor`（编辑器里的「显示常驻光标」），
光标事件才会派发**。不打开的话，界面画得再对，点哪儿都没反应。

> 对应到工程里：容器控件的属性里勾上**「显示常驻光标」**。
> 建议在**最外层那个容器**上勾一次，整棵树都生效。

### 门控 ③ 脚本必须在 `OnInit` 里调 `script:EnableUpdate(true)`
客户端脚本默认**不参与逐帧更新**（`updateEnabled = false`），运行时会直接跳过它的 `OnUpdate`：

```js
runScriptPhase(t, i) {
  ... !(t === "OnUpdate" && !n.updateEnabled) && this.callGlobalDt(r, t, i)
}
```

不开的后果非常隐蔽：`OnInit` / `OnStart` 都正常跑、日志也正常，
但 `OnUpdate` **一次都不执行** —— 计时不动、单击的铅笔笔记永远落不了格、
等待控件就绪的惰性重试也不会发生。
本工程的 `entry_client_script.lua` 里已经写了（见 `enable_update()`），**不要删**。

### 另外：文本显示需要奇匠等级
官方教程注明：**文本显示需要达到特定奇匠等级解锁【自定义文本外显】**。
等级不够时文本框不显示内容 —— 界面其它部分（按钮、图片）不受影响。

## 3. 每格/每张头像卡上还要挂的子控件

这几个子控件**必须叫固定的名字**，脚本是按名字找的（`parent:GetChild("note")`）：

### 3.1 每个格子 `cell.<r>.<c>` 三个子控件

| 子控件名 | 类型 | 位置(中心) | 大小 | 初始 | 作用 |
|---|---|---|---|---|---|
| `face` | 图片 | **跟所在格子完全相同** | 88 × 88 | 显示 | 格面/头像图。脚本用 `SetImage` 换图 |
| `note` | 文本框 | 同上 | 80 × 36 | 隐藏 | 铅笔笔记（单击留下的草稿） |
| `x` | 图片 | 同上 | 88 × 88 | 隐藏 | X 标记（"这格不可能是任何人"） |

然后把 `face` **拖到格子的「默认」状态节点**上（也建议挂到悬停/按下/不可用）——
官方说明：**预设按钮的外观来自它状态节点引用的子控件**，只改按钮自己看不出来。

### 3.2 每张头像卡 `tray.<id>` 两个子控件

| 子控件名 | 类型 | 位置(中心) | 大小 | 作用 |
|---|---|---|---|---|
| `face` | 图片 | **跟所在头像卡完全相同** | 与卡同 | 头像图 |
| `text` | 文本框 | 同上 | 与卡同 | 角色名。脚本没有 `SetText`，只能写 `.text` 字段 |

### 3.3 其它预设按钮
每个按钮都建议加一个居中的子控件 `text`（文本框），并把它挂到状态节点上。
脚本写按钮文字时优先写按钮自己的 `.text`，没有才去找子控件 `text`。

## 5. ⭐ 格子**不用手摆** —— 一个模板 + 一个「模板引用控件」就够了

> **2026-09-26 真机实测通过**：`格子模板索引 1073741876 可用；缺 24 个格子，开始补建` /
> `棋盘格子：25 / 25 存在（本次新建 23 个，模板索引 1073741876）`

### 5.0 ⭐ 推荐：**纯模板模式**（编辑器里一个真格子都不建）

最省控件的做法：**`board` 下只放一个 `tpl.cell`（模板引用控件），不建任何 `cell.*`。**
格子全部由脚本生成 —— 编辑器里跟格子有关的控件**只有 1 个**。

| 项 | 纯模板模式 | 传统手摆 |
|---|---|---|
| 编辑器里的格子控件 | **1 个**（`tpl.cell`） | 49 个 |
| 关卡尺寸变化 | **完全不用动编辑器** | 要重摆 |
| 副本外观来源 | **完全取自模板快照** | 各自配 |

这个模式下有三件事按"正常"处理（脚本会明确说出来，不会误报）：

1. 没有参照格子（`cell.1.1`）→ 体检打「**纯模板模式**」并跳过格子那段体检，**不报"找不到控件"**；
2. 不做图片盖章（`_cells_stamp` 需要参照格子）→ 所以**副本外观完全取决于模板快照**，
   模板里没配底图就重新存一次模板；
3. 缺格子数 = 全部（`rows×cols`），首次开局会一次性生成 25 / 36 / 49 个。

> `tpl.cell` 会被 `hide_unlisted` 自动隐藏，**不会显示在界面上**，位置大小随意。

### 5.1 三步（**关键是第 ② 步**）

| # | 做什么 |
|---|---|
| ① | **界面控件组管理 → 界面控件组库 → 客户端控件模板** →【添加客户端控件】→ 加一个「预设按钮」→ 在里面配好底图 + `face`/`note`/`x` 子控件 + 把 `face` 拖到「默认」状态节点 → **存为模板** |
| ② | 在容器画布里新建一个「**模板引用控件**」，让它**引用**刚存的模板 |
| ③ | 把它命名为 **`cell.1.1`**，然后**点击它记下「控件模板索引 ID」** |

> ### ⚠️ 第 ② 步是最容易错的一步
> **不能用模板"新建控件"，必须用「模板引用控件」去"引用"模板。**
> 这一步是真机试出来的 —— 官方文档给了入口与约束，但**没说这两件事要串起来**。

- **路线 A（已采用，最稳）**：填进 `lua/entry_client_script.lua` 的 `cfg.cells.prefab`，重新打包同步。
  本工程当前是 `1073741876`。日志里会看到 `cfg.cells.prefab = … ← 显式配置`。

```
[murdoku] 棋盘格子：25 / 25 存在（本次新建 23 个，模板索引 1073741876）
```

> `棋盘格子：X / Y 存在` 是**唯一可靠的"成了没有"信号** —— 副本可能因为模板快照里
> 没配美术而完全透明，光看画面分不出「没生成」和「生成了但看不见」。
>
> 新建数比缺格数少 1 是正常的：脚本会**先用第一个候选"试造"一个**来验证索引可用，
> 那个试造出来的会**直接当成第一个缺的格子收下**（不浪费）。

### 5.3 为什么「右键另存为模板」不行

官方《客户端控件和客户端脚本的定义》的硬约束：

> 除**客户端控件容器画布中的客户端控件**以及**客户端控件模板中的控件**外，其他控件均为**服务器控件**，
> **服务器控件的模板索引无法被客户端脚本调用**。

实测过的三种索引：

| 索引来源 | 结果 |
|---|---|
| `1073741848` 内置「预设按钮」基础模板 | ❌ 返回 nil |
| `1073741864` **右键**「另存为模板」得到的 | ❌ 也返回 nil |
| `1073741876` 客户端控件模板 + **模板引用控件** | ✅ **成功，25 / 25** |

### 5.4 ⚠️ 一个很容易踩的坑：**引用控件占着 `cell.1.1` 这个名字**

真机 17:17 / 17:23 截图 + 日志：`cell.1.1` 的 `prefabIndex` **正好等于**
`cfg.cells.prefab` —— 说明它**就是那个模板引用控件本身**，不是格子。后果：

- 它被算成"已存在" → 缺格子数少 1 → **那一格永远不会被生成**；
- 引用控件渲染不出格子副本 → 截图里 (1,1) 看着是**空的**（"第一个格子没造出来"）。

日志里的判据就两个数字，一眼可辨：

```
缺 24 个格子      ← ❌ 说明有 1 格是"编辑器里的控件"，没被生成
缺 25 个格子      ← ✅ 全部由脚本生成
```

**脚本现在会自动处理**（不用你改编辑器）：

1. 发现某个 `cell.<r>.<c>` 位置的控件**是编辑器手摆的**、且索引 == `cfg.cells.prefab`
   → 把它**改名让位**（`__tpl_ref_cell.1.1`）并隐藏；
2. 所有模板引用控件（`tpl.cell` 等约定名）**显式隐藏**；
3. 于是那一格变成"缺"，脚本**在那一格真的生成副本**。

> 为什么不能直接"同名覆盖"：两个控件都叫 `cell.1.1` 的话，`find` 会取到编辑器那个，
> 点击和渲染全打到错的对象上。所以必须**先改名让位**。
>
> 顺带一个实测结论：**关掉 `tpl.cell` 的「初始激活」不影响脚本**（日志完全一致）——
> 但**补不上 (1,1) 那个洞**，因为洞是 `cell.1.1` 造成的，不是 `tpl.cell`。

### 5.4.1 ⚠️ 两个索引字段**不是一回事**（官方原文）

| 类 | 字段 | 访问 | 官方说明 |
|---|---|---|---|
| `ClientUIBaseControl`（**所有**控件的基类） | `prefabIndex` | 只读 | 控件模板索引（**这个控件本身**是哪个模板的实例） |
| `ClientUIReferenceControl`（**模板引用控件**，只有这一个字段） | `referencedPrefabIndex` | 只读 | **引用**控件模板索引 |

所以：**判断「模板引用控件引用了哪张模板」要读 `referencedPrefabIndex`，不是 `prefabIndex`。**
脚本两个都读、两个都打进日志（`ref=` 那一栏），不会再混。

> `active` 也是**只读**，官方写着「true 时控件可见且挂载脚本逻辑运行，false 时控件不可见且脚本逻辑停止运行」。
> 也就是**可见性由 `active` 参与决定，而脚本改不了它** ——
> 所以脚本改用**把模板引用控件挪出画布**（位置 200000,200000 + 缩成 0 尺寸），
> 这样不管可见性怎么算，它都不可能盖住任何一个格子。
> 你在编辑器里关掉它的「初始激活」也可以，两者不冲突。

### 5.5 关卡切换：**编辑器完全不用动**

`ensure_cells(rows, cols)` 每次开局都按**当前关卡**的尺寸补建并摆正：

- 5×5 → 7×7：补建缺的格子；
- 7×7 → 5×5：多余的格子由 `hide_unlisted` / 渲染差集**自动隐藏**，不用删。

所以一套编辑器布局（**一个格子 + 一张模板**）通吃所有尺寸。

### 5.6 对手摆的兼容

编辑器里**已经摆好的格子脚本不会动**（只摆正位置），只补缺的那些。
所以「手摆一半 + 生成一半」也可以；全部手摆完整时脚本检测到"格子齐全"
会直接跳过生成。

> ⚠️ 模板是**存下来那一刻的快照**。之后又给模板里的格子加底图/子控件，
> **必须重新存一次模板**，否则生成的副本会缺东西（看着像"没生成"）。

## 6. 脚本挂载

1. `lua tools/bundle_client_script.lua` → 产出 `dist/client_script.lua`（7 个模块打成 1 个文件）。
2. 千星沙箱 → 客户端脚本资源管理器 → 新建脚本映射，指向 `dist/client_script.lua`。
3. 选中一个客户端控件（任意一个，比如 `root` 容器）→「脚本」页签 → 添加脚本 → 选这个映射。
4. 如果面板显示「暂无引用」：右键脚本记录 →【修改引用路径】→ 双击 `client_script.lua`。
5. 界面布局必须被**职业**引用一次才会在游玩中生效（官方硬性要求）。
