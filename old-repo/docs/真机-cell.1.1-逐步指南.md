# 真机逐步：怎样创建 `cell.1.1`

> 目标：做出**一个**格子 `cell.1.1`，让它
> ① 看得见 ② 点得动 ③ 能当模板复制出其余 48 格。
>
> 数值来源：`docs/控件坐标表-1600x900.md`（自动生成）。
> 这份只讲 `cell.1.1` 一个控件，不涉及其余 149 个。

---

## 前提：这三样应该已经好了

真机日志已经确认 `root` / `board` / `cell.1.1` 三个都存在，所以先只做**核对**：

| 项 | 值 | 说明 |
|---|---|---|
| 客户端控件容器 | 激活 + **可见** | 门控①。容器隐藏/没激活 → 里面的客户端控件全销毁、脚本停 |
| 最外层容器的「显示常驻光标」 | 建议手动勾上 | 门控②。**脚本会自己开**（日志见 `已由脚本打开 N 个容器的「显示常驻光标」`），勾了更稳 |
| 界面布局被「职业」引用 | 引用一次 | 门控④。不引用 → 编辑器和模拟器都对，一进游玩什么都没有 |
| `root` | 容器节点，父级=画布，中心 **800, 450**，1600 × 900 | 全屏根 |
| `board` | 容器节点，父级=`root`，中心 **767, 387**，733 × 733 | 棋盘区 |

> `board` 的位置/大小**不用很准** —— 脚本运行时会读 `board` 的**实际尺寸**重算格子边长，
> 所以 5×5 / 6×6 / 7×7 共用同一套控件。但别做得太离谱（比如比屏幕还大）。

---

## 第 0 步：先记住坐标的三条规则（所有控件都照这个）

1. **画布 1600×900，原点在左下角，Y 轴向上。**
2. 每个控件的**锚点**选「自定义」，**Min = Max = `0.5, 0.5`**；**中心(pivot) = `0.5, 0.5`**。
3. 于是「位置 X, Y」= 控件**中心点**的**绝对坐标**，**跟父级无关**。

> ⚠️ **第 3 条是最容易搞错的地方。** 因为位置是绝对坐标，
> **子控件的位置也是同一个绝对坐标，不需要换算成"相对父级的偏移"**。
> 也就是说下面 `face` / `note` / `x` 三个子控件的「位置」跟格子**填一样的数字**，
> 不要去想"父级在 767,387，所以我要减一下"。

---

## 第 1 步：建格子本体

在 `board` 下新建一个控件：

| 项 | 值 |
|---|---|
| **类型** | **预设按钮**（`PresetButton`） |
| 父级 | `board` |
| **名字** | **`cell.1.1`**（全小写、点号分隔、一字不差） |
| **位置(中心)** | **488, 666** |
| **大小** | **97 × 97** |
| 锚点 / 中心 | 自定义，Min=Max=`0.5, 0.5`，pivot=`0.5, 0.5` |

### ⚠️ 类型必须对

**必须是「预设按钮」或「光标检测区域」。** 这两类是官方 API 里**唯一**带
`AddCursorEventListener` 的控件（见 `docs/7.1-脚本API速查.md`）。

用**容器节点**或**文本框**代替 → 脚本收不到点击，日志里会明确打一句
`控件 cell.1.1 不支持光标事件（请用「预设按钮」或「光标检测区域」控件）`
（脚本不会静默失败，会告诉你原因）。这是最容易踩的一个坑。

### 两个开关必须开

| 开关 | 不开的后果 |
|---|---|
| **可被光标射线检测**（`raycastTarget`） | 界面看得见，但**点哪儿都没反应** |
| **可交互**（`interactable`） | 脚本按「这格能不能站人」切它，关了会一直是灰的 |

## 第 2 步：在格子里建 3 个子控件

**必须是格子的直接子控件**（脚本用 `parent:GetChild("face")` 取，**不递归**，
放深一层就找不到）。

| 子控件名 | 类型 | 位置(中心) | 大小 | 初始可见 | 作用 |
|---|---|---|---|---|---|
| **`face`** | 图片 | **488, 666** | 97 × 97 | **显示** | 格面 / 放置角色时换的就是它 |
| **`note`** | 文本框 | **488, 666** | 89 × 36 | **隐藏** | 铅笔笔记（单击留下的草稿） |
| **`x`** | 图片 | **488, 666** | 97 × 97 | **隐藏** | X 标记（"这格不可能是任何人"） |

要点：

- 名字**一字不差、全小写**。脚本找不到就自动跳过（不报错），但表现会缺失。
- 三个的位置都填 **488, 666** —— 和格子一样（绝对坐标，见第 0 步）。
- `note` 和 `x` **初始必须隐藏**，脚本运行时按需显示。
- **可选第 4 个**：`text` 文本框（脚本往上面写角色名；不建就写格子自己的文本）。
- 如果格子下已经有别的名字的子控件（比如默认叫「图片」的），**改成 `face`**，
  否则脚本认不到它。

## 第 3 步：挂图（不挂就完全看不见）

官方硬规则：**预设按钮自己不画任何东西，外观来自它「状态节点」引用的子控件。**
所以一行图都不加的话，控件都在、脚本也找得到，但**屏幕上什么都看不见**。

用 `assets/placeholder/` 里已经生成好的占位图（也可以直接用编辑器内置素材）：

| 子控件 | 素材 | 图片类型 |
|---|---|---|
| `face` | 一张格面底图（占位图或内置底板素材） | 基础或拉伸**都行**（见下） |
| `x` | X 图标（你已经有内置的「功能图标 x」） | 只能选**基础** |

### 「图片类型」基础 / 拉伸 到底差在哪（**已更正**）

> **真机实验（2026-09-26）**：**基础 和 拉伸 都会随图片控件的大小变化（总是填满控件本身）。**
> 所以"不选拉伸就不会跟着格子缩放 / 会溢出"是**错的**。

官方文档里其实是**两个不同的概念**，很容易读混：

| 概念 | 归属 | 取值 |
|---|---|---|
| **图片类型** | **控件**上的设置 | `基础` / `拉伸` |
| **图片属性** | **素材自己**的属性 | `普通` / `三宫格` / `九宫格` |

「拉伸」= "**启用该素材的拉伸属性**"，而素材的拉伸属性由「图片属性」决定：

| 素材的图片属性 | 基础 vs 拉伸 **有区别吗** |
|---|---|
| **普通** | ❌ **完全一样** —— 都铺满控件、四角都跟着形变 |
| 三宫格 | ✅ 拉伸保住那一对边；基础会压扁 |
| 九宫格 | ✅ 拉伸保住四角（圆角不糊）；基础把圆角压扁 |

**所以对你的格子来说**：

| 情况 | 怎么做 |
|---|---|
| 格面底图是**纯色 / 纯图案**（占位图） | 基础 / 拉伸 **随便选**，都能铺满格子 |
| 格面底图**带圆角 / 描边**（将来的真美术） | 素材做成 **九宫格**，图片类型选 **拉伸** → 圆角不被压扁 |
| `x` 的图标 | 只能基础，**也没关系** —— 一样铺满格子 |

> ⚠️ 因为**总是铺满控件**，真正要盯的是**长宽比**：格子是正方形（1:1），
> 所以格面素材也该按 1:1 出，否则会被拉变形。

**找不到「图片类型」这个设置项 → 说明「图片源」不是「静态引用」。**
它只在静态引用下才出现。

完整记录（含我上一版推论的更正）见 `docs/环境问题-诊断记录.md` 第 11、12 节。

### 为什么必须是「拉伸」

格子边长在 5×5 / 6×6 / 7×7 下分别是 **135 / 113 / 97 px**，
脚本运行时会改控件尺寸来适配当前关卡，**只有"拉伸"才能跟着变**。

想体验更好可以再挂（可选）：
`cell_hover.png` → 「悬停」节点、`cell_pressed.png` → 「按下」节点、
`cell_disabled.png` → 「不可用」节点。

## 第 4 步：把 `face` 挂到按钮的「默认」状态节点 ⭐ 最容易漏

入口：**选中 `cell.1.1` →【基础】→ 按钮设置 → 按钮状态节点**

两种做法任选：

1. **拖**：在层级面板里把 `face` **拖到**「默认」状态节点上；
2. **勾**：**单击**「默认」状态节点，在弹出的子控件列表里**勾选** `face`。

配好后点状态节点的**播放键**可以在编辑器里直接预览。

> **血泪教训**：只改**按钮自己**的图片/尺寸，画面上**完全看不出来**。
> 为这件事白测过一整天 —— 一定要配**子控件**。
>
> ⚠️ 这一步还直接决定第 6 步：**「客户端控件模板」存的是那一刻的快照**，
> 没挂状态节点的格子，复制出来的副本全是透明的。

## 第 6 步：**模板引用控件** + 客户端控件模板 → 省掉其余 48 格

> ### ✅ 这一条已经打通了（2026-09-26 16:07 真机实测）
>
> ```
> [murdoku] 格子模板索引 1073741876（来自 cfg.cells.prefab）可用；缺 24 个格子，开始补建
> [murdoku] 棋盘格子：25 / 25 存在（本次新建 23 个，模板索引 1073741876）
> ```
>
> **关键一步是用户试出来的**：**不能"用模板新建控件"，要新建一个「模板引用控件」去*引用*已保存的模板。**
> 做完之后 `cell.1.1.prefabIndex` 就变成了那张模板的索引，`InstantiateClientUIControl` 才认它。

### 6.1 正确的做法（三步）

| # | 做什么 |
|---|---|
| ① | **界面控件组管理 → 界面控件组库 → 客户端控件模板** →【添加客户端控件】→ 加一个「预设按钮」→ 在里面配好底图 + `face`/`note`/`x` 子控件 + 把 `face` 拖到「默认」状态节点 → **存为模板** |
| ② | 在**容器画布**里新建一个「**模板引用控件**」，让它**引用**刚存的模板（不是用模板"新建控件"） |
| ③ | 把它的名字改成 **`cell.1.1`**（或把你原来的 `cell.1.1` 换成它），然后**点击它记下「控件模板索引 ID」** |

拿到 ID 之后**二选一**：

| 路线 | 怎么做 | 优点 |
|---|---|---|
| **A（已采用）** | 把 ID 填进 `lua/entry_client_script.lua` 的 **`cfg.cells.prefab`**，重新打包同步 | 最稳，脚本会**最先试它**；日志里能看到 `cfg.cells.prefab = … ← 显式配置` |
| **B** | 什么都不填，靠脚本**扫全树**自动发现（`cfg.cells.auto_scan`，默认开） | 不用改代码，但它只会用到画布上**已存在**的引用控件索引 |

> 本工程当前 `cfg.cells.prefab = 1073741876`。

### 6.2 为什么「右键另存为模板」不行

官方《客户端控件和客户端脚本的定义》里的硬约束：

> 除**客户端控件容器画布中的客户端控件**以及**客户端控件模板中的控件**外，其他控件均为**服务器控件**，
> **服务器控件的模板索引无法被客户端脚本调用**。

实测过的三种索引：

| 索引来源 | 结果 |
|---|---|
| `1073741848` —— 内置「预设按钮」基础模板 | ❌ 返回 nil |
| `1073741864` —— **右键**「另存为模板」得到的 | ❌ 也返回 nil |
| `1073741876` —— 走「客户端控件模板 + **模板引用控件**」 | ✅ **成功，25 / 25** |

### 6.3 试玩时看这三行

```
[murdoku]   cfg.cells.prefab = 1073741876   ← **显式配置**，脚本会最先试它
[murdoku] 格子模板索引 1073741876（来自 cfg.cells.prefab）可用；缺 24 个格子，开始补建
[murdoku] 棋盘格子：25 / 25 存在（本次新建 23 个，模板索引 1073741876）
```

> `棋盘格子：X / Y 存在` 这行是**唯一可靠的"到底成了没有"信号** ——
> 副本可能因为模板快照里没配美术而完全透明，光看画面分不出「没生成」和「生成了但看不见」。
>
> 新建数比缺格数少 1 是正常的：脚本会**先用第一个候选"试造"一个**来验证索引可用，
> 那个试造出来的会**直接当成第一个缺的格子收下**（不浪费）。

### 6.4 下一步：验生成出来的格子能不能玩

生成通了之后，**紧接着要验的是副本是否完整**（这条还没验）：

| 现象 | 结论 |
|---|---|
| 一整片 5×5 格子、能写笔记、能划 X、能落子 | ✅ 模板复制完整 |
| 有格子但**点不动** | ⚠️ 副本缺 `raycastTarget` / 状态节点引用 → 我加"生成后补属性" |
| 有格子但**笔记 / X 不显示** | ⚠️ 副本缺 `note` / `x` 子控件 → 回 ① 补子控件后**重存模板** |

### 6.5 顺便：`x` 的初始可见性

你 14:45 的日志里 `x` 是 `visible=true`：

```
[murdoku]  ✅ 子控件 x 存在（visible=true）  imageType=Enum.ImageType.Basic imageId=100101
```

按设计它应该**初始隐藏**（脚本运行时才按需显示）。这一条**不影响正确性** ——
脚本每帧都会按模型把 `x` 的可见性写回正确值，所以每次开局都会自动纠正。
但**建议改成隐藏**：一是省一次首帧闪烁，二是模板快照更干净。
（`note` 你设对了：`visible=false` ✅）

## 第 7 步：49 格的说明

生成出来的副本来自**模板快照**，所以：

- 副本**自带** `face` / `note` / `x` 子控件和状态节点引用（只要你在第 2、4 步配好了再存的模板）；
- 副本的 `face` 图片脚本还会**自动从 `cell.1.1` 盖章过去**（`Adapter:_cells_stamp`），
  所以即使模板是"还没配图"那一刻存的，格面也能补上；
- **副本的 `note` / `x` 不会有图** —— 那两个子控件必须**在模板快照里就存在**。
  如果副本上写字/划 X 看不见，就是模板存档时还没建这两个子控件 → **重新另存一次模板**。

## 常见问题速查

| 现象 | 原因 | 处置 |
|---|---|---|
| 日志 `控件 cell.1.1 不支持光标事件` | 用错类型了 | 必须是**预设按钮**或**光标检测区域** |
| 格子看得见、点不动 | 射线检测没开 / 祖先容器没勾「显示常驻光标」 | 开 `可被光标射线检测`；日志里找 `已由脚本打开 N 个容器` 那行 |
| 格子完全看不见 | `face` 没挂状态节点 / 图片类型不是拉伸 | 回第 3、4 步 |
| **找不到「图片类型」这个设置项** | **「图片源」不是「静态引用」** | 把图片源改成**静态引用**，图片类型才会出现（官方文档：该参数只在静态引用下提供） |
| 选不到「拉伸」（只有「基础」） | **该素材属于「功能图标」等只有基础的类别** | 正常的 —— 只有**底板 / 分稿线**能拉伸。图标类请用**小图**（`x_mark` 88×88） |
| X 标记盖住了旁边格子 | 用了大图且该素材只能「基础」（= 按原始尺寸画） | 换成 88×88 的 `x_mark.png`（已重新生成） |
| 格子里的字不显示 | **奇匠等级**没解锁【自定义文本外显】 | **属预期**，按钮和图片不受影响；升等级后自然就有 |
| 副本全是透明的 | 模板是"没配美术那一刻"存的 | **重新存一次模板**（在客户端控件模板里改） |
| `全部实例化失败（返回 nil）` | 索引不在**客户端控件模板**体系里 | 回 **6.1**：界面控件组库 → 客户端控件模板 → 添加客户端控件 → 存为模板 |
| `x` 一开始就显示 | 忘了设初始隐藏 | **不影响正确性**（脚本每帧写回），但建议改成隐藏 |
| 副本上笔记 / X 看不见 | 模板快照里没有 `note` / `x` 子控件 | 补上子控件后**重新另存模板** |
| 生成后位置看着不对 | — | **无所谓**，脚本运行时会按本关实际 N 重新摆正所有格子 |
| 只在编辑器里对、进游玩什么都没有 | 界面布局没被「职业」引用 | 门控④ |
| 计时不动、笔记永远落不了格 | 门控③（`script:EnableUpdate`） | 别删 `lua/entry_client_script.lua` 里的 `enable_update()` |

## 命名速查（直接复制）

```
格子本体：  cell.1.1
子控件：    face      note      x      (可选 text)
模板控件：  tpl.cell
```

> 其余 48 格的名字：`cell.<行>.<列>`，行/列从 1 开始。
> 生成机制会自己命名，**你不用手动建它们**。
