## 二 ★★★ 结算的官方语义（**先懂这个再接线**）

出处：《关卡结算》（`official/guide/mhx1du08nhwo_关卡结算.md`）✓

- ★ **关卡结算** = 由**节点图触发**的行为 ✓ 触发后**整个关卡结束** ✓
  结果会传到**外围系统** ⇒ 更新**排行榜**、**竞技段位** ✓
- ★★ **结算状态是「每个玩家」的属性** ✓，由**两个字段**构成：
  | 字段 | 说明 |
  |---|---|
  | **逃跑合法性** | ★ 为**否**时 ⇒ 该玩家结算状态**一律是「逃跑状态」** ✗ |
  | **结算状态** | ★ **仅当逃跑合法性为「是」**，这个字段**才有意义** ✓ 取 未定 / 胜利 / 失败 ✓ |

  - **胜利** ⇒ 按计分模板拿**胜利分** ✓
  - **失败** ⇒ 拿失败分 ✓
  - **未定** ⇒ ★ **玩家默认就处在这个状态** ✓ 拿未定分 ✓

- ★ §四 列的管理节点：**结算关卡** / 设置玩家排名数值 / 设置阵营排名数值 /
  **设置玩家结算成功状态** / 设置阵营结算成功状态 ✓

### ★★ 一条官方原话（很重要）

《2.11 关卡结算》里写着 ✓：
> 「**不进行结算状态预设，直接使用结算关卡，默认会以"成功"结算**」

⇒ ★ 也就是说：**只放【结算关卡】也会按成功算** ✓
　★ 但 ⇒ **显式设成「胜利」更可控** ✓（推荐 ✓；两者在文档里用词是"成功/胜利"，**以编辑器里的枚举为准** ✓）

## 三 ★★★ 推荐接线（我建议的方案）

★ 设计建议（理由在下面）✓：
```
murdoku/solved  ⇒  ① 记一笔（可选）  ② ★ 把玩家结算状态设成 胜利
murdoku/settle  ⇒  ★ 结算关卡
```

★ **为什么 `solved` 就要设胜利** ✗（而不是只在 `settle` 时设）✓：
　 玩家的四个键里有 **「退出至菜单」** ✓ —— 他**破了案但没点「存档并结算」** ✓
　 ⇒ 若只在 `settle` 里设 ⇒ ★ 那种情况会以**未定**收场 ✗（玩家明明破了案 ✓）
　 ⇒ ★ 所以 **破案即设胜利** ✓、**真正结算另走 `settle`** ✓ 两个键都稳 ✓

★ 反过来说 ✓：**没破案就退出** ⇒ `murdoku/solved` 没发过 ⇒ 状态仍是**未定** ✓ 正确 ✓

## 四 ★★★ 逐步骤操作（在编辑器里做）

### 第 1 步　登记两条信号

1. 打开**千星沙箱** → **新建节点图** → 类型选 **服务器**
2. 节点图工具栏里点 **「服务器信号管理器」** → **添加信号**
3. 第 1 条：
   - **信号名**：`murdoku/solved`　★ **一字不差**（含正斜杠 `/` ✓）
   - **添加参数** ×4，按顺序：
     | 顺序 | 参数名（随便取，建议照抄）| **类型** |
     |---|---|---|
     | 1 | `level_id` | **字符串** |
     | 2 | `elapsed` | **整数** |
     | 3 | `moves` | **整数** |
     | 4 | `failed_accusations` | **整数** |
   - **应用修改**
4. 第 2 条：
   - **信号名**：`murdoku/settle`
   - **添加参数** ×1：`level_id` **字符串**
   - **应用修改**

> ⚠️ **参数名编辑器里不影响收发** ✓ 但**类型与顺序必须对上** ✗ ——
> 顺序就是客户端 `AddX` 的调用顺序 ✓（`M.SIGNAL_SCHEMA` 那张表就是它 ✓）

### 第 2 步　放节点、连线

★ **【监听信号】**（事件节点）在选定**信号名**之后，
　 **出参会自动多出该信号的每一个参数** ✓ —— 直接从这里取 `level_id` 等 ✓

**方案 A（推荐）：节点图挂在【玩家实体】上**

```
【监听信号 · murdoku/solved】
   ├─→【设置自定义变量】目标实体 =【获取关卡实体】
   │        变量名 = solved_level    变量值 =（监听信号出来的 level_id）
   └─→【设置玩家结算成功状态】玩家实体 =【获取自身实体】   结算状态 = 胜利

【监听信号 · murdoku/settle】
   └─→【结算关卡】
```

★ 为什么挂玩家实体 ✓：**信号是全局的** ✓（官方《信号》原文：
　「实体1发送的信号，**关卡内的任意实体均可以监听并接收这个信号**」✓）
　⇒ 挂在玩家实体上，**【获取自身实体】拿到的就是玩家实体** ✓
　⇒ **一步到位**，不用去找"哪个玩家" ✓

**方案 B：节点图挂在【关卡实体】上**

```
【监听信号 · murdoku/solved】
   ├─→【设置自定义变量】…（同 A）
   └─→【获取在场玩家实体列表】→（取第 1 项）→【设置玩家结算成功状态】结算状态 = 胜利

【监听信号 · murdoku/settle】
   └─→【结算关卡】
```
⚠️ ★ **"取列表第 1 项"那个节点的确切名字我没查到** ✗（`get_node_info` 索引不全 ✓）
　 ⇒ 你在编辑器里按实际名字挑一个（"获取列表中第 N 项"一类 ✓）
　 ⇒ 本作是**单人关卡** ⇒ 列表里就一个玩家 ✓ 取谁都一样 ✓

### 第 3 步　挂载与保存

- 把节点图**挂到**目标实体上（方案 A：玩家实体 / 方案 B：关卡实体）
- **保存**节点图 ✓
- ⚠️ 改完记得**保存关卡** ✓
