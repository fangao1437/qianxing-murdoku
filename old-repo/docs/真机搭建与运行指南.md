## 〇、先记住这四道门（少一道，界面就是"死的"）

历史上 90% 的"脚本没反应"都出在这四条上。**搭之前先读，搭完逐条核。**

| # | 门 | 在哪开 | 不开的后果 |
|---|---|---|---|
| ① | **客户端控件容器：激活 + 可见** | 容器节点的属性 | 控件销毁、脚本停 |
| ② | **「显示常驻光标」= 开** | 容器节点的属性（勾在最外层容器上一次即可） | 界面画得再对，**点哪儿都没反应** |
| ③ | **`script:EnableUpdate(true)`** | 已经写在 `lua/entry_client_script.lua` 的 `OnInit` 里 | `OnUpdate` **一次都不执行**：计时不走、铅笔笔记永远落不了格，**而且双击判定与长按判定全靠 `dt` 累加 → 也会一起失效**（只剩单击） |
| ④ | **界面布局必须被「职业」引用一次** | 职业配置里挂界面布局 | 编辑器和模拟器里看着都对，一进游玩就什么都没有 |
| ＋ | **文本外显需要奇匠等级** | 达到等级解锁【自定义文本外显】 | 文本框不显示内容（按钮/图片不受影响） |

> ② 和 ③ 是 2026-09-26 从模拟器实现里挖出来、并且和真机症状对得上的：
> - ② 的派发条件是"控件的某个祖先容器 `showCursor === true`"；
> - ③ 的派发条件是"`OnUpdate` 只发给 `updateEnabled` 的脚本"，默认是 `false`。
>
> 详见 `docs/控件坐标表-1600x900.md` 第 1 节（附反编译片段）。
>
> ⚠️ **③ 对移动端尤其致命**：触屏的"放置"是**长按**（按住 ≥0.45 秒），
> 这个计时完全依赖 `OnUpdate` 的 `dt`。③ 不开的话，PC 上双击和触屏上长按**都不会落子**。

### ✅ 门控 ② 现在由脚本自动处理，不用你手勾

`Adapter:enable_cursor()` 会在开局时把 10 个受管容器的 `showCursor` 直接写上去
（模拟器实测有效，`node tools/sim/probe_cursor.mjs` 就是这个实验）。

所以开局日志里会出现下面两种情况之一，**看日志就知道要不要动手**：

| 日志 | 含义 | 你要做什么 |
|---|---|---|
| `[murdoku] 已由脚本打开 10 个容器的「显示常驻光标」` | Lua 侧能写这个字段 | **什么都不用做** |
| 没有这一行 | 真机不开放该字段 | **手动勾选**容器的「显示常驻光标」 |

> 这条实验的做法值得记一下：建界面时**故意不打开** showCursor，
> 然后看「跳过教程」和「双击放置」还能不能生效 —— 能，就说明脚本救活了点击通道。

## 二、游戏内一次性准备

1. 打开 **千星沙箱**（客户端 `CN 7.1.0` 或更新）。
2. **先把当前产物同步进沙箱**（编辑器的文件选择器只能看到沙箱里的文件）：

   ```powershell
   cd "D:\新建文件夹\miHoYo Launcher\qianxing-murdoku"
   powershell -ExecutionPolicy Bypass -File tools\install_script_to_sandbox.ps1
   powershell -ExecutionPolicy Bypass -File tools\open_script_root.ps1 -NoOpen   # 认一下该选哪个
   ```

3. 进入 **客户端脚本资源管理器** → 新建**脚本映射**，指向**沙箱里那份**：

   ```
   C:\Users\<你>\AppData\LocalLow\miHoYo\原神\BeyondLocal\<uid>\
       Beyond_Local_Save_Level\<关卡存档id>\external_lua_file\client_script.lua
   ```

   ⚠️ **必须是 `LocalLow` 那一棵**。`AppData\Local\...` 下可能也有一份（历史上误拷的），
   那份**不是编辑器在用的** —— 选错了症状就是「脚本毫无反应」。
   `open_script_root.ps1` 会把误建的那棵标成 `WRONG ROOT (no .gil here)`。
   ⚠️ `<关卡存档id>` **每新建一个关卡就会变**，所以每次新关卡都要重跑上面两步。

4. 如果面板显示 **「暂无引用」**：
   右键那条脚本记录 → **【修改引用路径】** → 双击 `client_script.lua`。
   （这一步做没做，是"脚本到底挂上没有"的唯一判据。）
4. 打开 **日志窗口**，先勾上 **「客户端脚本」** 再点 **【确认选择】**。
   ⚠️ 不勾的话日志窗口里什么都看不到 —— 会误以为脚本没跑。
   ⚠️ `print` 的普通级日志**不落盘**，只能在游戏内日志窗口看，别去翻 `output_log`。

## 三、搭界面（这是最主要的手工活）

打开 `docs/控件坐标表-1600x900.md`，按 **第 2 节「建树顺序」** 的表从上往下建。

### 3.1 坐标怎么填（三条规则）

1. 画布 **1600×900**，原点在**左下角**，Y 轴**向上**。
2. 锚点选「自定义」，**Min = Max = `0.5, 0.5`**，**中心(pivot) = `0.5, 0.5`**。
3. 于是「位置 X, Y」= 控件**中心点**的绝对坐标，**跟父级无关** ——
   表里「位置(中心)」那一列**直接抄**，子控件也**不用换算**。

> 别把编辑器的「位置」和脚本的 `SetAnchoredPosition` 搞混：后者有父层级时是
> **相对父级中心**的偏移（官方 API 文档 1317~1322）。脚本自己处理这套换算，
> 你只需要把编辑器的「位置」填对。

### 3.2 建的顺序与层级

按表的顺序建，**父级必须先存在**。层级是：

```
画布
└─ root                     ← 容器节点，1600×900，整屏
   ├─ topbar                ← 顶栏
   │  ├─ hud.title / hud.subtitle / hud.timer / hud.moves
   │  ├─ tool.place / tool.x / tool.eraser
   │  └─ action.undo / redo / submit / hint / reveal
   ├─ left                  ← 左栏
   │  ├─ tray               ← 头像卡容器
   │  │  └─ tray.A … tray.V ← 5 张卡（本例是 A/B/C/D/V）
   │  ├─ clues
   │  │  └─ clue.1 … clue.N / clues.more
   │  └─ legend
   ├─ board                 ← 中央棋盘
   │  ├─ ruler.c.1 … ruler.c.5      ← 列标尺
   │  ├─ ruler.r.1 … ruler.r.5      ← 行标尺
   │  └─ cell.1.1 … cell.5.5        ← 25 个格子（预设按钮）
   ├─ right                 ← 右栏：hud.progress / score / violations / share / toast
   │  └─ action.howto / share / restart / back
   ├─ actions               ← 底部操作条：action.q.place / note / x / eraser / accuse
   ├─ intro                 ← 开屏教程（一直建出来，脚本按状态显示/隐藏）
   │  └─ intro.dots / title / body / skip / next
   └─ modal                 ← 各种弹窗（一直建出来）
      ├─ modal.title / body / stats
      ├─ modal.suspect.A … V
      ├─ modal.no_accomplice / cancel / again / share / next
```

> **`intro` 和 `modal` 里的控件必须一直存在**，不要"用到再建"。
> 脚本关弹窗时只会把它们**藏起来**；如果编辑器里压根没有，脚本按名字找不到，
> 指认面板就永远出不来。

### 3.3 每格 / 每张头像卡上要挂的子控件（名字必须一模一样）

脚本是按**固定名字**找子控件的（`parent:GetChild("note")`），改名字就失效。

| 挂在谁身上 | 子控件名 | 类型 | 位置 | 初始 |
|---|---|---|---|---|
| 每个 `cell.r.c` | `face` | 图片 | **跟所在格子完全相同** | 显示 |
| 每个 `cell.r.c` | `note` | 文本框 | 同上 | **隐藏** |
| 每个 `cell.r.c` | `x` | 图片 | 同上 | **隐藏** |
| 每张 `tray.X` | `face` | 图片 | **跟所在卡完全相同** | 显示 |
| 每张 `tray.X` | `text` | 文本框 | 同上 | 显示 |
| 每个预设按钮 | `text` | 文本框 | 同上 | 显示 |

然后把 `face`（格子）**拖到格子的「默认」状态节点**上，`text` 拖到按钮的「默认」状态节点上。

> **官方硬事实**：界面控件组库里的元件**游玩时不显示**，必须加到界面布局；
> **预设按钮的外观来自它的状态节点引用的子控件**（默认/悬停/按下/不可用）。
> 只改按钮自己的尺寸/图片，在画面里**完全看不出来** —— 我们为此白测过一整天。
> 拖法：拖拽子控件到状态节点上，或单击状态节点勾选。

### 3.4 文本与图片的来源

- 文本框：如果达到奇匠等级，先在编辑器里配好**自定义文本外显**，再让脚本写文字。
- 图片控件的 `imageSource`（图片来源）要在编辑器里配好；
  脚本调 `SetImage(imageSource, imageId)` 时**沿用编辑器配的来源**，只换 id。
  所以 `face` 的图片来源必须先在编辑器里设一次，否则运行时画像出不来。

### 3.5 格子的两种做法（**推荐 B**）

> ⚠️ **本节已按 2026-09-26 真机实测改写。** 权威版本见 `docs/本次搭建要求.md`（自动生成）。
> 曾经的"右键【另存为模板】"指引**是错的** —— 那个入口存出来的索引客户端脚本调不动。

**做法 A：手摆全部格子。**
按坐标表把格子全建出来。此时 `cfg.cells.prefab` **留空**即可 ——
脚本检测到格子齐全，只做"摆正"，不生成。
（缺点：25/36/49 格要按最大尺寸手摆一遍，且关卡尺寸变了要重摆。）

**做法 B（推荐，本工程当前采用）：纯模板模式 —— 编辑器里一个真格子都不建。**

| # | 做什么 |
|---|---|
| ① | **界面控件组管理 → 界面控件组库 → 客户端控件模板** →【添加客户端控件】→ 加一个「预设按钮」→ 在里面配好底图 + `face`/`note`/`x` 子控件 + 把 `face` 拖到「默认」状态节点 → **存为模板** |
| ② | 在容器画布里新建一个「**模板引用控件**」去**引用**刚存的模板（**不能**用模板"新建控件"——那样不算） |
| ③ | 把它命名为 **`tpl.cell`**，放在 `board` 下（位置大小随意，脚本会把它挪出画布） |
| ④ | 点击它，读出 **`referencedPrefabIndex`**（**不是** `prefabIndex`！），填进 `cfg.cells.prefab` |

本工程当前：`cfg.cells.prefab = 1073741876`，实测 `棋盘格子：25 / 25 存在（本次新建 25 个）`。

> ⚠️ 模板存的是**那一刻的快照**。之后又给模板里的格子加了底图/子控件，
> **必须重新存一次模板**，否则运行时生成的副本会缺东西 ——
> 看起来像"脚本没生成"，其实生成了，只是没外观。
>
> 纯模板模式下**没有参照格子**，所以脚本**不做图片盖章**，副本外观**完全取自模板快照**。

## 六、故障排查表

| 症状 | 最可能的原因 | 处置 |
|---|---|---|
| 日志窗口空白 | 没勾「客户端脚本」 | 勾上 → 【确认选择】 |
| 完全没有日志 | 脚本映射没关联上 | 看资源管理器是否「暂无引用」→【修改引用路径】 |

## 七、脚本目录在哪（两处，别搞混）

### A. 工程里 —— 改代码 / 打包的地方

```
D:\新建文件夹\miHoYo Launcher\qianxing-murdoku\
├─ lua\                   ← 改代码改这里（6 个模块 + 关卡数据）
└─ dist\client_script.lua ← 打包产物（9 个模块合成一个文件，约 227 KB）
```

改完 **必须重新打包**，否则 `dist` 还是旧的：

```powershell
cd "D:\新建文件夹\miHoYo Launcher\qianxing-murdoku"
$lua = "$env:LOCALAPPDATA\Programs\Lua\bin\lua.exe"
& $lua tools\bundle_client_script.lua
```

### B. 沙箱里 —— 编辑器「脚本映射」实际指向的地方

```
C:\Users\<你>\AppData\LocalLow\miHoYo\原神\BeyondLocal\<uid>\
    Beyond_Local_Save_Level\<关卡存档id>\external_lua_file\client_script.lua
```

**每次改完脚本，固定走这两步**（别手抄路径，存档 id 会变）：

```powershell
& $lua tools\bundle_client_script.lua
powershell -ExecutionPolicy Bypass -File tools\install_script_to_sandbox.ps1   # 同步进沙箱
powershell -ExecutionPolicy Bypass -File tools\open_script_root.ps1 -NoOpen    # 认一下选哪个
```

⚠️ **三条血泪注意**：

1. **必须是 `LocalLow`**，不是 `Local`。`AppData\Local\...` 下可能也有一份
   （以前误拷进去的），那份**编辑器不会用** —— 选错了症状就是「脚本毫无反应」。
   `open_script_root.ps1` 会把误建的那棵标成 `WRONG ROOT (no .gil here)`。
2. `<关卡存档id>` **每新建一个关卡就变**（这台机器上有 `1073741826`、`1073741827` 两个，
   靠 `.gil` 文件与目录时间戳区分，脚本会标出 `NEWEST`）。
3. 安装脚本会**同时同步 LocalLow 和 Local 的所有根** —— 只写一个地方会失效。
   它同步完会打印每个目标的字节数，跟源文件对齐才算成功。

改完界面布局要重跑：`lua tools\dump_layout.lua` → `node tools\gen_editor_guide.mjs`。
