## 〇 三十秒：这是什么，怎么跑起来

```
原神「千星奇域」UGC 的 2D 谋杀悬疑（murdoku）游戏
  · 界面控件在【编辑器】里搭  →  存档是 .gil
  · 逻辑【全部】在 Lua        →  lua/**
  · 打包成【单文件】注入客户端 →  dist/client_script.lua
```

★★ **为什么必须是"单文件"** ✗：官方规则是「只有在千星沙箱里**建立了映射**的 `.lua` 文件才会被打包上传」
　 ⇒ ★ **一个映射 = 一个文件** ✓ ⇒ ★ 多模块 `require` **不保证**上传后还能解析到彼此 ✗
　 ⇒ ★ 所以由 `tools/bundle_client_script.lua` 在**本地构建期**合成一份 ✓

### 三步出包（★ 顺序不能换 ✓）

```powershell
# ① 打包（唯一入口；它自带"模块被写空就拒绝打包"的护栏）
lua tools/bundle_client_script.lua

# ② 同步到【编辑器真正读的那个目录】（★ 不是 dist ✗）
powershell -ExecutionPolicy Bypass -File tools/install_script_to_sandbox.ps1

# ③ 回编辑器点刷新：客户端脚本资源管理器 → 脚本记录 → 编辑文件路径 → 环形箭头
```

★★ **编辑器永远不读 `dist/client_script.lua`** ✗ —— ★ 它读的是：

```
%USERPROFILE%\AppData\LocalLow\miHoYo\原神\BeyondLocal\<uid>\
  Beyond_Local_Save_Level\<关卡id>\external_lua_file\client_script.lua
```

★ 而**每次新建/切换关卡，编辑器都会生成一个新的 `external_lua_file` 目录** ✗
　 里面往往躺着**一份旧脚本** ⇒ ★ 表现成"我明明装了新脚本，游戏里却是旧行为" ✓
　 ⇒ ★★ **测试前必须重跑同步** ✓ ✓（完整判据见 `docs/交付流程-打包与同步.md`）

```
                 ┌──────────────────────────────────────────────┐
   编辑器 .gil ──▶│  引擎（客户端控件树 + 官方 Lua API）          │

   ┌────────────────────┴────────────────────────┴───────────────────┐

   │   · find / sub（控件查找 + 按代缓存）                            │
   │   · set_property(id, key, value)   ← 引擎侧改控件的两条路之一    │

   └────────────────────┬────────────────────────▲───────────────────┘
                        │ 规划（表）              │ 事件（表）
                        ▼                        │
   ┌─────────────────────────────────────────────┴───────────────────┐
   │  ui_controller.lua                                              │
   │   · layout_plan() → Array<{id, kind, parent, rect, …}>          │
   │   · render(vm)    → 视图快照 → set_property 计划                 │

   └────────────────────┬────────────────────────▲───────────────────┘

                        ▼                        │
   ┌─────────────────────────────────────────────┴───────────────────┐
```

2. ★ **脚本直接调控件方法**（`ctrl:SetSizeDelta(...)` 等 ✓）—— ★ 只出现在适配层 ✓

### 3.4 `.gil` 的四个坑（★ 都吃过 ✓）

| # | 事实 | 后果 |
|---|---|---|
| 1 | **同一个字段号在不同层级含义不同** ✗ | `#503` 可能是裸 ID 列表，也可能是普通嵌套消息（96% 是后者 ✗）；`#504` 顶层 = 父 / 嵌套 = 回指；`#506` 两种含义 |
| 2 | ★ **写完必须【从磁盘重读】断言** ✗ | 读内存或刚写出的 buffer 证明不了它落盘了 |
| 3 | ★ **`roundtrip` 逐字节一致 ≠ 改动生效** ✗ | ★ **"冻结整棵树"也能往返一致** ✓ |
| 4 | ★ 加一个控件要**两步** ✗ | ① 改父的 `#503`（子 id 列表）② 把新字段插进 holder 数组 |

### 3.5 控件句柄会**变陈旧** ✗（★ 世代缓存的核心前提 ✓）

★ 官方文档 ✓：★「玩家传送、断线重连时，**所有客户端控件都会被销毁**然后回到初始状态」✓
　 ★「客户端容器控件**隐藏或销毁**时，客户端控件**销毁**」✓

⇒ ★★ **`Adapter:find()` 命中缓存后从不校验句柄是否还活着** ✗ 是当年最大的坑 ✓
　 ⇒ ★ 可行路径 = **`game.GetClientUIRoots()` ＋ 限深树遍历** ✓

**换代（generation）机制**：

| 概念 | 实现 | 触发点 |
|---|---|---|
| 代数 | `Adapter._lookup_gen` | `invalidate_lookups(why, opts)` 每次 +1 |
| 名字缓存 | `self.controls`（**命中**） ＋ `self._misses`（**未命中**，带 TTL） | ★ 换代清空 ✓ |
| 子控件缓存 | `self.subs`（`"id.child" → 控件`） | ★ **只在 `ensure_cells` 按 `cell.` 前缀清** ✗ |
| 子控件**未命中** | `self._sub_miss[key] = _lookup_gen` | ★ **按代戳** ✓ ⇒ 自己会过期 ✓ |
| 父尺寸 | `self._geo_cache = {gen, pw, ph}` | ★ **代 + 值双判据** ✓ |
| 绑定闩锁 | `self.bound[id]` | ★★ **换代清空** ✓（见 §六 的 P0 ✓） |
| 按键闩锁 | `self.keymap` | ★★ **刻意不清** ✗（★ `bind_keys` 只有一个调用点 ＋ `keyboard_bound` 闩锁 ⇒ 清了 **键盘永久哑** ✓） |

★ `invalidate_lookups` 的调用点只有 **4 处**（★ 全项目 ✓）：

| 调用点 | 带 `keep_bindings` | 为什么 |
|---|---|---|
| `engine_adapter_qianxing.lua` · `create_control` | ✅ **带** | ★ 刚实例化就要 `bind_input` ⇒ 清了会让同一 id **双绑** ✗ |
| `engine_adapter_qianxing.lua` · `destroy_control` | ❌ | 控件真的没了 ⇒ 必须清 |
| `ui_controller.lua` · `sync_clue_grid`（`grid_refresh:`） | ❌ | `RefreshItems` 会重建列表项 ⇒ 刻意清 ✓（列表项自己另有 `_grid_bound[item]` ✓） |
| `ui_controller.lua` · `render`（`screen=`） | ❌ | ★ **换代的主要理由** ✓ |

### 5.2 几何写的"读回守卫"（★ 口径必须一致 ✓）

★ 口径 ✓：★ **读得到且已等于目标 ⇒ 不写** ✓；★ **读不到 ⇒ 照旧写** ✓（★ 不许因为读不到就不摆 ✓）

| 写 | 守卫 | 状态 |
|---|---|---|
| `SetPivot` | 读 `ctrl.pivotX/pivotY` 比 `(0.5, 0.5)` | ✅ 已加 |
| `SetSizeDelta`（`position` 分支） | 读 `GetSizeDelta()` 比目标 | ✅ 已加 |
