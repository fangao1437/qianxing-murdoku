## 一、先分清哪边做什么

```
┌──────────────────────────────┐        ┌──────────────────────────────┐
│  客户端脚本（Lua，本工程）    │        │  服务器节点图（编辑器里连）    │
│                              │        │                              │
│  画界面、收点击、算规则       │        │  管关卡流程、存档、结算、排行  │
│  求解、判定、动画             │        │  多人同步、发放奖励            │
│                              │        │                              │
│  game.ServerSignal(name)     │ ─────► │  接收自定义信号 → 做副作用     │
│    :AddInt/AddString/AddBool │        │                              │
│    :SendSignal()             │        │                              │
│                              │ ◄───── │  发送自定义信号 → 客户端回调    │
│  script:RegisterServerSignal │        │                              │
│    Handler(name, cb)         │        │                              │
└──────────────────────────────┘        └──────────────────────────────┘
```

**本工程的 Lua 已经把两边的"接口"都定好了**，你只需要在节点图里按名字接线。
信号名定义在 `lua/engine_adapter_qianxing.lua` 的 `M.SIGNALS`：

> ★★★★★ 2026-10-13 **本表已过时 ⇒ 请看 `docs/节点图接线-结算全流程.md`** ✗✓
>   那一份按**代码事实**重列了**全部 10 条**信号，并订正了下面两处错 ✓
>   ★ 订正 ①：`murdoku/sync_state` ✗ ⇒ 实际是 **`murdoku/sync`** ✓
>   ★ 订正 ②：本表**漏了 `murdoku/settle`（存档并结算）** ✗ —— 而它正是结算要接的那条 ✓
>   ★ 另：节点在编辑器里的正式名是 **【监听信号】/【发送信号】** ✓（不是"自定义信号" ✓）

| 信号名 | 方向 | 参数 | 什么时候发 |
|---|---|---|---|
| `murdoku/solved` | 客户端 → 服务器 | `关卡id`(String)、`用时秒`(Int)、`步数`(Int)、`误指认次数`(Int) | 破案结算的那一刻 |
| `murdoku/save` | 客户端 → 服务器 | `关卡id`、`状态码`(String)、`步数`(Int)、`用时`(Int)、`是否完成`(Bool) | 需要存档时（离开/主动保存） |
| `murdoku/restore` | 服务器 → 客户端 | `状态码`、`步数`、`用时`、`是否完成` | 玩家回到关卡时，把存档发回客户端 |
| ★ `murdoku/settle` | 客户端 → 服务器 | `关卡id`(String) | ★ **第 4 键「存档并结算」** |
| `murdoku/sync` | 服务器 → 客户端 | `who`(String)、`r`(Int)、`c`(Int) | 多人玩法里同步别人的落子 |

> ⚠️ 信号名必须**一字不差**。改名字要同时改 `M.SIGNALS` 和节点图。

## 二、服务器节点图怎么接（逐条）

在关卡里新建**节点图（服务器）**，按下面接。每一条都写清"触发条件 / 做什么"。

### 2.1 开局：把存档发回客户端

```
【关卡开始时】
  → 读取玩家存档变量 murdoku_save_<关卡id>
  → 如果非空：
        发送自定义信号 "murdoku/restore"
          参数：状态码(String) / 步数(Int) / 用时(Int) / 是否完成(Bool)
```

- 存档变量建议命名：`murdoku_save_` + 关卡 id（例：`murdoku_save_case_001`）。
- 客户端收到后会**自动把棋盘还原**到存档那一刻（`Murdoku.restore`）。
- 没存档就不发，客户端会正常开局。

### 2.2 客户端请求存档：写进服务器变量

```
【收到自定义信号 "murdoku/save"】
  → 把 参数1(String) 存到 murdoku_save_<关卡id>_state
  → 把 参数2(Int)    存到 murdoku_save_<关卡id>_moves
  → 把 参数3(Int)    存到 murdoku_save_<关卡id>_time
  → 把 参数4(Bool)   存到 murdoku_save_<关卡id>_solved
```

> **为什么拆成 4 个变量而不是存一个结构体**：官方《局内存档》文档明确
> **存档不支持结构体/字典**，只能存基本类型。这一点已经在本工程里踩过，
> 所以客户端那边发的就是拆开的参数（早期版本试图存整张表，写不进去）。

### 2.3 破案结算：发奖励 / 记排行

```
【收到自定义信号 "murdoku/solved"】
  → 记录 关卡id / 用时 / 步数 / 误指认次数
  → 达成条件时：发奖励、解锁下一关、写入排行榜
  → 可选：把 是否完成=true 写进 2.2 的存档变量
```

### 2.4 多人同步（可选，不做也不影响单人）

```
【玩家落子时】 客户端发 "murdoku/sync_state"（who, r, c）
              → 服务器转发给同关卡的其他玩家
【收到转发】   → 客户端收到 "murdoku/sync_state" → 自动摆上那一格
```

> 客户端侧已经实现：收到 `murdoku/sync_state` 会 `select_suspect` + `tap_cell` 再重绘。
> 服务器侧只要负责**转发**即可。

## 三、局内存档怎么落地

### 3.1 客户端已经做好的一半

`lua/main.lua` 里的 `Murdoku.save_now()` 会调用 `core:encode_state()` 生成一个
**分享码字符串**，然后发 `murdoku/save` 信号，带上：
`关卡id` / `状态码`（就是那个字符串）/ `步数` / `用时` / `是否完成`。

**分享码 = 整个棋盘的紧凑编码**（谁在哪一格、铅笔笔记、X 标记都包含），
所以"存档"和"分享"用的是同一套数据 —— 玩家把码发给别人，对方能还原同一个局面。

### 3.2 服务器侧要做的

就是 2.1 / 2.2 两条。**不需要**在服务器上理解棋盘结构，当字符串存就行。

### 3.3 什么时候会触发存档

| 时机 | 说明 |
|---|---|
| 破案结算时 | `on_solved` 回调里会发 `murdoku/solved`，你需要的话顺手写存档 |
| 主动离开 | 客户端 `on_destroy` 会 `save_now()` |
| 手动调用 | 想把存档挂到某个按钮上，就在节点图里给按钮接 `murdoku/save` 的请求 |

### 3.4 哪些东西存不进去（官方限制）

- ❌ 结构体 / 字典（所以拆成了 4 个基本类型变量）
- ❌ 自定义对象
- ✅ 整数 / 浮点 / 布尔 / 字符串

## 四、控件素材清单（照这个准备，尺寸都是画布 1600×900 下的像素）

> 尺寸来自自动生成的 `docs/控件坐标表-1600x900.md`。
> 图片都建议 **PNG 带透明通道**。

> ### 关于「基础 / 拉伸」——**已更正，别按旧结论准备素材**
>
> **真机实验（2026-09-26）**：**基础 和 拉伸 都会随图片控件的大小变化（总是填满控件本身）。**
> 所以"不能拉伸的图会按原始尺寸画、会溢出"是**错的**，素材**不需要为了这个做小**。
>
> 官方文档里是**两个概念**：
>
> | 概念 | 归属 | 取值 |
> |---|---|---|
> | **图片类型** | **控件**上的设置 | `基础` / `拉伸` |
> | **图片属性** | **素材自己**的属性 | `普通` / `三宫格` / `九宫格` |
>
> 「拉伸」= 启用素材的拉伸属性；区别**只在素材是三宫格/九宫格时才显现**：
>
> | 素材图片属性 | 基础 vs 拉伸 |
> |---|---|
> | **普通** | ❌ 完全一样（都铺满、四角都形变） |
> | 三宫格 / 九宫格 | ✅ 拉伸保住边/角，基础会压扁 |
>
> **所以真正要守的规矩变成三条**：
>
> 1. **纯色 / 纯图案素材** → 基础 / 拉伸随便选；
> 2. **有圆角 / 边框的美术**（按钮、面板、卡片底图）→ 做成**九宫格** + 图片类型选**拉伸**；
> 3. **尺寸不重要，长宽比重要** —— 总是铺满控件，长宽比不对才会被拉变形。
>
> 完整更正记录见 `docs/环境问题-诊断记录.md` 第 12 节。

### 4.1 必须的（没有就"看不见"）

| 用在哪 | 素材 | 参考尺寸 | 数量 | 备注 |
|---|---|---|---|---|
| **格子底图** | 方形底 / 描边 | **1:1**（格子在 5/6/7 人关是 135/113/97 的正方形） | 1 张 | 纯色随便；**带描边建议做九宫格 + 拉伸**。挂到 `cell.r.c` 的 `face`，再拖进「默认」状态节点 |
| **头像卡底图** | 圆角卡底 | **≈3:4**（卡片 68×87） | 1 张 | 圆角建议九宫格 + 拉伸。挂到 `tray.X` 的 `face` |
| **角色头像** | 头像图 | **≈3:4**（与卡片同比例） | 每个角色 1 张 | 脚本用 `SetImage` 换图，**图片来源要先在编辑器里配好**；比例不对会被拉变形 |
| **按钮四态** | 默认 / 悬停 / 按下 / 不可用 | 见下表 | 每类 1 套 | 官方：预设按钮外观来自状态节点引用的子控件；有圆角就做九宫格 |

### 4.3 文本外显（被奇匠等级门控）

- **文本显示需要达到特定奇匠等级解锁【自定义文本外显】**（官方教程原文）。
- 等级不够时：控件在、背景在，**字画不出来**。
- 对策：① 把等级刷到解锁（推荐，代码一行不用改）；
  ② 固定文案改用图片素材（把中文渲成 PNG 用图片控件）；
  ③ 动态数字（计时/步数）用 0–9 数字图集按位显隐。
- **本工程用到的文本控件**：`hud.title / hud.subtitle / hud.timer / hud.moves /
  hud.progress / hud.score / hud.violations / hud.share / hud.toast / clue.* /
  clues.more / legend / ruler.* / intro.* / modal.title / modal.body / modal.stats /
  每个按钮的 `text` 子控件 / 每格的 `note` 子控件`。
  等级没解锁时这一批全是"有框没字"。

### 4.4 音效（可选）

`lua/engine_adapter_qianxing.lua` 的 `Adapter:play_audio(audio_id)` 走
`game.PlayAudio2D(id)`。要出声音就在 `ui_controller.lua` 的 `M.EFFECTS` 里
把对应动作接上音频 id。**当前默认不播音频**（id 需要在编辑器里查）。

## 五、接完之后的验收顺序

1. **只接 2.2**（存档写入）→ 进游戏玩两下、退出、看服务器变量有没有值。
   —— 这一步能同时验证"信号通道是通的"和"存档格式对"。
2. **再接 2.1**（存档恢复）→ 重新进关卡，看棋盘是不是回到了刚才的样子。
3. **最后接 2.3**（结算）→ 破案一次，看排行/奖励有没有发。
4. 多人同步（2.4）**最后做**，它不影响单人能不能玩。

> 客户端那边这些路径都已经被模拟器回归测过了
> （`tools/sim/win_path.mjs` 会真的把一局打通到「破案！」），
> 所以如果第 1 步就不通，问题一定在**节点图的接线**，不在 Lua。
