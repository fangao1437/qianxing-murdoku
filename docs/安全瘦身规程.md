# 安全瘦身规程（**2026-10-03 用一次真机事故换来的**）

> 背景：项目里 `main.lua` 有若干 `if (frames % 300 == 0) then … end` 的诊断块。
> 我为了"省性能"把它们整块改成 `if false then`，结果 **棋盘从那天起就再没显示过**。
>
> 用户原话：「棋盘自从脚本瘦身后就再也没正常显示过，排查一下瘦身破坏了什么」
> —— 判断完全正确。

---

## 一、那次为什么坏（**根因是方法，不是某一行的错**）

```lua
if (frames % 300 == 0) then            -- ← 一个块
    …各种 print（诊断）…                 --   可以删
    if scr_now == "level" then
        -- ★ 每帧把 25 个格子的 face 点亮（SetVisible）★
        --   —— 这是**功能代码**，删不得
    end
    …更多 print…
end
```

**⇒ 整块 `if false` ⇒ 功能一起停** —— **而 `loadfile` 不报错**（语法仍然配平）
⇒ **症状是"画面少东西"，不是"报错"** ⇒ **极难定位**。

**⇒ 反过来也说明**：`loadfile` 通过 **不能**作为"改动安全"的证据。

---

## 二、正确规程（**三步，顺序不能换**）

| 步 | 动作 | 验证 |
|---|---|---|
| **① 先分家** | 把**功能代码**从诊断块里**物理搬出去**（搬到块外，**不是加 `if`**）| **搬完立刻 `loadfile` + 真机跑一次** |
| **② 只做这一件事** | **这一轮不删任何东西** —— 分家本身就是一个独立改动 | **确认画面对** |
| **③ 再删诊断** | 确认分家无误后，**删掉纯诊断行**（**删，而不是 `if false`**）| **再跑一次真机** |

**⇒ 关键**：**"分家"和"删代码"必须分成两轮** —— 我这轮把它们合成一轮，就出了这次事故。

---

## 三、怎么判断一行是"功能"还是"诊断"（**硬标准**）

| 特征 | 判定 | 处理 |
|---|---|---|
| **改控件状态**：`SetVisible` / `SetAnchoredPosition` / `SetSizeDelta` / `SetImage` / `imageColor` | **功能** | **绝不能删** |
| **建 / 销毁控件**：`InstantiateClientUIControl` / `Destroy` | **有副作用** | **必须删**（不是关 —— 关掉反而不执行，留着 `if false` 等于埋雷）|
| **只 `print` / 只拼字符串** | **诊断** | **可删** |
| **只读属性**：`GetAnchoredPosition` / `GetSizeDelta` / `.visible` | **无副作用** | **可删（连读取一起删）** |

---

## 四、用这个标准扫 `main.lua` 现有四块（**2026-10-03 实测结论**）

| 位置 | 内容 | 判定 | 建议 |
|---|---|---|---|
| **L1133** `% 300 == 0` | 容器 `UI定位` —— 只读属性 + print | **纯诊断** | **可整块删** |
| **L1186** `% 300 == 60` | **「六边形素材实例化探针」—— 每次真的 `InstantiateClientUIControl` 建两个控件再销毁** | **有副作用** | **★ 最该删的一块**（它正是"棋盘出现慢"的主因）|
| **L1231** `% 300 == 0` | **混着**：`格子定位` print **+ ★「每帧点亮 25 个 face」★** | **功能在里面** | **必须先分家**（把点亮那段搬出块外），再删 print |
| **L1382** `% 300 == 0 and level` | `格子子控件实况` 只读 + print | **纯诊断** | **可整块删** |

**⇒ 另外**：`entry_client_script.lua` 的 `debug_key` / `debug_image` / `debug_event`
只是**开关打印**，关掉安全 —— 但它们控制的打印在别处，所以**关开关**是安全的（上次坏的不是这里）。

---

## 五、执行顺序（**下一轮照这个做**）

```
第 1 步（本轮）：只把 L1231 里"点亮 face"那段搬到块外 —— 不删任何东西
                  → 真机验证棋盘仍在
第 2 步：删 L1186 整块（探针，有副作用，删掉最省）
                  → 真机验证棋盘仍在 + 表现变快
第 3 步：删 L1133 / L1382 两块（纯诊断）
                  → 真机验证
第 4 步：删 L1231 里剩下的 print（功能已经搬走了）
                  → 真机验证
```

**⇒ 每一步都单独真机验证** —— **任何一步出问题，退回上一步**（`versions\` 里有完整快照）。

---

## 六、教训（写给以后）

1. **`loadfile` 通过 ≠ 改动安全** —— 语法配平和功能完好是两件事。
2. **"关掉"比"删掉"更危险** —— 删掉至少一眼看得出没了；`if false` 会一直留在那里，
   而里面的功能代码**永远不会再跑**。
3. **一次只动一块，动完就验** —— 我这轮一次改了四处，导致无法二分定位。
4. **用户的"现象描述"往往比我的推断更准** —— 这次「自从瘦身后棋盘就没了」直接指出了
   改动的边界，我该第一时间按这个边界去二分，而不是自己猜结构。
