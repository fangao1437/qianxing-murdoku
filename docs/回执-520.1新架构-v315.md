## §2 脚本 v315 做了什么

| # | 改动 | 作用 |
|---|---|---|
| ① | `_ensure_cell_face(cell_id)`：在每格 `content` 的 **index 0** 实例化 `cell.face` 模板，命名 **`face`** | 原来所有写 `sub(cell,"face")` 的代码（图片 / 房间染色 / 可见性 / 尺寸）**一行不用改就换绑**到新 face；face 在最底 |
| ② | 在 `Adapter:sub()` 里加钩子：`cell.*` 下取不到 `"face"` 时**自动补建**（带防重入 guard） | 属性先到后到都不会丢 face 写入 |
| ③ | 家具模板 prefab：**优先从 `things` 的引用控件读 `referencedPrefabIndex`**（`furn,chair` 的逗号会归一化），cfg 表只作回退 | 不依赖"手工填 GUID"，用户以后在 things 里增删家具即可 |
| ④ | 家具实例父级：老 `content/furn` 没有就挂 **`content`**；并 `SetSiblingIndex = 1` | 层级 = **face(0) → 家具(1) → 墙/门/笔记/头像(2+)**：家具压在 face 上、又在头像与墙之下 |
| ⑤ | 新架构（有 `things`、content 无 obj/furn）下手搭层**跳过不报错** | 老存档/离线用例行为不变（回归测试覆盖） |
| ⑥ | v313 的时序修复保留（属性恒受理 + `_furn_try_all` 补造 + 切关销毁） | 属性先到/后到都能收敛 |

> 关于"用不用模板"：**模板还是要的**——`InstantiateClientUIControl` 只能从**模板 prefab** 复制控件；
> 但**不需要模板引用控件**（那是编辑器摆位用的），脚本直接读 things 里的引用值拿到 prefab 索引即可。
