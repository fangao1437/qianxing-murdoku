## 一、这个项目是什么

**原神「千星奇域」UGC 的 2D 谋杀悬疑游戏**（`lua` 客户端脚本 + 客户端控件）。
仓库：`fangao1437/qianxing-murdoku`

### 关键架构（★ 这是理解一切的前提 ✓）

| 层 | 文件 | 干什么 |
|---|---|---|
| ★ **客户端脚本** | `lua/ui_controller.lua`（~6200 行）| ★ 控件规划 + 渲染 + 输入 |
| ★ **适配器** | `lua/engine_adapter_qianxing.lua`（~5600 行）| ★ 把"规划"翻译成引擎 API 调用 |
| ★ **游戏核心** | `lua/murdoku_core.lua`（~2700 行）| ★ 纯逻辑：放置/笔记/胜负 |
| ★ **入口** | `lua/main.lua`（~2300 行）| ★ 主循环 + 一些**直遍历控件的补丁** |
| ★ **关卡数据** | `lua/levels/*.lua` | ★ 线索/嫌疑人/房间 |

★★ **引擎侧只有两条路能改控件** ✓：
1. ★ **规划 → `adapter:set_property(id, key, value)`** ✓
2. ★ **脚本直接 `ctrl:SetSizeDelta(...)` 等** ✓

## 二、★ 当前的核心模型（★ 这是最新的设计意图 ✓）


- ★ **头像对应 `face`** ✓
- ★★ **标记对应 `letter`** ✓

★ 卡片模板是 `clue`（含 `backrop1`/`backrop2`/`letter`/`what`/`face`/`who`/`gray`）✓

## 四、★★ 已确认的【存档结构】事实（★ 省你重查 ✓）

### 4.1 `.gil` 格式
- ★ **protobuf 单消息体** ✓ ＋ 5 个大端 u32 头 ＋ 4 字节尾 ✓
- ★★ **记录 = 树里的一个字段对象** ✗（★ 不是 `{id,name}` 结构 ✓）
- ★ 加一个控件需要两步：★ ① 改父的 `#503`（子 id 列表）② 把新字段插进 holder 数组 ✓

### 4.2 ★★★ **同一个字段号在不同层级含义不同** ✗（★ 这个坑吃过三次 ✓）

| 字段 | 陷阱 |
|---|---|
| ★ `#503` | ★ **可能是【裸 varint ID 列表】** ✗ ★ **也可能是【普通嵌套消息】** ✓ —— ★ 实测 2720 / 2785 是后者 ✓ |
| ★ `#504` | ★ **顶层 = 父控件 id** ✓ ★ **嵌套 = 状态块回指** ✗ |
| ★ `#506` | ★ `#80/#506` = `itemPrefabIndex` ✓ ★ `#81/#506` = 别的语义 ✗ |

★ **规矩** ✓：★ **凡按字段号取值，必须带【层级/路径】约束或【顶层限定】** ✓

### 4.3 ★★★ **模板控件在存档里有【2 份】** ✓
```
clue #1073742421  父=null             ← ★ itemPrefabIndex 指向它 ⇒ 【运行时列表项来源】✓
clue #1073742428  父=1073741844       ← ★ 模板层级根（ClientUIPrototypeHierarchyRoot）下那份 ✓
```
★ 同理：`cell.1.1` / `tpl-container` / `hex` / `letterC` 等都有两份 ✓

### 4.4 ★★★ **`Adapter:find()` 返回的是【陈旧句柄】** ✗
★ 引擎在**传送/重连/容器隐藏再显示**时会重建全部客户端控件 ✓
　 ⇒ ★ **旧的 `GetChild("assets")` = nil** ✗
　 ⇒ ★★ **可行路径 = `game.GetClientUIRoots()` ＋ 限深树遍历** ✓✓
　 ⇒ ★★★ **我今天有 4~5 个 bug 都源于这条** ✓（★ 头像 ✓ 描边 ✓ 单射取不到 ✓）

### 4.5 ★★ **写 `.gil` 的两个必守规矩**（★ 我们踩过 ✓）
- ★★ **写入后必须【从磁盘重读】断言** ✗ —— ★ 读内存或刚写出的 buffer 都证明不了它落盘了 ✓
- ★★★ **`roundtrip` 逐字节一致 ≠ 改动生效** ✗ —— ★ **"冻结整棵树"也能让往返一致** ✓（★ 今天这个 bug 骗了我们很久 ✓）
