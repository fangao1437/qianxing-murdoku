## 二、★ 真正的根因：新素材从未在 .gil 里注册成原型

前三轮（691 / 693 / 694）都在改 **Lua 的绘制路径**，方向全错了一半：694 确实把
`_spawn_whole_rug` 整块模板调用恢复了，但真机**根本拿不到可用的 prefab**。

692 新建 `furn.rug.4` / `furn.rug.5` 两套独立素材时，只补了「源 / 母本 / 引用三件套」、
`things.childList`、Lua 引用链，**漏了 .gil 里两处原型注册表**：

| 注册表 | 694 项数 | 既有可显示模板 | 692 新素材 |
|---|---|---|---|
| `/9/501` 顶层「根 / 原型 ID 列表」 | 43 | `furn.rug 1073747149`、`furn.rug.2 1073748252`、`furn.rug.3 1073749968`、`furn.plant.2 1073753953` … 全在 | **源 `1073760711` / `1073760734` 不在** |
| `/9/502`（`#501=1073741844`，`ClientUIPrototypeHierarchyRoot`）的 `#503` 母本列表 | 33 | 母本 `1073747157` / `1073748248` / `1073749965` / `1073753951` 全在 | **母本 `1073760712` / `1073760735` 不在** |
| `things.childList` | 13 | 引用控件全在 | 692 已追加 `1073760713` / `1073760736`（这一处是对的） |

引擎加载存档时按这两张表创建原型 ⇒ 两个新源 / 母本**从未被创建** ⇒ `things` 里的引用控件
指向不存在的 prefab ⇒ `game.InstantiateClientUIControl(1073760711/…, board.rugs)` 失败。
694 的行为级探针把 `InstantiateClientUIControl` mock 成永远成功，所以「五个变体全
`true:true`」全绿，却掩盖了 prefab 不存在这一层；而逐格 `furn` 手搭层在真机又被
`if self._furn_tpl_ok then return true end` 与 `_furn_arch_new` 两道门跳过 ⇒ 两条路径都落空。

**附带发现的结构差异**：692 构建器用 `f.sub.push(#504)`，把 46 条新记录里 44 条带父记录的
顶层 `#504` 全放到了**记录末尾**；而所有既有可显示模板（`furn.rug.2` 家族、`furn.plant.2`）
的 `#504` 都在第一个 `#505` 状态块**之前**。protobuf 字段顺序理论上无关，但存档编辑器
历史上出现过顺序依赖事故，故一并对齐。
