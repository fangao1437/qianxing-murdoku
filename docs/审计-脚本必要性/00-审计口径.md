# 审计口径 —— 「脚本代码是否都必要」

> 建立：2026-10-18（优化组第一轮）
> 目的：**只排查、不删除**。把「当前脚本里不必要的东西」逐条列成可核对的清单，
> 一轮之后按清单分批清理（用户原话：「先不做删除，完毕后逐步清理」）。

工程根：`D:\新建文件夹\miHoYo Launcher\qianxing-murdoku`
上机负载的唯一来源：`lua/**` → `tools/bundle_client_script.lua` → `dist/client_script.lua`（**1.34 MB**）→ 写进 `.gil` 内嵌 → 客户端执行。

---

## 一、什么叫「不必要」（五类，判定条件写死）

| 类 | 名称 | 判定条件（必须同时满足） |
|---|---|---|
| **A** | **死代码** | 定义存在，但**任何调用路径都到不了**：prod 侧 0 引用；且不是引擎回调、不是字符串/动态派发入口、不被测试断言依赖（或测试可同步改） |
| **B** | **结案探针** | 只为「定位某个已结案的 bug」而存在的诊断：`print` 探针、`diagnose_*`、`_probe_*`、账本/计数器、`cfg.*_diag` 开关。判定要给出**该 bug 已结案**的依据（回执文档/提交/修复位置） |
| **C** | **死分支 / 恒假路径** | 条件恒为假（`if false`、被写死的 `false` 配置、已裁掉的状态名），或分支里写的控件/状态**已不存在**（存档、layout plan、关卡数据三处都找不到） |
| **D** | **废弃模块 / 文件** | 整个文件不再参与上机路径，或只作为离线桩/测试夹具存在，却仍被打进 `dist/`（进包 = 上机负载） |
| **E** | **冗余数据** | 表里声明了但从不被读到的条目：线索类型、图标/音效 id、信号 schema、`ICONS/EFFECTS/SOUNDS`、关卡字段等 |

**不在本表内的，一律不算"不必要"**，例如：注释里的大段历史（不占上机负载，另立"注释瘦身"议题）、
`docs/` 文档、`.gil` 存档里的控件（属界面资产，不是脚本代码）。

## 二、证据要求（每条都要过这五问）

1. **位置**：`文件:行号`（定义处）＋ 判定所依据的引用处/缺失处。
2. **反向检查**：报告必须写「查过哪些可能让它变成必要的路径」，至少覆盖：
   - 动态派发：`表[变量]`、`M.EFFECTS[...]`、`states[...]`、`action` 字符串分发
   - **按名字寻址**：这个工程大量用**控件名字符串**驱动（`find("hex.back")`、`plan.nodes[].event.action`），
     所以"名字只出现在字符串里"也可能是**必要的**
   - 测试/工具依赖：`tests/**`、`tools/**`（`raw-deadcode.json` 里 test/tool 计数）
   - 引擎回调：`OnInit/OnStart/OnEnable/OnUpdate/OnLevelUpdate/OnDisable/OnDestroy` 是**引擎调用**，prod 0 引用是正常的
3. **结论标签**：`[实测]`（跑过/读过代码确认）·`[官方]`（文档）·`[模拟器]`·`[推断]`（未验证，不能作为删除依据）·`[未验证]`
4. **删除风险等级**：P0 零风险 / P1 低 / P2 中（要改测试或存档命名）/ P3 需用户决定或需真机验证
5. **反向证据**：如果找到"它其实还在用"的证据 ⇒ 必须在报告里写进「误报回收」段，不许静默丢弃。

## 三、禁止事项

- **不许改** `lua/**`、`tools/**`、`tests/**`、`dist/**`、`.gil`、存档 —— 本轮只写审计文档。
- **不许凭注释断言**。本工程的注释里有大量**已被现状推翻**的历史结论（见 `仓库注意事项.md`、`platform-facts` 口径）。
- **不许下"不存在/做不到"的否定结论**（`docs/资料索引.md` 的纪律：查不到 ≠ 不存在）。
- 不许开模拟器、不许跑 `runCase`、不许改存档（步骤 1–4 禁区）。
- PowerShell 读含中文文件**必须** `-Encoding UTF8`，数行数用 `[System.IO.File]::ReadAllLines($p).Count`。

## 四、输出格式（每份分报告统一）

```markdown
### <编号> <一句话名称>
| 项 | 值 |
|---|---|
| 类别 | A/B/C/D/E |
| 位置 | `lua/xxx.lua:1234`（定义） + 判据位置 |
| 规模 | 约 N 行 / N 字节（上机包里的占比） |
| 判据 | 为什么它不被需要（引用计数、哪些路径查过了） |
| 反向检查 | 动态派发 / 字符串寻址 / 测试依赖 / 引擎回调 四项各查了什么 |
| 删除风险 | P0–P3 + 理由 |
| 标签 | [实测] / [推断] … |
```

末尾必须给：**本文件合计**（各类条数、可删行数估计、P0 占比）。

## 五、机械底稿（所有人共用）

`tools/audit/deadcode.mjs`（新增，只读）→ `docs/审计-脚本必要性/raw-deadcode.json`

它做的事：先剥注释/字符串（保留行号），再抽定义（`function A.b(` / `local function b(` / `A.b = function`），
然后分三份语料数引用：prod = `lua/**`、test = `tests/**`、tool = `tools/**/*.lua`。
口径限制（报告里要照抄）：短名跨文件冲突会**漏报**；动态派发无法静态判定，单独列出。

复跑：`node tools/audit/deadcode.mjs`

## 六、本工程已知的「看起来像死代码、其实不是」

| 名字 | 为什么不是 |
|---|---|
| `OnInit/OnStart/OnEnable/OnUpdate/OnLevelUpdate/OnDisable/OnDestroy` | 引擎生命周期回调，prod 0 引用正常 |
| `M.EFFECTS.xxx` / `M.SOUNDS.xxx` / `M.SIGNALS.xxx` / `ICON_ASSETS.xxx` | 由字符串/枚举名派发，静态计数为 0 不代表死 |
| `entry_client_script.lua` 的 `auto_create_only` 白名单 | 按名字建控件，名字出现在字符串里 |
| `Murdoku.DIAG` 门内的诊断 | **仍被调用**，但只在开关打开时才有用 ⇒ 归 B 类"结案探针"而不是 A 类"死代码" |
| `tools/**` 里标"当前无人调用"的工具 | 索引里明写"**不删**，时机到了手工跑" ⇒ 不在清理范围 |
