## 一、评审响应与 746 调整目标

提交 `1056f21aca21` 对 744 与 745 的性能收益与潜在风险进行了静态独立审查，核心结论为：
- 建议保留 744 的重复写消除、索引退避，以及 745 的同关切页复用与事件驱动置顶；
- 指出 **6 处实现会在工作仅完成一部分或静默失败时记为成功（3 项 P1 + 3 项 P2）**，要求在继续压低调用数前先补齐恢复闭环并做故障注入实测；
- 指出此前 744 与 745 基准口径不统一（暂停 GC 堆增量 vs 自动 GC 堆净变化、不同帧数与桩），且切屏 12 次仍存在尾部 `GetChildren` 尖峰，要求统一桩与口径并报告切屏逐帧分位数和最慢帧树枚举次数。

746 针对以上全部问题完成了三部分工作：
1. **完整闭环 6 项评审改进（P1-1～P1-3、P2-1～P2-3）**，并对每项构造双版本故障注入测试（验证 745 复现缺陷、746 自动恢复并校验实际业务交互）；
2. **定位并消除切屏尾部与非关内倒计时期的 8,578 节点全树扫描尖峰**（4 项附加优化 + 1 项句柄销毁容错加固）；
3. **建立统一口径四代（743 / 744 / 745 / 746）高仿真基准**，在同一套 8,578 真实节点桩上统一汇报区间 CPU、暂停自动 GC 累计分配（`allocKB`）、引擎 API、`GetChildren`、`pcall` 及切屏逐帧 P50/P95/P99/Max 与最慢帧树枚举数。

## 三、切屏尾部热点定位与 5 项附加加固

在对 745 的 12 次连续切屏（`screen_switch_burst`）和 60 秒结算倒计时窗口做逐帧 `GetChildren` 调用栈采样时，定位到四类高频浪费与一处重建容错盲区，已在 746 一并解决：

1. **嵌套表浅比较引发的每秒重复下发（`Bonus-3`）**：`Controller:tick` 在开局前 60 秒倒计时期间每秒更新首页/选关按钮文案（`self.dirty = true`）；而 `same_value(a, b)` 只做了一层浅对比，导致含嵌套表的 `cell.1.2`（`furn` / `walls` / `doors` 等）每秒都被误判为属性变化，进而不断触发 `adapter:find("cell.1.2")` 与 8,578 节点全树索引重建。升级 `same_value` 支持递归表值比较后：
   - `steady_home` 300 帧 `GetChildren` 从 **8,578 → 0（-100%）**，API 从 **9,257 → 667（-92.8%）**；
   - `steady_select` 300 帧 `GetChildren` 从 **17,156 → 0（-100%）**，API 从 **25,059 → 7,885（-68.5%）**；
   - `tests/shop_cold_render.lua` 总写入数也从 `13,628` 降至 **`13,592`**。
2. **切屏非关内缺失 `fart.*` 触发全树重建（`Bonus-1` & `Bonus-3`）**：非关内切屏时 `_apply_furn_level()`（`_furn_level == false`）与 `_apply_baked()`（`want == false`）仍查询存档中不存在的 `fart.furn` / `fart.case_001`，在索引 TTL 到期瞬间造成单帧 **8,761 次 `GetChildren`** 尖峰。非关内直接早退后彻底消除了该尖峰。
3. **同关切屏精准清理 `_misses`（`Bonus-4`）**：745 同关切屏直接将 `adapter._misses = nil`，导致非关内互切（首页 ↔ 选关 ↔ 商店 ↔ 背包）把 `cell.*` 的缺失退避清零并再次触发全树索引重建。746 改为进关时全清、非关内切屏保留 `cell.*` 退避并清零其余页面控件退避，使 12 次切屏最慢单帧 `GetChildren` 从 **8,761 → 394（-95.5%）**。
4. **隐藏子树幂等标记与单节点合并 `pcall`（`Bonus-2`）**：已通过 `enforce_hidden_subtrees` 且保持隐藏状态的控件记入 `_hidden_enforced746`（重新显示或换代即失效），避免切屏重复遍历已隐藏子树，并合并单节点 `name`/`visible`/`GetChildren` 为单次静态 `pcall`。
5. **`clear_board_portraits` 重建容错加固**：在 `zone3` 销毁全部旧控件句柄后切屏的极端场景中，原无保护调用 `adapter:clear_board_portraits()` 会因访问已销毁旧句柄抛错；已用 `pcall(adapter.clear_board_portraits, adapter)` 包裹，确保随后顺利触发 `_root_alive745() == false` 回退全树重建。

## 六、局限说明与真机验收建议

- **测试局限**：以上性能、故障注入恢复与状态差分均来自基于真实 8,578 节点 `.gil` 控件树的离线高仿真环境，尚未导入千星奇域真机实测。
- **建议真机重点验收**：
  1. 在真机同一分辨率与 30/60 FPS 档位下用 745 与 746 重复 12 次连续切屏，对比冷启动与预热后逐帧 P95/Max 帧时及切屏体感；
  2. 进入关卡快速点选线索卡（验证 `gray` 灰层无拦截）、划 `X`（验证 `face` 恒亮与 `x` 保持 70%）；
  3. 切换手机宽高比/选关翻页（验证右箭头热区与视觉对齐且可正常翻页）、打开商店/背包（验证根容器居中、无偏位、撕边完整）。
