# 方案乙：每关一个网格视窗 —— 编辑器清单 + 脚本接线

> 2026-10-10　｜　用户选定方案："**每关一个视窗，脚本按关卡显示对应的视窗**" ✓
> ★ **为什么必须这么做** ✓：引擎给列表项的控件数**是固定的** ✓ ⇒ ★ **内容超出就必须滚动 ⇒ 控件回收 ⇒ 一串 bug** ✓

---

## 一、★ 根因（一串问题，一个来源）

真机实测（v116/v119 两份日志 ✓ 结论一致）：

```
★ 探针·本次 RefreshItems：传了 n=15 条；回调进来 7 次；视窗子控件 7 个
★ 探针·列表项控件：新控件 id=651 pos=1 ／ id=659 pos=2 ／ … ／ id=699 pos=7   （共 7 个）
★ 探针·控件复用：id=651 从 pos=1 **改代表** pos=8
★ 抢点击诊断：GetItemIndex 只出现 0 / 1 / 2 ⇒ 「点哪张都是同一个标记」✗
```

⇒ ★★ **15 条线索只有 7 个控件，靠循环复用** ✗
⇒ ★★★ **下面这些症状全是它的派生** ✓：

| 症状 | 与复用的关系 |
|---|---|
| 高亮"粘"在别的卡上 | ★ 控件换代表后，旧状态留在它身上 |
| 点后面的卡"选错人" | ★ `GetItemIndex` 在复用后失真 |
| 点一张选好几张 | ★ 多个控件叠在模板那个点上 |
| 弹回顶部 | ★ 重发 `RefreshItems` 会重置滚动 |

⇒ ★★ **只有"让内容装得下、根本不滚动"才能从根上消除** ✓ —— ★ **这就是方案乙** ✓

## 二、★ 要在编辑器里做什么

### 步骤 1：量出你一共需要几种尺寸

★ **决定因素是每关的线索条数** ✓。★ 现在有 **7 条** 和 **15 条** 两种 ✓。

★ **每种条数一个视窗** ✓，高度按这个公式算 ✓：
```
视窗高 ≥ 上边距 + 条数 × 项高 + (条数 − 1) × 纵间距 + 下边距
```
★ 代入现参数（边距 20/20 ✓ 项高 96 ✓ 纵间距 8 ✓）：

| 条数 | 需要的高度 | 建议视窗高 |
|---:|---:|---:|
| 5 | 20 + 480 + 32 + 20 = **552** | **560** |
| 7 | 20 + 672 + 48 + 20 = **760** | **768** |
| 15 | 20 + 1440 + 112 + 20 = **1592** ✗ 屏高只有 900 ✗ | ★ **放不下 ⇒ 15 条那关要么压小卡片要么分页** ✗ |

⚠️ ★★ **关键约束**：★ **画面只有 900 高** ✗ ⇒ ★ **一张卡 96 高时，最多装约 8 条** ✓
　 ⇒ ★ **15 条那关必然装不下** ✗ ⇒ ★ **要么把卡片压矮**（★ 例如 56 高 ⇒ 15×56+14×8+40 = **992** ✗ 仍超 ✓）
　 ⇒ ★★ **要么那一关拆成两栏/两页** ✓ —— ★ **这一条得你定** ✓

### 步骤 2：复制网格视窗

★ **每个条数做一个** ✓，★ **复制现有的 `clues.grid` 最省事** ✓（它的配置都是对的 ✓）：
1. ★ 在编辑器里**复制 `clues.grid`** ✓
2. ★ 改成对应高度 ✓（★ 只改高度 ✓ 别动其他 ✓）
3. ★ **命名务必统一** ✓ —— ★ 脚本按名字找 ✓：`clues.grid5` / `clues.grid7` / `clues.grid15` ✓
   （★ 名字里的数字 = 这一屏能装的**条数** ✓，不是关卡号 ✓）
4. ★ **全部叠在同一个位置** ✓（★ 脚本一次只显示一个 ✓，其余的藏起来 ✓）
5. ★ **模板引用保持 `clue`** ✓（★ 都指向同一个模板 ✓）

### 步骤 3：告诉脚本这份名单

★ 建好之后，★ **把名字发给 AI** ✓ 或自己填进 `lua/main.lua` 的
`cfg.clues_grid_by_count = { [7] = "clues.grid7", [15] = "clues.grid15" }` ✓
★ 脚本会按**当前关卡的线索条数**挑最合适的那个 ✓（★ 取"能装下且最小"的 ✓）
