# 图片引用方式 · 素材库规模 · 头像控件建在哪

> 用户 2026-10-04 提问：「图片引用还有除静态引用外的好几种，先查清每种的区别以及素材库大小，
> 再决定头像要不要引用外部资产 —— 这决定了头像控件要建在哪。」
> 下面每条都标了**出处**（本项目本地文档 / 真机实测），查不到的写「未能确认」，不猜。

---

## 一、引用方式一共 **8 种**（出处：`docs/7.1-脚本API速查.md:190-195`）

```lua
Enum.ImageType   = Basic(基础) | Stretch(拉伸)                -- imageType，读写
Enum.ImageSource = StaticReference(静态引用) | Item(道具) | Equipment(装备)
                 | Skill(技能) | UnitStatus(单位状态) | Faction(阵营)
                 | Currency(货币) | Prefab(元件)                 -- imageSource，只读
```

写入用 **`SetImage(imageSource, imageId)`**（同一个文档 185 行）；
`imageSource` / `imageId` 作为**属性**是**只读可读**的 —— 所以脚本**读得到、也能整体写**。

| 引用方式 | 像素从哪来 | 绑定时要给的 | 脚本能否换 | 适用 |
|---|---|---|---|---|
| **静态引用** StaticReference | **固定的素材资产**（内置素材库 或 **导入的外部资产**）| `imageId`（素材 id）| ✅ | **界面用图，全部走这条** |
| 道具 Item | 该**道具**的图标 | 道具 id | ✅ | 显示某件道具长什么样 |
| 装备 Equipment | 该**装备**的图标 | 装备 id | ✅ | 同上 |
| 技能 Skill | 该技能的图标 | 技能 id | ✅ | 同上 |
| 单位状态 UnitStatus | 某个**状态/buff** 的图标 | 状态 id | ✅ | 同上 |
| 阵营 Faction | 某**阵营**的图标 | 阵营 id | ✅ | 同上 |
| 货币 Currency | 某种**货币**的图标 | 货币 id | ✅ | 同上 |
| 元件 Prefab | 某个**元件**的图 | 元件 id | ✅ | 同上 |

### 三点结论

1. **静态引用 = 「直接指向一张素材图」**；其余七种 = **「指向游戏数据里的某个东西，由引擎把它的图标画出来」**。
   ⇒ 它们的**像素不来自素材库**，而来自游戏数据。所以「换个头像」在静态引用下是**换素材 id**，
   在道具/装备那几种下是**换数据 id**。
2. **只有静态引用能指向"导入的外部资产"** —— 见第三节。
3. **没有任何一种是"角色头像"**（列表里没有 Character/角色）。最接近的是 `Prefab(元件)`，
   但它指向的是 UGC 元件，不是原神角色。⇒ **要 5 张嫌疑人头像，只能靠素材库或外部资产。**

### ⚠️ 一个容易混的点（出处：同一文档 197-204）

「基础 / 拉伸」（`Enum.ImageType`）和「普通 / 三宫格 / 九宫格」（**素材资产自身的属性**）是**两回事**：

- 素材属性是 `普通` 时，基础 和 拉伸 **表现完全一样**（都铺满控件、四角都形变）；
- 只有素材是 `三宫格/九宫格` 时，选 `拉伸` 才会保住边角。
- ⇒ **「基础」也会铺满控件**，不会溢出。（本项目那些"静态引用不支持拉伸"的抱怨，根源是**素材本身是普通属性**，
  不是引用方式的问题；需要拉伸的地方改用「底板」类素材即可。）

## 四、⇒ 结论：头像控件建在哪（这是你真正要的决策）

两条路都**不需要**把头像控件摆进卡片里 —— 因为头像本身**没有文字**，
而脚本能建的控件恰好就是"不带文字的纯图"那类 ✅（判据见
`docs/线索卡-选中反馈与节点图分工.md` 第四节）。

| 方案 | 素材从哪来 | 头像控件**建在哪** | 换头像时要改什么 |
|---|---|---|---|
| **A. 内置素材**（推荐先走这条）| 素材库 **造物 112xxx / 道具 111xxx** | **脚本建**（纯图片模板 `prefab_icon` + `SetImage(StaticReference, id)`）| 改脚本里一个 id |
| **B. 外部资产** | 你自己导入的 `.gia` 资产 | **脚本建**；但**需要一个中间人**：编辑器里摆 `assets` 容器 + `portrait.A..E` 五个图片控件（图片源=静态引用→选中导入的资产）| **只动 `assets` 里的图**，脚本不用改 |
| **C. 道具/装备等七种动态引用** | 游戏数据 | 脚本建（`SetImage(Item, 道具id)`）| 换数据 id |

### 为什么外部资产需要那个"中间人"

脚本**读不到**"你导入的那个资产"的 id —— 它只能从一个**已经引用了该资产的控件**上读：

```
读 portrait.A 的 imageSource + imageId  →  SetImage(这两个值) 写到卡片头像上
```

这条链子**已经在格子上跑通了**（`Adapter:_cells_stamp` 注释原文：
「图片控件的 imageSource / imageId 是只读可读的（API 文档 1427~1434），
`SetImage(imageSource, imageId)` 是写接口（1503），所以可以直接照抄。」）

### 我的建议（先做 A，把 B 留作后路）

1. **先用内置「造物」类素材**（42 张里有现成角色形象）跑通整条线索区 —— **零导入成本**，
   而且头像控件**完全由脚本建**，编辑器里除了那 16 个文字控件什么都不用摆。
2. 等玩法定稿、你真要换成自己的画风时，再走 B：**导入资产 → 摆 `assets/portrait.A..E` → 脚本自动照抄**。
   **脚本一行都不用改**（它本来就写着"优先从 `portrait.X` 照抄，找不到就用"）。
3. ⚠️ 无论哪条路，**头像控件都不要摆进卡片** —— 摆进去就变成"每张卡都要你手动配图"，
   而放 `assets` 调色板里只需要配 5 次、且能脚本复用。

## 六、★ 那七种的 id 从哪来（用户追问：「除了静态引用其它都要输入 id，这些 id 怎么创建或找到」）

### 关键推断（有本地证据支撑）：**它们是"你在沙箱里创建的东西"的 id，不是原神本体的数据 id**

三条并列证据：

| 证据 | 内容 | 说明 |
|---|---|---|
| `docs/千星存档-gil格式.md:17` | `.gia` = **资产（元件 / 实体 / 技能 / 道具 / 节点图）** | 这五类**全是千星沙箱里"你自己做"的东西** ⇒ `Item(道具)` / `Skill(技能)` / `Prefab(元件)` 指向的正是它们 |
| `docs/7.1-Lua脚本情报.md:27` | 官方教程：资产（元件 / 技能 / **单位状态** / 地形 / 节点图等）**能导入导出** | 「单位状态」也在资产清单里 |
| `docs/编辑器搭建指南.md:438` | 结构体成员支持的类型：GUID / 整数 / 布尔 / 浮点 / 字符串 / **阵营** / 三维向量 / **元件ID** / **配置ID** | ⇒ 「阵营」「元件」在沙箱里都是**一等公民的数据类型**，各有一个 id |

⇒ **结论：这些 id 是"编辑器分配"的，不是你从原神图鉴里抄的。**
   （对照：静态引用填的是**素材库 id**（100001、107003 那种）；
   这七种填的是**你项目内某个东西的 id**。）

### 逐个：去哪创建、去哪找

| 引用方式 | 指向什么 | 在哪创建 | 怎么拿到 id |
|---|---|---|---|
| **Prefab(元件)** | **自定义元件** | **「元件库」**（沙箱里那个"自定义元件"）—— 出处 `docs/编辑器搭建指南.md:332` | 见下面「读出 id 的通用办法」 |
| Item(道具) / Skill(技能) | 沙箱资产（`.gia` 类型里就有） | 沙箱里新建对应资产 | 同上 |
| UnitStatus(单位状态) | 单位状态定义 | 同上（官方资产清单里有） | 同上 |
| Faction(阵营) | 阵营定义 | 沙箱的阵营设置 | 同上 |
| Equipment(装备) / Currency(货币) | **未能确认** | 未能确认 | 未能确认 |

**在编辑器里放一个"引用了那个东西"的控件，运行时读它的只读属性** —— 这是项目里已经跑通的套路：

|---|---|---|---|
| 客户端控件**模板** id | 「模板引用控件」 | **`referencedPrefabIndex`**（不是 `prefabIndex`！）| `docs/控件坐标表-1600x900.md:677-679`、`docs/真机搭建与运行指南.md:207` |

## 七、★★ 官方原文的修正：**非静态源不是"填 id"，而是"绑一个变量"**

官方《图片控件》原文（<https://act.mihoyo.com/ys/ugc/tutorial/detail/mh2oih9jou22>，
本地 `docs/api-cache/mh2oih9jou22.txt:35-36`）：

> **(2) 当图片源配置为其他类型时 —— 支持奇匠配置自定义变量，作为对应图片的标识使用**

⇒ 真实形态是：

```
图片源 = 道具   +   绑一个「自定义变量」（这个变量的值才是道具的配置ID）
```

而自定义变量支持 `元件ID` / `配置ID` 这类数据类型，**默认值由你在编辑器里填**
（<https://act.mihoyo.com/ys/ugc/tutorial/detail/mhso1b9wjica>，`mhso1b9wjica.md:25-28,59-63`）。

**所以链路是**：`节点图写变量` → `图片控件绑变量` → 控件显示对应图标。
（不是"填个数字就出图"。）

## 九·补、★ 元件引用不显示的三条候选原因（2026-10-04 用户实测：填了元件ID 但没有图）

| # | 候选原因 | 依据 | 怎么验 |
|---|---|---|---|
| **1（最可能）** | **选错了元件类型** —— 用户填的 `1077936252` 是**「动态单位元件」**（场景里是个 **3D 炸药桶模型**）；**3D 单位元件没有 2D 图**，图片控件拿不到可显示的像素 | 元件详情页顶部写着「动态单位元件」；元件列表里那些角色的缩略图都是**虚线占位图**（无预览）| 换一个**明确有 2D 图**的元件试（例如界面控件组元件/带图标的元件） |
| **2** | **这类引用在编辑器预览里本就不解析，要运行时才出图** | 本项目多次遇到"编辑器看不到、真机能看到"（服务器控件、客户端控件实例都是）| **进游戏/试玩**看，而不是只看编辑器预览 |
| **3** | 元件需要**在关卡里已放置/已加载**，或 id 不属于当前关卡 | 未确认 | 把该元件先放进场景，再看图片控件 |

## 九·补二、★ 决定性证据：**两个 id 空间完全不相交**（这才是"什么都不显示"的机制）

官方《ID修改》有一张 **ID 类型表**（社区缓存 `docs/community-cache/kb-all.json` → 官方 `mhsd6lrx3voe`，

## 十二、★★ 补充调查：四条**会改变判断**的新事实

（来源：官方《图片控件》配图逐张下载核对 + 本项目历史实测。所有配图 URL 见本节末。）

### 1. ★「外部资产」转存后分两类，**结局完全不同** —— 这是"跳板"问题的最新证据

官方流程：`系统菜单 → 资产导入导出工具 → 导入与转存 → 加载外部资产`
（文件放 `…\LocalLow\miHoYo\原神\BeyondLocal\Beyond_Local_Export`），然后**必须手动「转存所选资产」**
（官方 FAQ 原文：`导入外部资源后，外部资源统一放置在资产库中，根据需要手动单独转存`）。

| 转存出来的东西 | 能否用于客户端控件 |
|---|---|
| **控件模板** | ✅ 能显示 |
| **图片素材** | ❌ `InstantiateClientUIControl(索引)` **返回 nil**；且**外部资产的图片只能在服务器控件（编辑器里摆的）上显示，客户端控件容器子级里加载不了外部资产** |

⚠️ 而且项目当年还踩过更具体的一脚（`docs/客户端控件vs服务器控件.md:62-64`）：
把该资产**另存为模板之后**，"模板化就能实例化"这个想法**被用户当场纠正**
⇒ **导入的图片素材即使模板化，当时也没能变成可实例化的客户端控件。**

⇒ 结论：**外部资产走不通"脚本建控件"这条路**；要显示就只能**编辑器摆服务器控件**
（= 第十一节那两块墙，现在有 3 条独立证据）。

### 2. ★「动态引用」—— 对"以后要换头像"最省事的一种，**值得试**

官方配图逐像素看过：`图片源=动态引用` 的面板里**只有一个「素材ID」字段**，右边是**取变量**按钮，
左侧同时开着 **变量库**（玩家1…玩家8 / 玩家自身 / 关卡）。

⇒ **动态引用 = 「素材库素材，但由自定义变量的值决定是哪一张」。**

**它的价值**：**运行期换图 = 写一个变量，完全不用 `SetImage`** —— 比静态引用省事得多。

| 问号 | 状态 |
|---|---|
| 动态引用下**还有没有「图片类型」**（能否拉伸）| 未确认。官方把「图片类型/图片属性」只写在**静态引用**小节；但**基础也铺满控件** ⇒ 64×64 图标影响不大 |
| 脚本侧怎么读写动态引用 | **未能确认** —— `Enum.ImageSource` 里**没有** `DynamicReference` 这一项，也没有对应 API ⇒ 只能靠**节点图改变量** |

## 十三、★ 两个各 2 分钟的实验（做完就能定案）

### 测试 B —— 要不要改用「动态引用」
