## 一、评审响应与 747 优化目标

提交 `955ebd00434d` 对 742 v13 至 746 的性能收益、交互恢复缺陷与验证边界给出了系统性裁定，明确要求在继续追求更高帧率之前先修复所有高风险交互闭环并加固验证与写盘工程链路。747 逐条响应并落地全部四类工作：

1. **补齐 4 项 P1 交互与恢复闭环**：同根替换按钮自动换绑与开射线、线索灰层写失败后玩家原地不动自动重试、点击热区 `enable_raycast` 遇局部报错绝不提前收敛且定向补扫失败子树、切页隐藏 `enforce_hidden_subtrees` 遇错重新入队节流补藏；
2. **修复 4 项 P2 细节与 1 项长等待体验问题**：修复未定义全局变量 `cur_vis`（并引入 `luac -p -l` 字节码门禁）、商城回读严格校验读接口存在性、格子巡检“完整”定义补齐 `box` 容器、翻页失败项隔离重试不破整页稳态、以及将商城缺项挂回等待从 **12.43s 压缩至 1.43s**（且 40 秒内 0 次整页空转重绘、0 次全树枚举）；
3. **三项真实尾部与热点消峰（Perf-1～Perf-3）**：全树名称索引 `index_in` 剪枝纯静态画片大容器（全部仍由 `STATIC_PATH_655` O(1) 直查，补齐 `art685.mark.*` 静态动态路由）、关内稳态 `murdoku_set_vis` 与格子巡检对 `cell.*` 改走 `board`/`stage` O(1) 直查、`sync_adapt715r` 649 背景叶与 591 撕边叶改整批 `pcall` + 异常逐叶降级；
4. **加固构建与验证工程链**：`writeGil` 原子落盘防半成品占坑、`build_747.mjs` 强验收契约（逐项断言 schema / SHA256 / 21 项专项 / 5 轮基准）与 `luac` 字节码零新增未定义全局变量检查，五代（743–747）统一采用 **5 轮重复采样**（报告均值、中位数、标准差与逐帧 P50/P95/P99/Max）。

## 三、性能热点定位与三项尾部消峰（Perf-1～Perf-3）

通过逐行 `GetChildren` 与切屏耗时剖面，定位并消除了 746 遗留的三处大头：

1. **`Perf-1`：全树名称索引 `index_in` 剪枝纯静态美术画片大容器 + 补齐 `art685.mark.*` 静态动态路由**
   - 8,578 个真实控件节点中，超过 7,100 个属于纯静态画片、背景切块（649 叶）、撕边叶（591 叶）、教程矢量页碎片（`td.l1/l2/home.page.*` 2,200+ 叶）、静态装饰层（`art641.game`、`art642.select.backdrop`、`adapt715r.WAX.12`、`police-v19`）与游离家具模板碎片（`furn.*`），这些节点要么已由 `STATIC_PATH_655` O(1) 路径直查覆盖，要么由对应模块按组名调用 `GetChildren()` 访问。
   - 747 同步为 `art685.mark.overlay`、`art685.mark.X.Y` 与 `art685.mark.X.Y.stroke.Z` 补齐 `path_lookup_655` O(1) 动态路由，随后在 `index_in` 中登记大容器自身但不递归钻入其静态碎片，将单次 `_build_name_index` 遍历量从 **8,578 节点压降至 ~1,385 节点（-83.9%）**。
2. **`Perf-2`：关内稳态 `murdoku_set_vis` 与格子巡检对 `cell.*` 优先 O(1) `board`/`stage` 直查**
   - 746 中 `steady_level` 300 帧仍有 `17,179` 次 `GetChildren`，根因是 `murdoku_set_vis` 每 30 帧兜底查尚未实例化的 `cell.1.2`~`cell.5.5` 触发了 2 趟 8,578 节点全树 DFS。
   - 747 改为稳态非 `forcing` 期先查 `ad.controls` 与 `board`/`stage:GetChild(nm)` O(1) 直查（同时在 `fc745.stable == 0` 保留安全兜底），使 `steady_level` 300 帧 `GetChildren` 从 **17,179 → 2,793（-83.7%）**，CPU 均值从 **27.6ms → 11.8ms（-57.2%）**。
3. **`Perf-3`：`sync_adapt715r` 背景 649 叶与撕边 591 叶整批 `pcall` + 异常逐叶降级**
   - 切屏时将 649 个背景叶与 6 组撕边（591 叶）的 1,240 次热循环单叶 `pcall` 合并为 7 次整批 `pcall`（任一批抛错时自动降级回逐叶 `pcall`，不丢失异常隔离语义），进一步压缩切屏 P99（`14.2ms → 6.6ms`，**-53.5%**）与总切屏耗时（`47.6ms → 37.0ms`，**-22.3%**）。
