# 真机排查：控件"建了却找不到"

> 症状：编辑器里明明有 `root` / `board` / `cell.1.1`，脚本却报
> `[murdoku] 控件未找到：root（请在客户端控件容器里按此名字创建）`。

---

## ★ 真机实测结论（2026-09-26 01:05，已定案）

**根因是「时序」，不是名字、也不是层级。**

```
[murdoku] OnInit done（适配器已就绪，等 OnStart 开局）      ← 初始化没问题
[murdoku] ===== 客户端控件树（脚本能看到的，共 0 个节点）=====   ← ★ OnStart 时树是空的！
[murdoku] 控件还没就绪，交给 OnUpdate 重试
[murdoku] 已由脚本打开 2 个容器的「显示常驻光标」            ← 约 0.5 秒后，树有了
[murdoku] started (retry 1)                              ← 重试成功
```

### 客户端控件是在 `OnStart` **之后约 0.5 秒**才被创建出来的

于是：

| 版本 | 行为 | 结果 |
|---|---|---|
| 旧版 | `Murdoku.on_start` 照样返回会话 → `started = true` → **不再重试** → 只渲染了那一次（对着**空树**） | 把**所有**控件都报成「未找到」，看着像"你一个都没建" |
| 新版 | 探针失败**不开局**，交给 `OnUpdate` 每 0.5 秒重试（最多 30 秒） | `started (retry 1)`，正常跑起来 |

> **这条解释了历史上所有"编辑器和预览都对、一进游玩什么都没有"的困惑。**
> 也顺带说明：**试玩过程中把控件补齐是有效的** —— 只要在 30 秒内补上，脚本自己会接上。

### 怎么判断自己是不是这个情况

对比「控件未找到」的名单里**有没有你确实建了的那些名字**：

- **有** → 就是这个时序问题（旧包）→ 用新包重跑即可
- **没有** → 你已经建对了，剩下报的是**还没建的**控件，属正常

（2026-09-26 01:05 那份日志里，`root` / `board` / `cell.1.1` 都已经**不在**未找到名单里了。）

## 第一步：看有没有这三行（新包才会打）

```
[murdoku] OnInit done（适配器已就绪，等 OnStart 开局）      ← OnInit 完整走完
[murdoku] 画布 <W>×<H>，…                                  ← 脚本真在跑，且拿到画布尺寸
[murdoku] 已由脚本打开 N 个容器的「显示常驻光标」            ← 门控②自愈成功
```

| 情况 | 含义 |
|---|---|
| 有 `OnInit done` | ✅ 初始化没问题，往下看"控件为什么找不到" |
| 有 `OnInit 在【…】这一步失败：…` | ❌ 初始化炸了 —— **把那整行发我**，控件的事先放一放 |
| 一行都没有 | ❌ 脚本根本没执行 —— 回到 `docs/你现在要做的清单.md` 第 1 步 |

> 实测：真机画布就是 **1600×900**（日志 `画布 1600.00×900.00，与设计一致`），
> 所以 `docs/控件坐标表-1600x900.md` 可以直接照抄，不需要重算。

## 第二步：看 `找不到 board / cell.1.1` 后面那段

新包会把**脚本能看到的客户端控件**整个列出来，并直接给结论。

### A. 树是**空的**（`共 0 个节点`）

```
[murdoku] 客户端控件树是**空的**（0 个节点）…
[murdoku]   ① 界面布局没被【职业】引用 —— 战斗预设 → 职业 → 选择布局
[murdoku]   ② 控件做在了【界面控件组库】里 —— 必须【添加至界面布局】
[murdoku]   ③ 控件没放进【客户端控件容器】里面（或容器没勾【激活】/【可见】）
```

**先别急着改这三条** —— 如果是**开机第一瞬间**打出来的这句，那多半就是上面说的**时序**，
等 0.5 秒的重试就好。**只有当重试 30 秒后仍然打这句、并且打出
`等不到客户端控件，放弃自动开局`，才是真的没建/没引用。**

要确认的话看这两条的顺序：

- `控件还没就绪，交给 OnUpdate 重试` → 后面跟着 `started (retry N)` ⇒ **时序，已自愈** ✓
- 后面跟着 `等不到客户端控件，放弃自动开局` ⇒ **真的要改那三条** ✗

### B. 树里**有东西**，但就是没有 `board` / `cell.1.1`

```
[murdoku] 树里有 N 个节点，但里面没有 board / cell.1.1。
[murdoku]   近似 root 的名字有：Root / root(1) …   ← 把"差一点"的名字直接点出来
```

**这一类的病因才是"名字/层级不对"：**

- ⚠️ **精确匹配**：`root` ≠ `Root` ≠ `root ` ≠ `root(1)`
- ⚠️ **层级**：`board` 要是 `root` 的子节点；`cell.1.1` 要是 `board` 的子节点
- ⚠️ 名单标了 `vis=` / `act=`，能看到是不是被隐藏/停用了

## 常见做法确认：把「自带节点」改名为 root，行不行？

**行。** 脚本的查找是"从 `game.GetClientUIRoots()` 返回的根开始逐个比名字"，
**并且会匹配节点自身**（`find_in` 第一件事就是拿自己的 `name` 比）。
所以把一个自带节点直接改名成 `root` 是**合法做法**，不需要非得新建一个容器节点。

但改名之后，下面几条**一条都不能少**：

| 检查项 | 怎么确认 |
|---|---|
| 那个节点在**界面布局**里（不是界面控件组库） | 官方：控件组库里的元件游玩时不显示 |
| 界面布局**被职业引用**了 | 战斗预设 → 职业 → 选择布局 |
| 那个节点在**客户端控件容器**里（或它就是容器本身） | 看层级 |
| 容器**激活 + 可见** | 容器属性里勾上 |
| 名字是精确的 `root` | 没有空格、没有 `(1)` 后缀、大小写一致 |
| `board` 是 `root` 的子节点，`cell.1.1` 是 `board` 的子节点 | 看层级 |

⚠️ **改完名字要【界面控件组管理】→【保存修改】→ 保存关卡 → 重新试玩**，否则改动不进游玩态。

## 附：格子自动生成失败怎么办

真机实测会看到这条：

```
[murdoku] 有 24 个格子还没建，想自动生成但失败了（模板索引 1073741848，接口返回 nil）…
```

**原因**：`cell.1.1.prefabIndex` 返回的往往是**「预设按钮」这个基础控件的索引**
（这台机器上是 `1073741848`），拿它去 `InstantiateClientUIControl` 会**静默返回 nil**
（不报错）—— 基础模板不允许这样实例化。

**正确做法**（三选一，推荐 1）：

1. **纯模板模式（推荐，本工程当前采用）**：
   - 界面控件组管理 → 界面控件组库 → **客户端控件模板** →【添加客户端控件】
     → 加一个「预设按钮」、配好 `face`/`note`/`x` 子控件与状态节点 → **存为模板**；
   - 在 `board` 下新建一个「**模板引用控件**」去**引用**那张模板（**不能**用模板"新建控件"）；
   - 点击它读出 **`referencedPrefabIndex`**（**不是** `prefabIndex`），填进
     `lua/entry_client_script.lua` 的 `cfg.cells.prefab` → 重新打包同步。
   - 编辑器里**不需要建任何 `cell.*`**，25/36/49 格全部由脚本生成。
2. **手摆**：照 `docs/控件坐标表-1600x900.md` 手动把格子摆齐。
   脚本数到格子齐全就会**跳过生成**，只做「摆正」。
3. **靠扫描**：什么都不填，`cfg.cells.auto_scan`（默认开）会扫全树找可用索引 ——
   但它只能用**画布上已存在**的控件索引，所以仍需先放一个模板引用控件。

> ❌ **不要用「右键 `cell.1.1` →【另存为模板】」** —— 真机实测那个索引
> （`1073741864`）拿去实例化**照样返回 nil**。原因见
> 《客户端控件和客户端脚本的定义》：「服务器控件的模板索引**无法被客户端脚本调用**」。
>
> 权威版本见 `docs/本次搭建要求.md`（从代码自动生成）。

## 一张速查表

| 现象 | 病因 | 怎么办 |
|---|---|---|
| 未找到名单里**有**你确实建了的名字 | **时序**（OnStart 时树是空的） | 用新包，等重试（看 `started (retry N)`） |
| 树 0 个节点 + `放弃自动开局` | 布局没被职业引用 / 做在控件组库里 / 不在容器里 | 见上面 A 的三条 |
| 树有节点但缺某个名字 | 名字不完全一致（后缀/大小写/空格） | 看「近似 xx 的名字有：…」 |
| 树有节点但缺某个名字 | 挂错父级 | 按名单的缩进调整层级 |
| 有 `OnInit 在【…】失败` | 初始化某一步炸了 | 把整行发我 |
| 完全没有 `[murdoku]` 日志 | 脚本没执行 / 映射没关联 | 清单第 1 步 |
| `格子自动生成失败 … 返回 nil` | 模板索引是基础模板 | 见上面「附」的两条路 |
