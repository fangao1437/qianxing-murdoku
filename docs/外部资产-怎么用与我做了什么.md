## 二、重要发现：**「100+家具分享」是 3D 模型包，不是 2D 图片**

我把它解析了（`.gia` 与 `.gil` 同一个容器格式，能直接读）：

```
大小 1011840 字节    头：大小−4=1011836 ✅ 类型=3(.gia) 体长=1011816 ✅ 尾=0x679 ✅
varint 总数 103752
图片素材区间(100000–113000)：**0 个**     ← 没有任何 2D 图片素材
10^9~10^18 区间：7205 个（1079000000+ 是它自己的对象 id，另有颜色值 4294967295=白）

可读名字：bathroom_laundry__cleaning_cabinet__…  bathroom_laundry__cleaning_basket__…
```

**⇒ 里面是「3D 家具模型」（卫生间/清洁柜/洗衣篮…），不是 2D 图标。**
**⇒ 对我们的 2D 客户端 UI 没有直接用处。**

### 这还顺带说明了一件事

参考图（派蒙的执律庭实习）里那个"棋盘"**是俯视的 3D 场景** ——
格子上那些桌椅盆栽**是 3D 模型摆上去的**，不是 2D 图片。

**而我们这套是 2D 客户端控件**（实测：`cell.1.1 位置=(-237,237) 尺寸=124x124`）。
**⇒ 两者本质不同**：参考图的观感**没法在 2D 里完全复刻**。

## 三、我走的路：**自己画 → 导出 `.gia` → 你导入**

那个网站（Miliastra Image Editor）的 API 能程序化调用，于是：

```
我写 scene JSON（用基础图元描述图形）
  → POST https://qx.070077.xyz/api/export/gia   body={scene, giaGroupName}
  → 得到 .gia
  → 放进 Beyond_Local_Export
  → 你在千星「外部资产」导入
```

### 可用的图元（**这是编辑器里 `baseShapePresets` 的确切清单**，不是猜的）

| 图元 | 默认色 | 默认尺寸 |
|---|---|---|
| `ellipse` | #0f766e | 88×88 |
| `rectangle` | #c2410c | 102×70 |
| `triangle` | #7c3aed | 96×86 |
| `four_point_star` | #0f4c81 | 90×90 |

⚠️ **没有 `hexagon` / `line`**（我第一版猜的那两个不存在）—— 六边形得**拼**。

## 四、踩过的坑（都已修，注释在代码里）

| 坑 | 症状 |
|---|---|
| 直接 POST 场景本身 | **422** —— body 必须是 `{ scene, giaGroupName }` |
| `'file:///' + argv[1]` 判断"是否直接运行" | 路径含中文时 `import.meta.url` 是**百分号编码** ⇒ 永远不等 ⇒ **一行输出都没有**。用 `pathToFileURL()` |
| 头/尾都按小端读 | 尾读成 `0x79060000` ⇒ 误报。**全是**大端** |
| PowerShell `Set-Content -Encoding UTF8` 写 JSON | **加了 BOM** ⇒ `JSON.parse` 失败。要 `UTF8Encoding($false)` |
| 两个三角形想拼六边形 | 得到**八角星** —— 正解是**矩形 + 上下两个三角形** |
